# 解绑令签发流程（W57，用户 2026-10-31 批）

解绑令让一台机器人清机、解除和站点的绑定（W42 §7）。正常解绑在站点网页上做，**不需要解绑令**。只有站点用不了的时候才签：

- 站点主机坏了又没有备份，机器人还绑在旧站点上；
- 机器人转卖、换客户，原站点不配合解绑。

一张解绑令只对一台机器人（序列号）有效，24 小时内用，用过一次就作废。

## 一、客户申请

客户的管理员发邮件给公司，附上：

1. 机器人序列号（机器人身上贴纸上的 SN）；
2. 贴纸照片；
3. 购买凭证（合同、发票）；
4. 为什么要解绑。

## 二、公司核对

核对人（公司指定的人）对照销售记录核实：

- 这个序列号是卖给这个客户的（或有转让证明）；
- 申请人是这个客户的管理员（邮件来自客户登记过的联系人）。

对不上就不签，回邮件说明原因。

## 三、签发

插上放解绑令钥匙的加密 U 盘，在你的电脑上：

```bash
.venv/bin/python -m d1max_patrol.cli unbind-token sign \
  --private /media/<主U盘>/nexus-keys/unbind.key --serial <序列号> \
  --ledger <公司内部的>/解绑令台账.csv \
  --requester "<客户名 · 管理员姓名>" --checker "<核对人>" --purpose "<原因>"
```

- 屏幕上打出的一行 `D1MAXUNBIND1.…` 就是解绑令（也可以做成二维码，手机能扫）。
- 台账自动追加一行：时间、序列号、申请人、核对人、用途、过期时间、这张的随机号、钥匙编号。**台账放公司内部，不进仓库**。
- 有效期缺省 24 小时（`--hours` 可改，机器人最多认 7 天）。

## 四、交付和使用

- 把解绑令发给客户管理员或去现场的工程师（邮件或当面）。
- 在机器人旁边打开手机 App：站点列表右上角「设置」→「工程师工具」→「用解绑令解绑机器人」；粘贴或扫描解绑令，再扫机器人贴纸（手机会连上机器人的热点）。
- 机器人核对签名、序列号、有没有过期、有没有用过，然后清机，回到出厂状态。

## 五、钥匙丢了或泄露

见 `docs/钥匙生成与保管.md` 第四节：新公钥随下一次发行装进机器人；泄露的旧钥匙写进作废名单。
