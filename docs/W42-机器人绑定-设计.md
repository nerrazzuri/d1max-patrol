# W42 机器人绑定与解绑 · 设计

> 2026-10-30。来源：`docs/狗绑定与解绑-设计要点.md`（用户 10-27 定的方向，10-30 补了路由器、热点隔离、贴纸、改 WiFi 要站点确认）。
> 这份把方向落成能开工的做法；标「我定的」是我替你拿的主意，你可以改。**用户 2026-10-30 批了（「开始吧」），开工一期。**

## 1. 要做到什么

- 客户（业主、管理员）自己把一台新机器人加进站点：手机扫上装贴纸、填庄园 WiFi、站点上点批准。不用工程师、不用登进机器人。
- 客户自己解绑（转卖也走这条），机器人回到「没绑定」，同一张贴纸给下一位主人用。**解绑 = 恢复出厂**：机器人上这个客户的地图、录像、记录全部删掉（用户 10-30，见 §5.4）。
- 庄园 WiFi 换了，客户用热点重新配网；**改 WiFi 要站点确认**，路人扫贴纸改不了。
- 站点主机坏了又没备份：工程师拿「一台一张、24 小时、用一次」的解绑令解。

**不做**：公司后台在线签解绑令（W43）；机器人自己选站点、自动发现站点；一台机器人同时属于两个站点。

## 2. 名词

| 叫法 | 是什么 |
|---|---|
| 绑定码 | 每台随机 16 位（Crockford Base32，80 位随机），印在贴纸上。机器人里只存它的 SHA-256。证明「人就在机器人旁边」。 |
| 贴纸二维码 | `D1MAXBOT1.<base64url(JSON)>`，JSON：`s` 序列号、`c` 绑定码、`w` 热点名、`p` 热点密码、`f` 机器人配网证书指纹（前 32 位十六进制）。跟站点配对码 `D1MAXSITE1.`、开通码 `D1MAX1.` 前缀不同，扫错当场认得出。 |
| 配网服务 | 3588 上一个小服务 `d1max-bind`，只在路由器 LAN1 那一侧开一个端口（8450，HTTPS），热点上的手机只能碰到它。 |
| 绑定申请 | 机器人连上站点后在站点上挂的一条「等待批准」。 |
| 解绑令 | `D1MAXUNBIND1.<…>`：序列号 + 到期时间 + 随机号，用公司解绑钥匙（Ed25519，跟发行钥匙分开）签名。 |

机器人在站点上的编号 = **序列号**（我定的：省得批准时再起编号；显示名照旧可以改）。

## 3. 出厂：烧写工具

`d1max-patrol factory burn --serial <序列号>`（生产线上跑，3588 已刷好系统）：

1. 生成绑定码、热点名（`NW-<序列号后 6 位>`）、热点密码（随机 16 位）、配网服务的证书和私钥（自签，私钥只在机器人上）。
2. 写进 3588：`/etc/d1max/device.json`（序列号、绑定码哈希、热点名、证书指纹），`/etc/d1max/bind/` 下证书私钥，`unbind-pub.pem`（公司解绑公钥）。
3. 写进路由器：热点名、热点密码、改掉默认管理密码（每台随机，存进 `device.json`，只有 root 读得到）、VLAN 和两条防火墙规则（见设计要点「热点和内网怎么隔开」）。**怎么写进路由器见 §8，要等硬件答复。**
4. 出贴纸打印文件（PNG + PDF，60 × 40，二维码 30 mm），打完删掉，生产线不留。
5. 出厂检验：`d1max-patrol factory check --scan '<扫贴纸得到的那串>'`，核对绑定码哈希、热点名、证书指纹都对得上，再加上原来的 `selfcheck`。

工程师重新做贴纸（贴纸坏了）：`d1max-patrol factory rekey`，绑定码、热点密码、配网证书一起换，旧的作废。**只能在机器人没绑定、或者拿着解绑令的时候做**（我定的：不然拿着 root 的人可以绕开站点）。

## 4. 机器人这头：配网服务 `d1max-bind`

以 root 跑（要写 `/etc/d1max`、重启代理、改路由器），跟代理分开：代理出问题不影响重新配网。

状态（存 `/etc/d1max/bind/state.json`）：`unbound` → `pending`（连上站点、等批准）→ `bound`。

**热点那一侧的接口**（HTTPS 8450；每个请求都要带绑定码，错 5 次锁 10 分钟）：

| 接口 | 什么时候能用 | 做什么 |
|---|---|---|
| `GET /status` | 一直 | 序列号、状态、站点名、WiFi 连着没有、走的 WiFi 还是 4G、有没有挂着的 WiFi 改动 |
| `POST /bind` `{wifi:{ssid,psk}, site:{url,fp,name}}` | 只在 `unbound` | 存下 WiFi 和站点，路由器连 WiFi，去站点挂申请 |
| `POST /wifi` `{ssid,psk}` | 只在 `bound` | 按 §6 的规则改 WiFi |
| `POST /unbind` `{token}` | `bound` / `pending` | 验解绑令，清掉站点身份，回 `unbound` |
| `POST /cancel` | 只在 `pending` | 放弃这次绑定，回 `unbound` |

没有「换站点」接口：`bound` 时 `/bind` 一律拒。

**跟站点的往来**：机器人连站点 HTTPS 一律钉站点证书指纹（跟现在 `provision` 一样）。

**跟代理的往来**：本机 unix 套接字 `/run/d1max/bind.sock`。代理把「有 WiFi 改动等确认」报给站点、把站点的「确认 / 解绑」命令转给配网服务。

## 5. 站点这头

### 5.1 绑定申请

- `POST /api/bind/request`（**不用登录**，机器人调）：`{serial, nonce, model, version}`。站点记一条申请，回 `{request_id, poll_secret}`。
  - 同一序列号重复申请：替掉旧的那条。最多同时挂 10 条，多了回 429；每个来源地址每分钟 5 次。
  - 序列号已经绑在这个站点、没吊销：拒（「已经在这个站点了」）。
- `GET /api/bind/request/<id>?secret=…`（机器人轮询，5 秒一次）：`pending` / `rejected` / `approved`。
  `approved` 时带上开通令牌和 MQTT 地址，机器人接着走**现有的** `/api/enroll/claim` 领证书包，后面跟现在的 `provision` 一样。
- **24 小时**没人批准就作废（我定的：装机当天不一定有人守在控制室）。
- 批准（`manage` 权限，再输一次密码，跟解绑一样）：可以顺手起显示名。站点内部做的就是现有的 `enroll` + `enroll-code`。
- **核对码**：申请上显示一个 6 位数（从 `nonce` 算出来），手机向导上也显示同一个。两边对得上再批，防止有人冒用序列号挂假申请。

### 5.2 界面

- 网页「机器人」页：顶上一块「等待批准」，每条显示序列号、核对码、申请时间、从哪个地址来；按钮「批准」「拒绝」。
- 手机：同一块放在机器人列表顶上；有新申请推送给有 `manage` 权限的人。
- 原来的「添加机器人（开通码）」挪进「高级」，留给工程师兜底；命令行 `enroll` 不动。

### 5.3 解绑

- 站点点「解绑」：**先**通过 MQTT 给机器人发 `unbind`（机器人按 §5.4 恢复出厂，回 `unbound`），**再**走现有的吊销。机器人收没收到都照样吊销。
  确认框写明「机器人上的地图、录像、记录会全部删除，不能恢复」。
- 吊销后 MQTT 那边要重新加载 CRL 才拒连：现在是回给网页一句「去重启 broker」，改成站点自己重新加载（我定的，开工时看 broker 怎么起的再定具体做法）。
- **机器人当时不在线**：配网服务每 10 分钟问一次站点 `GET /api/bind/state?serial=…&cert=<证书指纹>`（钉指纹，不用登录，只回 `active` / `revoked` / `unknown`）。回 `revoked` 就自己清掉、回 `unbound`。
  `unknown`（站点重装了、没这台）不动，免得站点换机器的时候机器人把自己清了。

### 5.4 解绑 = 恢复出厂（用户 10-30）

三条解绑的路（站点点解绑、机器人发现自己被吊销、解绑令）最后都走同一个「清机」：

1. 停掉所有我们的服务（代理、定位、导航、避障、人员识别、雷达合并、外挂进程），解绑完成前不再起来。
2. **删**：
   - 数据根 `/var/lib/d1max` 整个（地图、发件箱、事件簿、录像片段、人员截图、幂等记录、定位和人员的本机套接字）；
     `D1MAX_OUTBOX` 指到别的盘的，那个目录也删；
   - `/etc/d1max` 里跟站点有关的：证书和私钥、`registration.json`、`evidence-pub.key`，`env` 里的站点地址、对时地址、
     地图号、原点等站点那几行；
   - 系统日志（journald 里我们服务的日志有位置、事件）；
   - 路由器里存的庄园 WiFi 名和密码。
3. **留**（出厂就有、跟客户无关的）：系统和程序、`device.json`（序列号、绑定码哈希、热点）、配网证书、解绑公钥、发行公钥、
   硬件标定和设备配置（雷达外参、`payload.json`、`board.json`、`cameras.json`）。
4. 删完对数据盘做一次 `fstrim`（固态盘上光删文件不保证数据真没了，trim 让盘把那些块真正丢掉）。
5. 全部做完才把状态改成 `unbound`、才回「解绑完成」；半路断电，开机接着清（状态先记成 `wiping`）。

做不到「物理上一定恢复不出来」：固态盘删了再 trim，一般工具读不回来，但不能保证专业设备也读不出。
真要做到，得把数据盘整个加密、解绑时销毁密钥 —— 这要在出厂镜像里分区加密，放进二期跟硬件一起定（我定的，你可以改）。

## 6. 改 WiFi（用户 10-30 定）

1. 手机连热点、扫贴纸，`POST /wifi`。
2. 配网服务判断机器人现在连不连得上站点（最近 2 分钟内跟站点通过）：
   - **连得上**：新 WiFi 先挂着，代理报给站点。站点网页、业主和管理员的手机弹「机器人 X 要把 WiFi 换成 …，确认吗」。
     确认了才换；换了以后 5 分钟连不上站点就退回旧 WiFi，并报给站点。没人确认就一直不生效（挂 24 小时作废）。
   - **连不上**（客户刚换了家里 WiFi）：先换新 WiFi 试连；连上站点就弹确认，**30 分钟**内确认就留下；
     没人确认、或者 30 分钟内根本连不上站点，退回旧 WiFi。
3. 手机向导一直显示进度（等确认 / 试连中 / 已生效 / 已退回）。

## 7. 解绑令（站点坏了、没备份）

- 公司那边：离线签名机上跑 `d1max-unbind sign --serial <序列号> --hours 24`，出一串字和二维码，发给现场工程师。W43 做出来以后改成工程师 App 在线申请。
- 机器人那边：验签名（出厂装的 `unbind-pub.pem`）、序列号对得上、没过期、随机号没用过（用过的记在 `/etc/d1max/bind/used-tokens`），然后清掉站点身份回 `unbound`。
- 解绑钥匙跟发行钥匙分开；私钥不进仓库、不进工程师手机。
- 3588 的时钟不准会影响「过期」判断：机器人认的是自己的时钟；用过一次就作废这一条不靠时钟。

## 8. 路由器：要等硬件或厂家答复

G806w 的 AT 指令（说明书第 10 章）只能**查**状态（`AT+NETSTATUS` 看走哪条线、`AT+WANINFO` 等），**不能设置**「WiFi 客户端连哪个 WiFi」；说明书里只有网页后台能改（4.6 节）。
配置备份是 `.tar.gz`，看着像 OpenWrt 系，可能有隐藏的接口，但说明书没写。

- 做法：代码里留一个「路由器」接口（连 WiFi、查连接状态、写热点和防火墙），先做一个假的给测试和演示站点用；G806w 的那份等答复。
- **要问硬件组 / 有人**：3588 怎么用程序改 G806w 的 WiFi 客户端（SSID、密码）、读连接状态？有没有 HTTP 接口、SSH、或别的；有人云的接口能不能离线用。
  实在没有，退路是我们照网页后台的请求去调（不稳，换固件可能失效）。

## 9. 手机 App

- 「添加机器人」向导：扫贴纸 → 选站点（已经配对过的站点） → 填庄园 WiFi（提示只支持 2.4 GHz） → 手机自动连热点、把东西发给机器人
  → 显示「连 WiFi… → 连站点… → 等待批准，核对码 123456」 → 手机断开热点回到正常网络 → 有 `manage` 权限的直接在手机上批准，没有的提示「请控制室批准」。
- 机器人详情页「改 WiFi」：扫贴纸 → 填新 WiFi → 显示 §6 的进度。
- 工程师入口（设置里藏一层）：扫解绑令 → 扫贴纸 → 解绑。
- 连热点：Android 用系统的「指定网络」方式（连上只给本 App 用，不影响手机上网）；iOS 要开「热点配置」权限（要在苹果开发者后台加）。
- 贴纸二维码坏了，可以手输绑定码；这时 App 核不了机器人证书指纹（只有二维码里有），会提示一句。（我定的：坏贴纸很少，工程师换贴纸就好。）

## 10. 安全小结

- 贴纸公开：绑定后的机器人，路人扫了只能看状态、提一个要站点确认的 WiFi 改动。
- 没绑定的机器人在装机那段时间里，有贴纸的人可以把它绑到**自己的**站点（要他自己的站点批准）。装机时间短，接受。
- 热点密码公开，热点上的流量别人能看：手机跟配网服务之间走 HTTPS、钉贴纸上的证书指纹，WiFi 密码不会被偷看。
- 热点上的人碰不到别的：路由器 VLAN + 防火墙、3588 的 nftables、不开转发（设计要点里那几道）。热像仪当明文设备，不另做（用户 10-30）。

## 11. 分两期

| 期 | 内容 | 要不要硬件 |
|---|---|---|
| 一期 | 站点：绑定申请、批准、核对码、解绑先通知、`bind/state`、CRL 自动重新加载；机器人：`d1max-bind`（假路由器）、跟代理的套接字；手机：添加向导、改 WiFi、工程师解绑；烧写和检验工具、离线解绑令工具；演示站点能演整套（假机器人带假热点） | 不要 |
| 二期 | G806w 路由器那份；3588 的 nftables 规则；样机实测（热点隔离四项、贴纸扫码距离、热点重连掉线） | 要 |

一期做完按惯例：全套测试 + 外审 + 演示站点真浏览器 / 真手机界面走一遍（演示站点通过就算完成）。

## 12. 要你看一眼的「我定的」

1. 站点上机器人编号用序列号。
2. 绑定申请 24 小时没人批作废；同时最多挂 10 条。
3. 批准要再输一次密码（跟解绑一样）。
4. 核对码 6 位，手机和站点两边对。
5. 重新做贴纸只能在没绑定或拿着解绑令的时候。
6. WiFi 改动在线时没人确认，24 小时作废；确认后换了 5 分钟连不上站点就退回。
7. 机器人不在线时被解绑：它每 10 分钟问一次站点，被吊销了自己清；站点回「不认识」不动。
8. 贴纸二维码坏了可以手输码，但核不了证书指纹。
9. 原来的「开通码添加」挪进「高级」留给工程师。
10. 清机先做「删除 + trim」；数据盘整盘加密、解绑销毁密钥放二期。
