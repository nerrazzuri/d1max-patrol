4. **叫停之后站点保持停着**（设计稿没提，内部评审应修）：以前狗上的软急停要人解除才能再动；站点
   的 halt 原来只是当场停车、中止任务，30 秒后排程照样把它派出去。现在站点记下「被谁叫停了」，
   派单、事件派遣、回待命点、遥控都不派，管理员、保安点「恢复」才派；业主能停不能恢复。
5. **狗说停车没成时站点回 502、手机说按机身急停**（内部评审）：以前 halt 一律回收下。

## 内部评审

只读子代理评审一轮（带实验：假根跑装机脚本四种情形、守卫模拟），结论先修再批准：阻断 1、应修 6、
小问题 7，**都已修或写进已知限制**：

- **阻断**：老狗升级上来，上一版是老服务那一代的槽（没有代理的启动脚本），老服务的单元又已经被
  装机脚本删了。新版代理连不上站点、没坐实，守卫数够次数退回老槽 —— 代理在那一版里起不来，狗
  就再也没有服务，只能重跑装机脚本救。→ **退不回去的就不退**：守卫留在新版、清掉在途标记、留条子
  （站点告警「上一版退不回去，狗留在新版」）；手工 `release rollback`、站点的「退」也拒；站点「上一版」
  不算老槽。
- **应修**：
  1. 6/7、7/7 只看文件在不在，不看代理的账号读不读得到证书 → 读不到就先不起。
  2. 叫停之后站点照样派单 → 叫停之后保持停着（见「与设计稿不同」第 4 条）。
  3. 暂停 / 继续 / 让开腿没了，没写出来 → 写进「丢了的能力」，请用户定。
  4. 手机遥控页切后台，定时器照样把按着的杆值发出去 → 切后台结束遥控，通知栏拉一下只发零速。
  5. `dist/` 里那个 APK 还被当成现场要带的包 → `dist/README.md`、现场执行单写明它不能用、要重编。
  6. 吊销之后 broker 要重启才重新读吊销表，文档没说 → 补上。
- **小问题**：老 env 缺新行不提示 → 逐个说；排程的 `robot` 键与 `ambiguous` 没写 → 任务包格式补上；
  老数据没人管 → 装机清单写明；部署测试只对字符串 → 加假根真跑；过时注释 → 改；
  停车失败照回收下 → 回 `stop_failed`、站点 502；SN 没人用 → 写进已知限制。
