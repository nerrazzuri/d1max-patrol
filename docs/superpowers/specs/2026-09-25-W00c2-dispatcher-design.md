## 0. 工单原文与范围

> 排程执行器迁站点（吸收 W06）、抢占与待命点（W14）、外部事件派遣（W16）；`schedule/alerts/baselines` 搬 site-node，删别名壳

事实（决定的依据）：

- **狗现在只会 `goto`。** 契约的资源表与断线策略表里只有 `goto`、`abort` 两行（`d1max_contract/resources.py`、`policy.py` 写明「其余任务类型各自工单再加」）。排程要派的是**整趟巡检**：多个点位、每点的动作（拍照、灯、云台、驻留）、策略（超时、重试、电量线、丢定位怎么办、循环几圈、归档留几天）。引擎 `MissionEngine` 早就会跑整趟 `Mission`，缺的是**契约里的任务类型**与代理侧的任务实现。没有它，站点排程没有东西可派。
- **老排程在狗上。** W06 的执行器是 `server.py::_StateHub._schedule_runner`：每 30 s 读任务包里的 `schedule.yaml`，`decide` → `pick` → 起飞检查 → `engine.start`。任务包（`engine/bundle.py`，1254 行）的设计原则是「**狗断网 72 小时还能照常上岗**」（商业化交付架构设计 §3.1）。总设计 §5 把排程归站点，这两条要对上：排程搬到站点，狗和站点之间断了，到点就不会自动出发。
- **排程与任务的解析是纯逻辑。** `schedule.py`（375 行）不碰盘、不看钟；`mission.py`（365 行）只依赖 `yaml` 与根包的 `Pose`。站点只许依赖契约包（W00c1 工作区测试守着），所以站点要用它们，得有一个双方都能 import 的地方。
- **`schedule/alerts/baselines` 还有老用户。** 老 HTTP 面（`server.py`、`app/alert_sources.py`、`app/watch.py`）、`inspect/judge.py` 都 import 它们；这些要到 W00c4 老 HTTP 面退役才没人用。别名壳 `d1max_patrol.engine` 被 81 个测试文件、`app/`、`cli.py`、`inspect/`、`d1max_console` 引用。
- **抢占的机制在代理里已经有了**（W00：资源账本、优先级、先停旧、等停止确认、再给新）。W14 缺的是**站点侧的规则**（什么任务能打断什么）与**待命点**（多个、做完回哪一个）。
- **外部事件的来源没定。** 方案书写的是 CCTV/AI 触发；具体品牌、推送方式（HTTP 回调、ONVIF 事件、MQTT）都没有资料。拦截点（站点权威的地图对象）目前也没有数据结构。

## 1. 决定一：W00c2 再拆三张

| 选项 | 内容 |
|---|---|
| **A（推荐）** | 拆三张，顺序做：<br>**W00c2a 巡检任务 + 站点排程**：契约加 `patrol` 任务类型（资源表、断线策略表各一行，黄金夹具）；代理 `PatrolTask` 在 `MissionEngine` 上跑整趟；站点存任务与排程、跑排程执行器（`decide/pick` 同一套，`last_started` 落库）、派 `patrol`。<br>**W00c2b 抢占与待命点**：站点侧抢占规则（优先级表、谁能打断谁、被打断的巡检怎么续）；多个待命点、任务结束回哪一个。<br>**W00c2c 外部事件派遣**：站点收外部事件的入口（先做一个签名 HTTP 回调）→ 选狗 → 去拦截点；拦截点进站点地图数据。<br>**模块搬家与删别名壳挪到 W00c4**：老 HTTP 面退役时它们才没有老用户，那时一起搬、一起删。 |
| B | 一张做完。改动量又回到万行级；外部事件那一块还缺输入资料 |

## 2. 决定二：巡检任务在契约里长什么样（针对 c2a）

| 选项 | 内容 |
|---|---|
| **A（推荐）** | **命令里带完整任务定义。** `patrol` 的 payload = `{"mission": <任务定义>, "map": {map_id, version}}`，代理用现有 `parse_mission` 校验、地图版本对得上才收、在引擎上跑。站点是任务与地图的权威（总设计 §1），狗上不需要事先有这份任务。大小：一趟 50 个点约 20 KB，在 broker 256 KB 上限内 |
| B | 命令里只带 `mission_id`，狗从本地任务包里找。报文小，但站点改了任务要先把包推到狗上，两份权威要对账 |

## 3. 决定三：排程在哪执行（针对 c2a）

| 选项 | 内容 |
|---|---|
| **A（推荐）** | **站点执行排程**（总设计 §5）。站点到点派 `patrol`；狗与站点断开期间不自动出发，到点的那一次按排程自己的 `on_missed`（`skip / run_late / alarm`）处理，恢复连接后站点补一条记录。代价：放弃「狗断网 72 小时照常上岗」 |
| B | 站点下发任务包，排程仍在狗上执行（老 W06 的执行器搬进代理），站点只看结果。保留断网上岗，但排程有两个执行者，谁起了哪一趟要对账；站点改排程要推包 |
| C | 站点为主，狗在断站点超过 N 分钟后按本地包兜底。最稳，也最复杂：两边都要实现、还要防重复出发 |

推荐 A 的理由：庄园场景里站点就在现场局域网上，「狗断站点」多半是狗自己出了问题（掉网、没电、死机），这时自动出发的价值有限；安防事件派遣（c2c）无论如何都要站点在线。若将来要断网上岗，可以在 A 之上加 C 的兜底，不推翻 A。

## 4. 决定四：站点上的任务与排程从哪来（针对 c2a）

| 选项 | 内容 |
|---|---|
| **A（推荐）** | **导入现有任务包**：`d1max-site import-bundle <目录>` 与 `POST /api/bundles`，复用任务包的格式与校验（`bundle.yaml` + `missions/*.yaml` + `schedule.yaml`）。手机端、工具链现在产出的就是这个格式，c4 之前不用改 |
| B | 站点 API 逐条增删改任务与排程（JSON）。更「SaaS」，但要新做编辑与校验，手机端也得跟着改 |

## 5. 决定五：解析代码放哪，让站点与代理都能用（针对 c2a）

| 选项 | 内容 |
|---|---|
| **A（推荐）** | **任务与排程的数据模型、解析、`decide/pick` 搬进契约包**（`d1max_contract.mission`、`d1max_contract.schedule`），它们本来就是「狗与站点之间的约定」。`mission.py` 依赖的 `Pose` 一起给契约一个最小版本（`x, y, yaw`）。robot-agent 的 `engine/mission.py`、`engine/schedule.py` 改成转手 import 契约里的，老用户不受影响。契约包因此多依赖 `PyYAML`（已在离线轮子里） |
| B | 站点自己抄一份解析代码。最快，但两份会漂移 |
| C | 站点依赖 robot-agent 包。违反总设计的分层（站点不该装狗上的代理） |

## 6. W00c2a 的形状（按推荐项）

- **契约**：`patrol` 进资源表（`motion`、`camera`、`light`、`head`）与断线策略表（`continue_if_safe`，排队 `abort`）；`d1max_contract.mission`、`d1max_contract.schedule`、最小 `Pose`；黄金夹具加 `patrol` 命令。
- **代理**：`PatrolTask`（`EngineGotoTask` 的推广：整趟 `Mission`、每个航点的结果进事件 `patrol_waypoint`、终态映射同 goto）；能力报文里 `tasks.patrol`；`engine/mission.py`、`engine/schedule.py` 改为转手。
- **站点**：`missions`、`schedules`、`schedule_runs` 三张表；`import-bundle`；排程执行器（每 30 s 一拍，时区跟任务包走，`last_started` 落库，站点重启不重复起；钟偏超阈值不起，沿用 `clock_skew`）；`POST /api/robots/<id>/patrol`（手动起一趟）；`GET /api/schedule`（每条排程下次何时、上次结果）。
- **验收**：导入一个任务包 → 排程到点 → 站点派 `patrol` → sim 狗跑完整趟（拍照动作在 sim 上记事件，不真拍）→ 站点记下这趟的结果；站点重启后同一时刻不再起第二次；狗离线时到点 → 按 `on_missed` 处理并记账。

**不在 c2a 内**：抢占规则与待命点（c2b）、外部事件（c2c）、照片与证据回传站点（§3.4，另开工单）、手机（c4）。

## 7. 风险

- 决定三选 A 等于正式放弃「狗断网 72 小时照常上岗」。这条写在早先的商业化交付架构设计里，拍板时请确认。
- 契约包多一个 `PyYAML` 依赖；狗上与站点上都已经有它（根包依赖它）。
- sim 狗不会拍照：`photo` 动作在 sim 上只记事件。真拍照与照片回传站点要等真机与证据链路工单。
