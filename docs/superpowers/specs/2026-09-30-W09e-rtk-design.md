## 摸底

- 狗上 RTK 模组 LK1220D 在 `/dev/ttyTHS3` @ 460800，被厂家驱动 `sixents_gps_driver`（root，`/opt/runtime/bin/start_rtk_driver.sh`）独占；厂家驱动的改正只认六分 SDK、
  发 `/rtk_pvh`（`robots_dog_msgs/UniRtkPvh`：`pos_type`、`svs_num`、`diff_age_s`、经纬度与标准差）。模组的输出格式与配置命令（Unicore 风格）没核过。
- 代理跑在 venv 里、**没有 ROS**；ROS 的东西在系统 Python（定位器、建图脚本都是这样）。
- 站点到狗只有 `cmd`、`teleop` 两种下行主题（mTLS + ACL，按狗分）。
- 定位：W09a 的桥 + W09b 的定位器；已知限制「定位器自信地跳错、之后一直稳定地错」要绝对参照（RTK 或人）。地图版本的平面系由 `frames.json` 定（W09c）。

## 决定（都按推荐）

### 一、改正数据与 RTK 来源（W09e 第 1 块）

1. **站点收基站**：`d1max-site serve --rtcm-source serial:/dev/ttyUSB0:115200` 或 `tcp:<主机>:<端口>`（UM982 直连站点主机的 USB 串口，或经网口 / 串口服务器）。
   按 RTCM3 帧切（`0xD3` 头、10 位长度、CRC-24Q），坏帧丢、计数；每读到一批好帧就发给**每台在线的狗**。1005/1006 报文解出基站坐标（给人看）。
   串口不装 pyserial：termios 裸模式。没配就不起。
2. **经 MQTT 下发**：新的下行主题 `site/<s>/robot/<r>/rtcm`，QoS 0、不保留（改正数据过时了没用，不补投）；broker ACL 站点写、狗读自己的；代理的主题守卫放行订阅。
3. **狗上的 RTK 来源接口**（决策 21）：`RtkSource`：`start()`、`close()`、`feed(rtcm字节)`、`latest() → RtkFix | None`。两种实现，`--rtk own|vendor|none`（默认 `none`，**不动厂家驱动**）：
   - **`own`**：我们自己的串口驱动（`--rtk-device /dev/ttyTHS3 --rtk-baud 460800`）：读线程按行解 NMEA **GGA**（定位质量 0/1/2/4/5 → 无 / 单点 / 差分 / 固定 / 浮点，
     卫星数、HDOP、经纬高、差分龄期）与 **GST**（经纬标准差）；`feed` 把站点转来的 RTCM 原样写进串口（锁住写）；起来时按配置发一串初始化命令
     （`--rtk-init` 文件，一行一条，比如让模组出 GGA/GST；**默认空** —— 模组命令没核过，真机项）。**用它的前提是停掉厂家驱动**（串口独占），这一步归装机、
     由人决定，代码里不碰。
   - **`vendor`**：读厂家驱动发的 `/rtk_pvh` —— 代理没有 ROS，经一个小辅助进程 `deploy/d1max-rtk-vendor`（ROS 系统 Python，订 `/rtk_pvh`、一行一条 JSON 吐到标准输出）；
     代理起它、读它的输出。改正走厂家那一套，`feed` 什么都不做（说一句「厂家模式：改正归厂家」）。
4. **`RtkFix`**：`{fix, lat, lon, alt, sats, hdop, std_h_m, age_s, stamp_ms}`（`fix` ∈ `none|single|dgps|float|fixed`）；遥测带 `rtk`（每拍最新一条，
   超过 2 s 没更新算 `stale`）；老狗不带。站点单狗视图、值守汇总、手机单狗页显示「RTK：固定 / 浮点 / 单点 / 无，卫星 N，精度 X cm，改正龄期 Y s」。
   能力里 `rtk: {"source": "own|vendor"}`。

### 二、地图与经纬度配准（W09e 第 2 块）

5. 边走边建 / 录包时代理把 RTK 解按收到的时刻记进包目录 `rtk.jsonl`（只记 `fixed`/`float`）。
6. 建图脚本 `--rtk <rtk.jsonl>`：MOLA 轨迹（雷达位置）按 `frames.json` 投到地图平面，跟同一时刻（±0.1 s）的 RTK 解（经纬高 → 以第一个固定解为原点的 ENU）配对；
   只用固定解、至少 20 对、走过的范围至少 10 m；二维刚体（旋转 + 平移、不缩放）最小二乘；残差 RMS > 0.3 m 不写（`build.json` 记原因）。写 `geo.json`：
   `{"origin": {"lat", "lon", "alt"}, "yaw_deg"（地图 x 轴相对正东，逆时针）, "tx", "ty"（ENU 原点在地图系的位置）, "rms_m", "pairs", "antenna_in_base": [x, y]}`。
   **可选文件**：没有 RTK、配不上都不影响这一版能用（不进 `GEOMETRY_FILES`，进清单、校验照常）。天线相对雷达的杆臂按 `--rtk-antenna x,y`（机体系，默认 0,0 —— 真机量）。
7. 不做：高程配准、双天线航向（`UNIHEADING`）、PPP、基站坐标自测平均（UM982 的基站模式配置归装机，真机项）。

### 三、RTK 进定位（W09e 第 3 块）

8. 代理这一侧（W09a 的桥之后）加 **RTK 核对**：正在用的图有 `geo.json`、RTK 是**固定解**且标准差 ≤ 0.10 m、改正龄期 ≤ 5 s → 把 RTK 换到地图系（加杆臂）跟定位器的
   位姿比：连续 3 s 差 > max(1.0 m, 3σ) → **定位器不可信**（「RTK 说差 X m」），请定位器在 RTK 位置附近重定位（朝向用定位器的，W09a 的自动重定位那一路）；
   对上了什么都不做（第一版不拿 RTK 顶替定位器、不做因子图融合）。浮点解、单点解只给人看，不参与判断。
9. 不做：RTK 主导定位（开阔草坪上 RTK 直接给位置）、GNSS-LIO 紧耦合、双天线 —— 要真机数据定。

## 真机项（摘要）

模组的输出格式与初始化命令、停厂家驱动之后我们的串口读写、UM982 基站模式与 RTCM 报文、站点主机的串口、WiFi 下改正龄期、固定解多久出来、杆臂、树下失锁、配准残差、
RTK 核对抓不抓得住定位器跳错。

## 测试

- 契约：RTCM3 切帧（好帧、坏 CRC、半帧拼接、垃圾字节里找头）；新主题与 ACL；遥测 `rtk` 往返、老狗不带。
- 站点：假串口（pty）与 TCP 源喂录好的帧 → 发给在线的狗、不发给离线的；坏帧计数；1005 解出基站坐标；没配不起。
- 代理：`own` 用 pty 当模组：GGA/GST 解析（各种定位质量、坏校验和、半行）、RTCM 原样写进去、初始化命令、串口断了重开；`vendor` 用假辅助进程；
  `none` 不起；遥测与能力；录包时记 `rtk.jsonl`。
- 建图脚本：合成轨迹 + 已知旋转平移的 RTK 解 → 解出 `geo.json`（误差 < 5 cm）；对数不够、范围太小、残差太大不写；杆臂。
- RTK 核对：对得上不动；固定解连续差 > 1 m → 不可信、按 RTK 重定位；浮点解不参与；龄期太老不参与；没有 `geo.json` 不参与；单帧跳一下不触发。
