# W00c5d · 维护功能与数据搬到站点 —— 设计稿

日期：2026-09-25 · 工单：W00c5d（L，依赖 W00c5c）
状态：**按推荐（用户 2026-09-25 授权连续推进：「从W00c5a到W00c5e直接做完」；「W00c5d都在服务器上，所有信息都不能在狗上，除非网络断联，若断联，临时存储到临时硬盘/狗子上，硬件还在确认中」）**。七个决定都取推荐项。**受决策 8 约束**。

## 0. 事实（2026-09-25 摸底）

- **决策 8**：站点是唯一权威；狗上只许有运行必需的工作副本（当前地图、正在跑的任务、幂等记录，可随时从站点重下）与**断网暂存发件箱**（恢复后上传、站点确认即删，位置可配置、有上限）。
- **狗上 `server.py`**（74 条路由 + 静态页）里的维护功能：
  - 盘况：`/api/storage`、`sweep`、`/api/upload`；
  - 建图：录包、离线重建、进程日志；地图：列表、载入、栅格、回家点、初始位姿；
  - 任务运行记录：列表、详情、照片、报告、判读、复核；
  - 导出：打 zip、下载、确认；备份：备份盘初始化、同步、弹出，每 60 s 自动同步；
  - 发布：安装（包得先在狗上）、激活、回滚、自检；任务包：应用、回滚。
  - 手机只用盘况；其余只有 `server.py` 自带的网页在用，有的根本没人用。
- **上传链路只有一半**：
  - 狗这头的上传队列与分块上传都在：1 MiB 一块；站点按已存前缀重算 sha256，对上才算这块传到；断了续传；
  - 站点那头的接收端**从来没写**（`d1max_console` 只有存储类，没有 HTTP 入口，也没有鉴权）；
  - 只有 `server.py` 起上传泵，代理（`d1max-agent`）不起。
- **代理模式下的运行记录**：巡检任务在引擎上跑，照片等落 `store_dir/runs`，没人上传、没人删。
- **盘况**：站点告警登记了 `disk_80/upload_backlog/bundle_lag`，但没有来源；值守汇总里狗的四个存储字段恒为空（`NO_DOG_STORAGE`）；遥测和能力里没有存储字段。
- **地图**：
  - 代理的 `loaded_map` 是环境变量里写死的；HAL 没有地图原语；
  - 自建图路线（录包 → slam_toolbox 离线重建）在狗上（要 ROS）；厂商图在厂商导航服务里，拿不出来。
- **判读**：在狗上同步调云端大模型（网络为主，不吃算力），基线在狗上。
- **发布**：
  - 双槽、启动后自检、失败回滚都有；特权操作走 sudoers 白名单；
  - **缺口**：包得先在狗上，没人下载；HTTP 装机不建 venv。
- **站点**：
  - API 与 broker 用站点 CA 签的同一张服务端证书；
  - 狗上有 `/etc/d1max/tls/{ca.crt,robot.crt,robot.key}`（MQTT 的 mTLS 用的）；
  - 站点没有地图、运行记录、证据、备份、发布的表与接口。

## 1. 决定一：狗与站点之间搬文件走什么

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | **狗专用的 HTTPS 口**（`--intake-port`，默认 8444）。**mTLS 必须**，与 MQTT 同一张站点 CA、同一份吊销表，另外按登记表核对证书指纹：狗的身份就是证书，不另发令牌。上行沿用现成的分块续传协议（`PUT /intake/put`，头里带相对路径、偏移、总长；站点按已存前缀重算 sha256 回执）；下行（地图、发布包）在同一个口上 `GET`。手机从不碰这个口，防火墙可以只放狗段 |
| B | 文件走 MQTT。照片、录包按块塞进 broker，持久会话里堆大包 |
| C | 跟手机共用 API 口、客户端证书可选。两套鉴权混在一个处理器里，出错面大 |

## 2. 决定二：狗上留什么、什么时候删（决策 8 落实）

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | **发件箱** = 代理的 `--outbox`（默认 `/var/lib/d1max/outbox`，可以指到临时硬盘）+ 上限 `--outbox-max-gb`（默认 20）。<br>• 运行记录、照片、建图录包、生成的地图都**直接写进发件箱**，边跑边传。<br>• **站点确认一整趟都收到了、而且这一趟已经结束**（任务进终态），代理就把这一趟整个删掉；没确认的一个字节都不删。<br>• 水位：发件箱所在的盘用到 80% → 站点告警 `disk_80`；到 90%、或发件箱超上限 → 代理拒绝新的巡检（`storage_full`），事件派遣的 `goto` 照接（不拍照、不产生文件）。<br>• 狗上别的东西：当前地图（工作副本）；事件簿与幂等记录**压实**（已确认的事件、超过 24 h 的幂等记录定期清掉，不再只增不减） |
| B | 传完不删，等人工清理（现在的 `sweep`）。违反决策 8 |
| C | 超上限时自动删最老的没传完的。等于静默丢证据 |

## 3. 决定三：盘况怎么上站点

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | 遥测里加可选的 `storage`，每 10 s 带一次：发件箱所在盘的已用比例、发件箱字节数与上限、待传文件数与字节数、最老一条待传的等待时长。站点收下存进状态，告警来源判两条：`disk_80`（已用 ≥ 80%）、`upload_backlog`（在线时最老待传超过 30 min）。值守汇总填上 `disk_used_ratio`、`upload_backlog`。`bundle_lag` 在代理模式下没有意义（任务随命令下发，狗上没有任务包），改为说明「狗上没有任务包」。`backup` 改为站点自己的备份状态（决定六） |
| B | 另开一个 `storage` 主题。多一条 ACL、多一份 retained，没必要 |

## 4. 决定四：运行记录、证据、判读、复核

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | **全在站点**。<br>• 站点收文件时按路径 `<机器人>/<任务>/<时刻>/<文件>` 落 `<站点目录>/evidence/`，并登记 `runs` 表（机器人、任务、时刻、状态、照片数、判读结论、复核状态）。<br>• **判读挪到站点**：一趟收齐之后，站点用现成的判读模块、站点上的基线（`<站点目录>/baselines/`）判；没配 API 密钥就都是 `pending`。<br>• **复核**在站点记（管理员、保安），会回写 `review.json`。<br>• API：`GET /api/runs`（按狗、时间段）、`GET /api/runs/<id>`、`GET /api/runs/<id>/files/<名字>`（`view`，业主也能看）、`POST /api/runs/<id>/judge`、`POST /api/runs/<id>/review/<照片>`。<br>• 手机站点模式加「记录」：列表 → 一趟的照片、判读结论、复核按钮 |
| B | 判读留在狗上、结果再传。基线在狗上，违反决策 8 |

## 5. 决定五：建图与地图

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | **站点有地图目录**，是地图的唯一权威。<br>• 表 `maps`：地图号、版本、来源狗、文件清单与哈希、状态。<br>• **狗上只有正在用的那一张**（工作副本）。<br>• 建图经站点：命令 `mapping`（开始/停止录包，不是任务、不动狗，由人经站点遥控开着走），录包写进发件箱、上传站点。<br>• 重建：命令 `map_build`，在狗上跑现成的离线重建（要 ROS）；生成的地图写进发件箱、上传，站点收齐登记成新版本。<br>• 下发：命令 `map_activate {map_id, version, 文件清单与哈希}` → 代理从站点下载到工作目录、逐个核哈希 → 适配器载入 → `loaded_map` 改成动态的，能力重发。<br>• 这几样都按能力开关（适配器没有就不报，站点就不给按钮）。厂商图在厂商服务里拿不出来：站点只记元数据，照旧按版本号挡派单 |
| B | 地图目录留在狗上、站点只看。违反决策 8 |

## 6. 决定六：导出与备份

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | **导出在站点**：管理员按时间段、按狗打 zip（站点证据库里的原样文件 + 清单 + sha256），经 API 下载，记审计。<br>**备份是站点自己的**：每小时一次，`sqlite3 backup` 出一份库，再把证据库增量镜像到 `site.json` 配的备份目录（站点主机上的外接盘）。值守汇总的 `backup` 显示上次成功距今多久，超过 25 h 出告警 `backup_stale`。狗上的备份盘、导出（`server.py` 那一套）随 W00c5e 退役 |
| B | 站点不管备份。站点成了唯一权威，就得有备份 |

## 7. 决定七：发布安装

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | **站点有发布目录**：管理员在站点主机上 `d1max-site release add <包>`（算 sha256、登记）。<br>• 命令 `release_install {name, sha256, size}` → 代理从狗专用口下载到发件箱旁的暂存目录、核哈希 → 用现成的 `release.install` 落槽 → **建 venv**（离线轮子在包里，补上 HTTP 装机缺的这一步）→ 回报「已暂存」。<br>• 命令 `release_activate`：要空闲（没有任务在跑）、电量够、盘够 → 现成的激活（写 pending、切链接、重启）→ 启动后自检过了才算提交，不过就回滚。版本号在能力里上报。<br>• 回滚：`release_rollback`。<br>• 站点 API：`GET /api/releases`、`POST /api/robots/<id>/release/{install,activate,rollback}`（管理员），记审计。<br>• **真机项**：真 Orin 上装、激活、自检、回滚都要跑一遍 |
| B | 发布仍靠 ssh 拷包。站点管不到版本，OTA 缺口还在 |

## 9. 验收

- **仿真端到端**：
  - 仿真狗巡检拍照 → 照片边跑边传到站点 → 一趟结束、站点确认 → 狗上这一趟没了；
  - 站点列表与详情看得到；判读（假模型）出结论；复核记下来。
- **断网**：站点↔狗断开期间照片留在发件箱；恢复后续传；确认前一个字节都不删。
- **发件箱与水位**：
  - 发件箱满了拒绝巡检、照接 `goto`；
  - 水位事实上站点，出 `disk_80`、`upload_backlog`；值守汇总有数。
- **鉴权**：接收口没有证书、证书吊销了、证书指纹对不上登记的，都连不上；狗 A 不能写狗 B 的路径。
- **导出与备份**：导出 zip 的清单与哈希对得上；备份目录里有库和证据；备份过期出告警。
- **地图**：站点下发地图 → 仿真狗载入 → `loaded_map` 变了 → 站点按新版本派单；哈希不对不载入。
- **发布**：临时目录里模拟双槽：站点下发包 → 代理核哈希、落槽 → 激活 → 自检过了提交；自检不过回滚。
- **真机项（3c）**：
  - 发件箱放在临时硬盘上；
  - 4G 下上传一趟的时长；
  - 真 Orin 上的发布安装、激活、回滚；
  - 建图录包上传的时长。
