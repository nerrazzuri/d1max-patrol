# W00c2c · 外部事件派遣 —— 设计稿

日期：2026-09-25 · 工单：W00c2c（M，依赖 W00c2b；吸收 W16「外部事件 → 选狗 → 去拦截点」）
状态：**按推荐（用户 2026-09-25 授权连续推进：「把整个 W00 跑完再给外审，都按你推荐的来」）**。四个决定都取推荐项。

## 0. 事实

- 方案书的触发源是 CCTV/AI；**具体品牌、推送方式没有资料**。所以入口要做成与品牌无关的一层，将来每种摄像头/NVR 写一个小转换器往这层推。
- 拦截点是站点权威的地图对象（总设计 §1），目前没有数据结构。
- 决策 5 已定：站点可下发任务级指令，不可遥控。事件派遣发的是 `goto`（任务级）。
- W00c2b 已有：优先级表（事件派遣 `80`，高于排程 10–49 与手动 60）、待命点与自动回。
- 站点现在不订遥测，不知道狗在哪。

## 1. 决定一：事件从哪进来

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | **签名 HTTP 回调** `POST /api/incidents`：每个事件源（`source`）在站点登记，得到一个共享密钥；请求头带 `X-D1MAX-Source`、`X-D1MAX-Timestamp`（毫秒）、`X-D1MAX-Signature = hex(HMAC-SHA256(密钥, 时间戳 + "." + 原始请求体))`。时间差超 5 分钟拒（防重放），同一 `(source, event_id)` 只处理一次。不走账号登录（摄像头不会登录），但只认登记过的源 |
| B | ONVIF 事件订阅。绑死一种协议，还要站点主动去连每台摄像头 |
| C | 摄像头直接发 MQTT。要给摄像头签证书、扩 ACL |

事件体：`{"event_id", "type", "zone", "occurred_at", "detail"?}`；`type` 先认 `intrusion`（其余记账不派）。

## 2. 决定二：事件怎么落到一个拦截点

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | 站点登记**拦截点**（名字、地图、x、y、yaw）与**防区 → 拦截点**的映射；事件报 `zone`，站点查映射。摄像头不需要知道地图坐标 |
| B | 事件直接带坐标。每台摄像头都要标定到狗的地图上 |

## 3. 决定三：派哪台狗

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | 能派的狗（在线、新鲜、就绪、地图对得上；**正在跑的巡检不算忙**——事件优先级更高，会抢占它）里**离拦截点最近**的一台；距离用狗最近一次遥测的位姿。没有位姿的狗排在有位姿的后面；都没有 → 按 robot_id 取第一台。站点因此订上遥测（契约的 `DispatchClient` 加遥测回调） |
| B | 固定一台「值班狗」。简单，但两台狗时浪费一台 |

## 4. 决定四：派出去做什么、重复事件怎么办

| 选项 | 内容 |
|---|---|
| **A（推荐，取）** | 以优先级 `80` 派 `goto` 去拦截点（抢占巡检与回程）；到了之后照常由 W00c2b 自动回待命点（「停留、驱离、保持距离」这些动作归后面的工单）。**同一防区 60 s 内的后续事件合并**到第一条，不重复出动；每条事件都进账（`incidents` 表：来源、类型、防区、拦截点、派了谁、task_id、去向、结果），并推给 SSE（`kind: incident`） |
| B | 每条事件都派一次。摄像头一次入侵报十几条，狗会被来回抢占 |

## 5. 形状

- 契约：`DispatchClient.on_telemetry` 与 `telemetry` 属性（订 `…/telemetry`）。
- 站点：`incidents.py`（事件源登记与验签、拦截点与防区映射、`IncidentDesk.handle`：验签 → 去重 → 合并 → 选狗 → 派单 → 记账 → 推送）；`dispatcher` 存每台狗最近的位姿；API `POST /api/incidents`（验签，不要登录）、`GET /api/incidents`（要登录）、`POST /api/intercepts`、`POST /api/zones`；CLI `source add`（打印密钥一次）、`intercept`、`zone`。
- 代理不改。

## 6. 验收

- 登记源 → 登记拦截点与防区 → 签名正确的事件 → 派 `goto`（优先级 80）给最近的狗 → 狗到拦截点 → 自动回待命点。
- 正在跑排程巡检时来事件 → 巡检 `preempted`，狗去拦截点。
- 签名错、时间戳过期、未登记的源 → 401，不派；同一 `event_id` 再来 → 200 但标 `duplicate`，不派；同一防区 60 s 内第二条 → 合并，不派。
- 防区没映射 / 没有能派的狗 → 记账（`unmapped` / `no_robot`），不派。
