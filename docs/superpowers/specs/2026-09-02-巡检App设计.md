## 1. 目标

把巡检的整条链路收进一个浏览器页面：**建图 → 在图上标点 → 编排任务 → 一键跑 → 实时看 → 判读 → 出报告**。

在此之前，这条链路散在五处：`field-agent.sh`（控制权）、`docs/建图定位与巡检管线.md` 里的十几条命令（建图定位）、`scripts/live_viewer.py`（看位置）、`scripts/patrol_snap.sh`（抓拍）、以及尚不存在的任务引擎。每换一步就要切一次终端，且顺序错了没人提醒。

### 1.1 已定的前提（不再讨论）

| 决定 | 内容 |
|---|---|
| 形态 | Python 起 HTTP 服务 + 浏览器单页。**纯标准库，无构建步骤** |
| 边界 | 建图也在 app 里（全流程） |
| 判读 | VLM 自动判读 + 人复核 |
| 使用场景 | 工程版，手动触发。现场有人、急停在手。不做无人值守、不做定时调度 |
| 跑在哪 | 先笔记本。代码不绑机器，板载作为后续部署目标 |
| 控制权 | app **不**接管，`field-agent.sh` 继续独立跑 |

**为什么不用现代前端栈**：现场笔记本要能 `git pull` 完直接跑，装不了 npm、可能没网。这条约束比"框架顺手"重要。页面用原生 JS 加 Canvas，不引任何在线 CDN 资源——外网不通时页面也必须完整。

## 2. 进程模型

三个进程，边界按**谁的命最长**划：

```
field-agent.sh ──→ patrol_agent (C++)              最长命：握着控制权
                          ▲ TCP 8090 JSONL         app 死了它也活着
                          │
                   d1max-app (Python)              中等：一次现场作业
                    ├ asyncio 线程：任务引擎 + NavBackend + DeviceBackend
                    └ HTTP 线程池：页面 / REST / SSE / MJPEG
                          ▲             ▲              ▲
                  8091 JSONL      8092 JSONL      RTSP 8554
              ros2_pose_bridge  ros2_map_bridge   ffmpeg → MJPEG
                （已有）           （新建）        最短命：一个观众一条
```

**为什么 app 不接管控制权**：控制权拿不回来（清单 #46/#47），一旦松手只能重启 RK3588 重抢开机窗口。app 是要频繁重启的东西——改代码、崩了、换配置。把一次抢不回来的东西绑在一个会频繁重启的进程上，是拿最贵的资源赌最便宜的方便。

### 2.1 app 内部：引擎不认识 HTTP

一个进程，两类线程，一条明确的桥：

- **asyncio 线程**独占任务引擎、`NavBackend`、`DeviceBackend`。**所有状态只有这一份**，无锁。
- **HTTP 线程池**（`ThreadingHTTPServer`）只管 HTTP 协议本身。SSE 与 MJPEG 各占一条线程，慢客户端不互相堵。
- 桥只有两个方向：
  - 下行 `asyncio.run_coroutine_threadsafe(engine.xxx(), loop)`，HTTP 线程等结果；
  - 上行复用**已有的** `EventEmitter`——事件扇出到每个 SSE 订阅者。契约测试里那套事件流是同一个东西，不新造。

这条边界的用处是：**任务引擎是纯库对象，不 import 任何 HTTP 的东西**，能脱离 app 单独测（主规范 §7.2 的第三层照跑）。将来要把引擎抽成常驻守护进程（改前端不打断正在跑的任务），只换这座桥，引擎不动。**现在不做**——还没有需要它的证据。

**代价（明确接受）**：重启 app 会打断正在跑的任务。机器随之停下，这是安全的一侧；控制权在 `field-agent` 手里不受影响；`events.jsonl` 边跑边落盘，断掉的那次能从盘上还原到哪一步。

### 2.2 端口

| 端口 | 谁开 | 用途 |
|---|---|---|
| 8090 | patrol_agent | SDK 旁路 JSONL（已有） |
| 8091 | ros2_pose_bridge | 地图系位姿 JSONL（已有） |
| 8092 | ros2_map_bridge | 占据栅格 JSONL（**新建**） |
| 8095 | d1max-app | 页面与 API |
| 8554 | 机器 | 前/后相机 RTSP（厂商，清单 #29） |

`scripts/live_viewer.py` 在 app 跑通后删除——它的能力被完整覆盖，留着只会分叉。

## 3. 地图桥（新建）

`tools/ros2_map_bridge.py`，与 `ros2_pose_bridge.py` 同一个模子：

- 零依赖 rclpy 脚本，跑在 ROS2 的系统 Python 下，**不 import 本仓库任何东西**；线协议权威定义在 `src/d1max_patrol/protocol/map_frames.py`，改协议要同时改两处。
- **单向：只出不进。** 没有命令通道，任何控制指令都无法经它误伤建图或定位。
- 订 `/map`（`nav_msgs/OccupancyGrid`），每收到一帧转成 JSONL 广播。
- 栅格可以很大（20 m × 20 m、5 cm 分辨率是 16 万格）。所以：
  - 帧内 `data` 用 **RLE + base64** 压，空闲区连成大段，实测压缩比很高；
  - 客户端要的是"看得见变化"而不是每帧都要，桥按 `--max-hz`（默认 1.0）**降频**，中间帧直接丢——占据栅格是全量快照不是增量，丢帧无损。

**为什么 `/map` 能收到而当初 AMCL 收不到**：AMCL 那条路死在 `map_server` 的 **latched** `/map` 上（zenoh 传不了 latched，清单 #63）。slam_toolbox 建图时发的是周期性重发的普通话题，不依赖 latched 语义。而且离线重建阶段（§4）跑在隔离域 + FastDDS 上，压根不经过 zenoh。

## 4. 建图：照搬已验证的离线管线

**现场跑通的是离线重建**（`docs/建图定位与巡检管线.md` §2）：录包 → 隔离域回放 → 存图 + 序列化。不是在线 SLAM。

app **不改这条管线**，只把它从十几条命令变成两个按钮：

```
[开始建图]   → app 起 ros2 bag record（实时域 24 + zenoh）
               ↓  你用页面上的遥控走一圈，绕回起点闭环
[停止并重建] → app 依次起 4 个进程（隔离域 93 + FastDDS + use_sim_time）：
                  async_slam_toolbox_node / static_transform_publisher /
                  pointcloud_to_laserscan_node / bag play
               ↓  地图桥推 /map，页面上看着图一格格长出来
               ↓  放完自动 map_saver_cli + serialize_map
[图出来了]   → 页面显示成品图，可命名保存，可直接拿去标点
```

**为什么不改成在线建图**：在线要让 `pointcloud_to_laserscan` + `slam_toolbox` 在实时域收 `/front_lidar`，而点云话题经 zenoh 的表现没验证过，zenoh 已经坑过一次（#63）。离线这条路是**现场亲手跑通过**的。而且录包本身有价值：参数不满意可以换参数重建，不用把狗再牵出来走一遍。

在线建图列为后续可选项，不在本版。

### 4.1 进程管理层

`src/d1max_patrol/app/procs.py`：

- 每个受管进程一份声明式配置：命令行、**独立的环境变量**（域号与 RMW 实现不同，这是硬需求）、日志文件、就绪判据、超时。
- 日志落 `runs/app-logs/<名字>-<UTC>.log`，页面上能实时尾随（SSE）——**建图失败时人得看得见为什么**，否则只有一个"失败了"。
- 生命周期与 app 绑定：app 退出时，所有它起的子进程一律 `SIGTERM` → 3 秒 → `SIGKILL`。**这跟 `patrol_agent` 相反**，因为这些进程都是可以随便重来的，留着只会占端口和域号。
- 用 `start_new_session=True` 起，杀的时候杀整个进程组——`ros2 launch` 会派生一堆孙子进程，只杀父的会留下孤儿占着话题。

## 5. 遥控：脉冲 + 守死人开关

页面上的方向键是建图时唯一的驱动方式，因此它的安全约束最硬。

- **每次按下发一拍**（默认 0.4 秒），松开即止，按住则连续补拍。这与 `LocalNavBackend` 是同一套脉冲哲学，理由也一样：`Move` 的量是百分比且有死区，控制量必须始终压在死区之上（清单 #37/#38），靠**缩短时长**而不是**降低控制量**来做小幅移动。页面上的"慢"按钮减的是每拍时长，不是控制量。
- **守死人开关**：页面每 200 ms 发一次心跳；服务端 600 ms 收不到就立刻停止遥控。切走标签页、页面崩了、WiFi 断了——机器都停。
- **遥控与任务互斥**：任务在跑时遥控被拒，反之亦然。判断在引擎层，不靠界面把按钮变灰（界面可能是旧的）。
- **急停常驻**：软急停按钮在所有页签上都在同一个位置，且不需要任何确认。
- 页面**明写**：实时画面有 0.5～2 秒延迟，**不得作为遥控依据**；遥控要求人在现场、急停在手。

## 6. 实时画面

`rtsp://<机器>:8554/front` 与 `/back`（清单 #29，`patrol_snap.sh` 已在用）。

浏览器放不了 RTSP，所以 app 用 ffmpeg 转 MJPEG：一个观众一条 ffmpeg 子进程，输出 `multipart/x-mixed-replace` 直接喂 `<img>`。

- 并发上限 2 条，超了返回明确提示而不是排队。
- 没装 ffmpeg / 拉流失败：页面显示**一句人话**（"拉不到前相机：ffmpeg 未安装"），不是一个破图标。
- 观众断开立即杀掉对应 ffmpeg——不然一晚上能攒出几十个进程。

## 7. 任务：在图上编，不写文件

### 7.1 任务定义格式

沿用主规范 §6.1 的 YAML，**新增一个字段**：

```yaml
waypoints:
  - name: P1_transformer
    pose: {position: {x: 1.2, y: 3.4, z: 0.0}, orientation: {...}}
    check: "配电柜门是否关闭，指示灯是否全绿"   # ← 新增：给 VLM 的判读依据
    actions:
      - {type: photo, camera: front}
```

**这是对主规范 §6.1 的唯一扩展**，理由：判读要求"该看什么"必须跟点位绑定。写成自由文本而不是枚举，因为每个点位要看的东西天差地别，枚举一定不够用；而 VLM 恰好吃自由文本。`check` 缺省时判读退化为"描述你看到的异常"。

任务文件仍存在 `missions/<id>.yaml`，**app 读写的就是这个文件**——不引数据库，不搞私有格式。手写 YAML 和在页面上编是同一份东西，随时可以互相切换，也能进 git 看 diff。

### 7.2 编排流程

1. 加载一张图，图渲染在 Canvas 上。
2. **点一下**放一个点位，**拖一下**定朝向（拖动方向即 yaw）。
3. 右侧给这个点位填名字、`check` 提示词、动作列表（`dwell` / `photo` / `light` / `head`）。
4. 拖拽调整点位顺序；顺序就是巡检顺序。
5. 保存 → 写 YAML。

**当前位姿一键取点**：站到想拍的位置，点"取当前位置"。比在图上估坐标准得多，也是现场最顺手的做法。

## 8. 运行与监控

`[跑]` → PREFLIGHT 五项检查（主规范 §6.2）逐条显示通过与否，**不通过就不启动，并指出是哪一条**。

跑起来之后页面上：机器在图上的实时位置与朝向、当前点位与进度、事件流（同 `events.jsonl`）、实时画面、电量。`[暂停] [继续] [中止]` 常驻。

安全与降级完全按主规范 §6.4 那张表，一行都不改。特别地：**ABORT 就是停车 + 记录 + 告警，不含任何自动位移**（不自动返航、不自动趴下）。

## 9. 判读：采集与判读彻底解耦

**跑完先落盘，判读是事后可重放的一步。** 断网照样跑完全程，回头有网再补判读。这不是退化路径，是默认设计——现场网络本来就不可靠，把判读放进采集的关键路径上，等于让一次跑白跑。

`src/d1max_patrol/inspect/judge.py`：

- 输入：一个 run 目录 + 任务定义里的 `check`。
- 对每张照片调 Anthropic Messages API，同时把**上一次同点位的照片**一并送进去做对比——照片文件名带点位名（主规范 §6.5），跨日期天然可聚合。
- 结构化输出：`{verdict: normal | abnormal | unclear, confidence, reason, evidence}`。
- 落 `findings.json`。人工复核写 `review.json`（**另一个文件**，绝不覆盖模型的原始结论）。
- 报告里两者都在：模型说什么、人改成了什么。**结论以人的为准**，但模型说过的话要留痕——事后追责时"当初模型提示过"和"当初没人提"是两回事。
- 模型默认 `claude-opus-5`，可配 `claude-sonnet-5`（量大时省钱）。密钥读 `ANTHROPIC_API_KEY` 环境变量，**不进配置文件、不进仓库**。
- 无网或无密钥：判读标记 `pending`，报告照出，页面上一个按钮随时重跑。

判读**永远是建议**。页面上模型给的结论和人给的结论在视觉上分得很开，不能让人以为模型的结论已经是定论。

## 10. HTTP 接口

```
GET  /                          单页
GET  /static/*                  app.js / app.css（随仓库走，无 CDN）
GET  /api/state                 全量快照（页面打开时对齐）
GET  /api/events                SSE：状态与事件增量

POST /api/backend               切后端 {name: vendor|local}
GET  /api/maps                  地图列表 + 当前后端的能力集
POST /api/maps/load             {map_id}
GET  /api/maps/<id>/grid        占据栅格（JSON，RLE）
POST /api/pose/initial          {x, y, yaw} 点图设初始位姿（仅 local 路线）

POST /api/mapping/record/start  起 bag record
POST /api/mapping/record/stop   停 bag record
POST /api/mapping/rebuild       离线重建 + 存图 {map_id}
GET  /api/mapping/live          SSE：重建过程中的栅格帧
GET  /api/procs/<name>/log      SSE：子进程日志尾随

POST /api/teleop                {fwd, lat, yaw, seconds} 一拍
POST /api/teleop/heartbeat      守死人心跳
POST /api/estop                 {on: true|false}

GET  /api/missions              任务列表
GET  /api/missions/<id>         任务定义
PUT  /api/missions/<id>         保存任务定义
POST /api/missions/<id>/run     跑
POST /api/run/{pause,resume,abort}

GET  /api/runs                  历史运行
GET  /api/runs/<id>             manifest + 事件 + 照片索引 + 判读结论
GET  /api/runs/<id>/photos/<f>  照片
POST /api/runs/<id>/judge       触发/重跑判读
PUT  /api/runs/<id>/review/<f>  人工复核结论
GET  /api/runs/<id>/report.{md,html}

GET  /api/video/<front|back>    MJPEG
```

**约定**：所有写操作是 POST/PUT，所有 GET 无副作用。错误返回 `{"error": "人话", "detail": "..."}`，HTTP 状态码取 4xx/5xx——**错误信息面向现场的人，不是给堆栈用的**。

**不做鉴权**，因为是局域网单人工程工具。作为交换，默认只监听 `127.0.0.1`；要跨机访问必须显式 `--listen 0.0.0.0:8095`，且启动时打印一行醒目警告。**绝不能接到公网**——这个页面能让一台四足机器人走起来。

## 11. 页面结构

单页，五个页签，左侧固定不动：

```
┌─────────────────────────┬──────────────────────────┐
│                         │  [建图][地图与点位][任务] │
│      地图 Canvas        │  [运行][判读与报告]       │
│   （机器位姿实时叠加）  │                          │
│                         │   （随页签变化的内容）   │
├─────────────────────────┤                          │
│   实时画面 前 / 后      │                          │
├─────────────────────────┤                          │
│ ● 定位桥 ● agent ● 控制权 ● 电量    [软急停]      │
└─────────────────────────┴──────────────────────────┘
```

- 地图、画面、状态灯、急停**永远在**，切页签不动。理由：这四样是"机器现在什么情况"的全部答案，任何时候都不该需要多点一下才能看到。
- 三盏状态灯分别是定位桥、`patrol_agent`、控制权。**控制权那盏灭了，页面上要直说"控制权丢了，只能重启 RK3588 重抢开机窗口"**，而不是一个红点——这个失败模式代价太大，不能让人猜。
- 响应式：手机上能看能急停，编排任务仍建议在桌面做。

## 13. 测试策略

沿用主规范 §7.2 的五层，本文只说增量：

- **地图桥线协议**：与 `pose_frames` 同规格的编解码测试，含一条拿 `ros2_map_bridge.py` 里手抄的字面量重放的对齐测试。
- **仿真地图桥** `SimMapServer`：与 `SimPoseServer` 同规格，让 app 能完全对着仿真器跑。**这是本设计的核心可测性安排**——建图、标点、跑任务、出报告，整条链路无真机可测。
- **进程管理层**：拿 `python -c "..."` 当被管进程，测启动、就绪判据、超时、杀进程组、日志落盘。不需要 ROS。
- **HTTP 层**：起真的服务、用 `urllib` 打真的请求。断言状态码、错误信息是人话、GET 无副作用。
- **守死人开关**：心跳停了必须在 600 ms 内停车——这条是安全测试，不是功能测试。
- **判读**：把 Anthropic 客户端做成可注入的，用假客户端测编排、重试、`pending` 落盘与重跑。**不打真 API**。
- **页面**：不引浏览器自动化。页面逻辑薄、状态全在服务端，值得测的都在服务端。

## 14. 第一版明确不做

- 定时调度与无人值守（控制权拿不回来、回充与卡住自救都没做，这条路现在走不通）
- 鉴权与多用户
