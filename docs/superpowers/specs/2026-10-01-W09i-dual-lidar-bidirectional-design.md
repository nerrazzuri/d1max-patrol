## 摸底（2026-10-01）

- 建图（MOLA）、定位器、建图预览只吃 `/front_lidar`；W11 感知有后雷达接口，但外参是猜的（前雷达镜像），只用它的「挡」。
- **6 个录包都只有前雷达**；后雷达话题 `/rear_lidar`（`rslidar_tail`）在不在发、多少帧，没在狗上确认过。
- DIFOP 里的出厂标定是**每台雷达内部 IMU ↔ 激光**的外参（`tools/lio/README.md`），**不是两台雷达之间的** —— 后雷达相对前雷达的外参只能自己标。
- SDK 能调转头尾（`ReverseHeadTail`）、报 `head_direction`；**调头之后 SDK 的里程、速度命令的正方向跟不跟着翻，没在狗上验过**。
- W11a：不是「狗头为前」就不许自己走（这一单做完之后放开）。

## 决定（都按推荐）

### 1. 两个坐标系，约定写死

- **机身系 B**：x 指向**狗头**（装前雷达 `rslidar_head` 的那一头），**不随调头变**。地图位姿的朝向、遥测、原点、巡检点的朝向（拍照方向）、定位器、
  感知的局部栅格、守卫，**全在机身系**。
- **行进方向** d：狗头为前 d = +1，狗尾为前 d = −1。只影响「往哪个方向走」：跟踪器按 d 走、守卫按速度的正负扫前面或后面、净空许可看那一头。
- **HAL 契约**：里程、速度命令**一律机身系**（vx > 0 = 往狗头那边走）。SDK 是不是跟着头尾翻，由**适配器**换算：
  d1max 适配器加参数 `sdk_follows_head`（默认 `true` = 调头之后 SDK 的「前」变成狗尾那边；**真机项**核），换算里程（x、y、yaw、vx）与速度命令。
  仿真狗本来就是机身系。这样调头那一刻里程不跳、锚定与定位桥的交叉校验都不受影响。

### 2. 后雷达外参：机身几何当初值，点云配准精修

- 存 `/etc/d1max/lidars.json`（每台狗一份，不跟图走）：`T_front_rear`（后雷达系 → 前雷达系，4×4）、`calibrated`（真标过没有）、标定的残差与日期。
  没有这份文件 = **几何初值**（头尾对称：绕竖直轴转 π、沿「前」相距 0.8086 m）、`calibrated: false`。
- 标定工具 `d1max-loc calibrate-rear <录包>`（开发机离线）：
  1. 前雷达建图（现有流水线）得到轨迹；按轨迹把前雷达的帧叠成点地图（体素 5 cm）；
  2. 后雷达每一帧按「那一刻的前雷达位姿 × T_front_rear」放进地图，找最近点（体素哈希近邻，不引 scipy），**所有帧一起**解同一个 T（Kabsch），迭代到收敛；
  3. 守门：对上的点占比 ≥ 50%、残差中位数 ≤ 5 cm、离初值 ≤ 0.3 m / 20°，不满足不写文件（说原因）；
  4. 两台雷达的时间戳差（同一台主机打的戳）在录包里核一遍，记下来。
- 前雷达仍按每张图的 `frames.json`（建图时标的，不变）。

### 3. 合并点云：拼进前雷达系，下游都不用改

- 合并库 `d1max_localizer/merge.py`：后雷达帧找时间最近的前雷达帧（≤ 50 ms），按 `T_front_rear` 换进前雷达系、拼起来、体素降采样（5 cm）—— 下游（MOLA、`frames.json`、定位器、
  建图预览、感知）看到的还是「前雷达系的一帧点云」，只是两头都有。
- **离线建图**：录包里有 `/rear_lidar` 且有 `lidars.json` → 先写一个合并话题的录包，MOLA 跑合并话题；没有就照旧只用前雷达（不出错）。
- **在线**：新节点 `d1max-lidar-merge`（ROS，跟定位器、感知一样是我们的 systemd 单元）发 `/d1max/merged_lidar`（best_effort）；定位器、在线建图、建图预览的
  `--lidar-topic` 改成它。合并节点没起、后雷达没数据 → 只发前雷达那份（降级，不断）。
- 时间：拼的时候不做逐点去畸变（≤ 50 ms × 0.6 m/s = 3 cm，写进已知限制）；离线建图有轨迹，按轨迹补偿。
- 录包：建图录包加 `/rear_lidar`、`/rear_lidar/imu`。

### 4. 感知、守卫、许可按行进方向

- 感知用 `lidars.json` 的后雷达外参；`calibrated: true` 之后后雷达的「空」也算（W11 的「只用挡」放开）。
- 守卫支持往后扫（vx < 0：镜像），去掉 W11 的「不许后退」—— 换成「只许按行进方向走」（d = −1 时 vx ≤ 0）。
- 净空许可：感知同时算两头的走廊（`dist_head`、`dist_tail`），`clear {ms, head, tail}`；旁路进程按 SDK 当前的头尾方向选那一头的许可（协议 6）。
- 跟踪器：朝向误差按「行进方向」算（d = −1 时机身朝向加 π），vx = d·速度；到点对朝向仍按**机身系**（拍照方向）。
- 规划不变（地图上的路跟头尾无关）；原地转的外接圆不变。

### 5. 放开 W11a 的闸

- 狗尾为前时允许自己走的条件：**后雷达外参标过**（`calibrated: true`）、配了避障时感知报后雷达在用（`rear: true`）。不满足照旧不许自己走（W11a 的原因写清楚）。
- 头尾**不知道**（`unknown`）照旧不许。
- 以后可以让代理自己调头代替原地掉头（窄通道里有用）—— 归 W25，这一单不做。

### 6. 仿真与测试（没有狗）

- **点云仿真**：三维小世界（墙、柱子、箱子、地面），按两台雷达的位姿与半球视场生成点（带噪声）；狗按轨迹走 —— 用来测合并（拼出来的点在机身系里对得上）、
  标定（从错 10 cm / 5° 的初值收回到 1 cm / 0.3° 以内；对不上的情形拒）。
- 代理：仿真狗加头尾方向；狗尾为前时跟踪、守卫往后扫、许可选后面那头、到点对朝向按机身系；`sdk_follows_head` 两种换算都测（d1max 适配器 + 仿真旁路进程）。
- 回放工具：`tools/w09i_merge_replay.py`（有合并录包时比建图质量、定位指标；现在只能跑仿真生成的包）。

## 不做

自己调头（W25）；逐点去畸变（在线）；超声；侧面盲带（两台半球雷达都看不见机身两侧，合并也一样）。

## 真机项（要你在场）

1. 狗上 `/rear_lidar` 在不在发、帧率、时间戳跟前雷达同不同源；
2. 录前后雷达一起的包：狗头为前、狗尾为前各走一圈（慢、带转弯）；
3. 用这个包标后雷达外参、建合并图，跟只用前雷达的比；
4. 调头时 SDK 的里程、速度命令方向怎么变（定 `sdk_follows_head`）；
5. 狗尾为前跑一趟巡检（感知、守卫、许可都看后面）。
