## 问题

1. **电量到线的返航走直线。** 引擎 `_go_home` 先调后端的 `return_home()`，只有后端**同步拒绝**时才走 W04 的沿来路回
   （`_retrace_home`）。代理唯一的导航桥 `HalNavBackend` 登记了原点就 `goto(原点)` —— 直线 P 控制、不规划、不避障
   （`bridges/hal_nav.py:161`；原点在装配时就登记，`assembly.py:60`）。W04 当初要防的「直线穿墙」在真链路上又回来了。
2. **更常见的一种「回家」也走直线，而且没人值守**：站点派的任务正常跑完（`task_done`）后，站点**自动**给狗派一条回默认
   待命点的 `goto`（W00c2b，`site/standby.py`）—— 每趟巡检之后，狗从最后一个巡检点直线走回待命点。

## 决定（都按推荐）

1. **直线桥不认 `return_home`**：同步抛 `NavRequestError`，引擎走沿来路回（倒序各段 + 最后一段到原点；每一段都是巡检
   时走过的线段）。
   - A（推荐）：如上。
   - B：直线桥自己实现「沿来路」。——桥不知道任务的来路，引擎知道；W04 已经把这件事放在引擎里。
2. **代理在能力里报导航走哪种路**：`tasks.goto.path`，直线桥报 `"straight"`；规划器上线后（W10）报 `"planned"`。
   站点读不到（老代理）一律按 `"straight"` 算。
3. **巡检跑完之后的自动回待命点，对 `"straight"` 的狗改成沿来路回**：
   - A（推荐）：站点从命令记录里取出刚跑完那一趟的任务定义，派一趟**回程巡检**：那一趟的航点倒序（只要位姿，不带动作）
     + 最后一个点是默认待命点；最低优先级（`STANDBY_RETURN`），`task_id` 仍以 `standby-` 开头（回程结束后不再回、被
     抢占不回，跟现在一样）；点位失败跳过（`on_waypoint_failed=skip`，一次定生死）—— 回程里某个点走不到，接着往下一个走，
     不在路上反复重试。
   - B：照旧直线 `goto`，靠 W00c6i 的技术闸（没人监护就不许动）兜。——有人在场也还是直线。
   - C：代理记住上一趟的来路，把「回待命点」的 `goto` 换成倒序路线。——代理要跨任务记状态；站点本来就有任务定义。
   - 取不到那一趟的任务定义（命令记录没了、解析不了）→ **不回**，推一条 `standby_failed`（原因写明）；不退回直线。
4. **`goto` 任务跑完之后照旧直线回待命点**（不改）：`goto` 的起点多半就是待命点，直线回去就是来路；过渡期 `goto`
   （包括自动回待命点）受 W00c6i 的监护租约约束（人在场、一断就停）。起点不是待命点时直线回去不一定是来路 —— 写进
   已知限制，W10 规划器上线后解决。（设计初稿曾想「不自动回」，那会改掉 W00c2b 已有的行为、牵动一串测试，而兜底已经有了。）
5. `"planned"` 的狗（W10 之后）：一律照旧发 `goto`，由代理规划。
6. 引擎 `_go_home` 里关于「厂商 `start_nav_return_home` 会不会重新规划」那段注释已经过时（代理不用厂商导航），改写成现状。
7. 返航每段超时仍是 300 s（每段是巡检的一条线段，按 0.2–0.6 m/s 够 60–180 m）；按路径长度动态算归 W10（W08 决定 6）。

## 不做

- 手动「回待命点」的直线问题：过渡期由 W00c6i 的监护租约管（有人在场、一断就停）；W10 之后由规划器管。
- 回程途中被人接管、暂停再继续：暂停/继续、让开腿已暂缓（决策 9）。

## 测试

- 代理：直线桥 `return_home` 同步拒绝；电量到线 → 引擎沿来路回（仿真狗真跑一趟：走到第 3 个点时电量到线，狗按 2→1→原点
  的顺序回，不走直线）；能力里 `goto.path == "straight"`。
- 站点：巡检 `task_done` 后对 `"straight"` 的狗派回程巡检（倒序航点 + 待命点、没有动作、`skip`、最低优先级、`standby-`
  前缀）；读不到 `path` 按 `"straight"`；取不到任务定义不回、推 `standby_failed`；`goto` 跑完照旧直线回；`"planned"`
  的狗巡检后也照旧派 `goto`；回程自己结束后不再回。

## 内审之后的改动（按推荐）

内审（先修再批准）在仿真里复现了三种「沿来路回、其实走了一条没走过的直线」，都修：

1. **半路电量返航不算跑完**（阻断 1）：引擎返航回到原点落 DONE，代理以前照报 `task_done`，站点当成「停在最后一个点」派回程
   巡检 —— 狗先直线奔从没到过的最后一点。→ 引擎报 `returned`（返航起因）；代理见到就报 `task_failed`，原因带上起因（电量
   → 站点按电量告警、不自动回）；结果条数少于「点数 × 圈数」也报失败。站点再兜一道：这一趟每个点都报了到才派回程。
2. **来路是真走过的路**（阻断 2、应修 2、小问题「没到的点也在回路里」「跑两圈」）：
   - 引擎开跑（进 RUNNING）时记下**出发点**（导航后端新增 `current_pose()`，直线桥报运控里程；报不出按原点）；每到一个点
     记一笔，点位失败时记下狗停在哪。回路按这份记录倒着走；同一个点到过两次就把中间那一圈抹掉；走完一段划掉一段（暂停再
     继续、接管完再继续都接着走当前这一段）。
   - 回到出发点后，出发点离原点 ≤ 1 m 才走最后那一小段；远了**原地停**，按返航失败收尾（原因带上返航起因）。
   - A（推荐）：如上。B：出发点不是原点时照走「出发点 → 原点」直线。——那一段没走过，正是这张单要消掉的东西。
3. **回程巡检半路电量到线接着往前走**（阻断 2）：它是从远端出发的，按来路倒着走是往远端走、离家更远。契约 `Policy` 新增
   `on_battery_low`：`return_home`（默认，线格式里不写）/ `continue`（到返航线不掉头，到中止线原地停）。站点的回程巡检填
   `continue`。
   - A（推荐）：契约加字段。B：把回程巡检的返航线压到中止线。——返航线是动态的（中止线 + 回家成本），压不住。
4. **回程巡检继承原任务的 policy**（阻断 3）：超时、电量线、丢定位/丢控制权的处置、保留天数都照原任务；只改三样 ——
   点位失败**中止**（原地停；跳过一点就是一条没走过的直线）、只跑一圈、`on_battery_low: continue`。
5. **直线后端的电量估算按沿来路的长度**（内审之外自查出来的，同一件事的另一半）：返航线（飞行中）、出发线（起飞前）以前都按
   直线回原点估，而直线后端回家是沿来路倒着走 —— 掉头太晚，回程走到一半碰中止线。现在：导航后端报 `PATH_KIND`（基类默认
   `straight`，跟默认拒绝 `return_home` 一致；厂商导航 `planned`）；`straight` 的返航线按「正要去的点 → 来路倒着 → 出发点 →
   原点」估；出发线按「出发点 → 各点 → 倒着回 → 出发点 → 原点」估；回家那一趟本身（`continue`）只算单程。出发线也从狗
   **现在在哪**算起（应修 1：回程巡检从远端出发，以前按原点出发算、白算一段，电够回来的狗被拒、困在远端）。
6. 站点「沿来路回」只在确定狗停在最后一个巡检点时才派（应修 3、小问题）：命令记录只看 `patrol`/`goto`（`abort` 用的也是
   这个 task_id）；查不到 → 不回、推 `standby_failed`，不退回直线；原巡检的地图与版本要跟待命点对得上。
7. **遥控放租之后，直线的狗不自动回待命点**（应修 4）：起点是人刚开到的任意位置，人在场、知道狗在哪，要回就手动叫；会规划的
   狗照旧回。
8. 返航每段超时取 `max(300 s, 这一趟的点位超时)`；待命点航点名去掉 `.`、跟来路重名时加序号；回程巡检失败的告警标题写
   「回待命点没成，停在半路」；`compose_capabilities` 的 `nav_path` 改必填；直线桥里没人读的 `set_home`/`_home` 删掉；
   契约夹具 `capabilities.json` 补上 `goto.path` 与 `autonomy`。
