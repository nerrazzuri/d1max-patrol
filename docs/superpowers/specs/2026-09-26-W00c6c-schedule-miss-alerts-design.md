# W00c6c 排程没派出去要报警 · 设计稿

> 状态：**按推荐**（用户 2026-09-26「全部采纳，A，B，C和几项能力回复的全做了」；决策 10，C = P1：正式无人值守之前做完）。
> 来源：核查 W01–W07 外审分析时新发现的 C。

## 问题

站点排程执行器（W00c2a）每条排程每一轮的去向都记一行 `schedule_runs`，但除了 `started`，别的去向**只记账、不告诉人**：

| 去向 | 什么时候 | 以前 |
|---|---|---|
| `no_robot` | 到点了没有能派的狗（掉线、忙、地图不对、要人监护……） | 只记一行 |
| `ambiguous` | 不止一台能派、排程没写 `robot`，站点不替人挑 | 只记一行 |
| `skew` | 站点的钟跟参照差太多，不起 | 只记一行（钟差本身另有 P2 `clock_skew`，但「这一轮没跑」没人知道） |
| `dispatch_failed` | 派了、狗明确拒收（或发之前就被拦下） | 只记一行 |
| `alarm` | 窗口过了，排程写的是 `on_missed: alarm` —— **明说了要报警** | 只记一行 |
| `skip` | 窗口过了，排程写的是 `on_missed: skip` | 只记一行 |
| `displaced` | 同一拍有更优先的排程占了狗 | 只记一行 |
| （回执超时） | 发出去了、回执没回来，这一轮按起跑过算 | `started` 那行加一句备注 |

只有整拍抛异常才报 `schedule_died`（P1）。结果是：狗掉线、钟不准、配错了狗，到点没人巡逻，值守的人一概不知道。

## 决定（都按推荐）

1. **「这一轮没跑」都报警**，按人要做的事分两级（告警表的判据：P1 要人立刻动身，P2 今天之内）：
   - **P1 `schedule_missed`「排程这一轮没跑」**：`no_robot`、`ambiguous`、`skew`、`dispatch_failed`、`alarm`。
     这一轮本该有狗去巡逻而没去，人要么自己去看、要么马上把狗弄好。
   - **P2 `schedule_skipped`「排程跳过了一轮」**：`skip`。排程自己写了「错过就算了」，但错过本身还是要让人知道
     （多半是狗掉线、没电），今天之内查。
   - **不报**：`displaced`（同一拍给了更优先的排程，不是没人巡逻；这一轮后面照样按 `decide` 判，窗口过了会落成
     `skip`/`alarm`，那时再报）；`started`。
   - **回执超时**：P2 `schedule_unconfirmed`「排程派出去了、没收到回执」—— 狗可能在跑、也可能没收到；这一轮不再重派
     （W00c2a 的既有规矩），人今天之内核一下。
   - A（推荐）：如上。B：全部 P1。——`skip` 是配置里认可了的，跟「本该跑没跑」不是一件事，同级会被当噪声。
     C：只报 `alarm`（排程自己要求的）。——`no_robot`、`skew` 这些才是最该知道的。
2. **同一轮同一种去向只报一次**：跟账一样，`schedule_runs` 的唯一键（排程、这一轮、去向）插进去了才报；每 30 s 一拍
   不会反复报。不同的排程、不同的轮次按告警簿的规矩合并（同一只狗同一个 kind 未确认、窗口内就合成一条、计数加一，
   标题与详情换成最新的）。
3. **报到哪只狗名下**：派给了哪只狗（`dispatch_failed`、回执超时）就报在那只狗名下；没派出去的（`no_robot`、
   `ambiguous`、`skew`、`alarm`、`skip`）排程写了 `robot` 就报在那只狗名下，没写就报在站点名下（`SITE`，跟
   `schedule_died` 一样）。
4. **标题说清是哪条排程、为什么**：`排程 {id} 这一轮没跑:{去向的人话}`，详情是账里那句备注（比如「A 要人监护,不接
   排程」「迟了 45 分钟,按 on_missed=alarm」）。
5. **怎么接**：`SiteScheduler` 加一个可选的回调 `on_outcome(entry_id, robot_id, outcome, note)`，只在账真的新记了一行
   （或 `started` 被回执改成 `dispatch_failed`）时调；站点主程序把它接到 `SiteAlertSources.on_schedule_outcome`。回调
   自己炸了只记日志，不许带走排程这一拍（跟 `schedule_died` 的告警同一个理由）。
6. **过渡期（W00c6i）**：真狗要人监护，排程不派给它，到点记 `no_robot`「要人监护,不接排程」—— 现在会报 P1。这是对的：
   配了排程、狗却还不能自己去，这件事人该知道。已知限制里写明：过渡期别给真狗配排程，或者接受每轮一条 P1。

## 不做

- 手机端不用改：值守屏按告警簿的标题、级别显示，新 kind 不需要专门的文案。
- 狗离线时站点不替它补跑（W00c2a 设计决定三 A 的代价），不变。

## 测试

- 站点（`test_site_schedule.py`，真代理 + 仿真狗 + 假钟）：到点狗掉线 → 一条 P1、标题带排程 id；再过几拍不重复报；
  不止一台能派 → P1；钟差超阈值 → P1；狗拒收 → P1（报在那只狗名下）；`on_missed: alarm` 窗口过了 → P1；`on_missed: skip`
  → P2；`displaced` 不报；回执超时 → P2；正常起跑不报；回调炸了排程照走。
- 告警表：三个新 kind 登记了级别。

## 内审之后的改动（按推荐）

内审（先修再批准）：上面「新记一行就说」在两条排程抢同一只狗、上一趟超时、状态抖一下这些常见情况下会误报 P1（这一轮随后
照常起跑了），而且一轮会说两三次。改成**知道这一轮不会按时跑的时候说，一轮只说一次**：

1. 狗在跑别的任务、这一拍给了更优先的排程：记 `busy`/`displaced`，不说；窗口过了还没跑，由 `skip`/`alarm` 那一步说。
2. `no_robot`/`ambiguous`/`skew`：等宽限期（半个窗口与 5 分钟取小，从这一轮第一次派不出去算），还没起跑才说。
   - A（推荐）：如上。B：窗口关了才说（`skip`/`alarm`）。——窗口 30 分钟，狗掉线了要半小时后才知道。
3. `dispatch_failed`、`alarm`、`skip`：当场说（这一轮还没说过的话）。
4. **狗要人监护**（W00c6i 过渡期）：单独记 `supervised`，告警 **P2 `schedule_blocked`**「派不了」—— 人要做的是改配置，不是
   立刻动身（以前每轮一条 P1、还会升到响声）。
5. **回执超时**：不再当场报 P2；过 2 分钟还没见狗在跑这一趟、没收到晚到的「收下」回执、也没有结果，说 `lost`（P1）。
6. 账里加 `told_ms`（这一轮说过没有；老库的行当说过了），回调炸了下一拍再说，进程死在记账与说之间也补得上（只翻最近 24 小时）。
7. 几条排程合成一条告警时，标题列出每一条排程（告警簿新增「这一刻再报会合进哪一条」的查询，合并判断只有一份）。
8. `skew` 只在给了时间参照时才会出现，站点主程序现在没接参照（靠 NTP），写进已知限制。
