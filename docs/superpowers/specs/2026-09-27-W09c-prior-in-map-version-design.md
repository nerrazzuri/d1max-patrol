## 问题

W09b 的定位器要地图目录里有 `prior.mm`（MOLA 的局部地图）和 `frames.json`（坐标换算），现在只能在开发机上手工做。产品里的建图还是
W00c5d 那条：狗上录包 → 用 slam_toolbox 离线建二维图（`.pgm/.yaml/.posegraph/.data`）→ 上传站点 → 管理员激活 → 狗下载。要让地图版本
自带定位先验、并且**跟规划栅格在同一个平面坐标系里**（不然导航去的点跟定位报的位置差一个旋转平移），还要把「边走边建」（决策 17）接上。

## 摸底（2026-09-27）

- 地图版本 `MapRef{map_id, version, files}`：每个文件名 + 大小 + sha256，最多 16 个文件、每个 ≤ 2 GiB；契约不限扩展名，但狗上建图只收
  `.pgm/.yaml/.posegraph/.data`（`mapping.py` 的 `MAP_EXTS`）。
- 站点只收有对应 `map_build` 命令的狗传地图（`maps.py` 的 `_build_issued`）；收完整个版本才登记；不删旧版本。
- 狗下载整张图一共 1800 s、不能续传；装的时候新旧两份同时在盘上；建图的那只狗传完就删、激活时再下回来。
- **真狗（`adapter-d1max`）没有 `load_map`，不宣告 `map_activate`**（W00c5d 真机项 3c.22）；W08 决定 5 说换图归代理的导航后端、不归 HAL。
- 定位器那头（W09b）不用改：`set_prior` 带着 `dir_of(ref)`，要里面有 `prior.mm` + `frames.json`。

### 先验大小与压缩（开发机实测）

一层楼的先验 530 MB（coverage2）、150 MB（newdog2）。MOLA 自带 `mm-kf-regroup`（把关键帧并成少而大的「超级关键帧」、按体素降采样，
「为只定位准备」），拿 W09b 的回放工具比：

| 先验（coverage2） | 大小 | 跨次回放：代理判可信 / 可信时误差 p95 / 最大 | 自洽回放 | 每帧耗时 p95 |
|---|---|---|---|---|
| 原样 | 530 MB | 78% / 0.99 m / 1.59 m | coverage2 99%、newdog2 96%（最大 0.22 m） | 101 ms |
| 合并 + 0.3 m 体素 + 切小 | 24 MB | 69% / 0.30 m / 0.41 m | **coverage2 起步对不上、newdog2（玻璃展厅）信的帧里错到 5.9 m** | 112–182 ms |

结论：压缩在一组数据上更好、在玻璃环境里更容易自信地错 —— **参数要按场地用回放验，不能一刀切**。

## 决定（都按推荐）

1. **拆两张**：**W09c1** 地图版本带先验（建图流水线换成 MOLA、先验与规划栅格同一个平面、「哪里有图」、站点拒图外的巡逻点、
   真狗不经 HAL 换图、建图的狗不再下回来）；**W09c2** 边走边建（录包的同时 MOLA 建图模式在线跑，停下就打包）。W09f 在 W09c2 之后。
2. **一个地图版本里的文件**（W08 决定 5 的「几何版本」）：
   - `prior.mm` —— MOLA 的局部地图（定位先验）；
   - `frames.json` —— 坐标换算（W09b），从建图轨迹标出来，前雷达偏移按 SDK 文档 404.3 mm；
   - `floor.pgm` + `floor.yaml` —— 二维规划栅格，**按 `frames.json` 的平面画**（原点、朝向跟定位报的位置一致）；
   - `coverage.json` —— 「哪里有图」：建图时走过的路（平面上每 0.5 m 一点）；
   - `build.json` —— 怎么建的（来源录包、MOLA 版本与参数、先验打包参数、各步耗时），给人看、给回放复现。
   站点、手机的预览照旧用 `floor.pgm/.yaml`。
3. **建图流水线换成 MOLA**（`map_build` 从录包建、W09c2 的在线建都走同一个打包）：
   `mola-lidar-odometry-cli` 建图（雷达里程计 + 存局部地图、轨迹、simplemap）→ `frames` 标定 → 先验打包（见 4）→ 栅格（simplemap →
   点云 → 按 `frames.json` 的平面、用走过的轨迹做 log-odds 射线法；照 `tools/lio/mola/render_floormap.py` 做成代码库里的模块）→
   `coverage.json` → `build.json`。slam_toolbox 那条退役（W08 决定 5：它只剩出栅格这一个用处，现在栅格也由 MOLA 的结果出）。
4. **先验打包可配置、默认不压缩**：`prior_pack` = `none`（默认）| `regroup(voxel, extent)`。压缩参数要用 `d1max-loc replay` 在这块场地的
   录包上比过（跨次、自洽都看）再换，写进 `build.json`。530 MB 的下发靠：建图的狗留着本地那份（第 7 条）、别的狗走 WiFi、下载能续传
   （第 8 条）。
5. **「哪里有图」**（2026-09-30 用户定，外审同意；原来写的是「存路线 / 巡检点时、下发 goto 时」都查）：
   - **不做保存路线时的强制巡检点检查**：任务只绑定地图号、不绑定版本，保存时按哪一版查，结论地图一升级就过期，是虚假的安全保证。
   - **派单时按狗实际加载的 `map_id + map_version` 检查巡检点与 goto 的目标，这是权威安全闸**：点要在「建图时走过的路」5 m 以内、且在栅格的可通行格子上；
     不在就拒，说清楚「这个点离建图时走过的地方 X 米，定位不可靠，先把那里建进图」。旧版本（没有 `coverage.json`）不检查。
   - 以后可以加**不挡人的编辑期预检提示**，但必须标明是按哪个地图版本查的，且不能替代派单检查；地图版本升级后，旧的编辑期预检结果视为过期。
6. **换图不经 HAL**（W08 决定 5）：配了定位器（`--localizer bridge`）的狗，`map_activate` = 下载 → 等空闲 → 换地图号与原点 → 经桥请定位器
   换先验；不调 `hal.load_map`，能力照样宣告 `map_activate`。没配定位器的狗照旧（要 HAL 的 `load_map`）。
7. **建图的狗不再下回来**：建好的版本在狗上先放进 `MapKeeper` 的本地库（跟下载来的同一个格式）；上传照旧；激活同一个版本时本地已有、
   sha256 对得上就不下载（决策 8：当前在用的地图是允许的工作副本）。
8. **下载能续传**：站点下载接口支持 `Range`；狗上断了从断点接着下，整张图的期限按大小算（按 1 Mbit/s 算、至少 30 min）。
9. **站点收地图不再在最后一块的请求里同步重算**：原来收到 `map.json` 时重算每个文件的哈希、整份拷进目录（60 s 的请求超时对几百 MB
   不够稳）。改成用收块时已经算好的整个文件的哈希（狗也拿它核过，记在收件目录里一个点开头的旁注里，文件没收完或重传就作废）、同一块盘上
   改名不拷 —— 请求里几乎不花时间，又保留了「收不下当场拒、狗隔离留着那份」（放后台的话狗已经收到 200 删了自己那份，出错图就悄悄没了）。
   （实现时改的，2026-09-27。）
10. **W09c2 边走边建**：`mapping start {name, map_id, version}`（站点据此放行上传，像 `map_build`）：录包照录、同时 MOLA 建图模式在线跑
   （ROS 启动文件、建图打开、存 simplemap 与轨迹）；`mapping stop` → 停 MOLA、存盘 → 走第 3 条的打包（不用再回放录包）→ 上传、放进
   本地库。验收指标：走完到图可用 ≤ 5 分钟（开发机实测，Orin 真机量）；跟不上就退回「停下后从录包建」。
11. **回放工具补一处**：按核心要的「再请一次」模拟（原来重定位没照办时回放里一直卡着，W09c 压缩实验踩到）。

## W09c2 细化（2026-09-27，开发机原型之后；都按推荐）

原型（newdog2 录包在隔离域里放，MOLA 在线建图订它）：

| 做法 | 结果 |
|---|---|
| `ros2 launch mola_lidar_odometry …`，停时对进程组发 SIGTERM | launch 自己先退了，底下的 `mola-cli` 成了孤儿、stdout 断了，**一个文件都没存** |
| 直接起 `mola-cli`（MOLA 自带的 `lidar_odometry_ros2.yaml`，开关都给环境变量），SIGINT / SIGTERM 停 | 局部地图 147 MB、simplemap 199 MB、轨迹都存下，**3.5 s**；订雷达用 best_effort：只收到 82% 的帧（本机 DDS 传大点云丢的），图左半边出重影 |
| 同上，订雷达用 reliable | **99.5%** 的帧；图跟离线建的一样干净；停下 → 打包（`--reuse`，读录包打真射线）77 s，走过的 248 个点 0 个被拒 |

厂商前雷达发的就是 reliable（录包 metadata：reliability 1、depth 100），所以订 reliable。

1. **命令**：`mapping start {name, map_id, version}`，地图号与版本要么都给、要么都不给（不给照旧只录包）。站点像 `map_build` 一样挡撞版本
   （站点上已有、别的狗正在建），并据此放行这台狗传这一版。手机的「开始录包」加两栏（空着只录包）。
2. **狗上**：录包、在线建图都经 `deploy/d1max-ros`（source ROS 再执行）起 —— 代理的服务里没有 source ROS，**原来录包直接起 `ros2`，真狗上起不来**
   （这次发现，一并修）。在线建图直接起 `mola-cli`，走实时域，存盘的路径指到这张图的中间目录；开录前清掉同名旧产物、原点作废。
3. **停**：录包、在线建图一起停，在线建图给 300 s 存盘。之后在后台（重建那个槽）打包：建图脚本 `--reuse`；打不成（MOLA 半路没了、存下的不齐……）
   退回在录包上从头建。`map_built` 带 `mode`（`live` / `bag`）与退回的原因。
4. **不做**：在线建图时的实时看图（W09f）；定位器（W09b，只定位）跟在线建图同时跑时 Orin 的 CPU —— 真机量。

## 不做

- 实时看图（W09f）；RTK、对时（W09e、W09d）；站点上建图（决策 15 留的口子，本张不做）；先验压缩参数的最终选择（要真机、更多录包）；
  地理配准（W08 决定 5 以后）；站点地图版本的保留期（仍然不删）。

## 真机项

1. Orin 上 MOLA 建图：边走边建时每帧耗时、内存；走完到图可用的时间（目标 ≤ 5 min）。
2. 真狗 `map_activate`（配了定位器）：换图、定位器换先验、狗按新图走。
3. 530 MB 级的先验经 WiFi 下发、断网续传。
4. 规划栅格跟定位位置对得上：在手机的地图上看狗的位置跟墙对不对得上。
5. 站点拒图外的点：在图外标一个巡检点，看提示。
