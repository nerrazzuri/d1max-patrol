# 避障设计（乙路线）

写于 2026-09-05。这是对 `2026-09-02-自建导航后端设计.md` 的**增补**，不是替代：
那份文档 §2 写着「**不做动态避障。**超声波 `/uss_driver/*` 只订不用；撞上东西靠
急停和人」，本文档推翻的正是这一条，并写清楚为什么、以及边界划在哪。

## 1. 现状：避障有一半已经有了

| 场景 | 谁在避障 | 依据 |
|------|---------|------|
| 甲：厂商导航跑任务 | **厂商导航主机自己避** | SDK 文档「导航主机：负责建图、定位导航、**避障**、自主充电等感知功能」。我们只在它绕不过去时收到 `ALG_NAV_BLOCKED`(13330) |
| 乙：自建导航跑任务 | **没有** | `自建导航后端设计.md` §2 明文不做。点到点走直线 |
| 手机遥控 | **没有** | `app/teleop.py` 只有守死人心跳，断了停车 |
| 建图时牵着走 | **没有** | 代码上就是遥控那条路 |

**本文档只管乙路线这一处。** 遥控和建图这一版不装，理由是那两处有人在看着、
在按着，而乙路线是无人自主行走 —— 缺口的性质不一样。甲路线也不叠，理由见 §9。

## 2. 边界

**做**：乙路线自主行走时，撞上去之前停住；停住后做有限次侧移试探，绕得过就继续，
绕不过就报「被挡住」交给现有规则表。

**不做**：

- **不接 Nav2。** 理由跟 `自建导航后端设计.md` §2 一字不改：Nav2 末段会把速度降到
  0.05 m/s 量级，正好落进 `Move` 的死区（清单 #37：`fwd=0.11` 几乎不动），会**静默
  失败**。本文档做的是「刹停 + 侧移试探」，不是局部规划器。
- **不做全局重规划。** 绕不过去就报失败，不去找另一条路。巡检路线是人预先标好的点。
- **守卫不主动发急停。** 见 §5。
- **不订后雷达。** 乙路线不倒车。

## 3. 为什么是「刹停 + 侧移试探」，不是别的

两个硬约束把方案空间压到很窄：

**一、运动接口是脉冲式开环，没有连续速度。** `walk(seconds, forward, lateral, yaw)`
给一个时长和一组**百分比**控制量，到点自己停。死区不小（`min_fwd = 0.30`）。
所以「接近障碍时平滑减速」在这台机器上**做不到** —— 能做的动作只有三个：
发下一拍、不发下一拍、发急停。这条直接导向「刹停」。

**二、四足的「障碍」跟轮式不是一回事。** 参数表：连续攀爬台阶 25 cm、极限跨越障碍
80 cm、带负载跨越 50 cm、最窄通过宽度 50 cm。把地面以上一切都当障碍，狗会在门槛前
永远停着不动。所以必须取高度带，见 §6。

侧移（而不是转向绕行）的理由：**朝向始终不变**，所以「偏离原路线多远」是一个标量，
横移预算一封顶，就有了「不会越绕越偏」的硬保证。转向绕行会让偏离变成二维问题，
而且可能绕进没建过图的区域。代价是只绕得开窄的东西（箱子、椅子），绕不开一排桌子 ——
这一版接受这个代价。

## 4. 架构：一条新的传感线，一个纯函数守卫

```
  ┌─ ROS2 侧（Orin NX 上，系统 python3，有 rclpy）──────────┐
  │  /front_lidar                (PointCloud2, 96 线, 10 Hz) │
  │  /uss_driver/uss_{left,right}/range  (Range, 5 m)        │
  │      └── tools/ros2_obstacle_bridge.py                   │
  │            TF 到 base_link → 取高度带 → 压成 72 个扇区   │
  │                 ↓ TCP/JSONL :8093（只出不进）            │
  └──────────────────────────────────────────────────────────┘
                        ↓
  ┌─ Python 侧（本仓库 venv，无 rclpy）──────────────────────┐
  │  ObstacleLink   收帧、判新鲜度                            │
  │  ObstacleGuard  纯函数判据（走廊、选边），能穷举测试      │
  │      ↑ 注入                                               │
  │  LocalNavBackend._drive()   每次发拍前问一句              │
  └──────────────────────────────────────────────────────────┘
```

三条都是照抄这个仓库已有的规矩：

- **走 TCP/JSONL 桥，不在 venv 里 `import rclpy`。** 跟 `tools/ros2_pose_bridge.py`
  同一个理由：venv 里没有 rclpy，往里塞是死路。副作用是 `d1max_patrol` 整包保持
  **纯标准库可测**，契约测试喂的是 TCP 上的 JSONL，不是 ROS 节点。
- **桥做薄**（主规范 §5.2）。桥里只有**机身几何**（高度带 = 机身能撞到的高度范围、
  按方位角分桶），**没有行为策略**（刹不刹、往哪挪、试几次）。这条线要划清楚：
  换传感器不用重写策略，改策略不用碰 ROS2。
- **判据做成纯函数**，样板是 `engine/safety.py`。「出事那一刻该怎么办」这种最难在
  现场复现的逻辑，恰恰最需要能穷举。

**为什么用 `/front_lidar` 而不是厂商的 `/laser_scan`：** 跟建图那条管线同一个理由
（`建图定位与巡检管线.md`）—— 厂商 `/laser_scan` 用 Livox 窄视场加图像分割过滤，
**桌椅扫不全**。避障漏掉一把椅子的后果比建图漏掉严重。

**为什么压成 72 个扇区而不是只报「前方最近距离」：** 侧移要选往哪边挪，必须知道
哪一侧是空的。一个标量做不了这个决定。

## 5. 守卫的权力：只有「否决下一拍」

**守卫不主动发急停。**

脉冲式开环下「不发下一拍」就是停，滞后有上界 —— 一拍。这一点 `LocalNavBackend.stop()`
的注释里已经论证过：脉冲已经下到旁路进程了，取消 Python 侧的等待并不会让机器停下来。
所以守卫能做的、也只需要做的，就是不发下一拍。

急停要人为复位，代价大得多，那是规则表和人的决定，不是一个传感器守卫该自己做的。

## 6. 高度带：下沿 0.15 m

上沿 **1.50 m**：狗肩高一米出头，再高的东西（吊灯、桥架、管道）撞不到。这个值跟
建图管线取的 0.1–1.5 m 上沿一致。

下沿 **0.15 m**，这是个取舍：

| 下沿 | 后果 |
|------|------|
| 0.05 m | 地上一个鞋盒就把它停住。全程误停，操作员会把避障关掉 —— 那等于没做 |
| **0.15 m** | 高过脚踝的算障碍。25 cm 台阶也会被判障碍，但室内巡检场地的台阶是固定设施，标点时本来就该绕开 |
| 0.30 m | 赌它能跨过 30 cm 的实心箱子。但 80 cm 是**极限跨越**，带负载只有 50 cm，而巡检时它背着上装。赌输就是硬撞 |

**选保守那一边，因为代价不对称**：误停的代价是这个点判失败（可恢复，有人复核），
硬撞的代价是修机器。

点云在雷达坐标系里，高度带要在 **base_link** 系上取 —— 桥用 TF 变换，跟建图管线里
`pointcloud_to_laserscan` 的 `target_frame:=base_link` 同一个做法（那条命令用的是
`min_height:=0.1 max_height:=1.5`，上沿一致，下沿这里抬到 0.15）。硬件手册 4.4 节
「传感器坐标（相对机身 BASE 原点）」给了全部传感器的毫米级安装坐标，外参不用自己量。

### 6.1 先把雷达朝向那 180° 治了，否则这一整套是反的

`建图定位与巡检管线.md` 第 6 节记着：**速腾前雷达疑似朝后装，建出的图内部朝向差
180°**（清单 #64，根治办法是把 `static_transform_publisher` 的 `--yaw` 设 `3.14159`
重建图）。

建图那边这个错被藏住了 —— 场地是矩形，对称，图和位置看着都没毛病。**避障藏不住**：
朝向反了 180°，「0 号扇区正前方」实际指向狗屁股后面，于是它会为身后不存在的东西
刹停，同时对正前方的墙全无反应。

所以 **#64 是这一版的前置项，不是并行项**。落地顺序：先根治外参、重建图，再上避障。
桥启动时应当把它拿到的 `front_lidar → base_link` 变换打进日志，人一眼能看出 yaw
是 0 还是 π。

## 7. 线协议（`obstacle_frames`）

单向、换行分隔 JSON，桥只出不进。复用 `pose_frames` 的风格与 `PROTO_VERSION` 惯例。
端口 **8093**。已占用的：8090 `patrol_agent`、8091 位姿桥
（`tools/ros2_pose_bridge.py`）、8092 地图桥（`tools/ros2_map_bridge.py`）。

```json
{"t":"hello","proto":1,"base_frame":"base_link","sectors":72,"span_deg":5.0}
{"t":"obst","ts_ms":1756800000000,"ok":true,"d":[1.23,1.3,null],"uss":{"l":0.42,"r":null}}
{"t":"obst","ok":false,"reason":"2.0s 没收到点云"}
```

- `d` 是 72 个值，**0 号扇区中心对准 base_link 的 +X（正前方），逆时针为正**，
  每个跨 5°。值是该扇区内最近点的**水平距离**（米，保留两位）；`null` = 这个扇区
  什么都没看到。上面的示例为了短只写了三个，实际必须是 72 个。
- `uss` 两个字段来自左右超声波，`null` = 超出量程或没数据。它是近距补盲：超声波
  正好左右各一个，而侧移恰恰需要知道左右空不空。
- 桥固定 10 Hz 发送，**即使查不到也发**（心跳兼失败通知），跟位姿桥一样。

### 7.1 看不见的时候必须当成有障碍

这是整份文档最重要的一条：

**`ok:false`、帧过期、连接断开，一律等价于「前方堵着」，不是「前方是空的」。**

传感器坏了当成没障碍，就是闭着眼睛全速前进 —— 那比没有避障更危险，因为操作员
以为有。判据：**超过 `stale_after_s` 没收到 `ok:true` 的帧就判定看不见**，
守卫一律否决。这跟位姿桥「没有帧本身也是一种信息」是同一条规则。

## 8. 侧移试探：一个独立阶段

### 8.1 为什么必须是独立阶段

`_drive` 的卡住判据靠「`remaining` 有没有变小」，而 `remaining` 的**量纲跟着阶段变** ——
代码里已有的注释说得很清楚：拿转向阶段的弧度去跟前进阶段的米比大小是错的，所以
阶段一换就重置 `best` 和 `stalled`。

侧移时**离目标的距离根本不会变小，甚至会变大**。直接把侧移拍插进 `_ADVANCE`，
`stalled` 会累加到 `stuck_pulses` 然后返回 `FAILED` —— **避障刚一生效就把正常绕行
判成卡死**。所以新增第四个阶段 `_SIDESTEP`，跟 `_TURN_TO_GOAL` / `_ADVANCE` /
`_FINAL_YAW` 并列。

### 8.2 `_SIDESTEP` 的进展量纲：剩余横移预算

`remaining = max_sidestep_m − 已横移距离`，而**已横移距离取自实际位姿**
（定位给的是地图系位姿，算得出来），不是取自「发了几拍」。

这样定义之后，现有的卡住判据**一行不用改就正确了**：

- 狗真的在挪 → 已横移变大 → `remaining` 变小 → 有进展。
- 狗没挪（**横移死区没顶上去**）→ `remaining` 不变 → `stalled++` → 攒够
  `stuck_pulses` 判卡住。

第二条是这一版真正的风险点：**横移死区从来没人量过**。清单 #37/#38 只量了**前进**
那一路（`fwd=0.11` 几乎不动、0.3 明显走），转向那一路至今没量过（清单 #56 挂着），
横移更是连条目都没有。要是 `min_lat` 设低了顶不过死区，狗原地不动而我们以为在挪，
一路挪到预算耗尽全程零位移。用实际位姿做进展量纲，这个故障当场就暴露，而不是等
预算烧完。

这条同时是横移死区的**现场自测**：真机第一次跑就能看出 `min_lat` 够不够。

### 8.3 流程

```
_ADVANCE 发拍前，算出这一拍打算走多远 reach
  └ guard.forward_blocked(view, reach)?
      否 → 照常发拍
      是 → 进 _SIDESTEP
            ├ 左右哪边空？（侧向扇区 + 超声波）
            │    两边都堵 → 放弃，报被挡住
            │    只有一边空 → 就那边
            │    都空 → 选离目标近的那边
            ├ 发一拍横移，重测位姿，累加已横移
            ├ 前方通了 → 回 _ADVANCE
            ├ 已横移 ≥ max_sidestep_m → 放弃，报被挡住
            ├ 位姿没动（死区）→ 卡住判据接管 → FAILED
            └ 否则继续横移
```

**绕过去之后不用转回来。** 侧移不改朝向，循环下一轮会重新算 `heading_err`，
自然会进 `_TURN_TO_GOAL` 修正。这是侧移方案的天然好处。

**横移预算按每个目标点累计，不按每次阻塞重置。** 否则「挡一次挪一点」可以无限
zigzag，「不会越绕越偏」的保证就没了。到下一个点才清零。

### 8.4 走廊判据，不是锥角

`forward_blocked` 检查的是机身前方一个**矩形**内有没有点：

- 宽 = 走廊半宽 `corridor_half_w` 的两倍。最窄通过宽度是 50 cm，取半宽 **0.40 m**
  （机身 + 两侧余量）。
- 长 = `max(reach, brake_m)`。`reach` 是这一拍打算走的距离，算得出来：
  `cmd × fwd_speed_mps × seconds`，按现有默认值满打满算约 0.5 m。
  `brake_m` 起步取 **1.00 m**（一拍行程 + settle 期间的余量 + 定位误差）。

从极坐标 `(角度, 距离)` 判一个点在不在矩形里是纯几何，能穷举测。

**为什么不用锥角：** 锥角会在远处误伤 —— 一个 5 m 外、偏 20° 的柱子在锥里，
但狗根本不会碰到它。巡检场地两边全是设备，用锥角的结果是全程刹停。

## 9. 放弃之后接什么：一行规则都不用改

试探耗尽（或两边都堵、或看不见）之后，`LocalNavBackend` **不直接返回 `FAILED`**，
而是 `emit` 一个：

```python
AlgErrorEvent(items=(AlgErrorItem(code=ALG_NAV_BLOCKED,
                                  description="<具体哪一种>", severity=0),))
```

`ALG_NAV_BLOCKED` 就是 13330 —— **厂商导航被挡住时推的那个码**。于是 `engine/safety.py`
现成的那条规则原样接管：先等 `BLOCKED_WAIT_S = 20s`，还堵着就 `FAIL_WAYPOINT`。
那条注释写的理由（「人从狗前面走过去要几秒，叉车挪开要十几秒 —— 等一下比直接判
这个点失败划算」）在乙路线上一字不差地成立。

`description` 要区分开，因为现场排障全靠它：
`"前方被挡住,两侧都不通"` / `"横移 1.2m 仍未绕开"` / `"障碍传感器 2.0s 无数据"`。
`severity` 填 0：厂商的 severity 语义未知，而规则表本来就只看 code，不看 severity。

**副产品：甲乙两路线在「被挡住」这件事上行为完全一致，契约测试两边共用** ——
这正是 `NavBackend` 这个口一直在做的事。这也是不给自建避障新造一个故障码的理由：
新造一个码，规则表就要多一行，两条路线就会分叉。

**甲路线为什么不叠这一层：** 甲路线上拍不是我们发的，是厂商导航主机自己在驱狗，
我们唯一能插手的动作是急停，而急停会打断整个任务。厂商已经在避障，我们再叠一道
更保守的急停，最可能的结果是它想侧身挤过去时被我们打断 —— 大量误中断换来的安全
边际很小。信厂商。

## 10. 怎么测（没有机器也要能测完）

| 层 | 怎么测 |
|----|--------|
| 桥的几何压缩 | 抽成**不依赖 rclpy 的纯函数**（吃 `(x, y, z)` 数组，吐 72 个扇区），单测穷举：地面点滤掉、高处点滤掉、同扇区取最近、空扇区给 `null` |
| `ObstacleGuard` | 纯函数，跟 `safety.py` 一个路子。走廊判据（矩形内外、边界值）、选边逻辑（一边空 / 都空 / 都堵）全部穷举 |
| 看不见 = 有障碍 | 单独一条：`ok:false`、帧过期、连接断开，三种都必须否决 |
| `LocalNavBackend` 集成 | `d1max_sim` 新增 `obstacle_server`，跟 `pose_server` 同构，能按脚本吐障碍帧。「前方 0.8 m 突然出现障碍 → 侧移两拍 → 通了 → 继续 → 到点」这条完整时序在笔记本上跑通 |
| 死区那一坑 | 专门一条：横移拍发出去但位姿不动，必须判卡住，**不能烧完预算** |
| 契约一致 | 甲乙两边被挡住时推的事件形状一致，规则表的裁决一致 |

**禁止删除或跳过任何已有测试。** 套件数只能往上走。

## 11. 真机才能定的三个数

离线定不了、必须标定的只有三个，进 `docs/真机待验证清单.md`：

| 参数 | 初值 | 怎么标 |
|------|------|--------|
| 高度带下沿 `band_low` | 0.15 m | 拿 bag 离线重放，看误停率。场地里有台阶就再看一遍 |
| 刹停线 `brake_m` | 1.00 m | 让它对着墙走，量实际停在多远。一拍行程受死区影响，可能跟算的对不上 |
| 横移死区 `min_lat` | 0.30 m | 发一拍横移看位姿动没动，从 0.30 往上试。**只有前进那一路量过（#37：0.11 不动、0.3 明显走），转向还欠着（#56），横移连条目都没有** |

前两个能靠 bag 离线调，**第三个必须狗在场** —— 它是这一版唯一一件不带机器就完不成的事。

## 12. 这一版不做，但接口留着

- **遥控和建图的刹停。** `ObstacleGuard` 是注入的纯函数，`app/teleop.py` 以后要用
  直接注入同一个，不用重写判据。
