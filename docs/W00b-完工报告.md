## 设计取舍（审核请重点看）

1. **别名壳是同一个对象，不是复制。** `monkeypatch("d1max_patrol.engine.preflight._check_x")` 与真身一处改两处变；logger 名、`__module__`、`__file__` 都是新名字。壳的 docstring 写明，W00c 删。
2. **engine 整棵搬，站点模块借住。** `release → bundle → schedule` 这条依赖决定了不能只搬一半；`schedule/alerts/baselines` 在 robot-agent 里只是借住，文件头标了。
3. **桥的状态机时序是仿真器的参数**（0.3 s / 0.5 s）。真机上这两个数是 W00d 要测的（`真机待验证清单` #1、#12）；引擎压在这上面（`_await_nav_standby`）。
4. **引擎的 DONE 不等于任务成功。** `retry_then_skip` 会把到不了的航点跳过然后 DONE；单航点 goto 看 `results[].ok`，不 ok 就是 `failed`，理由用航点的 `note`。
5. **`goto` 不再有自己的控制律实例。** 速度环只在 `HalNavBackend` 里一份；命令里的 `max_speed_mps` 由 `nav.set_speed` 承接（引擎不管速度）。
6. **legacy HTTP 必须同一进程。** 两个进程都要 sidecar 控制权（§7.1）；共用同一台引擎也让手机与站点的任务走同一套 `EngineBusy` 仲裁。
7. **单元装而不 enable。** 现在 enable 得到的是每 5 秒重连一个不存在地址的进程；W00c 一到就是 `systemctl enable`。`d1max-privileged` 的 `install-unit` 只管主单元，agent 单元暂不经 OTA 更新（W00c 一起定）。
8. **别名壳让「根下的解释器」也要装三个包。** 自查发现的阻断项：`/opt/d1max/bin/python`（2/7 建的版本无关 venv）原来只装根包，而 boot-guard、bundle guard、3/7 的 `release install`、7/7 的 `activate`/`migrate-data`、`d1max-restart-now` 里的迁移全从它跑——`d1max_patrol.engine` 变成别名壳后 import 就要 `d1max_agent`，装机会在 3/7 炸、开机守卫一次都跑不了。修：2/7 在根包之后同样装三个包（老包没带 `packages/` 就跳过），pip 条数守卫 5→6，新增 `test_根下的解释器venv也装三个包_不然别名壳一import就炸`。
9. **goto 的终态要等导航回 StandBy。** 终态一出，代理就放资源、起排队的下一趟；下一趟的预飞 `nav_ready` 要看到 StandBy。内部评审抓到：只等 `stopped()` 的话，抢占时新任务正好撞上旧任务 Cancelled 的 0.5 s 驻留，预飞红，结果「旧的停了、新的也 failed」。代价是抢占多等一个驻留期（sim 0.5 s，真机值归 W00d）。
10. **重定位是空操作，不是拒绝。** 拒绝的话引擎把任何一次 LOC_LOST 都当整趟中止。空操作让引擎走它原有的「停下、等 `CONTINUOUS_LOC`（30 s 上限）、重发当前点」。真机上要不要映到厂商重定位，归 W00d。
11. **限速设不进去就 failed，不再按 HAL 上限走。** 原来是记一条 warning 然后全速走，比命令要求的快；低于死区的限速现在在桥里就被拒。
12. **测试里驱动引擎要多让几个循环轮次。** 引擎的协程在 `asyncio.wait_for(queue.get())` 上等命令，一拍里要 `sleep(0)` 数次才消化完一条 abort/pause；测试驱动器每拍让 4 次。这是测试驱动器的事实，不是产品代码的时序假设。

## 内部评审

只读子代理评审一轮，**阻断 2 条，都已修**：

1. **抢占后新任务 failed。** 旧任务终态只等 `stopped()`，此时导航还在 Cancelled 驻留期，新任务的预飞 `nav_ready` 红。修：终态前还要等 StandBy（取舍 9）。测试 `test_抢占后新任务能走完_不撞导航的终态驻留`，突变 M10。
2. **离线轮子目录没有 paho-mqtt。** `install.sh` 装 `contract[mqtt]`，`--no-index` 下 2/7 就断。修：补轮子、`SHA256SUMS`、README；加测试逐个核三个包的外部依赖与 mqtt 扩展都有轮子且哈希对得上。突变 M11。

建议项的处理：

| 建议 | 处理 |
|---|---|
| 别名壳名单要对真身目录 | 做了，M24 |
| 低于死区的限速该拒；上一趟限速不该带到下一趟 | 做了，M13、M14；设不进去改为 `failed`（取舍 11） |
| 导航桥 `close()` 要回 StandBy | 做了，M12 |
| 重定位被拒让任何 LOC_LOST 都中止整趟 | 改成空操作（取舍 10），M21；真机项进 `庄园场景待真机测试.md` §3b |
| 运行时从不连设备桥，老 HTTP 面的灯永远红 | 做了，M16；`HAL.connect()` 在契约里注明幂等 |
| `BatteryEvent` 每拍一条，暂停期间刷 `paused_event` | 改为跨整数百分点或充电状态变化才发，M15 |
| `start()` 之前的 abort 被忽略 | 做了，M22 |
| `engine.start()` 非 `EngineBusy` 异常让任务挂在 PENDING 占资源 | 做了，M23 |
| 不接 SIGTERM | 做了，M17 |
| `hal.tick` 在 try 外 | 做了，单独兜，M19 |
| broker 连不上退 1，单元注释说「每 5 秒重连」 | 退 1 保留并补测试（M18），注释改成「连不上退 1，由 Restart 每 5 秒再起」 |

| legacy 模式下 Teleop 的 `walk` 不支持 | 不改，记在下面「legacy 模式的限制」 |

**legacy 模式的限制**（`--legacy-http` 下老 HTTP 面接的是 HAL 桥，不是 sidecar）：手机的「定时行走」「站立/趴下」会被拒（桥不做 SDK 级动作，报 `DeviceBackendError`）；建图、地图管理、路径管理报不支持；灯与云台在 sim 上是空操作。巡检任务、暂停/继续/中止、状态与归档照常。W00b 不在狗上起 agent，这些不影响现场；W00d 的 adapter-d1max 补上 SDK 级动作。
