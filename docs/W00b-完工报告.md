## 设计取舍（审核请重点看）

1. **别名壳是同一个对象，不是复制。** `monkeypatch("d1max_patrol.engine.preflight._check_x")` 与真身一处改两处变；logger 名、`__module__`、`__file__` 都是新名字。壳的 docstring 写明，W00c 删。
2. **engine 整棵搬，站点模块借住。** `release → bundle → schedule` 这条依赖决定了不能只搬一半；`schedule/alerts/baselines` 在 robot-agent 里只是借住，文件头标了。
3. **桥的状态机时序是仿真器的参数**（0.3 s / 0.5 s）。真机上这两个数是 W00d 要测的（`真机待验证清单` #1、#12）；引擎压在这上面（`_await_nav_standby`）。
4. **引擎的 DONE 不等于任务成功。** `retry_then_skip` 会把到不了的航点跳过然后 DONE；单航点 goto 看 `results[].ok`，不 ok 就是 `failed`，理由用航点的 `note`。
5. **`goto` 不再有自己的控制律实例。** 速度环只在 `HalNavBackend` 里一份；命令里的 `max_speed_mps` 由 `nav.set_speed` 承接（引擎不管速度）。
6. **legacy HTTP 必须同一进程。** 两个进程都要 sidecar 控制权（§7.1）；共用同一台引擎也让手机与站点的任务走同一套 `EngineBusy` 仲裁。
7. **单元装而不 enable。** 现在 enable 得到的是每 5 秒重连一个不存在地址的进程；W00c 一到就是 `systemctl enable`。`d1max-privileged` 的 `install-unit` 只管主单元，agent 单元暂不经 OTA 更新（W00c 一起定）。
8. **别名壳让「根下的解释器」也要装三个包。** 自查发现的阻断项：`/opt/d1max/bin/python`（2/7 建的版本无关 venv）原来只装根包，而 boot-guard、bundle guard、3/7 的 `release install`、7/7 的 `activate`/`migrate-data`、`d1max-restart-now` 里的迁移全从它跑——`d1max_patrol.engine` 变成别名壳后 import 就要 `d1max_agent`，装机会在 3/7 炸、开机守卫一次都跑不了。修：2/7 在根包之后同样装三个包（老包没带 `packages/` 就跳过），pip 条数守卫 5→6，新增 `test_根下的解释器venv也装三个包_不然别名壳一import就炸`。
9. **测试里驱动引擎要多让几个循环轮次。** 引擎的协程在 `asyncio.wait_for(queue.get())` 上等命令，一拍里要 `sleep(0)` 数次才消化完一条 abort/pause；测试驱动器每拍让 4 次。这是测试驱动器的事实，不是产品代码的时序假设。
