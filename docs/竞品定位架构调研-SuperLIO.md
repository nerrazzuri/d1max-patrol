## 一、为什么现在看它

11-02 现场（`docs/现场工单草稿-2026-11-02.md`）MOLA 暴露的问题，都跟「每帧拿激光直接对地图做 ICP 定位」有关：

- 转弯就自动重定位一次（每趟 5 s 停顿），连着几次就把任务判失败（工单 13、16、18）。
- (2.7, −1.1) 朝西南、玻璃在右手边时，**站着不动**也在真位置和玻璃外 (5.6, 1.0) 之间来回跳（工单 18，工单 27 没好）。
- 「自动找位置」两天都只有 0.39 / 0.43 贴合度，被拒（工单 15）。
- MOLA 在 Orin 上丢 30% 雷达帧（CPU 不够）。
- 商场建图 126 m 一圈首尾差 12.5 m（没回环，工单 19、20）。

## 二、Super-LIO 是什么（公开资料）

- 论文：Wang 等，*Super-LIO: A Robust and Efficient LiDAR-Inertial Odometry System with a Compact Mapping Strategy*，
  arXiv 2509.05723（2025-09，v2 2025-12），RA-L 2026。代码 GitHub `Liansheng-Wang/Super-LIO`，ROS1 / ROS2（Humble 可）分支。
- **许可证 GPL-3.0**：我们闭源发行，直接链接 / 改它的代码要先问清楚法律影响；单独进程跑、或者只借思路另写，风险小得多。
- 算法：FAST-LIO2 一系 —— IMU 与激光紧耦合、迭代误差状态卡尔曼（IESKF）、点到平面残差；改进两处：
  - **OctVox**：哈希体素地图，每个体素固定 2×2×2 共 8 个子体素、各存一个代表点（增量均值去噪），点密度有上限，
    LRU 淘汰旧体素，地图不会无限长。
  - **HKNN**：近邻搜索按子体素预排的距离组遍历、提前截止。
- 论文数字：Orin NX 每帧约 **10.5 ms**（FAST-LIO2 41 ms、iG-LIO 21 ms）；公开数据集平均 RMSE 0.74 m（FAST-LIO2 0.81 m）。
  实验用：最大迭代 4、地图体素 0.5 m、降采样体素 0.5 m。
- **没有回环、没有全局优化**：纯里程计前端。论文没讨论玻璃、退化场景。

## 三、竞品怎么搭的（架构，参数值见笔记本那份）

竞品**不靠一个算法包办**，分两层：

1. **里程计层：Super-LIO**，只吃狗的前雷达和它的 IMU（没用后雷达、没用腿部里程）。输出平滑、不跳的相对位姿和去畸变点云。
   开着**零速更新（ZUPT）**：判定站着不动时强制速度为 0。体素地图有容量上限、按年龄 / 距离淘汰。还有倾斜告警。
2. **定位层：3D 粒子滤波（AMCL）**，在建好的 3D 点云图上用似然场打分；**运动模型用里程计层的相对位姿**，所以单帧匹配差
   不会让位姿跳；点云同时用上装自己的雷达和 Super-LIO 的点云；有跳变检测、匹配分、「丢了」信号；能融 GPS；
   **断电时把位置存盘，开机接着用**。
3. **重定位：全局配准**，粗配准用 KISS-Matcher（不要初始位置），细配准用 GICP 类（累积几帧再配，有内点率门槛）。
4. 地图同时出 2D 栅格（规划）、3D 点云（定位）、体素 / 高程。

## 四、对我们的建议（按价值）

1. **定位分层：里程计 + 粒子滤波（或带门槛的扫描匹配）**。MOLA 现在每帧对图 ICP，一帧错就锁错、就重定位。
   改成「LIO 出平滑相对位姿 → 在图上做多假设定位」，玻璃锁错、站着跳、转弯重定位这一串问题的根子就去掉了。
   这是架构级改动，先做下面第 4 条的离线对比再定。
2. **零速更新（ZUPT）**：成本低、收益直接 —— 站着不动不许定位漂。可以先在我们自己的定位器 / 代理里加（腿部「站立」
   状态 + IMU 静止判定）。
3. **「自动找位置」换全局配准**（KISS-Matcher 一类，或累积多帧的 FPFH + TEASER / GICP），代替现在套墙打分。
4. **用 11-02 商场第 2 遍的包做离线对比**：包 `mall-1102b-20261102T070824Z`（OneDrive `D1Max/现场录包/2026-11-02/`），
   那一圈**起点终点是同一个地方**，MOLA 算出首尾差 12.5 m。同一个包跑 Super-LIO（ROS2 Humble 分支）比：
   首尾闭合误差、Orin 上每帧耗时 / CPU、转弯时有没有跳。办公室那几个包（玻璃那段）也一起跑。数据说话再决定换不换。
   **已做（11-02 下午）**：直接在机器人上实时跑，商场 158 m 首尾 5.3 cm、跟竞品同一圈平均差 4.3 cm、办公室玻璃那段不跳，
   见 `docs/Super-LIO现场验证-2026-11-02.md`。
5. **断电记住位置**（开机先用存的位置 + 校验）、**地图体素淘汰**（长时间巡逻内存不涨）。
6. 回环仍要我们自己做（Super-LIO 也没有）：工单 20 的 `mola-sm-lc-cli` 照做；如果前端换成 Super-LIO，回环要另配
   （位姿图 + ICP / Scan Context 一类）。

## 五、要注意

- GPL-3.0 见上；产品化前定法律口径。
- 竞品只用前雷达做 LIO；我们现在是前后合并 + IMU（`d1max-lidar-merge`，合并节点自己就要 ~170% CPU）。
  对比时两种输入都试。
- 竞品上装跑在独立的电脑上；我们 V2 所有东西在 RK3588 上，算力预算要算进去（Super-LIO 论文的 Orin NX 数字可以当参照）。
