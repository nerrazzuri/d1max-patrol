# W21 上装 HAL · 设计与完工报告

> 工单：「RS485（`/dev/ttyCH9344USB5`）驱动喇叭/警灯/警笛/聚光灯；`SetPeriphPower` 管供电；音频优先级仲裁。SDK 无任何音频接口」。分支 `w21-payload` → PR。设计与报告合一份。

## 用户决定（2026-10-07，决策 36）

上装还没选型。四项都按推荐：

1. **先做通用框架 + 假设备**：驱动、优先级仲裁、能力上报、手机按钮都做，用假继电器板、假播放测；型号到了只改适配那一层。
2. **喇叭**：USB 声卡 + 功放喇叭，插狗的 USB3.0 口，Orin 上用 ALSA 放。录好的话术、文字转语音都能放。
3. **警灯、警笛、聚光灯**：都当开关，经一块通用的 **RS485 Modbus RTU 继电器板**开关。
4. **供电第一版不管**：上装常电（扩展舱按钮开着），开关都靠继电器板。

## 先查清的事实

- 狗身上没有任何音频接口。两版 SDK、硬件手册里都没有喇叭、麦克风。
- 扩展口（SDK 开发指南 §1.5）：48V 10A、24V 20A、24V 3A + 网口、12V 5A + 网口、串口（RS232、RS485、SBUS×2、PPS）、USB3.0 两个。整机所有供电口加起来最多 480 W。
- RS485 是 `/dev/ttyCH9344USB5`，接在 M12 接头的第 4 脚（A）、第 5 脚（B），第 8 脚是 GND。
- **`SetPeriphPower` 只在 SDK 0.2.0 里有**，只管三路（48V、24V、12V）。狗的平台是 0.2.4，只能配 SDK 0.1.1，我们的旁路进程也是按 0.1.1 编的。所以台账原文「`SetPeriphPower` 管供电」现在做不到。要用它得先让厂家把平台升到 0.3.0（V4），所有真机项都要重验。决策 36 选了不管供电。
- 方案书原文不在仓库里，也没有任何上装型号。

## 怎么做的

### 一条命令：`deter`

站点经 MQTT 发给狗上的代理，载荷两头用同一份校验（契约 `deter.py`）：

| 字段 | 说明 |
|---|---|
| `output` | `strobe` 警灯、`siren` 警笛、`spotlight` 聚光灯、`speaker` 喇叭 |
| `on` | 开还是关 |
| `max_s` | 开的时候必带，0–600 秒。**到点狗上自己关** |
| `clip` | 只给喇叭：话术名，或 `tts:<语言>:<文字>`（最多 300 字） |
| `priority` | 只给喇叭，0–100。**站点定**：手机手动按的是 60（`MANUAL`），请求体里的不认 |

几处要紧的判断：
- **不是任务**（照 `video` 的做法）：不占任务槽、不进任务状态机。巡检、去拦截点的路上照样能开，开了也不打断它们（有测试）。
- **声光一定会自己停**：每次开都带最长时间，到点 HAL 那一层自己关，站点没了、断网了也一样。代理断开 HAL（收尾）时全关；起来时先全关，因为上次进程死掉时开着的继电器不会自己关。
- **喇叭优先级仲裁在代理里**：同一时间只放一段。新来的比正在放的低，回 `busy`；一样高或更高的，打断正在放的。**关喇叭不看优先级**：让它安静永远可以。W22 驱离、事件派遣用更高的优先级，手动的就打断不了它们。
- 每次开、关都记一条 `deter` 事件（哪一路、开多久、放的哪段话术），断网时留在狗上，回来补传。W22 复盘要用。
- 钟差闸（W09h）：开要钟差合格，跟视频一样；**关始终放行**。
- **不进幂等记录**（同 `video`）：重投的旧命令至多把那一路从现在再开 `max_s`，有上限。

### 上装配置（狗上 `/etc/d1max/payload.json`）

```json
{
  "relay": {
    "port": "/dev/ttyCH9344USB5",
    "baud": 9600,
    "slave": 1,
    "coils": {"strobe": 0, "siren": 1, "spotlight": 2}
  },
  "audio": {
    "device": "plughw:1,0",
    "clips_dir": "/var/lib/d1max/clips",
    "tts_command": "espeak-ng -v {lang} -w {wav} {text}"
  }
}
```

- `coils` 写哪一路接在继电器板的第几个线圈（从 0 数），没写的就是没接；两路不许接同一个线圈。
- 没接喇叭就不写 `audio.device`；不要 TTS 就不写 `tts_command`。
- 文件不在，就当没装上装：能力全报 false，手机上没有「上装…」。

## 外审第一轮（2026-10-07）：FIX-THEN-APPROVE，3 条阻断，已修

**阻断 1：再开、再关的时候通信失败，自动关的保障就丢了。** 原来 `set()` 先取消旧定时器、再去写继电器板。写失败了，旧定时器已经取消、新的又没建起来：
- 警笛开着时，手动关那一下板子没回 → 原来的截止时间过了，警笛还开着，也没有定时器了；
- 再开一次失败也一样；
- 板子其实执行了「开」、只是应答丢了：同样没有关闭保障。

修法：继电器改成**每一路一个期望状态，加一个一直在跑的看护循环**。
- 期望里记着「开到几点」，过了就变成「关」。看的时候按当时的钟算，不等定时器。
- 期望跟板子**确认过的**状态对不上，或者状态不明（写失败之后、刚起来时），看护循环就每 0.5 秒重写一次，直到板子确认。
- **开没成一律把期望改成「关」**：板子可能其实开了，宁可接着关。命令照样回失败。
- 写失败就把这一路标成「状态不明」，看护循环会补写。
- 每一路一把锁：到点关和新来的命令不交叉；快到点时又开一次，按新的截止时间算。

**阻断 2：起来时全关失败，之后不再重试。** 原来失败只记一行日志。

修法：
- 起来时每一路都当「状态不明、要关」，先试一遍；关不掉不挡代理起来，看护循环接着关，直到关上。
- **状态不明、关不上的几路当成狗的故障报上去**（`payload_<哪一路>`，不致命）；关上了故障自己消失。（站点那头的告警原来没接上，见下面「复查」。）

**阻断 3：喇叭放没放成都回成功，优先级也一直占到 `max_s`。** 原来播放器在后台起，起不来只记日志，TTS、播放器的退出码也不查。代理随即记一条「开」事件，并占着优先级直到 `max_s`。

修法：
- 当场起进程：有 TTS 先合成完、退出码不是 0 就报错；播放器起不来（比如 `aplay` 不在）就报错。代理回 `device: …`，不记「开」事件，也不占优先级。
- 播放在后台，放完、放坏了（退出码不是 0）、到点了，都经 HAL 回调代理。代理**当场放开优先级**，并记一条 `deter` 事件（`ended: done/failed`，带原因）。短话术放完，低优先级的马上就能放。
- 被新的一段打断、被关掉的那一段不回调，不会把新放的那段的优先级放掉。

补的测试（都按外审的复现方式写）：
- 驱动：
  - 开着时手动关失败，原截止时间过了照样关上，期间报状态不明；
  - 再开一次失败，接着关；
  - 板子执行了「开」、应答丢了：状态变成不明，接着关上；
  - 快到点时又开，旧的到点不许把新开的关掉；
  - 起来时全关失败：代理照起、三路都报故障，通信一恢复就关上、故障消失；
  - 真狗 HAL 把关不上的几路当故障报；
  - 播放器不在当场报错、不回调；TTS 退出码不对当场报错、不放；
  - 放完、放坏了、到点都回调，被打断的、被关的不回调。
- 代理：喇叭起不来回拒绝、不记「开」、不占优先级；短话术放完当场放开优先级、记结束事件。
- 突变 12 条全被抓住：开没成不改成「要关」、写失败不标不明、开关时不起看护、起来时不起看护、到点不变「要关」、不报故障、TTS 不查退出码、播放器起不来不报错、放完不回调、退出码不对也算放完、代理不接回调、HAL 不报上装故障。
  - 「写失败不标不明」第一轮没抓住：那条测试里那一路从来没确认过（一开始就是不明），看护循环本来就会补写。改成先确认过「关」、再丢应答，就抓住了。

## 外审复查（2026-10-07）：FIX-THEN-APPROVE，剩 2 条，已修

**1. 上装关不上，站点不出告警。** 狗报了 `payload_*` 故障，可站点的告警源对 `robot_fault` 只认「跌倒」。上一轮报告里写的「站点照常出告警」并没有做到：我只查了狗那头报出去了，没查站点收没收。

修法：
- 每一路一种告警：`payload_strobe` / `payload_siren` / `payload_spotlight`，都是 P1（夜里警笛、聚光灯一直开着，人得去看）。每一路分开记，是因为告警簿按「狗 + 种类」合并：合成一种的话，后报的一路会盖掉先报的，恢复时也没法一路一路地解决。
- **以告警簿为准**（同 W19 摄像头）：`robot_fault` 带的是整个故障集合（集合变了才发，代理起来先发一次全集）。
  - 这一路在集合里、簿子里还没挂着，就报；
  - 不在集合里了，就解决。
  - 所以重复上报不会重复报；站点重启后内存空了，照样对得上。

**2. TTS 合成时占着狗上代理的命令锁，「关喇叭」要排队。** 上一轮把 TTS 改成当场合成完再回，最长 30 秒，这期间代理的全局命令锁一直被占着。「关喇叭」和别的命令都得排在后面，合成进程也一直活着。

修法：
- 不在调用方里等合成：当场只起合成进程（起不来照样当场报错），合成、播放都放到后台。
- 合成失败（退出码不是 0）、放坏了、放完了、到点了，都经回调告诉代理。代理当场放开优先级、记事件。
- 合成中关喇叭：合成进程当场掐掉，**不再起播放器**。
- 刚合成完、正在起播放器的那一下被关掉：起出来的播放器也掐掉，不许留着放。

补的测试：
- 站点：
  - 每一路一条 P1、标题写明哪一路；重复上报不重复报、计数不涨；聚光灯好了只解决聚光灯；
  - 站点重启（新的告警台、新的告警源，同一个库）后，重复上报照样不重复，好了照样解决；
  - 别的狗的故障不串；
  - **端到端**：仿真狗报 `payload_siren` → 真代理发 `robot_fault` → 真站点出 P1 → 故障消了，告警自己解决。
- 驱动：
  - TTS 合成要 30 秒时，调用当场返回；合成中关掉，合成进程掐掉、不再起播放器、不回调；
  - 卡在起播放器的那一下被关掉，起出来的也掐掉；
  - TTS 退出码不对，回调失败、不放。
- 代理（真代理、真命令锁）：TTS 合成要 30 秒时，开喇叭那一条当场回，紧接着关喇叭也当场做，合成进程被掐、不再起播放器。
- 突变 7 条全被抓住：
  - 站点：不接上装故障、不看告警簿就重复报、好了不解决、上装故障只算 P2；

## 外审第二次复查（2026-10-07）：FIX-THEN-APPROVE，剩 1 条，已修

**上装告警报、解决失败之后不会再试，站点重启也补不上。** 上一轮只在收到故障事件的那一下处理告警。可派遣器是**先把事件存进库、再调告警源**：
- 回调那一下没成（比如库锁住了），同一事件重投会被去重跳过；
- 故障集合没变，狗也不会再发新事件；
- 所以这条告警永远补不上。恢复后解决没成，也是同样的缺口。

修法：**按每台狗最近一次报的故障全集，每拍对账告警**。
- 收到 `robot_fault` 先把全集记在内存里，再报、解决；这一下没成只记日志，不往外抛。
- 站点告警循环每拍（5 秒）按记着的全集对账：该挂的没挂就报，不该挂的还挂着就解决。一台狗炸了不挡别的台。
- 站点起来后第一拍，从事件库读回每台狗**最近一条** `robot_fault`（按站点收到的时刻），再对账；读库失败了下一拍再读。
- 事件表加了一个索引（种类、狗、收到时刻），读「每台狗最近一条」时不扫整张表。

补的测试：
- 第一次报告警没成，重投同一事件也补不上，下一拍对账补上，再一拍不重复报；
- 好了但解决没成，下一拍接着解决；
- 事件落了库、告警一次都没做成，站点重启：按每台最近一条对账。A 只剩警笛、警灯早就好了；B 都好了，老告警解决；
- 读库失败，下一拍再读；
- 一台对账炸了，不挡别的台。

突变 5 条全被抓住：每拍不对账、起来不读库、读成最旧的一条、读库失败就算读过了、一台炸了别的台也不对账（这一条第一轮没抓住，补了上面最后一条测试）。

## 已知限制、要你做的

- **没接过真上装**（决策 36）。型号定了先在桌上接，按《庄园场景待真机测试》§3j 一项一项验：
  - 串口在不在、代理账号有没有 `dialout`、`audio` 组权限；
  - 继电器板站号、波特率；各路开关、到点自己关、重启全关；
  - 声卡设备名、话术、TTS；
  - 各路从哪个口取电、全开时的电流。
- **`/dev/ttyCH9344USB5` 到底挂在 Orin 还是 RK3588 上，SDK 文档没写清**。代理跑在 Orin 上；如果这个口在 RK3588 上，就得改成经旁路进程转发，或者在 Orin 上另插一个 USB 转 RS485。真机第一项就查这个。
- **代理进程被 `kill -9` 的那几秒**：继电器板保持原状，要等 systemd 拉起代理，起来时关上（关不上就一直关，并报故障）。这是继电器板的物理性质；真要更稳，可以选带「通电延时自动断」功能的继电器板（Modbus 闪开指令），型号定了再看。
- 爆闪的闪法由警灯自己的模式决定，我们只管开关。
- 供电不管（决策 36）：上装常电。要按需断电省电，得先升平台用 `SetPeriphPower`（只有 48V、24V、12V 三路）。
- 狗上有没有 `espeak-ng` 不知道，离线装要事先准备好包。不装也行：只放录好的话术。
- 喇叭的「对讲」（人在手机上说、狗上放）是 W27，要先拍板决策 4（App 内对讲还是实体对讲机）。
- 分级驱离（L0–L4，自动按顺序开灯、放话术、鸣笛）是 W22，用的就是这一单的 `deter` 命令，优先级用事件档。
