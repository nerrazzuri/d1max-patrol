# W21 上装 HAL · 设计与完工报告

> 工单：「RS485（`/dev/ttyCH9344USB5`）驱动喇叭/警灯/警笛/聚光灯；`SetPeriphPower` 管供电；音频优先级仲裁。SDK 无任何音频接口」。分支 `w21-payload` → PR。设计与报告合一份。

## 用户决定（2026-10-07，决策 36）

上装还没选型。四项都按推荐：

1. **先做通用框架 + 假设备**：驱动、优先级仲裁、能力上报、手机按钮都做，用假继电器板、假播放测；型号到了只改适配那一层。
2. **喇叭**：USB 声卡 + 功放喇叭，插狗的 USB3.0 口，Orin 上用 ALSA 放。录好的话术、文字转语音都能放。
3. **警灯、警笛、聚光灯**：都当开关，经一块通用的 **RS485 Modbus RTU 继电器板**开关。
4. **供电第一版不管**：上装常电（扩展舱按钮开着），开关都靠继电器板。

## 先查清的事实

- 狗身上没有任何音频接口。两版 SDK、硬件手册里都没有喇叭、麦克风。
- 扩展口（SDK 开发指南 §1.5）：48V 10A、24V 20A、24V 3A + 网口、12V 5A + 网口、串口（RS232、RS485、SBUS×2、PPS）、USB3.0 两个。整机所有供电口加起来最多 480 W。
- RS485 是 `/dev/ttyCH9344USB5`，接在 M12 接头的第 4 脚（A）、第 5 脚（B），第 8 脚是 GND。
- **`SetPeriphPower` 只在 SDK 0.2.0 里有**，只管三路（48V、24V、12V）。狗的平台是 0.2.4，只能配 SDK 0.1.1，我们的旁路进程也是按 0.1.1 编的。所以台账原文「`SetPeriphPower` 管供电」现在做不到。要用它得先让厂家把平台升到 0.3.0（V4），所有真机项都要重验。决策 36 选了不管供电。
- 方案书原文不在仓库里，也没有任何上装型号。

## 怎么做的

### 一条命令：`deter`

站点经 MQTT 发给狗上的代理，载荷两头用同一份校验（契约 `deter.py`）：

| 字段 | 说明 |
|---|---|
| `output` | `strobe` 警灯、`siren` 警笛、`spotlight` 聚光灯、`speaker` 喇叭 |
| `on` | 开还是关 |
| `max_s` | 开的时候必带，0–600 秒。**到点狗上自己关** |
| `clip` | 只给喇叭：话术名，或 `tts:<语言>:<文字>`（最多 300 字） |
| `priority` | 只给喇叭，0–100。**站点定**：手机手动按的是 60（`MANUAL`），请求体里的不认 |

几处要紧的判断：
- **不是任务**（照 `video` 的做法）：不占任务槽、不进任务状态机。巡检、去拦截点的路上照样能开，开了也不打断它们（有测试）。
- **声光一定会自己停**：每次开都带最长时间，到点 HAL 那一层自己关，站点没了、断网了也一样。代理断开 HAL（收尾）时全关；起来时先全关，因为上次进程死掉时开着的继电器不会自己关。
- **喇叭优先级仲裁在代理里**：同一时间只放一段。新来的比正在放的低，回 `busy`；一样高或更高的，打断正在放的。**关喇叭不看优先级**：让它安静永远可以。W22 驱离、事件派遣用更高的优先级，手动的就打断不了它们。
- 每次开、关都记一条 `deter` 事件（哪一路、开多久、放的哪段话术），断网时留在狗上，回来补传。W22 复盘要用。
- 钟差闸（W09h）：开要钟差合格，跟视频一样；**关始终放行**。
- **不进幂等记录**（同 `video`）：重投的旧命令至多把那一路从现在再开 `max_s`，有上限。

| 层 | 内容 | 文件 |
|---|---|---|
| 契约 | `deter` 载荷与校验；HAL 加 `siren(on, max_s)`；执行器能力加 `strobe`（警灯，跟狗自带的前后灯 `light` 分开）；声光类「关」的写法统一（`strobe(ch, "off", 0)`、`siren(False, 0)`、`sound("", 0)`、`spotlight(False, 0)`）；黄金夹具 `command_deter` | `contract/deter.py`、`hal.py`、`fixtures.py` |

| 真狗 HAL | 有上装配置就接上；能力照实报（哪一路接了才报 true）；第一次连上时全关一遍（之后连接幂等，不再关）；断开时全关；`sound_clips()` 列出话术目录下的 wav | `adapter-d1max/hal.py` |
| 仿真狗 | `payload=True` 时四路都有，按仿真的钟算到点关，带两段假话术；演示用 `d1max-agent --hal sim --sim-payload` | `adapter-sim/robot.py` |
| 代理 | `DeterDesk`：校验、看这一路接没接（没接回 `unsupported`，不碰设备）、喇叭优先级仲裁、调 HAL、记事件；设备的错回 `device: …` 原样给站点。能力 `tasks.deter = {outputs, max_s, clips, tts}`，一路都没接就不报。命令行 `--payload`（默认 `/etc/d1max/payload.json`，文件不在就是没装） | `robot-agent/deter.py`、`commands.py`、`runtime.py`、`main.py` |

### 上装配置（狗上 `/etc/d1max/payload.json`）

```json
{
  "relay": {
    "port": "/dev/ttyCH9344USB5",
    "baud": 9600,
    "slave": 1,
    "coils": {"strobe": 0, "siren": 1, "spotlight": 2}
  },
  "audio": {
    "device": "plughw:1,0",
    "clips_dir": "/var/lib/d1max/clips",
    "tts_command": "espeak-ng -v {lang} -w {wav} {text}"
  }
}
```

- `coils` 写哪一路接在继电器板的第几个线圈（从 0 数），没写的就是没接；两路不许接同一个线圈。
- 没接喇叭就不写 `audio.device`；不要 TTS 就不写 `tts_command`。
- 文件不在，就当没装上装：能力全报 false，手机上没有「上装…」。

## 测试

- **上装驱动**（`test_payload.py`，17 条）：
  - 假继电器板挂在 pty 另一头，按 Modbus RTU 回；
  - CRC 标准例子；写、读线圈；板子不回、CRC 错、回异常码都报错；站号不对的不认；
  - 配置只认三路、线圈不许重复；
  - 到点自己关、再开重算；没接的、时长不对的拒；起来全关、收尾全关；到点关不掉过 1 秒再关；
  - 喇叭放话术、到点掐掉播放进程、新的打断旧的；话术名不许越出目录；TTS 没配就拒、配了先合成再放；
  - 真狗 HAL 装了上装：能力照实报、入口走继电器板和喇叭、断开全关；没装就四路都报没有。
- **仿真狗**：开了带时长、到点算关、关就关。
- **代理**（`test_deter.py`，8 条）：
  - 能力里报接了哪几路、能放哪些话术；没装不报、来了回 `unsupported`；
  - 开警笛到点自己关，开、关都记事件；载荷不对回 `payload`，不动设备；
  - 喇叭优先级：低的 busy、一样高打断、关不看优先级、放完了谁都能放；没有这段话术回设备的错；
  - **不占任务槽：去一个点的路上照样能开警灯，那一趟不受影响**；
  - 只派接上的那几路（假 HAL 没报聚光灯，调了也不报错，代理自己挡住）。
- **站点**（`test_site_deter.py`，5 条，真 HTTP → 真代理 → 仿真狗）：
  - 保安开警笛 → 狗上开了 → 到点自己关 → 进审计；
  - 业主 403、没登录 401、载荷不对 400；
  - **喇叭优先级站点定，请求体里写 100 也按 60 发**；
  - 没装上装的狗回 409；狗报的上装能力原样给手机。
  - 钟差闸分类：开 gated、关 safe。
- **契约**：HAL 方法清单加 `siren`；夹具 `command_deter`。
- **手机**（`site_deter_test.dart`，5 条）：
  - 入口按角色和狗的能力出现；只列接上的几路；开带默认时长、关随时；
  - 喇叭挑话术放、现打一段、停；狗没配 TTS 就没有现打那一行；
  - 狗拒了说人话。
- **突变测试 20 条全被抓住**：
  - 到点不关、起来不全关、收尾不全关、不核 CRC、到点关不掉不再试、喇叭到点不掐、话术名不检查、HAL 断开不关上装；

## 已知限制、要你做的

- **没接过真上装**（决策 36）。型号定了先在桌上接，按《庄园场景待真机测试》§3j 一项一项验：
  - 串口在不在、代理账号有没有 `dialout`、`audio` 组权限；
  - 继电器板站号、波特率；各路开关、到点自己关、重启全关；
  - 声卡设备名、话术、TTS；
  - 各路从哪个口取电、全开时的电流。
- **`/dev/ttyCH9344USB5` 到底挂在 Orin 还是 RK3588 上，SDK 文档没写清**。代理跑在 Orin 上；如果这个口在 RK3588 上，就得改成经旁路进程转发，或者在 Orin 上另插一个 USB 转 RS485。真机第一项就查这个。
- **代理进程被 `kill -9` 的那几秒**：继电器板保持原状，要等 systemd 拉起代理、起来全关那一下才灭。这是继电器板的物理性质；真要更稳，可以选带「通电延时自动断」功能的继电器板（Modbus 闪开指令），型号定了再看。
- 爆闪的闪法由警灯自己的模式决定，我们只管开关。
- 供电不管（决策 36）：上装常电。要按需断电省电，得先升平台用 `SetPeriphPower`（只有 48V、24V、12V 三路）。
- 狗上有没有 `espeak-ng` 不知道，离线装要事先准备好包。不装也行：只放录好的话术。
- 喇叭的「对讲」（人在手机上说、狗上放）是 W27，要先拍板决策 4（App 内对讲还是实体对讲机）。
- 分级驱离（L0–L4，自动按顺序开灯、放话术、鸣笛）是 W22，用的就是这一单的 `deter` 命令，优先级用事件档。
