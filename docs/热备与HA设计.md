# 站点热备与 HA：控制权怎么交接（设计稿）

> RC 加固 H11（决策 56）：**只设计、写测试，不实现**。不接 PostgreSQL、Pacemaker、etcd。
> 这一稿只回答一件事：两台站点主机的时候，**谁说了算、狗听谁的、换主的那一刻在途的事怎么办**。
> 数据怎么复制过去（用什么引擎）故意不定，第七节只写它要满足什么。
> 配套的可执行模型和脑裂测试：`tests/ha_model/`（纯逻辑，不碰产品代码）。

## 0. 现在是什么样

- 一个站点一台主机：SQLite、自己的 Mosquitto、自己的 CA。坏了靠备份恢复到新主机（A2，最多丢一小时）。
- 恢复出来的站点**身份不变**（同一个 CA、同一张服务证书）：狗和手机不用重新登记。HA 沿用这一点：**两台主机是同一个站点身份**，狗和手机分不出也不需要分出是哪一台。
- 命令里已经有一个代次 `control_epoch`（每台狗一个，记在登记表里）：狗只收不比自己记的小的。这是每台狗「控制权交接」的计数，不是站点换主的计数。
- 狗重连后发的第一条是 `Reconcile`（我是哪次开机、在跑哪个任务），站点以它为准。站点重启后的对账就是靠它。
- 声光每次开只管 45 秒，站点 20 秒续一次；站点没了，狗上最多 45 秒全关。

HA 要加的东西很少，因为「主机突然没了、另一台从稍旧的数据接着干」跟「站点崩了重启」是**同一条路**，这条路已经做过、审过（系统审查 SR1）。新的只有一个问题：**旧的那台可能还活着。**

## 1. 三个词

| 名字 | 是什么 | 存哪儿 | 什么时候变 |
|---|---|---|---|
| `site_epoch` | 站点的任期号，整数，只增不减 | 站点库（跟着数据一起复制到备机）；每台狗自己也记着见过的最大值，落盘 | **只有「升主」这一个动作**把它加一 |
| `leader_id` | 这台主机是谁（`a`、`b`） | 主机本地的文件，**不复制**（复制了两台就同名了） | 装机时定，不变 |
| `command_epoch` | 一条命令带的代次：`(site_epoch, control_epoch)` 两个数一起 | 命令报文里 | 每条命令发出时取当时的值 |

狗收命令的规矩（在现有的「`control_epoch` 不小于我记的」上加一条）：

1. 命令的 `site_epoch` **小于**我见过的最大值 → 不执行，回执写明「站点过期」，带上我见过的最大值；
2. **大于** → 先把新的最大值落盘，再往下判；
3. 之后照旧判 `control_epoch`、有效期、钟差、前置条件。

「先落盘再执行」不能反过来：反了的话，狗执行完新主的命令、还没记下就重启，起来又会听旧主的。

## 2. 谁是主

- **同一时刻只许一台在「主」的状态。** 主：发命令、跑排程、跑告警循环、收证据、开着给狗连的 broker。
- 备机：收复制过来的数据，**给狗连的 broker 端口不开**，不发任何命令，接口只读（值班台上能看、明写「这是备机」）。
- 第一版**不自动换主**。两台机器没有第三方作证，谁也分不清「对方死了」和「我跟对方之间的网线断了」；自动换主在这种时候会出两个主。换主是人下的命令：`d1max-site promote`。
- 以后要自动，先加一个**见证**（第三个很小的节点，只投票不存数据），主拿租约才干活。见第八节，不在第一版。

## 3. 怎么证明自己是主

对狗：**任期号**。狗不看是哪台主机发的（两台证书一样），只看 `site_epoch`。新主的任期号一定比旧主大，因为：

- 任期号只在升主时加一；
- 升主的那台必须已经拿到它**听说过的最大任期号**所在的那份数据（备机一直在收复制，天然满足；旧主想再当主，要先当备机把数据同步回来，见第五节）；
- 所以不会有两台各自把任期号加到同一个数。

对人、对另一台主机：主把 `{site_epoch, leader_id, 从几点起}` 发成自己 broker 上的一条保留消息（`…/site/leader`），接口 `/healthz` 里也带。

## 4. 狗怎么知道旧站点过期了

三道，任何一道起作用就够：

1. **连上 broker 先看保留的 `site/leader`**：任期号比我记的小 → 断开，换地址表里的下一个。狗的配置里站点地址是一张表（两台主机），不是一个。
2. **命令带任期号**（第一节）：就算连在旧主的 broker 上，旧任期的命令也不执行。
3. **回执**：狗回「站点过期」时带上它见过的最大任期号。旧主收到一条这样的回执，就知道自己被换下去了，立刻**自己下台**（第五节）。

要说清楚的边界：一台狗在换主之后**从来没碰到过新主**（它跟旧主在分区的同一边），它不知道任期变了，会继续听旧主的。这种情况靠第五节的「人确认」兜住，任期号兜不住。

## 5. 分区、旧主回来

**换主之前，人要确认旧主已经不能指挥狗了**：断电，或者把它的网线拔了。命令上要显式写（`promote --old-leader-is-off`），不写不升。这是第一版唯一的「隔离」手段，所以写进操作手册的第一行。

| 情况 | 会怎样 |
|---|---|
| 主坏了（断电、盘坏） | 人在备机上 `promote`。任期加一，开 broker，跑一遍「重启对账」（第六节）。狗连过来看到新任期 |
| 主备之间的网断了，主还能连狗 | 主照常干活，报 P2「备机跟不上」。**不换主。** 备机上的数据越来越旧，这时候硬升会丢这段时间的数据，命令要再加一个确认才给升 |
| 主被隔开了（它连不到狗，备机连得到） | 人确认之后升备机。旧主还开着但碰不到狗；网通了以后它连到新主或者收到狗的「站点过期」回执 → 下台 |
| 人没确认就升了、旧主其实还连着一部分狗（**脑裂**） | 碰过新主的狗不听旧主的（任期号）。只跟旧主连着的狗还听旧主的，直到旧主下台。两边都可能对同一条入侵派狗。这是这套设计**防不住**的情况，所以升主要人确认 |
| 旧主回来（重启、网通了） | 起来第一件事：问一下对方的任期号、看一眼对方 broker 上的 `site/leader`。发现比自己大 → 进「下台」状态，**不开 broker、不跑任何会发命令的循环** |

**下台的旧主**：只读；值班台顶上一条通栏「这台已经不是主，去 xx」；改东西的接口回 503 带新主的地址。它在分区期间自己写的那些（确认过的告警、收到的证据）跟新主的数据**分叉了**，不自动合并：导出成一个「分叉包」给人看，然后整台清掉、作为备机从新主重新同步。自动合并两边的告警状态，出错了没人看得出来。

## 6. 换主那一刻在途的事

原则：**换主 = 站点从一份稍旧的数据重启。** 新主升上来以后走的就是现有的重启对账，不写新路。丢的是「最后一次复制之后」的那一小段（第七节给上限）。

| 在途的 | 新主怎么办 | 靠什么保证不出事 |
|---|---|---|
| 已经发出去、狗还没回执的命令 | 不重发。等狗的 `Reconcile`：它在跑什么就认什么 | `command_id` 幂等、命令有有效期；旧命令过期自己作废 |
| 写了意图、还没发出去的（派遣、撤任务、删证据） | 意图在库里、复制过来了：照意图接着做。没复制过来：这件事等于没发生，触发它的那个源（摄像头事件、排程的那一趟、人点的那一下）要重来 | 「先落盘再动作」（SR1）；排程漏跑会报警（W00c6c） |
| **驱离中** | 会话复制过来了：按 `Reconcile` 接上，从同一级继续续声光。没复制过来：新主不知道有这一场，**狗上的声光 45 秒内自己全关**，狗停在原地等命令；那条入侵告警如果也没过来，要靠事件源再报 | 声光 45 秒自己关（W22）；狗没有命令不会自己动 |
| 人在遥控 | 遥控租约断了，狗按「遥控断线」停车。人重新接管 | 现有的遥控看门狗 |
| 狗上攒着没传完的照片、录像 | 连上新主接着传 | 现有的断点续传 |
| 推到手机的 P1 | 队列在库里：没发完的通道接着发；重复的在手机上盖掉原来那条 | H9 的按通道记账、通知标记 |
| 连续录像（站点录的） | 旧主上的那一段丢了，新主从升上来那一刻接着录 | 手册写明：连续录像不保证 |

所以**必须同步复制、不许丢的只有三样**：P1 告警、驱离会话、发出去的命令的意图。别的可以异步。第七节。

## 7. 数据怎么过去（只写要求）

- 有顺序、能查出缺口：每一笔带位置号，备机知道自己到哪儿了、缺没缺。
- 上面那三样：备机健康时，**主等备机说收到了再算写成**（等不到，过一个很短的时限就不等了，改成异步，同时报 P2「备机跟不上」）。这样备机健康时这三样的丢失是 0。
- 别的：异步，落后不超过几秒；落后超过一分钟报 P2。
- 照片、录像、地图、CA 目录、站点配置也要过去（现在的备份已经知道该带哪些）。
- 三把密钥（口令密钥、备份密钥、证据私钥）两台都要有，装备机时从托管包放进去；**不走复制通道**。
- 任期号在库里，跟数据一起走。

用什么实现（SQLite 的日志流、换数据库）等这一稿定了、做了数据访问层的边界（H12）再选。

## 8. 以后：见证与自动换主（不在第一版）

加第三个节点，只做一件事：给「主」发租约。主每隔几秒续一次，续不上超过租期就**自己停手**（不再发会让狗动的命令，只许停止、解除一类）；备机要等租期过完再加一段余量才许自动升。时间用各自的单调钟算时长，不比较两台机器的墙上钟。这一套要单独设计、单独审。

## 9. 不变式（测试要钉住的）

1. **任期只增**：任何一台狗记的最大任期号不会变小，重启也不会。
2. **不听旧的**：狗见过任期 N 之后，任期小于 N 的命令一条都不执行。
3. **先记再做**：狗执行任期 N 的命令之前，N 已经落盘。
4. **升主才加**：除了升主，没有任何路径改任期号；升主每次只加一。
5. **不会同号**：两台主机不会各自升到同一个任期号。
6. **下台不发**：旧主一旦知道有更大的任期（对方告诉它、狗的回执告诉它、broker 上看到），就不再发任何命令，重启以后也不发。
7. **备机不发**：没升主的备机不发命令、不开给狗连的 broker。
8. **换主不靠运气关声光**：换主时不管驱离会话有没有复制过来，狗上的声光最迟 45 秒关。

`tests/ha_model/` 里是一个只有几十行的模型（站点、狗、能不能连通）和这八条的测试，包括「人没确认就升了」的脑裂：模型里能看到哪些狗会听错的那一边，以及旧主什么时候下台。模型不是实现；实现的时候，这些测试的场景要在仿真狗上原样再做一遍。

## 10. 实现时要动的地方（先列着，不做）

- 契约：`Command` 加 `site_epoch`；回执加「站点过期」和狗见过的最大任期；兼容级别加一（狗和站点要一起升）。
- 狗：最大任期落盘；连上先看 `site/leader`；站点地址从一个变成一张表。
- 站点：`meta.site_epoch`；主机本地的 `leader_id`；`promote`、`rejoin` 两条命令；「备机」「下台」两个状态下所有会发命令的循环不跑；值班台的通栏。
- 手机、值班台：地址表；碰到 503「不是主」换地址。
- 证据、告警接口在备机和下台的主机上只读。

## 11. 要用户定的

1. 第一版换主靠人下命令、而且要人确认旧主已经断开，不自动。同意吗？（我建议同意：两台机器没有见证，自动换主一定有出两个主的时候。）
2. 驱离会话没复制过来时，新主**不**替狗接着驱离（声光 45 秒后自己关，等人或者等事件源再报）。同意吗？（我建议同意：新主不知道现场的情况，替它续等于盲开警笛。）
3. 旧主分区期间自己记下的东西不自动合并，导出给人看。同意吗？
