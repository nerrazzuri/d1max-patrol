# D1 Max 视觉规范（B0 专业版）

> 2026-10-11 定，取代同日上午的「A 配色 + C 布局」方向。依据用户的两条要求：
> - **「要设计成专业的，而不是为了漂亮设计」**；
> - **值班页以视频为主**：所有狗的前后两路在一页内，可以滚动；地图放在另一个页签。
>
> 方案由设计助手按 frontend-design 技能和控制室行业规范评审得出：ISA-101、ISO 11064 / 9241-303、VMS 惯例、ISA-18.2、ISO 13850。用户同意了四条建议：
> 1. 按专业版做；
> 2. 第一版就做 P2 搁置；
> 3. P2 不闪；
> 4. 字体用 Atkinson Hyperlegible。
>
> - 数值的唯一来源：`design/tokens.json`。
> - `tests/test_design_tokens.py` 检查四件事：
>   - 对比度够 WCAG AA；
>   - 报警色专用，正常状态不着色；
>   - 优先级三重编码（颜色 + 形状 + 文字）；
>   - 「全部急停」靠外框达标。
> - 样稿：画布 https://claude.ai/artifact/2JqDNRH8tHNsYfoCEDTZgP 的「Pro」一组。
> - 告警中英文标题：`design/i18n/alerts.json`。
>
> 页面分两组：
> - **值班组**：Live（视频墙）、Map、Alarms、Recordings、Reports；
> - **管理组**（只有管理员看得到）：Robots & cameras、Maps & zones、Users、Lists、System。
>
> Lists 第一版只做「时段 / 人员授权」，比如园丁每周二上午在后花园，这段时间那里看见人不报警。人脸名单和车牌名单另行立项。

## 一、依据的专业实践

| 依据 | 采用的要点 | 在本方案里体现为 |
|---|---|---|
| **ISA-101 高性能 HMI** | 中性灰底；颜色只给异常和报警；不用装饰色；报警色不挪作他用；报警优先级用「颜色 + 形状 + 文字」三重编码；只有**未确认**报警闪烁 | 正常状态（巡逻、充电、待命、实时）一律中性灰，不再用绿色；红 / 琥珀只表示 P1 / P2；P1/P2/P3 各有固定形状；只有未确认的 P1 闪 |
| **ISO 11064 控制室人机工效**（及 ISO 9241-303 字符大小） | 长时间值守用低眩光深灰而不是纯黑或大面积亮色；在常规视距（约 70 cm）下可读；信息密度适合 8–12 小时盯屏 | 界面底色深灰 `#1C1D1F`；最小可读字 14px（画面 OSD 也是 14）；正文 16；无大面积高亮色块 |
| **专业 VMS 惯例**（Milestone XProtect Smart Client、Genetec Security Desk、海康 iVMS 视频墙） | 规则网格；每路画面叠加「摄像头名 + 时间」；实时 / 录像指示；报警画面高亮；报警队列 + 确认流程；操作员任何时候都知道哪块画面是哪路 | 每路画面 OSD 写全名 `D1-01 Front` + 时间；`Live` / `Paused` / `Rec` 指示；报警的狗画面置顶加框；底部常驻**报警队列**表格 |
| **ISA-18.2 报警管理** | 区分「未确认 / 已确认 / 已解除」；搁置（shelving）需有理由且自动到期；未确认与已确认在视觉上必须不同；队列按「未确认 → 优先级 → 时间」排序 | P1/P2 每条都有明确状态；「I'll handle it」= 确认，「False alarm / Resolve」= 解除；P2 可搁置（带理由、定时恢复），P1 不可搁置 |
| **ISO 13850 / IEC 60204-1 急停** | 急停执行器用红色，位置固定、随时可达 | 「Stop all」是全站**唯一**允许用红色的控件（报警色的唯一例外），配八边形图标，固定在顶栏最右，每页都在 |

**刻意偏离标准的地方（并说明理由）**：
- ISA-101 一般让所有未确认报警都闪。本系统 **P2 未确认不闪**，只用「New」标记 + 粗体：P2 的定义是「今天处理」（摄像头掉线、被撞、备份过期），整夜闪烁会造成报警疲劳，反而让 P1 不显眼。
- 视频画面槽用纯黑 `#000000`，不按 ISO 11064 用深灰：这是视频本身的黑边（与所有 VMS 一致），不是界面底色；界面底色仍是深灰。

## 二、设计方案

**一句话**：中性深灰的工具界面，视频按 VMS 规则网格排列、每路画面自带名字和时间；平时屏幕上没有颜色；颜色只在出现 P1 / P2 时出现，并且始终配形状和文字；报警走「队列 → 确认 → 解除」的标准流程。

### 2.1 颜色

**中性色（界面骨架，6 个核心值）**

| 名称 | token | 值 | 用途 |
|---|---|---|---|
| Video well | `well` | `#000000` | 视频画面槽 / 黑边，地图场地 |
| Background | `bg` | `#1C1D1F` | 页面底（ISO 11064 深灰） |
| Surface | `surface` | `#252628` | 顶栏、狗铭牌条、报警队列、面板 |
| Raised | `raised` | `#303134` | 选中页签、悬停行、菜单、分段控件选中段 |
| Control border | `borderControl` | `#85878C` | 按钮 / 输入框 / 分段控件的边 |
| Text | `text` | `#E2E2E2` | 正文、标题；也是「普通主按钮」的实底（上面放 `bg` 色字） |

辅助中性：`textSecondary #C0C0C0`、`textMuted #A0A0A0`（最淡可读字）、`textDisabled #6A6A6A`（只给禁用 / 装饰）、`rule #3C3D40`（装饰分隔线）、`hatch #2C2D30`（离线斜纹第二色）、`onSolid #FFFFFF`、`osdPlate rgba(0,0,0,0.7)`（OSD 底板；最坏情况压在纯白画面上等效 `#4D4D4D`）。

**语义色（只表示异常 / 报警 / 选择，互不挪用）**

| 含义 | token | 值 | 用在 | 不准用在 |
|---|---|---|---|---|

### 2.2 字体

| 角色 | 字体 | 许可 / 来源 | 理由（功能性） |
|---|---|---|---|
| 界面文字 | **Atkinson Hyperlegible Next**（可变，用 400 / 600 / 700） | SIL OFL 1.1，Braille Institute 2025；Fontsource / google/fonts 均可取，自托管 latin 子集 woff2 | 为低视力和疲劳阅读设计，0/O、1/l/I、5/S、8/B 明确可分。值班员要在凌晨读 `D1-01`、时间、距离，误读字符是实际风险 |
| OSD、时钟、时间列 | **Atkinson Hyperlegible Mono**（500 / 600） | SIL OFL 1.1，同上 | 与正文同家族；等宽只用于需要逐位对齐的时间和画面叠字（VMS 惯例） |
| 中文 | 系统回落：`'Noto Sans SC', 'Microsoft YaHei UI', 'PingFang SC', system-ui` | 系统字 | CSP 只允许自托管 latin 子集；中文不下载 |

```
--font-sans: 'Atkinson Hyperlegible Next', 'Noto Sans SC', 'Microsoft YaHei UI', 'PingFang SC', system-ui, sans-serif;
--font-mono: 'Atkinson Hyperlegible Mono', 'Noto Sans SC', 'Microsoft YaHei UI', ui-monospace, monospace;
```
> 落地前核对 Fontsource 包名（`@fontsource-variable/atkinson-hyperlegible-next`、`@fontsource/atkinson-hyperlegible-mono`）；不可用则从 google/fonts `ofl/` 取 TTF 用 pyftsubset 子集化。若客户想少改，**IBM Plex Sans / Mono 也合格**（OFL、可自托管），只是对易混字符的区分不如 Atkinson。

**字号**（以 70 cm 视距、24 英寸 1080p 级显示器估算：16px 约合 ISO 9241-303 的最小推荐字符高度；因此可读文字不低于 14px，并提供 100% / 125% 显示缩放设置）

| token | 字号 / 行高 | 字重 | 字体 | 用在 |
|---|---|---|---|---|
| `osd` | 14 / 18 | 600 | Mono | 画面叠字：`D1-01 Front`、时间、`Live` / `Paused` / `Rec` |
| `caption` | 14 / 20 | 400 | Sans | 次要说明、离线说明 |
| `label` | 14 / 20 | 600 | Sans | 状态字、页签、徽标、表头 |
| `body` | 16 / 24 | 400 | Sans | 正文、队列行、按钮（按钮 600） |
| `heading` | 18 / 24 | 600 | Sans | 面板标题 |
| `unitId` | 18 / 24 | 700 | Sans | 狗铭牌条上的编号 |
| `title` | 21 / 28 | 700 | Sans | 报警画面头条标题、页标题 |
| `clock` | 21 / 28 | 600 | Mono | 顶栏时钟 |
| `phoneTitle` | 24 / 30 | 700 | Sans | 手机 P1 地点 |

不用全大写、不加字距、英文 Sentence case；中文 600 用 500。

### 2.3 视频墙（Live 页，1440×900）

**结构（自上而下）**：顶栏 56 → 跳转条 40（狗 > 4 只时）→ 视频网格（可滚动）→ 报警队列（底部常驻，展开 168 / 收起 40）。

**网格**：左右边距 16，两列，每列 696，列距 16（宽屏 ≥ 2200 时三列）。一只狗 = 一个外壳：铭牌条 32 + 前后两路画面（各约 346×195，16:9，中间 2px 缝）。外壳约 229 高。画面保持摄像头原始宽高比，不足处纯黑，不裁切。
**排序**：按编号固定（操作员靠位置记画面，VMS 惯例）；唯一例外：有未解除 P1 的狗置顶。离线的狗原位收成 48 高窄条。

#### 顶栏（每页相同）

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ D1 Max  Live Map Alerts Robots Recordings Reports   [◆1 ▲2]  [Armed|Home|Visitor]  02:15:08  [EN|中文]  Wang v  [⯃ Stop all] │
└──────────────────────────────────────────────────────────────────────────────────────────────────────┘
```
- 页签选中 = `raised` 底 + 2px `text` 下划线（不用颜色）。
- `[◆1 ▲2]`：未解除的 P1 / P2 计数（形状 + 数字 + 颜色），点击展开底部队列。没有报警时显示 `No active alarms`（`textMuted`）。
- 模式分段控件中性；当前模式 `raised` 底 + 图标。
- `Stop all`：`p1` 实底 + 2px `p1Frame` 框 + 八边形图标，固定最右。
- < 1280：Recordings / Reports 收进 `More`；< 720：页签变底部标签栏，Stop all 留顶栏。

#### 一只狗的外壳

```
┌ 铭牌条 32 (surface) ─────────────────────────────────────────────────────────────────────────┐
│ D1-01   Patrolling   [▮▮▮ ] 78%   Front lawn, lap 3                         [Map] [Full screen] │

│ D1-01 Front                     02:15:08     ││ D1-01 Back                      02:15:08      │ ← OSD 上沿：摄像头全名 + 时间
│                                              ││                                               │
│                (live, 5 fps)                 ││        (last frame, dimmed to 50%)            │
│                                              ││                                               │
│ ● Live                                Rec    ││ ‖ Paused at 02:13:40                          │ ← OSD 下沿：实时/暂停 + 录像
└──────────────────────────────────────────────┴┴──────────────────────────────────────────────┘
```
- **每路画面都写全名 `D1-01 Front`**（不只是「Front」）：全屏、截图、导出时也知道是哪路——VMS 的基本要求。
- 正常状态全部中性：`Patrolling`、`Charging`、`Returning`、`Idle`、`Manual` 都是 `text` 色字 + 灰图标。
- 异常才着色：`Deterring` / `E-stopped` / `Fell over` → `p1Text` + ◆；`Offline` / `Battery 18%` / `1 camera offline` → `p2` + ▲。
- 实时指示：白色实心点 + `Live`（中性）；暂停：⏸ + `Paused at 02:13:40`，画面压暗 50%；重连：`Reconnecting…`；拒流：`Stream busy: 6 viewers already`；录像中：`Rec`（中性白字，不用红点——红色只留给报警）。
- 单路掉线：该槽居中 `D1-01 Back offline since 23:10`（`p2` ▲），这是一条 P2，同时进入队列。
- **离线的狗**（48 高，`surface`/`hatch` 斜纹，不拉流）：
  `D1-03   ▲ Offline since 23:52. Last seen near West gate.                     [Map]`

### 2.6 功能焦点（取代「一个大胆的视觉元素」）

按客户要求，不做为好看而设的视觉亮点。唯一被强调的是**报警画面处理**，它完全由功能决定：
- 有报警的狗置顶、放大，前后两路都保持实时；
- 未确认 / 已确认 / 已解除三种状态外观不同（闪框 → 稳定框 → 回原位）；
- 报警信息、证据帧、操作按钮集中在同一块，值班员不用在地图、弹窗、卡片之间来回找；
- 报警队列与报警画面一一对应、同步状态。

其余一切保持安静：无品牌色、无渐变、无阴影、无悬停动效、无大数字；正常状态无颜色。

### 2.7 动效规则

| 场景 | 动效 | 减少动态（`prefers-reduced-motion`）时 |
|---|---|---|
| P1 未确认 | 报警画面框、队列 P1 徽标、地图 P1 点同步闪：不透明度 100% ↔ 40%，1.6 s 周期，**直到确认** | 不闪；框加粗到 4px，头条保留 `Unacknowledged for …` 文字 |
| P1 已确认 / P2 任意状态 | 不动 | 同 |
| `Unacknowledged for 0:42` | 每秒更新文字 | 同 |
| 状态变化、按钮按下、对话框 | ≤ 120 ms 淡变，只回应操作 | 瞬变 |
| 跳转条滚动 | 平滑滚动 | 瞬移 |
| 其它 | **无**：无入场动画、无悬停放大、无装饰动画 | — |

另：有未确认 P1 时，浏览器标签标题改为 `(1) P1 alarm | D1 Max`，值班员切到别的窗口也能看到。声音报警建议后续按 ISA-18.2 按优先级区分音调，单独定。
