# 狗绑定与解绑（客户自己加狗）· 设计要点

> 2026-10-27 跟用户讨论定的方向，用户说「差不多，先记下」。还不是完整设计，开工前再细化、再给用户批。
> 台账 W42。公司运维后台另列 W43（解绑令的签发要用到它）。

## 为什么

现在加狗要工程师登进狗执行 `provision --code`（`docs/装机清单.md`），客户做不了。用户 2026-10-27：
站点出了问题要删掉再加狗时，「这就不需要工程师过去了」——业主、保安自己就要能加。
另外装机清单里没有「狗连庄园 WiFi」这一步；客户以后改了 WiFi 密码，狗连不上，站点也找不到它。

## 定下来的

1. **绑定码贴在上装上**（用户：交付卡会丢）。工程师装机时生成，打成二维码贴上；狗里只存它的指纹。
2. **上装热点一直开着**（用户定的）。
   - **还没绑定**：手机 App 连热点、扫绑定码，狗核对；App 把庄园 WiFi 和站点地址、证书指纹（手机跟站点配对过，
     本来就知道）发给狗；狗连上站点，显示「等待批准」；业主在网页或手机上批准，站点发证书。**绑定后绑定码失效**
     ——狗被偷了，看得到码也绑不走。
   - **绑定以后**：热点那一侧只能看状态、改 WiFi（要扫码），**不能换站点、不能解绑**。热点上只开一个很小的配网服务，
     跟狗里其它东西隔开。
3. **解绑**
   - 正常：业主在站点上点「解绑」→ 站点通知狗 → 狗清掉证书和站点信息，回到「还没绑定」，绑定码重新生效。
     **转卖**就走这条：原主人解绑，新主人照绑定流程来。
   - 站点主机坏了、没备份：只能找我们工程师。**不做通用的「万能钥匙」**（泄露一次所有狗都能被绑走）：
     **一只狗一张解绑令**——只对这一只狗的序列号有效、限时（24 小时）、用一次作废；狗用出厂装好的公司公钥验签。
     解绑用**单独一把钥匙**，不跟升级包签名的发行钥匙共用（被盗也推不了假升级包）。
   - 解绑令由**工程师 App 申请、公司服务器签发**（用户：每次回公司太麻烦），签名私钥不进工程师手机；
     公司留记录（谁、何时、哪只狗），以后可加主管审批。这是 W43 公司后台的一部分。
     后台做出来之前的临时办法：工程师把序列号发给公司值班的人，值班的人在离线签名机上签好，把解绑令（文字或二维码）发回现场。
4. **站点从备份恢复**（商业化 A2）：站点身份不变，狗照常认，不用重新绑定。

## 硬件团队的回答（2026-10-30）

- 上装路由器已换成**有人 USR-G806w**（不再用 ZR9741G）。**能同时连庄园 WiFi、同时开本机热点**——说明书里是两个分开的设置；
  4G 做备份，网络切换设成 WiFi 优先、4G 备份，一路断了自动切另一路。**「热点一直开着」不用改。**
- 限制：只能连庄园的 **2.4 GHz** WiFi（连不了 5 GHz）；热点最多同时连 20 台；庄园 WiFi 断了重连时热点可能短暂掉一下，
  到货后实测。若实测掉线明显、客户感觉得到，硬件在盒里加一台小 AP 专门发热点，软件需求不变。
- 对软件的影响：手机 App 配网时要提示「只支持 2.4 GHz」（庄园只有 5 GHz 的要先在路由器上开 2.4 GHz）；
  配网过程中热点可能断一下，App 要能自己重连、接着等结果。

## 还要问硬件团队

- 热点和狗内网怎么隔开（V2 对接说明要求热点和内网隔离，具体在路由器上怎么设）。
- 上装上贴码的位置、要不要一个物理按键（目前设计不依赖按键）。
