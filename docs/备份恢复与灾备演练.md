# 站点备份、恢复与灾备演练

> 给运维、交付的人看。商业化 A2（决策 53）。技术细节见 `docs/商业化A2-完工报告.md`。

## 一、备份里有什么

站点每小时自动备份一次，写到 `site.json` 里 `backup_dir` 配的外接盘：

| 备份里的目录 | 是什么 | 加密 |
|---|---|---|
| `db/site-<时刻>.db.d1seal` | 站点数据库快照，留最近 7 份 | 是 |
| `config/site.json.d1seal` | 站点配置（站点号、主机名、端口……） | 是 |
| `ca/` | **站点身份**：CA 私钥、站点服务证书、签发过的狗证书、吊销列表 | 是（只进加密的备份） |
| `broker/` | MQTT 服务的配置 | 是 |
| `evidence/` | 巡检照片、事件记录 | 是 |
| `maps/`、`bags/`、`releases/` | 地图、建图录包、升级包 | 是 |

**不在备份里的**：
- 三把密钥：备份密钥、口令密钥、证据私钥；
- 连续录像：太大，按 30 天留存，只在站点上。

三把密钥**装机时就要离线另存**（U 盘放保险柜，或者交给客户 IT 保管）：

| 密钥 | 在站点上的位置 | 丢了会怎样 |
|---|---|---|
| 备份密钥 | `/etc/d1max-site/backup.key` | 备份全部解不开 |
| 口令密钥 | `/etc/d1max-site/secrets.key` | 摄像头口令、事件源密钥要重配 |
| 证据私钥 | `/etc/d1max-site/evidence.key` | 狗封好、还没解开的照片和录像再也解不开 |

## 二、站点自己会做的检查

- **每周自动抽查一次**，看备份能不能用：
  - 最新的库快照解得开、完整性检查过；
  - 站点身份齐全；
  - 库里登记的每一趟在备份里都有；
  - 抽 200 个文件核对加密校验。
- 抽查没过，报 **P2「站点备份校验没过：出了事可能恢复不了」**；修好以后下一次抽查过了，告警自动解决。
- 手机上的值守汇总里能看到上次备份、上次抽查、上次演练的时间和结果。

## 三、手动全量校验

```sh
sudo -u d1max-site d1max-site backup-verify /var/lib/d1max-site-backup --key /etc/d1max-site/backup.key
```

会核对：
- 最新一次**做完了**的备份（每次备份做完会发一份文件清单）：清单上的每个文件都在；
- 每个文件的加密校验对得上；
- 库里登记的每一趟、每张照片都在；
- 站点配置、MQTT 配置、站点身份都齐。

备份盘大的话要跑一阵。结果是 `ok: true` 才算能恢复成完整的站点；`problems` 里一条一条写着哪里不对。没加密的备份不带站点身份，只算数据备份，不会过。

## 四、站点主机坏了：恢复到新主机

1. **先**把离线另存的三把密钥放回新主机的 `/etc/d1max-site/`（`secrets.key`、`backup.key`、`evidence.key`）。
2. 用**恢复模式**装软件：

   ```sh
   sudo bash deploy/site/install-site.sh --recover
   ```

   恢复模式只装软件、用户、目录和服务单元：
   - **不生成密钥**：三把没放回就停下，因为换了钥匙，备份就解不开了；
   - **不 `init`**：不建新的站点身份；
   - **不起服务**。

   密钥的权限、属主由脚本改好。
3. 接上备份盘，恢复：

   ```sh
   sudo -u d1max-site d1max-site --home /var/lib/d1max-site restore /var/lib/d1max-site-backup \
       --key /etc/d1max-site/backup.key
   ```

   - 只往**空的**站点目录里恢复，不会盖掉已有的站点；
   - 用最新一次**做完了**的备份；做到一半断了的那次不用；
   - 恢复出来的文件、目录只有站点用户能读写，私钥一直是 `0600`；
   - 恢复完会自己校验一遍，`ok: true` 才算成。
4. 起服务：

   ```sh
   systemctl start d1max-mosquitto d1max-site
   ```

5. **核对站点证书指纹**：运行 `d1max-site fingerprint`，结果要跟原来一样。
   - 一样的话，狗不用重新登记，手机也不用重新添加站点；
   - 新主机的 IP 或主机名变了，要改狗上 `/etc/d1max/env` 里的站点地址。
6. 看一眼手机：狗都连上了，告警、运行记录、照片都在。

**丢的东西**：
- 最后一次备份以后的改动，最多 1 小时；
- 站点上的连续录像。

狗上还没传完的照片和记录，狗连上新站点后会接着传。

## 五、灾备演练（建议每季度一次、交付验收时一次）

```sh
sudo -u d1max-site d1max-site backup-drill
```

- 用站点配的备份盘和备份密钥，把最新的备份恢复到一个临时目录，校验，再跟正在跑的站点对一下数（狗、账号、运行记录、任务包），然后删掉临时目录。
- 不动正在跑的站点。
- 结果记进站点，值守汇总里看得到。对数只给人看：库快照最多晚一个小时，这期间新收的、删掉的会让两边差几条，不算失败。

演练时顺便核对：
- 离线另存的三把密钥还在、拿得到；
- 恢复步骤谁来做、要多久。

记到交付文档里。
