# 真机测试单 2026-11-05：POC 网络（不带 V2 上装，走对方 Wi-Fi 连我们的代理）

来源：用户 2026-11-04 晚。POC 时 V2 上装到不了：我们的整套服务照现在这样跑在机器人的 Orin 上；Orin、RK3588 都没有无线网卡，
网络只能借**竞品上装**（anbot，背上那台独立主控，`192.168.168.19`，见 `docs/厂家建图定位调研.md` 第一部分）的 Wi-Fi。
**竞品主控到 Orin 的桥接要关掉**：Orin 上的 `~/bridge_start.sh`（`ros1_bridge`，把 `/front_lidar`、`/rear_lidar`、雷达 IMU
桥到竞品的 ROS1，master 在 `192.168.113.203:11311`）。关它的理由：省 Orin 的 CPU（桥点云很吃 CPU）；更要紧的是两套导航
不能同时管一台机器人 —— 桥要是双向的（`dynamic_bridge` 默认什么话题都桥），竞品的规划器发的速度指令也可能过来。
我们的人员桥（`D1MAX_PERSONS_*`）本来就是本机模式，只确认一下。

**笔记本测、台式机改代码**：哪一步不对，把现象、日志发回台式机，不要在现场改代码。
**这张单子不让机器人动**：全程站着或趴着都行，不发巡逻、不发 goto。

日志统一放 `runs/field-logs/2026-11-05-poc-net/`。`/etc/d1max/env` 里有设备 PIN：**不要整份拷到笔记本、不要贴进日志**，
只看、只改下面几行。

## 0. 先记下原样（改坏了照它改回去）

在 Orin 上：

```bash
sudo cp -a /etc/d1max/env /etc/d1max/env.bak-20261105      # 备份留在 Orin 上
ip -br addr; ip route; resolvectl status 2>/dev/null | head -20
grep -E '^D1MAX_(SITE_MQTT|SITE_NTP|PERSONS_[A-Z]+)=' /etc/d1max/env
systemctl is-active d1max-agent d1max-persons d1max-localizer d1max-sidecar
```

把 `ip` 两条和 `grep` 那几行（没有 PIN）存进日志目录 `before.txt`。

## 1. 关掉竞品主控到 Orin 的桥接

**只停、不删**：脚本、竞品的任何文件都不动，测完要能原样恢复。

1. 找到它怎么起的、进程号多少，记进日志 `bridge.txt`：

   ```bash
   ps -eo pid,ppid,user,lstart,cmd | grep -E 'bridge_start|ros1_bridge|dynamic_bridge|parameter_bridge' | grep -v grep
   systemctl list-units --all | grep -i bridge; systemctl --user list-units --all 2>/dev/null | grep -i bridge
   crontab -l 2>/dev/null; sudo crontab -l 2>/dev/null; ls ~/.config/autostart 2>/dev/null; grep -n bridge /etc/rc.local 2>/dev/null
   cat ~/bridge_start.sh                                      # 看它桥哪些话题、是不是双向
   ss -tnp | grep -E ':11311|192\.168\.113\.'                # 跟竞品 ROS1 的连接
   ```

2. 停：是 systemd 起的就 `sudo systemctl stop <单元>`；不是的话，**按上面记下的进程号**停（先停 `bridge_start.sh`
   那个父进程，再看子进程还在不在）：`kill <pid>`。不要按名字 `pkill`。
3. 开机自己起的（systemd 单元 `enable` 着、crontab `@reboot`、autostart）：POC 期间要不要关掉自启，**问用户**，
   本测试单不改自启 —— 机器人一重启桥就回来，这一点写进日志。

**通过**：第 1 条的 `ps` 再跑一遍没有桥的进程；`ss` 里跟 `11311` 的连接没了；
我们这边 `systemctl is-active d1max-agent d1max-localizer d1max-sidecar` 照样 active，网页上定位、遥测照常
（我们不靠这个桥：我们直接读 Orin 上的雷达）；`top` 里 Orin 的 CPU 跟停之前比，记下降了多少。

再确认我们的人员桥是本机模式：`grep -E '^D1MAX_PERSONS_(CONNECT|LISTEN)=' /etc/d1max/env` 什么都不出就对了。

## 2. 竞品的 Wi-Fi 接到 Orin

两个无线网别混（用户 11-04 确认）：`XG2WIFI_C40221` 是**机器狗自己发的**热点（笔记本平时连它，`192.168.234.x`，
经 `192.168.234.1` 到机器人内网 `192.168.168.0/24`）；**竞品发的是 `26WG` 开头的那个**。

竞品主控跟 Orin 都在机器人内网 `192.168.168.0/24` 里，不用插线。先弄清楚 `26WG…` 这个网，记进日志：
笔记本连上它拿到的地址、网关、网段（`ip -br addr`、`ip route`）；连上以后能不能出外网（它是不是带 4G / 连着现场网）；
从它这个网段能不能直接 ping 通 Orin `192.168.168.100`（`ping`、`traceroute`）—— 通了说明竞品主控在两个网之间转发。
笔记本怎么连：USB 网卡照旧连 `XG2WIFI_C40221`（保底的那条线，别断）；内置网卡暂时从 iPhone 热点换到 `26WG…`
（跟台式机的消息这段时间会断，测完换回 iPhone 热点再把结果发回来）。
Orin 上 `ip route get <站点主机 IP>`：看回站点的包从哪走。

- **A. 站点主机就在 `26WG…` 上**（比如现场笔记本连着它）：Orin 只要一条回这个网段的路：
  `sudo ip route add <26WG 的网段>/24 via <竞品主控在 192.168.168.x 上的地址>`（临时，重启就没；已经通就不用加）。
- **B. 站点在公网、竞品主控能出外网**：**临时**把 Orin 的默认路由指过去：
  `sudo ip route replace default via <竞品主控 192.168.168.x>`，重启就恢复。要竞品主控肯给 `192.168.168.0/24` 做转发（NAT），
  不肯就走不通，记下来。
- 两种都先确认笔记本经 `XG2WIFI_C40221` 连机器人那条线不会断。改路由这一步要用户在场。

**通过**：Orin 上 `ping -c 5 <站点主机>` 通；能出外网的话 `ping -c 5 223.5.5.5` 也通。延迟、丢包记进日志。

## 3. 代理连站点

1. 站点主机：现场笔记本，或者公网那台（看对方 Wi-Fi 让不让出外网），**用户定**。
2. Orin 上先单独测端口：`nc -vz <站点主机> 8883`（对时：`nc -uvz <站点主机> 123`，UDP 测不准，以第 4 步为准）。
3. 改 `/etc/d1max/env`：`D1MAX_SITE_MQTT=mqtts://<站点主机>:8883`；`D1MAX_SITE_NTP=<站点主机>`（站点经 SSH 隧道接过来、是 127.x 的时候必须单独填它）。
4. 对时源跟着改：先 `sudo cp -a /etc/chrony/conf.d/d1max.conf /etc/chrony/conf.d/d1max.conf.bak-20261105`，
   再把里面 `server ... iburst prefer trust` 那一行的主机换成新的站点主机，`sudo systemctl restart chrony`；
   然后 `sudo systemctl restart d1max-agent`。

**通过**：网页上这台机器人在线，遥测在刷新（位置、电量、定位状态），状态不显示「不新鲜」。

## 4. 对时

`timedatectl`；`chronyc sources -v`（看站点那一行有 `*`）。

**通过**：Orin 跟站点的钟差在 1 秒以内。11-04 机器人从 1970 年起来过，这一步一定要看。

## 5. 带宽（不动机器人）

网页打开实时视频，开 10 分钟。同时在 Orin 上 `ping -i 1 <站点主机>` 记 10 分钟。

**记下**：视频卡不卡、断没断；ping 的平均值、最大值、丢包率；站点有没有报「状态不新鲜」或掉线。

## 6. 断网再连上

把对方 Wi-Fi 断开 60 秒（拔网线，或者让对方关一下），再接回去。

**通过**：网页上这台机器人变成离线；接回去 1 分钟内自己恢复在线，不用重启任何服务。记下离线、恢复各用了多久。

## 7. 改回原样（测完必须做）

```bash
sudo cp -a /etc/d1max/env.bak-20261105 /etc/d1max/env
sudo cp -a /etc/chrony/conf.d/d1max.conf.bak-20261105 /etc/chrony/conf.d/d1max.conf && sudo systemctl restart chrony
sudo ip route replace default via <before.txt 里原来的网关>      # 只有第 2 步走了 B 才要
sudo ip route del <第 2 步 A 加的那条> 2>/dev/null                 # 只有第 2 步走了 A、加过才要
sudo systemctl restart d1max-agent d1max-persons
# 竞品的桥:用户要恢复就按 bridge.txt 记的原样起(systemd 的 start 单元;脚本起的照原来的命令、原来的用户);
# 不急的话重启一次机器人,它自己就起来了
```

**通过**：跟第 0 步记的一样（`ip route`、那几行 env、四个服务都 active）；竞品的桥按用户的意思恢复了没有，写进日志。

## 交回台式机

日志目录打包；每一步写通过 / 不通过，不通过的附现象。另外三件：竞品的桥是怎么起的、是不是双向（`bridge.txt`）；竞品的 Wi-Fi 是热点还是连外网、能不能给 Orin 转发；
站点主机最后用的是哪台、怎么连的。
