# 商业化 A3 · 密钥与签名 · 设计与完工报告

> 商业化 A 阶段（决策 53）。W30 已经做了狗的升级包签名、Android 正式签名、站点口令和备份加密；这一单补交付要用的三样：密钥能离线托管、能自检、发行钥匙能换。

## 做了什么

### 一、站点密钥托管包

以前手册说「三把密钥离线另存」，实际是叫人把几个二进制文件一个个拷走，容易丢、容易拿混。

- **导出** `d1max-site keys-export --out <U 盘上的文件>`：
  - 把口令密钥、备份密钥、证据私钥，配了推送的还有极光的 Master Secret，打成**一个文件**；
  - 用**口令**加密：scrypt 派生，加上站点同一套 AES-256-CTR + HMAC；
  - 文件 0600；
  - 口令至少 12 个字符，交互输入两遍，或者用 `D1MAX_KEYS_PASSPHRASE`；
  - 缺了必需的密钥、或者密钥有毛病，就不打包。
- **导回** `d1max-site keys-import <托管包>`（以 root 跑）：
  - 放回 `/etc/d1max-site/`，权限 `root:d1max-site 0440`；
  - 已经有、而且一样的跳过；**不一样的不盖**（盖错了旧备份就解不开），确定要盖加 `--force`；
  - 口令不对、包被改过，一个都不放。
- **站点装机脚本恢复模式**接上了：`install-site.sh --recover --keys <托管包>`，装好软件以后问口令、放回密钥。
  - 顺带修了一个洞：恢复模式下，装机脚本以前会把缺的密钥**先生成一把新的**，托管包就导不回来了。现在恢复模式绝不生成。

### 二、密钥自检

- `d1max-site keys-status`：每把密钥在不在、长度对不对、权限是不是太宽，各给一个**短指纹**（SHA-256 前 16 位），用来对照离线那份是不是同一把。有毛病时返回非 0。
- **体检**（A1）里加了「密钥」一项，有毛病管理员看得到。

### 三、发行钥匙能换

以前狗只认一把发行公钥：私钥泄露了、或者要换，就得重装所有狗。

- 狗和站点除了 `release-pub.pem`，**同目录 `release-pub.d/*.pem` 里的公钥也认**，哪一把验得过都算。
- 换钥匙的步骤：
  1. 生成新钥匙；
  2. 新公钥放进仓库的 `deploy/release-pub.d/`，装机、升级时装到狗上、站点上；
  3. 以后用新私钥签；
  4. 所有狗都换过来以后，删掉旧公钥。**删掉就是吊销**。
- 狗上的 `release-pub.d/` 跟包里的保持一致：包里删掉的（吊销了的），装机时狗上也删。卸载时一并删除。
- `relsign.key_id`：公钥的短指纹，对照用。
- **限制**：站点下发的升级不碰 `/etc`（代理没有权限写）。换公钥要跑一次装机脚本：现场去，或者远程 ssh。

## 测试

- **自检**：都在时给短指纹，没配推送不算毛病；少了、长度不对、权限太宽，各查得出。
- **托管包**：
  - 来回一样，文件 0600，包里看不到任何一把密钥，明文和十六进制都看不到；口令不对解不开；
  - 导回到空目录是 0440；一样的跳过；不一样的不盖，`--force` 才盖；
  - 口令太短不打包，缺了必需的不打包、也不留半截文件。
- **命令行**：自检、导出；删一把以后自检报错；导回以后自检好了。
- **体检**里有密钥一项。
- **换发行钥匙**：
  - 新钥匙签的包，没放公钥时不认，放进 `.d` 以后认；
  - 换钥匙过程中旧钥匙签的也还认；
  - 删掉旧公钥以后旧签名不认；只剩 `.d` 里的也认。
- **站点装机脚本**：恢复模式不生成密钥，托管包在装好软件以后才导回。
- 狗的装机、卸载脚本「写了什么就删什么」配对检查，以及契约包、站点发布目录的测试，都过了。
- **突变**：8 条全抓住：不认 `.d`、权限不查、长度不查、不一样也盖、导回权限太宽、口令长度不查、缺了也打包、恢复模式也生成。

## 要你做的

1. **发行钥匙**（W30 就留下的，现在仍然要做）：在你自己的电脑上 `d1max-patrol release keygen ~/d1max-release.key deploy/release-pub.pem`，私钥离线保管，公钥提交进仓库。
2. **每个站点装好以后**：`d1max-site keys-export --out /media/<U 盘>/<站点名>.d1keys`，U 盘和口令**分开**保管。
3. **Android 正式 keystore**（W30 就留下的）：`keytool` 生成，离线保管，打包时加 `-Pd1max.requireReleaseKey=true`。

## 没做的

- 站点口令密钥、备份密钥的**轮换**：换了要把库里的口令重新加密、旧备份要留着旧钥匙才解得开，流程复杂，用得少。等真有需要（比如密钥泄露）再做，现在的办法是托管包 + 恢复。
- TPM、硬件密钥：整块站点硬盘被拿走时，密钥跟库在同一块盘上，防不住。等有硬件再说。
