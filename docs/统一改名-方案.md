# 统一改名 d1max → nexwar：方案（用户 11-04 批准，11-05 按实际做法更新）

用户 11-04 定：**全部改**——服务、程序、目录、Python 包，仓库改名为 `nexus-warden-patrol`。这周内做完，POC 在 11-17。

## 量

1043 个文件、约 1.1 万处；103 个 `D1MAX_*` 环境变量；10 个 systemd 单元；8 个 Python 包；手机端 Dart 包名出现 379 处。

## 已经装好的机器人、站点怎么迁

装机脚本（`install.sh`、`install-site.sh`）一开始调 `deploy/nexwar_migrate prepare`，装完调 `finish`。人不用单独跑。

1. 没有老东西什么都不做（新机器、迁过的机器），可以重跑。
2. 新旧两个目录**都有内容**时不猜，停下（退出 2），让人看一眼。
3. 先把配置（`/etc/d1max*`、WireGuard 配置，里面有私钥、PIN）打包到 `/var/backups/nexwar-migrate-<时间>.tar.gz`，只有 root 能读。
4. 记下老单元里哪些开着，停掉、禁用、删单元文件和自启链。
5. 目录、文件原地 `mv`，不复制：证书、私钥、设备 PIN、地图、发件箱原样搬。
6. 配置文件（env、`.conf`、`.json`、`.yaml`）里的键 `D1MAX_X` 改成 `NEXWAR_X`，值里的老路径改成新路径。只改不打印；机型名 `NEXWAR_HAL=d1max` 不动。
7. 站点账号 `d1max-site` 改名 `nexwar_site`。
8. `finish`：prepare 时开着的单元按新名字再开（现场手工开过的旁路、雷达合并、WireGuard 不能丢）。

**跟原方案不一样的（11-05 做的时候定的）**：

- **不留老路径的软链接**：代码、脚本只认新路径；软链接会让卸载、足迹对账多一套名字。
- **改名这一版不走远程升级**：老版本的单元找不到新包里的启动脚本，起不来，开机守卫会退回上一版。所以要现场跑一次装机脚本（用户在场，只换软件，不动机器人）。

**兼容一个版本**：

- 环境里还有 `D1MAX_X`、没有 `NEXWAR_X` 的，进程起来时照抄过去，记一条警告（只记键名）。
- 机器人上还没重新编译的旁路进程把令牌写在 `~/.d1max/sidecar.token`：新路径没有就读老的。
- 老录包里的合并雷达话题 `/d1max/merged_lidar`：建图照样按前雷达系认。
- 老机器人传数据用的 `X-D1Max-*` 请求头：站点照收。

## 不改的

- 已经签发的证书、贴纸上的绑定码；
- 已经录的包、已经出的图、现场数据目录（`runs/field-c40221/...`）；
- 历史文档里的旧名字（设计稿、外审记录、完工报告）：讲的是当时的事；
- 厂家的东西（`refs/` 资料、SDK 名字）；**机型名 `d1max`**（`--hal d1max`、`NEXWAR_HAL=d1max`、适配器 `adapter-d1max`、`D1MaxHal`、给这款机型调的 Nav2 行为树 `*_d1max.xml`）；
- 已经印出去的码的前缀（`D1MAXSITE1.`、`D1MAXBOT1.`、`D1MAXUNBIND1.`、`D1MAXB1.`）；
- 机器人上现场开发用的目录（`~/d1max-motion`、`~/d1max-field`）。

## 顺序和验证

1. 先合 W73，在 master 上开分支；改名期间不开别的分支。
2. 机械改名（脚本 + 人工核对边角）→ CI 的 ruff 检查 → 全套测试（Python、网页、手机）→ 演示站点起来看一遍。
3. 迁移脚本在台式机上用模拟的旧目录树验一遍；真机迁移排在 POC 之前，用户在场时做：只换软件，不动机器人。
4. 外审一轮 → 合并 → 改 GitHub 仓库名（先确认）→ 台式机、笔记本改远端地址。

## 风险

- 机器人上 `/etc/d1max/env` 有设备 PIN、`tls/` 有私钥：迁移只 `mv`、先备份，不打印内容。
- 正在跑的 72 小时浸泡测试（到 11-05 19:40）用的是老代码副本，不受影响；跑完前不装新版。
- 演示站点 8480 改完重启一次。

## 11-05 C40221 真机迁移补的三处

第一次在真机（C40221）上迁移时现场暴露的，现场已经手工处理过，代码在分支 field-poc-1105 上补：

1. **Super-LIO 工作区**：colcon 的 `setup.sh`、`*.dsv` 里写死编译时的绝对路径。目录从 `/opt/d1max/superlio` 挪走以后，source 报「build time path doesn't exist」，定位器起不来。
   - 迁移的 `relocate` 把 `/opt/nexwar/superlio/*/install` 下的文本文件只换路径，二进制不碰。
   - 定位器启动脚本 source 前给 `COLCON_CURRENT_PREFIX`，以后再挪目录也不怕。
2. **现场手写的旁路单元 `d1max-field-sidecar`**：迁移把它删了，可它的程序、地址、参数都写在 ExecStart 里；版本里的 `nexwar_sidecar` 只装没开，代理连不上旁路，一直重启。
   - 迁移删单元前把 ExecStart 拆成 `NEXWAR_SIDECAR_BIN / ROBOT / LISTEN / ARGS`。跟缺省一样的不写，`--fifo`、`--token-file` 不带。
   - 这几项补进 `/etc/nexwar/env`，已经填了的不盖。
   - `d1max-field-X` 按 `nexwar_X` 再开。
   - 启动命令认不出来的，说明要手工填。
3. **站点 `init --home <相对路径>`**：mosquitto.conf 里的 acl、证书写成了相对路径，换个目录起 broker 就找不到（笔记本现场）。现在 init 一律写绝对路径。
