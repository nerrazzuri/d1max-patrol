## 问题

老服务切版本之前有一份七项清单，人点「升级前检查」看得到哪几项不过。W00c5e 删了老服务、版本改由站点管之后：代理收到
`release_activate` 只回**一个**拒绝原因，人在切之前看不到清单；装好之后槽里的包被改坏了不再有人核；任务包 schema 那一项
没人查了；备份提示没了。

## 交付

| 层 | 改了什么 | 文件 |
|---|---|---|
| 契约 | `Ack.data`（可选对象）：命令的答复放在回执里，只在有数据时写，老报文照读；新命令 `release_precheck {name}` | `messages.py`、`releases.py` |
| 契约 | `tree_sha256(..., keep=)`：只算要的那些相对路径（同一个算法，不另起一套） | `digest.py` |
| 代理 | 清单是纯函数（`release_precheck.py`，取值与判断分开）：空闲、电量 ≥30%、盘、要切的不是在跑的、装好了、**槽里的包现在还对**（按打包的规矩重算指纹，跳过 venv、`__pycache__`）、切过去起得来、定位器/感知/外参（现在「还没部署」、不拦；运行时留 `precheck_sources` 口，W09/W11 挂上之后不健康就拦，来源自己炸了按不健康） | `release_precheck.py`、`engine/release.py`、`release_ops.py` |
| 代理 | `release_activate` 按同一份清单判：第一个拦住的项的原因码照旧（新增 `package_corrupt`、来源名），**回执里带整份清单**；`release_precheck` 只算、不做事，清单在回执里；能力里报 `release_precheck`；退版本的空闲判断跟清单用同一个函数，读电量让出之后收下之前再看一眼 | `runtime.py`、`commands.py` |
| 站点 | 登记版本时记下它要的任务包 schema、导入任务包时记下包的 schema（老库补列，默认 1）；`POST /api/robots/<id>/release {"action": "precheck", "name"}`：发 `release_precheck`，合上站点这边两项 —— **任务包 schema**（新版要的 ≤ 站点当前任务包的；拦）、**站点备份**（多久前成功过；只提示）；`activate` 之前站点先核 schema，不过 409 | `releases.py`、`catalog.py`、`db.py`、`api.py` |
| 手机 | 版本页每台狗多一个「查」：选一版 → 清单（拦的不过项在前、提示的标「提示」、过了的在后）；「切」被狗拒时把回执里的清单摆出来 | `ui/site_releases.dart` |

老七项各归谁：包 → 狗（装的时候核 + 切之前再核槽）；schema → 站点；盘、电量、空闲 → 狗；上装 → **不再单列**（没有自动升级，
重启只重启代理，SDK 会话由旁路进程握着；切过去起不来开机守卫会退回）；备份 → 站点（提示）。

## 与设计稿不同的地方

无。

## 已知限制

- 电量门槛是 30%（W00c5d 定的），老服务是 50%（那时带上装要整机重启）。
- 核槽要读整棵槽：包越大越慢（估计 300 MB 在 Orin 上一两秒），在线程里做，不挡代理；站点等回执 10 s。
- 定位器、感知、外参三项现在只是占位（「还没部署」），W09、W11 接上之后才真查。
- `schema` 这一项只在站点有当前任务包时有得比；站点没有任务包就写「没有可比的」、不拦。
- 真机没验：真狗上的「查」「切」（W00d 之后的真机项）。
