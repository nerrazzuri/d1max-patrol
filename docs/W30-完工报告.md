四项都按推荐：
1. **第一版不做人脸**：不采集、不存人脸特征（PDPA 下是敏感个人数据）。「自己人」靠现有的在家 / 访客模式和保安判断。W30 只做 PDPA 基础：

## 做成什么样

### 一、发布签名

**狗的升级包**：
- **怎么签**（契约 `relsign.py`）：Ed25519，**纯 Python**（`ed25519.py`，只用标准库，见「外审第一轮」第 1 条；原来调 `openssl` 的做法在狗上用不了）。
- **签什么**：`release.json` 里这四项的规范 JSON：`name`、`version`、`content_sha256`（整棵包的指纹）、`requires_mission_schema`。
  - 签名写回 `release.json` 的 `signature`。`release.json` 不算进包的指纹，所以写回去不改指纹。
  - 包里任何一个字节、或者这四项任何一项变了，签名都对不上。
- **工具**（在发行方的电脑上跑）：
  - `d1max-patrol release keygen <私钥> <公钥>`：私钥 0600，已经有了不盖；
  - `d1max-patrol release sign <包> --key <私钥>`：先核包内指纹，对得上才签。
- **狗上**：
  - 站点下发的版本，下载、核哈希、解开之后，**落槽之前先验签名**，验不过一个字节都不落、不建 venv；
  - 公钥 `/etc/d1max/release-pub.pem`（`D1MAX_RELEASE_PUBKEY` 可改）。**没有公钥就拒**；`/etc/d1max/env` 写 `D1MAX_RELEASE_UNSIGNED_OK=1` 才放行，只许开发、仿真用，起来会打警告；
  - U 盘装机（`release install`）也验；没装公钥要加 `--unsigned` 才装。
- **装机脚本**：
  - 包里带了 `deploy/release-pub.pem` 就装到 `/etc/d1max/`。装机是人在现场、包是人拿来的，可信；
  - 狗上没有公钥时，这一次照装，但会说清「站点下发的版本会被拒」；
  - 卸载时一并删除。
- **站点**：配了公钥（`/etc/d1max-site/release-pub.pem`，`site.json` 的 `release_pubkey` 可改）就在 `release-add` 登记时先验，验不过不登记，免得下发了才在狗那头失败。

**Android**：
- `android/key.properties`（不进仓库，已在 `.gitignore`）写着 keystore 位置和口令，有它就用正式钥匙签 release；
- 没有它退回调试钥匙，CI 和开发机照样能编；
- **发给客户的包要加 `-Pd1max.requireReleaseKey=true`**：没有正式钥匙就直接失败，不会悄悄发出调试签名的包。
- 实测：没钥匙加这个参数，编译失败；配了临时 keystore，签出来的证书就是它。

### 二、站点里的口令加密

- **怎么加密**（`sealbox.py`）：AES-256-CTR（`openssl enc`）加 HMAC-SHA256（先加密后算 MAC），加密密钥和 MAC 密钥都从主密钥按用途派生。
  - 每次随机盐，同一个值加密两次也不一样；
  - 口令从环境变量交给子进程，不上命令行；
  - 解不开（密钥不对、被改过）就报错，绝不回半截明文。
- **库里**：摄像头口令、事件源共享密钥落库前加密（`enc1:` 开头），读出来解开（在内存里缓存，验签不用每次起 openssl）。
  - 老库里的明文，站点起来时就地加密；
  - 命令行（`camera-add`、`source-add`）也走同一把钥匙。
- **主密钥** `/etc/d1max-site/secrets.key`：**不跟库放一起、不进备份**，只有站点用户能读（`root:d1max-site 0440`）。
  - 站点安装脚本生成；**已经有了绝不重新生成**（换了钥匙，库里的口令就解不开了）；
  - 站点服务对 `/etc` 只读，只读不建。

### 三、备份加密与恢复

- 配了备份密钥（`/etc/d1max-site/backup.key`，同上）就**全部加密**：
  - 库快照是 `site-<时刻>.db.d1seal`；
  - 镜像的每个文件是 `<原名>.d1seal`，修改时间跟原文件一样，增量照算，没变的不重加密。
- **以前的明文备份**：加密一份就删掉对应的明文那份。
- **恢复**：`d1max-site backup-open <备份目录> <空目录> --key <备份密钥>`，逐个核 MAC 再解开；解不开就报是哪个文件。
- **备份密钥要离线另存**（站点安装脚本最后会提醒）：站点主机坏了、没有这把钥匙，备份就恢复不了。

### 四、PDPA 基础（`privacy.py`）

- **保留期限**：
  - 运行记录（巡检照片、人员截图、事件现场照）默认留 **90 天**（`site.json` 的 `retention.evidence_days`），按站点最后收到它的时刻算；到期删掉目录、登记、**备份里的那一份**；
  - 录像照 W18 的 30 天（`retention.recordings_days`）；
  - **标了「留着」的不删**：运行记录新加「留着」（库结构 31 版，`runs.keep`），手机上一趟记录右上角的书签（保安、管理员能标，业主不能），同录像。
- **按时间段删**（当事人要求删除时）：
  - 命令：`d1max-site privacy-purge --since … --until … [--robot …] --reason "…"`；
  - 删这段时间里的运行记录（跟这段时间有交叠的）和录像（开始时刻在这段里的），**连备份**；
  - **标了留着的不删**，单独列出来；
  - 必须写原因，记审计。
  - 第一版不认人脸，只能按时间和地点删。
- **谁看过、导出过**：都记审计（`VIEW` / `DOWNLOAD`，带账号、对象、来源 IP）。
  - 包括：看一趟的记录、看照片、放录像、看摄像头实时画面、下载导出包；
  - 同一个人看同一样东西，**10 分钟内只记一次**（放录像、看画面会连着请求好多次）；
  - 记不下来不挡看。

## 外审第一轮（2026-10-08）：FIX-THEN-APPROVE，4 条阻断，已修

**1. 狗上的 OpenSSL 验不了 Ed25519。** 验签调的是 `openssl pkeyutl -rawin`，可 OpenSSL 1.1.1 的 `pkeyutl` 不支持 Ed25519（官方文档写明），狗上是 Ubuntu 20.04 的 1.1.1，合法签名的包也会被拒。我报告里写「1.1.1 支持」是错的。

修法：**Ed25519 改成纯 Python**（契约 `ed25519.py`）：
- 照 RFC 8032 的参考算法写，只用标准库，狗上不加依赖、跟 OpenSSL 版本无关；
- 验签一次约 2 毫秒；
- 生成、签名、验签全不调 `openssl`。密钥文件还是跟 OpenSSL 一样的 PEM：`openssl genpkey` 生成的私钥也认，我们生成的 OpenSSL 也认；
- 拒可塑签名（`s ≥ q`）。

**2. 切到加密备份后，旧备份里还有明文。** 镜像只跟着现有的源文件走；站点上已经删了的照片、地图，旧明文备份还在，备份却报成功。

修法：开了加密之后，**每次备份把整个备份目录里不是密文的文件都加密、删掉明文**，不管源文件还在不在（修改时间照旧，增量不受影响）。

**3. 删了证据，导出包里还有原照片。** 删证据只删了证据目录、备份和登记，没管 `exports/` 里已经打好的 zip，还能下载。

修法：**删证据连导出一起删**（到期删、按时间段删都是）：
- 导出的说明里记下包了哪几趟（`run_ids`），删证据时把里面有这几趟的导出（zip 和说明）删掉；
- 老的导出没记是哪几趟的，也删（宁可多删，它们本来就只留 7 天）；
- **正在打的**：打完换上之前，在锁里核一遍里面的记录都还在，有被删的就作废、不留 zip；「删导出」跟「打完换上」用同一把锁，不会一边删一边换上；
- `privacy-purge` 会说连带删了几份导出。

**4. 恢复说明漏了 `secrets.key`。** 只提醒离线另存 `backup.key`，可库里的口令靠另一把 `secrets.key`，它也不进备份。新主机上备份能解开、库能打开，口令却解不开。

修法：
- 安装脚本最后**两把都提醒**离线另存，并说清各自管什么；
- 口令解不开时报错写明「`secrets.key` 不是加密时那一把，换新主机恢复时要把原来的放回去」；
- 补了完整的换新主机恢复测试。

### 换新主机恢复

1. 新主机照常跑站点安装脚本，然后**先停服务**（`systemctl stop d1max-site d1max-mosquitto`）。
2. 把离线另存的两把密钥放回 `/etc/d1max-site/`，覆盖安装脚本刚生成的两把（`root:d1max-site 0440`）。
3. `d1max-site backup-open <备份盘目录> <空目录> --key /etc/d1max-site/backup.key`。
4. 把解出来的最新一份 `db/site-<时刻>.db` 拷成 `/var/lib/d1max-site/site.db`；`evidence/`、`maps/`、`bags/`、`releases/` 拷回 `/var/lib/d1max-site/` 下对应的目录；属主改成 `d1max-site`。
5. CA（`/var/lib/d1max-site/ca/`）不在备份里：要么从旧盘救回来，要么重新 `init` 后给每台狗重新 `enroll`、换证书包。
6. 启动服务，看日志里摄像头连上、事件源验签正常。

补的测试：
- **Ed25519**：
  - RFC 8032 的三个测试向量（公钥、签名逐字节一样）；改一位、改消息都不认；不成形的公钥、签名不认；可塑签名（s+q）不认；
  - 跟本机 OpenSSL 3 互相认：OpenSSL 生成的钥匙读得懂；OpenSSL 签的我们验得过，我们签的 OpenSSL 验得过；我们生成的 PEM OpenSSL 认；
  - **发布包签名全程不碰 openssl**（把 `subprocess.run` 换成一调就报错，生成、签名、验签照常）。
- **旧明文备份**：站点上早删了的照片、地图，旧备份里的明文都变成密文，搜不到原字节。
- **导出**：
  - 按时间段删 A 的记录，A 的导出跟着删、下载不到，B 的导出不动；
  - 打包时那一趟被删了，打完作废、不留 zip 和临时文件；
  - 到期删的，导出也删。
- **换新主机恢复**：旧站点加密口令、加密备份 → 新主机用备份密钥解开、库放回；用新生成的 `secrets.key` 解不开，报错说要放回原来那一把；放回之后口令照常。
- 突变 8 条全被抓住：验签不看签名、不查 s 小于 q、验签又调 openssl、旧明文备份不处理、导出不跟着删、到期删不删导出、打完不核、删别人的导出。「不查 s 小于 q」第一轮没抓住：原来的测试用的 s 本身就不成立，改成可塑签名（s+q）后抓住了。

## 外审复查（2026-10-08）：FIX-THEN-APPROVE，剩 2 条，已修

**1. 导出删不掉，就再也没有重试的依据。** 先删运行记录、再删导出。删 zip 时如果出错（临时权限、盘出问题），运行记录已经没了。再跑一次删除、定时清理、重启，都找不到原来的记录号，导出还能下载。

修法：**「这一趟的导出要删」落库**（`export_purges`，库结构 32 版）：
- 跟删运行记录的登记在**同一个事务**里写；
- 删导出时按表里记着的全部记录号删，**删成了才清**；删不掉（抛错）就留着；
- 下一次删除、定时清理（每 10 分钟）、站点重启后的第一次清理，都接着删；
- 删导出先删 zip、后删说明：zip 删不掉时说明还在，下次照样找得到。

**2. 旧备份留下的明文临时文件被跳过。** 加密收尾时一律跳过 `.tmp`、`.part`。以前的明文备份拷到一半被打断，会留下装着照片、地图原文的 `.tmp`。

修法：加密收尾时，备份目录里的 `.tmp`、`.part` **一律删掉**，不加密也不留：
- 备份只在杂事线程里一趟一趟地跑，走到这一步时这一趟自己的临时文件都已经换名了，剩下的都是以前中断留下的半截文件；
- 源目录里的 `.tmp`，镜像本来就不拷，备份里不会有正经的这种文件。

补的测试：
- 删 zip 第一次报错：运行记录删了、导出还在、意图记着；恢复后再跑一次删除（运行记录早没了），按记着的删掉，删成了才清；
- 删的时候没接导出（像重启前的旧站点）：重启后定时清理接着删；

## 已知限制、要你做的

- **要你做（发行签名）**：
  1. 在你自己的电脑上 `d1max-patrol release keygen ~/d1max-release.key deploy/release-pub.pem`，**私钥离线保管**（U 盘加保险柜，丢了就再也签不了；泄露了要换钥匙、重装所有狗的公钥）；
  2. 把 `deploy/release-pub.pem` 提交进仓库；
  3. 以后每个包 `release pack` 之后 `release sign` 再拿去装、登记。
- **在那之前**：现在仓库里还没有公钥。狗上重跑装机脚本时，这一次照装，但站点下发的版本会被拒。笔记本那台测试狗可以先在 `/etc/d1max/env` 写 `D1MAX_RELEASE_UNSIGNED_OK=1`。
- **要你做（Android）**：用 `keytool` 生成正式 keystore（离线保管），写 `mobile/android/key.properties`，发版本时 `flutter build apk --release -Pd1max.requireReleaseKey=true --build-name … --build-number …`。
- **要你做（站点）**：重跑站点安装脚本会生成两把密钥；**两把都马上离线另存一份**（见下面「换新主机恢复」）。
- ~~狗上的 OpenSSL 版本~~：外审指出 1.1.1 的 `pkeyutl` 不支持 Ed25519（我原来写「支持」是错的），已改成纯 Python 验签，跟狗上 OpenSSL 版本无关。真机仍要装一个签名包验一次（§3p）。
- **主密钥跟库在同一块盘上**（`/etc` 和 `/var/lib` 是同一块盘）：防的是备份盘被拿走、库文件被单独拷走；整块站点硬盘被拿走就防不住，要 TPM（以后商业化 A 阶段）。
- **狗上断网暂存的证据没加密**：决策 43 选项里写了，但这一单没做。狗上的发件箱是边写边传、站点确认就删，要加密得改引擎写照片和上传整条链路，并且要用站点公钥加密，钥匙不能放在狗上，量大、风险高。建议单开一单（W30b），等你定。
- **按时间段删只按时间和地点**：认不出哪张照片里是谁（第一版不做人脸）。
- **iOS 不做**（决策 43）。
