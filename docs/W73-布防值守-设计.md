# W73 布防值守设计（布防 = 机器人自己值守，外部设备是加分项）

> 用户 2026-11-03 晚到 11-04 的讨论（逐条认可过）：
> 「现在防区这功能依靠外来的信息让机器狗出发去验证。如果客户没有外部设备，这个布防功能就是废的。而且就算有外部设备，他们还得知道我们布防区的名字和地点，这个太不合逻辑了。」
>
> 用户定下的四条：
> 1. 5 个防区，客户可以让站点**自动生成**防区路线（可设在防区里多转两圈、多拍照），也可以**手动**画（某个防区需要一直过去查）。
> 2. 防区路线**只在布防时用**，不能拿去当巡逻路线；布防的设置可以多开放一些，现在的时间段设置保留。
> 3. **巡逻是独立的功能**：画路线、按时间排；每个点的预计时间尽量精确到秒。
> 4. 先设了布防，再排巡逻时**时间撞了（同一台机器人）就不让保存**。
>
> 补充（同一次讨论）：电量要闭环 —— 估出几点要补能、补多久；没有充电桩就提醒保安换电池（热插拔，**机器人站着不趴下**，**一块一块换**：第一块装好有电了再换第二块）；补能期间来了报警怎么办要有交代。回撤线用户建议 20–25%。
>
> 下文标「我定的」是讨论里没逐字定、由我取的默认，审文档时请重点看。

## 一、现在的问题

- 「布防」只是一个开关：决定入侵来了派不派机器人、机器人看见人报不报。**机器人什么时候在外面转，由巡逻排程另外定，跟布防没关系** —— 布防时段里机器人可能一直站在待命点，哪儿也没看。
- 入侵靠外部设备报**防区名**（`zone`），站点再按「防区名 → 拦截点」的映射派机器人。客户的设备要知道我们的防区名，拦截点要人手工起名、手工映射。
- 「防区」在地图上可以圈（`areas.py`），也可以只是个名字（摄像头、拦截点用的），两套并存，「布置 → 防区」页可能显示「暂无防区」而入侵照样按名字派。

## 二、要什么 / 不做什么

要：

- **没有任何外部设备，布防也是实打实的功能**：布防时段里机器人按防区路线循环巡查、空档守在值守位、看见人报警。
- **布防看得见、查得到**：每个防区「上次有机器人看过是几分钟前」，超时报警；每次布防一份值守记录。
- **防区只在地图上圈一次**，防区路线、值守位、出事时去哪看，都由站点在圈好的防区里算出来（人可以挪）。
- **电量闭环**：从布防开始前的检查，到补能、换电、补能期间的报警，每一步都有兜底，不会出现「没电站着、没人知道」。
- 外部设备（摄像头、报警主机、门磁）**按装在地图上的位置绑定**，不再报防区名。

不做（第一版）：

- 不做「拍照比对报变化」、夜间热像找人（以后单独立项）。
- 不做多楼层。
- 不做自动充电桩的新对接（厂家 SDK 已有自主回充、站点 W13 已有回充流程，原样沿用；本单只把它接进补能闭环）。
- 不改人员检测本身（W24/W33），只改「什么时候、在哪儿」看。

## 三、几个概念（我定的命名，界面文字）

| 叫法 | 是什么 | 谁用 |
|---|---|---|
| **防区** | 地图上圈出的一块（多边形），有名字、有「留守时撤防」开关 | 布防、入侵归类、授权名单 |
| **防区路线** | 一条只给布防用的路线，经过一个或几个防区；自动生成或手画 | 只有布防值守 |
| **巡逻路线** | 现在的路线库里的路线，单独排时间 | 只有巡逻排程、手动巡逻 |
| **值守位** | 防区里一个带朝向的位置（面朝大门、通道口），空档时机器人站在这儿盯 | 布防值守 |
| **查看点** | 出事时机器人去哪看（替代现在手工起名的「拦截点」）；防区里自动算，可挪 | 入侵派遣 |
| **补能位** | 充电桩前对准点（有桩）或换电位（没桩，建议在保安室附近） | 补能 |

两种路线在库里是两类（`kind: guard | patrol`），**互相不能替代**：防区路线不出现在巡逻排程、手动巡逻的选择里；巡逻路线不能挂到布防上（用户第 2 条）。

## 四、防区与防区路线

### 4.1 防区

- 在「布置 → 防区」里圈，跟现在一样存在 `areas`（每张图每个版本一份）。
- **名字只是给人看的标签**，可以用中文（现在防区名限 ASCII 的规矩只留给老的外部接口兼容）。
- 圈好以后，站点在防区里自动算一个**查看点**（防区里离路网最近、走得通、看得最开阔的点，我定的：先取「路网上离防区形心最近、通过可达检查的点」，简单可解释），一个默认**值守位**（同一点，朝向防区形心）。人可以拖动、转朝向。

### 4.2 防区路线：自动生成

- 选一个或几个防区 →「生成路线」。站点：
  1. 在每个防区里沿路网（没画路网就用代价地图上的可走区域）取巡查点：防区边界内、走得通、彼此相隔约 5–8 m（我定的），覆盖防区里走得到的地方；
  2. 按距离排出一圈顺序（从补能位出发、回到补能位，最近邻 + 两两交换改进，我定的）；
  3. 逐段做可达检查（跟现在存路线时同一套 `intercept_reach`），走不通的段标红、不让保存；
  4. 每个防区可设：**多转几圈**（同一防区的点重复几遍，默认 1）、每点**停几秒**、每点**拍几张**、拍照朝向（默认朝防区里面）。
- 生成后可以手动拖点、加点、删点，存的时候照样逐段检查。
- 地图换版本：防区路线跟巡逻路线一样绑定地图版本；新版本上要重新校验，走不通的提示「重新生成」。

### 4.3 防区路线：手动画

- 跟现在画巡逻路线一样，在地图上点出途经点；只是存成 `guard` 类。
- 某个防区要「一直过去查」：手画的路线里可以重复经过这个防区（用户第 1 条）。

### 4.4 一条还是几条

- 一次布防可以挂**多条**防区路线，每条分给一台（或「任意一台」）机器人；防区可以重叠，但站点提示「东区被两条路线都覆盖」。
- 没有被任何防区路线覆盖的布防中防区：保存时提示「西区布防了但没有机器人去看」（只提示，不拦：可能交给摄像头）。

## 五、布防值守怎么跑

### 5.1 布防设置（在现在的「布防时间」页上扩）

现在的时间段、例外日期、留守撤防、临时撤防（访客）**全部保留**（用户第 2 条）。新增每段布防的「值守方案」：

- 用哪几条防区路线，各给哪台机器人（或任意一台）；
- 每圈之间的**间隔**（默认「跑完马上下一圈」，可设每 N 分钟一圈）；
- **顺序打乱**开关（我定的，默认关）：同一条路线每圈的起点、方向随机，防止被人摸清规律；
- 补能方式：有充电桩 / 保安换电（每台机器人一项，跟着机器人走）。

保存时站点算出并显示**值守预报**（§7.1）：每台机器人这一段布防大约跑几圈、每个防区大约多久被看一次、几点要补能、补能期间哪些防区没人看。

### 5.2 运行

布防一开始（时间表到点，或有人点「现在布防」）：

1. 分到防区路线的机器人从当前位置出发，跑防区路线；
2. 跑完一圈：离下一圈还有空档 → 去**值守位**站着盯（不趴下；看见人照样报，§5.4）；没空档 → 直接下一圈；
3. 循环到布防结束；结束时把手上这一圈跑完的点记上，然后回待命点（我定的：不硬停在半路）；
4. **留守**：只跑布防中的防区的那几段；防区路线整段落在撤防防区里的点**跳过**（不去、不拍）；**临时撤防**期间同样跳过对应防区，到点恢复。

### 5.3 被打断以后接着跑哪儿

打断来源：看见人或外部设备报警去现场（§5.4）、保安手动派去某处查看、补能（§7）。

- 处理完回来，**从「距上次看过最久」的那个防区的第一个点**接着跑（不是从被打断的那个点，也不是从头），一圈里已经看过的防区不重复。
- 记一笔：哪一圈、在哪个点被什么打断、多久以后接上。

### 5.4 出事以后

- 机器人看见人（布防中、该防区此刻布防、不在授权名单）→ 报 P1（现在的 W33 逻辑；站在值守位上时按**值守位所属的防区**判，不按机器人身子落在哪块多边形里 —— 值守位常在防区边上，我定的），**停在原地盯着、推画面**，等保安下结论（误报 / 真警 / 驱离）；保安结束或 N 分钟没人管（我定的：5 分钟后再推一次、10 分钟推给经理）→ 接着值守。
- 外部设备报警 → 按 §8 算出在哪儿、去哪看 → 派**最近的有空、电量过出动线（§7.2）**的机器人去查看点；值守中的机器人可以被抽走。
- 布防期间保安手动派机器人去某处：允许，算「查看」不算巡逻，处理完回来按 §5.3 接着跑。

### 5.5 「多久没看」与超时报警

- 机器人**走过**防区里的点、或**站在**朝向这个防区的值守位上，就算「看着这个防区」，站点记下这个防区的「最后看过时间」。
- 每个防区一个**最长间隔**（默认 = 值守预报里算出的间隔 × 1.5，最少 15 分钟，我定的；管理员可改）。超过 → P2「东区已 45 分钟没巡到（原因：A 在换电 / A 被挡住 / A 掉线）」；恢复看到自动解除（W72 状态类告警的规矩）。
- 地图页、值班页、布防页：每个防区上标「上次看过 X 分钟前」，颜色按是否超时。

### 5.6 值守记录

每一段布防一份：每个防区每次被看的时间、照片、没到的点、被打断的次数与原因、补能的起止和谁换的电、缺口时长、缺口期间来过的报警和处理结果。第二天交班能翻（报表页），也能导出。

## 六、巡逻排程（独立功能）

### 6.1 不变的

路线库、排程（时间、星期、开始窗口、错过怎么办）、选机器人、派 `patrol` 全部沿用（`scheduler.py`）。巡逻只用 `patrol` 类路线。

### 6.2 每个点的预计时间（精确到秒）

- **第一次（没跑过）**：每段 = 规划路径长度（路网 / 代价地图上的 A*，不是直线）÷ 设定速度（1.0 / 0.6 / 0.3 m/s 那一档）+ 原地转向时间（按转角 ÷ 转速）+ 这个点的动作时长（停留秒数、拍照每张约 2 s，我定的）。
- **跑过以后**：每段用最近 5 次实际用时的中位数（从 `patrol_waypoint` 事件的时间戳算），页面同时显示「预计 / 上次实际」。
- 显示精确到秒；但要说明这是估算 —— 「看得清就快」（决策 76）、绕障、等人让路都会让实际时间浮动。
- 速度档一改，所有预计时间跟着重算，冲突（§6.3）重新检查。

### 6.3 冲突检查（保存时拦）

- **按机器人算，不按全站**：布防只占用值守方案里分到的机器人；没分到的机器人照样能排巡逻。
- 巡逻占用的时间段 = 开始时间 … 开始时间 + 开始窗口 + 整条路线的**保守用时**（实际用时的 90 分位，没跑过用预计 × 1.3）+ 2 分钟回待命点余量（我定的）。
- 布防占用的时间段 = 布防时间表里这台机器人被分到值守的时段（含例外日期；**跨午夜的段**按两天算对）。
- 新排程跟已有布防撞 → **不让保存**，写清楚「A 在周一 21:50–22:31 有巡逻，跟 22:00 开始的布防撞了」（用户第 4 条）。
- **反过来也拦**：先有巡逻排程，再改布防时间表或值守方案撞上了 → 也不让保存，列出撞上的是哪几条巡逻（我定的：对称拦，不偷偷让巡逻失效）。
- 排程写「任意一台」：只要那个时段里至少有一台机器人不被布防占用就能保存；到点时只从没被占用的里挑。

### 6.4 运行时撞上（保存时拦不住的）

- 巡逻跑超了，拖进布防时段：**布防优先**，巡逻在当前点结束（`preempted`），记「未跑完，原因：布防开始」，机器人转去值守。
- 有人点「现在布防」，而机器人正在巡逻：同上，布防优先。
- 布防期间（手动或时间表）到点的巡逻排程：这台机器人在值守，记 `skip`「布防中」，不派（任意一台的排程照旧挑空闲的）。

## 七、电量闭环

### 7.1 值守预报（保存布防 / 布防开始时算，跑起来每圈修正）

- 输入：每条防区路线一圈的用时（§6.2）、空档的值守时长、每台机器人**走路 / 站着**每分钟的耗电（按这台机器人的历史电量曲线学，没数据时用保守默认值：按厂家满载续航 3.5 h，走路、站着都按 100% / 210 min ≈ 0.48%/min 算，我定的）、当前电量。
- 输出：本段布防**预计补能几次、大约几点、每次多久**：
  - 有桩：补能时长按充电曲线（厂家标充满 < 1.5 h；学到的实际曲线优先）；
  - 换电：补能时长 = 保安到场（默认 5 分钟，学实际）+ 换两块（默认 3 分钟，我定的）。
- 布防**开始前 30 分钟**检查：当前电量撑不到第一次计划补能 → 推送保安「布防前请先充电 / 换电池」。
- 跑起来以后每圈按实际掉电重算；补能时间提前了就推送更新（「A 补能时间提前到 00:25」）。
- 只有 1 台机器人又没桩：保存时明说「本方案需要夜间换电 2 次，每次约 8 分钟各防区没人看，期间只靠摄像头」；要真不间断只能两台轮换或配桩。

### 7.2 三条电量线（统一，替换现在散落的几个数）

厂家硬线：**任一块电池在位且电量 < 10%**，机器人自动停车着地（SDK 开发指南 2.3.3；SDK 故障码 `PowerControlPowerEmpty`；10–20% 只是 `PowerControlPowerLow` 警告）。

| 线 | 值 | 到了做什么 |
|---|---|---|
| **停止线** | **15%** | 原地停（站着不动，不趴），报 P1「A 电量耗尽，停在 XX」；离厂家硬线留 5 个点给人赶过来（满载约 10 分钟，站着更久，待实测） |
| **回撤线** | **max(25%，15% + 回补能位耗电 × 1.5)** | 结束手上这段，去补能位；离补能位远就自动提前走（用户建议 20–25%，取 25% 作下限） |
| **出站线** | 按任务算，见下 | 低于就不派 |

出站线：

- 布防跑一圈：出发时电量要够「跑完这一圈 + 回补能位」后还在回撤线以上，即 `25% + 一圈耗电 × 1.2`（一圈 15 分钟约 7% → 约 33%）；不够就先补能。
- 报警出动：够「去查看点 + 停着看 5 分钟 + 回补能位」后还在**停止线**以上就派（报警要求放宽一档）。
- 补能中的机器人被叫去出警：同上一条（替换现在「回充中不到 50% 不派」，决策 45 的这一条改掉）。

现在代码里要并进来的：任务策略 `battery_abort_pct` 25 → 停止线 15、`battery_return_pct` 25 → 回撤线；站点回充起线 30%（`charging.py`）、入侵派遣「≤ 30% 排最后」（`incidents.py`）、「回充中 < 50% 不派」→ 都改用上面这三条。断线按不安全处理的 15%（`BATTERY_FLOOR_PCT`）不变。远程升级要 80%（`release_queue.py`）、升级前检查 30% 不在本单范围，不动。

**哪个电量数算这几条线**：现在机器人只报两块里低的那块（`adapter-d1max/hal.py`）。厂家硬线是按单块判的，所以这几条线**按低的那块算**（保守）。两块是同时放电还是先放满的那块，要真机确认（§11 第 5 条）；如果是先放满的，换了一块以后可以改按两块合起来算出站线，确认后再改。

### 7.3 有充电桩

沿用 W13 的回充流程（派到桩前对准点 → 厂家自主回充 `dock` → 充满出桩），只是：起线改成回撤线；充到多少回来接着值守（我定的：充到值守预报算出的「够撑到布防结束或下次计划补能」，最多 95%，不一定等满）；回充中来报警按 §7.2 出站线判。

### 7.4 没有充电桩：保安换电

前提：要先让机器人**分别上报两块电池**（SDK `BatteryData` 已有 `power1/2`、`present1/2`、充电状态；现在旁路进程只报低的那块、不报充电）—— 本单要改契约 `Battery` 和旁路。

流程：

1. 预计补能前 **15 分钟**推 P2「约 00:40 A 需要换电池，请准备两块满电电池」。
2. 到回撤线，机器人去**换电位**，**站着不趴下**，推 P1「A 已到换电位，请来换电池」。等的时候照样看人。
3. 手机 App 和网页一步一步引导（站点按两块电池的在位、电量自动判断进度，保安不用点「下一步」）：
   1. 「先换 **1 号**（电量低的那块，显示几号在哪一侧）」；
   2. 1 号拔出：「不要动 2 号」（软件拦不住人手，只能靠醒目提示 + 机身上贴 1、2 号标签）；
   3. 新 1 号插上、电量读到正常（≥ 80%，我定的）：「现在换 **2 号**」；
   4. 2 号也换好：「换好了」—— 站点自动确认，机器人按 §5.3 接着值守。
4. 保安一直不来：**10 分钟**再推一次，**20 分钟**推给经理（用户认可的数）；电量到停止线报 P1。
5. 换电过程中机器人不断电（热插拔），站点上显示「换电中」，不算掉线、不报离线。
6. 换到一半（只换了一块）就走了：提示「2 号还没换」，按低的那块判电量线，照常往下走流程。

### 7.5 补能期间来了报警

站点按顺序判断：

1. 有别的机器人有空、电量过出动线 → 派它去；
2. 补能中的这台过了出动线 → 中断补能去现场（有桩：先出桩；换电：**正在换的那一步不打断**，等这一块装上），处理完回来接着补能；
3. 都不行 → 不派，报 P1「东区摄像头报入侵，机器人电量不足无法前往，请人工到场或看摄像头画面」，附摄像头实时画面；正在换电的保安手机上直接弹出。

不会出现「报警来了、静静地没人管」。

### 7.6 看得见

- 布防页**时间轴**：每台机器人一行，值守 / 补能 / 缺口三色；补能期间哪些防区没人看。
- 实时：「补能中，预计 01:45 恢复」，超时没恢复报 P2。
- 值守记录里每次补能：起止、谁换的（按 App 上谁的账号在看引导，我定的；没人看就写「未知」）、缺口时长、缺口期间的报警。

## 八、外部设备按位置绑定

- 摄像头、报警主机、门磁：先在站点登记成一台**设备**，在地图上点出位置；摄像头再画出它看的方向和范围（扇形）。
- **摄像头**：站点用 ONVIF 主动订阅事件（W19 已有，`cctv.py`），摄像头那边什么都不用配，不用知道我们的防区。
- **只会发通知的设备**：站点给每台设备一个**专属地址**（带这台设备自己的密钥，沿用现在的签名回调），设备只说「我被触发了」。
- 在哪、属于哪个防区、机器人去哪看：**站点按设备在图上的位置算** —— 查看点 = 设备看着的那片地方里离路网最近、走得通的点（摄像头取扇形中线上约一半距离处，门磁取门旁），比防区查看点更准；防区 = 这个点落在哪个防区里（用来判这个防区此刻布不布防）。
- 老接口兼容：现在按防区名报的 `POST /api/incidents` 继续收（老摄像头、老 AI 盒子），防区名按「圈好的防区的名字」找，找不到再按老的「防区名 → 拦截点」映射；新装的一律走设备登记。

## 九、页面

- **布置 → 防区**：圈防区；每个防区显示查看点、值守位（可拖、可转朝向）；「生成防区路线」。
- **布置 → 防区路线**（新标签，跟「巡逻路线」分开）：生成 / 手画 / 编辑，每防区的圈数、停留、拍照设置；逐段可达检查。
- **布置 → 巡逻路线**：不变，每个点显示「预计 hh:mm:ss / 上次实际」。
- **布防时间**：现有时间段 + 每段的值守方案 + 值守预报 + 时间轴；「现在」卡片照旧。
- **巡逻排程**：保存时的冲突提示。
- **地图 / 值班**：每个防区「上次看过 X 分钟前」；补能中、换电中的机器人状态。
- **机器人详情**：两块电池分别显示；补能状态；换电引导入口。
- **手机 App**：保安端的换电引导（最重要 —— 保安换电时手里拿的是手机）、补能提醒、值守状态；新屏进 `test/layout_matrix_test.dart`，文字走 `tr(en, zh)`。

## 十、权限

- 防区、防区路线、值守方案、布防时间表：管理员、经理（跟现在布防时间表同一档）。
- 开关布防：保安能布防、不能撤防（现在的规矩不变）。
- 换电引导：保安、经理、管理员都能看、都能操作（其实不需要操作，站点自动判）。

## 十一、要在真机上确认的（用户在场时做，不在场不动机器人）

1. 一块电池 < 10%、另一块满电时，机器人会不会停车着地（手册按字面是「任一块」）。
2. 站着热插拔换电安不安全：切换瞬间掉不掉电、抖不抖。
3. 「15% 以下不能动」是厂家 App 的限制、还是电池 / 运控本身的。
4. 机身上哪块是 SDK 的 `power1`、哪块是 `power2`（贴标签）。
5. 两块是一起放电，还是先放电量高的那块（决定 §7.2 用哪个数）。
6. 走路、站着、看人时每分钟耗电；换两块电池实际要几分钟；有桩时的充电曲线。

这些没测出来之前，全部按 §7.1 的保守默认值和 §7.2「按低的那块」跑。

## 十二、老数据怎么过渡

- 现有路线 → 全部归 `patrol` 类（巡逻路线），排程不动。
- 现有「拦截点 + 防区名映射」→ 保留可用（老接口兼容，§8）；圈好防区以后在防区页提示「这个防区的查看点已自动生成，老的拦截点 ic-east 可以删」。
- 现有布防时间表 → 原样保留；没配值守方案的布防段，行为跟现在一样（只管报警派不派），布防页提示「这段布防没有机器人值守」。

## 十四、审文档时请看的「我定的」

1. 查看点 / 值守位的自动选法（§4.1）：路网上离防区形心最近的可达点。
2. 自动生成的巡查点间距 5–8 m、顺序用最近邻 + 交换改进（§4.2）。
3. 布防结束时把手上这一圈跑完再回（§5.2 第 3 条）。
4. 被打断后从「最久没看的防区」接着跑（§5.3）。
5. 「多久没看」超时线 = 预报间隔 × 1.5、最少 15 分钟（§5.5）。
6. 冲突余量：保守用时 = 90 分位或预计 × 1.3，加 2 分钟（§6.3）；改布防撞上已有巡逻也拦（对称）。
7. 耗电默认 0.48%/min（满载 3.5 h），换电默认 5 + 3 分钟（§7.1）。
8. 有桩时不一定充满，充到「够用」最多 95%（§7.3）。
9. 换电引导里第一块装好的判据 ≥ 80%（§7.4）。
10. 顺序打乱默认关（§5.1）。
