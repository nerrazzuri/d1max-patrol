# POC 界面与遥控 设计（周计划第三节，2026-11-05）

依据 `docs/周计划/2026-11-05至11-08.md` 第三节，共 8 项。全部在改名后的代码上做，分支 `poc-ui-teleop`。
每项都有测试（Python、网页 vitest、Flutter），演示站点上用网页和手机都能点通；最后外审一轮再合并。

## 1. 站立、趴下、蹲下

- **命令**：新增 `posture`，载荷 `{mode: stand|lie|crawl}`。它不是任务，不占任务槽。代理收到后自己检查，过了才执行，跟警示 `deter` 一样：
  1. 有没在结束的任务在跑 → `busy: 正在执行任务 <id>`；
  2. 正在叫停（`halting`）；
  3. 翻倒或被抱起（`force_gate`）；
  4. 在充电桩上（`motion_gate`）；
  5. 急停生效（`estop`）。
- **执行**：检查都过了，调 HAL `set_motion_mode(mode)`。HAL 要等状态帧跟上（最多 10 秒），回执里带上最终姿态。
  - 站点给这条命令的回执超时设为 20 秒，不用默认的 10 秒。
- **旁路（C++）**：新增 `crawl` 命令，执行 `Crawl(3000)`。SDK 0.1.1 的 `sdk_client.hpp` 里有这个接口，跟 lie 一样要求握着控制权。Python 侧新增 `SidecarDeviceBackend.crawl()`；HAL 收到 `crawl` 后等 SDK 进入 `CRAWL` 状态。
  - **旁路要在机器人上重新编译**，第一次上真机要用户在场：排到下周，跟速度档一起。
- **仿真适配器**：同样支持这三种姿态，演示站点能点。
- **能力**：代理报 `tasks.posture = {modes: [...]}`。站点、网页、手机只显示这台机器人报了的那几种。
- **站点**：
  - 接口 `POST /api/robots/<id>/posture {mode}`，权限 `teleop`，跟遥控一样：会让机身动的手动操作。
  - 写审计；拒了回 409，把机器人给的原因原样带上。
- **网页和手机**：机器人详情里加三个按钮，点了先弹二次确认，写明会发生什么。之后显示结果或失败原因；有任务在跑时按钮置灰，旁边写原因。

## 2. 遥控速度档

- **站点安全设置**新增 `teleop_speeds = {slow: 0.3, mid: 0.6, fast: 1.0}`（m/s），管理员可改，要满足 `0 < slow ≤ mid ≤ fast ≤ 1.5`。
- **租约**：站点给遥控租约时带上 `max_vx_mps`（= 快档）。代理按 `min(机身能力, max_vx_mps)` 限幅；原来写死的“机身能力的一半”只在租约没带这个值时才用（兼容老站点）。
- **手机**：遥控页加“慢 / 中 / 快”切换，摇杆满推 = 该档速度，转向按同比例缩放。上次选的档记在本机。
- **现有降速规则照旧**：全机器人限速（天气等）、硬禁区守卫都在代理里，比速度档后算；附近有人时的降速照现有规则。

## 3. 遥控指令被丢的原因

- **原因码**：代理的帧闸原来记 `epoch / seq / late`，新增两条：
  - `no_video`：画面断了，不执行；
  - `video_recovered`：画面断过又恢复以后，要先收到一帧摇杆回中的，才接着执行。画面回来时操作员手可能还推着杆，免得机器人突然冲出去。
- **回传**：每次续租的回执带上 `drops`（各原因的累计数）和最近一条原因、时刻。站点原样转给手机（跟硬禁区提示走同一条路）。
- **手机提示**：
  - `late` →「指令被判迟到：钟差或网络」
  - `video_recovered` →「画面刚恢复，请先松开摇杆」
  - `no_video` →「无画面」
  - `seq` / `epoch` →「指令顺序不对（重连中）」
  - 提示只在这几秒内有新增丢帧时显示。

## 4. 回原点、中止并回原点

- **站点接口** `POST /api/robots/<id>/home/return {abort?: bool}`，权限 `dispatch`：
  - 这台机器人在当前地图上没有原点 → 409「当前地图上还没有原点：在原点位置点“设为原点”」。
  - 有任务在跑：
    - `abort` 不为真 → 409「正在执行任务，要先中止：用“中止并回原点”」；
    - `abort` 为真 → 先中止，等它进终态（最多 15 秒），再派。
  - 派一条 `goto` 到原点：优先级 `STANDBY_RETURN`，任务号前缀 `standby-`，这样自动回程的去重也认它。导航后端是 Nav2 就走 Nav2。
- **网页和手机**：两个按钮“回原点”“中止并回原点”。后者要二次确认，没任务在跑时不显示。

## 5. 路线页「派机器人跑一趟」

- 路线页每条路线加“派一趟”：先调已有的预计时间（`route_eta.estimate`），弹窗显示预计时长、派给哪台、现在要不要排队；确认后走现有的临时巡逻派单。
- 防区页顶部加一行提示：「防区只管报警；巡逻请到路线页派」。

## 6. 手机换图进度

- 代理在下载、校验、切换、加载定位各阶段发 `map_progress` 事件，带上阶段、已下载字节、总字节、失败原因。站点存最近一份，接口返回；手机显示：
  - 已下载多少 MB、按最近速度估算还要多久；
  - 校验、切换、定位加载各阶段；
  - 失败原因原文。

## 7. 开通码二维码用局域网地址

- 二维码和开通码里的站点地址，按站点主机的网卡列出局域网 IPv4，跳过回环、`docker*`、`br-*`、`veth*`。手动配置的 `--hostname` 照旧排在最前。
- 一个都没有时，页面上说清楚：「没找到局域网地址，请在站点设置里填对外地址」，而不是给 127.0.0.1。

## 8. 告警测试模式

- 管理员开启“告警测试模式”（带结束时刻，最长 2 小时）。期间产生的告警都打上 `test` 标记，照常推送，标题前加「测试」。
- “结束测试并清掉”一键把带标记的告警全部删掉（审计记一条，写明删了几条）；不带标记的不动。
- 到点自动结束，但不自动删。
