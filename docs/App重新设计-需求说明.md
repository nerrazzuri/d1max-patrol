# Nexus Warden 手机 App：重新设计需求说明

> 给设计师（或设计用的 AI）的完整说明。可以整份当 prompt 用。
> 现有 App 功能齐全但界面不好看、层级乱，这次要重新做视觉和信息架构。**功能一条不能少，页面怎么组织可以重排。**

---

## 1. 这是什么产品

**Nexus Warden** 是 Nexus Dynamic 的庄园安防系统：几只四足机器狗在庄园里巡逻、看见人会报警并驱离。系统有三部分：

- **机器狗**：自主巡逻，带前后两路相机、声光驱离装置。
- **站点**：庄园里的一台主机，是唯一的指挥中心。狗的状态、告警、画面、录像、地图都在站点上。
- **操作界面**：网页值班台（值班室的大屏，主力）和**手机 App（这次要设计的）**。

手机 App 只连站点，不直接连狗。一部手机可以加多个站点（比如一个人管几处庄园）。

## 2. 谁在用、什么时候用

| 角色 | 是谁 | 典型场景 | 能做什么 |
|---|---|---|---|
| **保安** guard | 值班保安，可能在巡逻路上、在岗亭、半夜被叫醒 | 手机响了，有人闯入，要在十几秒内看清是不是真的、决定怎么办 | 看一切；确认和关闭告警；派狗、叫停、遥控、驱离 |
| **业主** owner | 庄园主人，不在现场 | 偶尔打开看看家里是否安全；收到告警时看一眼 | 看一切；叫停；切换布防模式。**不能**派狗、遥控、处理告警 |
| **管理员** admin | 安装和维护人员 | 装机、调试、换地图、升级软件、排查故障 | 全部，包括地图、软件版本、站点体检、诊断包 |

**最重要的使用时刻**：凌晨、单手、紧张、可能在走路。手机在这一刻要做到：一眼看懂出了什么事，一下就能点到该点的按钮，不会点错。

## 3. 设计要求

### 3.1 总方向

- **专业的安防工具，不是消费类 App。** 参考对象是专业视频监控（VMS）、工业控制室界面，不是智能家居 App。
- **平时安静，出事醒目。** 没有告警时界面克制、信息密度适中；有 P1 告警时它压过一切。
- **好看，但好看来自秩序**：清晰的层级、统一的间距、精确的对齐、克制的用色。不要靠渐变、插画、大圆角卡片堆砌。
- 现有版本的问题（要解决的）：层级不清、按钮一大排平铺、列表和操作混在一起、看不出哪个最重要、视觉粗糙。

### 3.2 必须遵守的硬规矩

1. **颜色只给告警用。** 红色只表示 P1（要人马上动身），琥珀色只表示 P2（要处理但不急）。正常状态不上色，不用绿色表示「正常」。品牌色不能和这两个颜色撞。
2. **告警优先级三重编码**：颜色 + 形状 + 文字同时出现（比如 P1 是红色 + 菱形 + 「P1」字样），色弱的人也分得清。
3. **急停类按钮永远够得着**：「叫停」「全部急停」在相关页面上位置固定、面积够大、不需要滚动才能看到。
4. **危险操作要二次确认**，普通操作不要。危险的有：开警笛、遥控、切换软件版本、在原点重设位置、判定误报。
5. **状态不许含糊**：「没有告警」和「还没读到」是两回事，要分开写；数据过期了要明说过期多久，不能把旧数据当新的显示。
6. **按钮按角色显示**：业主看不到派狗、遥控、处理告警的按钮；只有管理员看得到管理入口。不要显示一个点了必定被拒的按钮。
7. **英文为主，中文可切换**。所有文案两种语言都要给，设计稿要用英文和中文各验一遍，中文不能溢出。
8. **竖屏和横屏都要支持**；遥控页只做横屏。最小适配宽度竖屏 360、横屏 568×360。
9. **对比度达到 WCAG AA**；可点击区域不小于 48×48；尊重系统的「减少动态效果」设置。
10. **动效极少**：只有未确认的 P1 可以闪（慢闪，直到有人确认）。没有入场动画、没有装饰动画。

### 3.3 可以自由发挥的

- 深色还是浅色主题、具体配色、字体、图标风格、圆角大小、导航方式（底部标签栏、抽屉、还是别的）。
- 页面怎么合并、拆分、重排。下面第 5 节是现在的结构，仅供了解功能，不是必须照搬。
- 现有版本用的是中性深灰 + Atkinson Hyperlegible 字体，可以沿用也可以换。

### 3.4 技术约束

- Flutter 实现，Android 为主，同一套代码也出 Windows / Linux 桌面版；之后会做 iOS 和鸿蒙。请用 Flutter 容易实现的组件和效果。
- 实时画面是从站点转来的视频流，手机上一次只拉一路（前或后），比例 16:9。
- 网络可能差：每个页面都要有「加载中」「没连上」「数据过期」三种状态的样子。

## 4. 核心概念（设计时要认识的东西）

| 概念 | 说明 |
|---|---|
| 站点 | 一处庄园。有名字、地址、当前布防模式 |
| 狗 | 机器狗。有编号（如 D1-02）、在线/离线、电量、正在做什么、定位是否可信 |
| 告警 | 三级：**P1** 马上去（有人闯入、狗翻倒）、**P2** 要处理（证书快到期、推送发不出去）、**P3** 知道就行。每条有「未确认 → 已确认 → 已关闭」三个状态 |
| 驱离 | 狗对闯入者逐级升级：1 级灯光 → 2 级语音 → 3 级警笛。可以自动升级，也可以人手动升级或结束 |
| 布防模式 | 布防 / 在家 / 访客。决定看见人要不要报警 |
| 防区、拦截点 | 庄园分成几个防区；每个防区对应一个狗去拦截的位置 |
| 待命点 | 狗没事时待着的位置 |
| 巡检 | 狗按路线走一圈并拍照；每一趟有记录和照片 |
| 录像 | 狗的前后相机连续录像，按时间轴回看 |
| 地图 | 庄园的平面图，上面有狗的位置、防区、禁行区 |

## 5. 现在有哪些页面、各做什么

### A. 进入

| 页面 | 功能 | 去哪 |
|---|---|---|
| **A1 站点列表** | App 的起点。列出已添加的站点；添加、删除站点；点一个站点去登录 | → A2 添加站点；→ 登录 → B1 |
| **A2 添加站点** | 两种方式：扫站点的配对二维码，或粘贴配对码 / 手填地址。然后填账号 | → A3 扫码；完成回 A1 |
| **A3 扫码** | 相机取景框扫配对二维码 | 扫到回 A2 |
| **登录** | 输口令。现在是个弹窗 | → B1 |

**空状态很重要**：第一次打开没有任何站点，要引导用户添加，而不是一个空白列表。

### B. 站点首页

| 页面 | 功能 | 去哪 |
|---|---|---|
| **B1 狗的列表**（现在的首页） | 每只狗一行：编号、在线/离线、电量、正在做什么。顶上是当前布防模式、正在进行的驱离、推送是否就绪、后台值守开关。还有一排入口：值守、版本、地图、记录、事件、排程、摄像头、天气、体检 | → C1 单狗页；→ 各功能页 |
| **B2 值守** | 「现在要不要我管」的总览，从上到下三件事：① 有没有要我马上动身的 P1；② 其余没处理的告警；③ 每只狗和站点自己有没有在悄悄坏掉（离线、电量低、时钟不准、磁盘满） | → D1 告警现场 |
| **B3 布防模式** | 切换布防 / 在家 / 访客；访客模式可以选防区和时长；设置哪些防区在家时也布防 | — |

> 现状的问题：B1 既是狗的列表又是功能入口大杂烩。「值守」才是保安真正的首页，却藏在一个图标后面。

### C. 一只狗

| 页面 | 功能 | 去哪 |
|---|---|---|
| **C1 单狗页** | 这只狗的状态、定位是否可信、实时画面（前/后切换）。操作：**叫停**、派巡检、回待命点、设位置、遥控、录像、上装（声光）。管理员多几项：录包、标原点、建图日志、待命点管理 | → C2 遥控；→ C3 录像；→ C4 驱离；→ G 组管理页 |
| **C2 遥控**（只横屏） | 全屏实时画面 + 两个虚拟摇杆（前进后退、转向）+ 一个大的「停」。进入即接管，退出即放手；被别人占用时说明是谁 | 返回 C1 |
| **C3 录像** | 这只狗的录像时间轴（哪段有、哪段缺），选时间回放，前/后切换，可标记「留着不删」 | — |
| **C4 驱离控制** | 这只狗当前驱离到第几级、每一级开了什么（灯、语音、警笛）、多久后自动升级；手动升级、结束驱离 | — |

> 现状的问题：C1 上十几个按钮平铺成一堆，最常用的（叫停、看画面）和一年用一次的（标原点）长得一样。

### D. 告警（最重要的一组）

| 页面 | 功能 | 去哪 |
|---|---|---|
| **D1 告警现场页** | 一条告警的全部：级别和标题、多久没人确认、**现场实时画面**（前/后切换）和触发时的抓拍、位置（哪个防区、最近的人离狗多远）、当前驱离到几级、事件经过时间线（含「30 秒后无人响应将升级为警笛」这种预告）。四个大按钮：**我来处理**（确认）、**开警笛**、**误报**（关闭）、对讲（暂未实现，置灰） | → 地图上看位置；→ C4 驱离控制；→ 相关那一趟的记录 |

**这一页是整个 App 的重心**，请投入最多的设计精力。要求：

- 竖屏单手可操作，四个按钮在拇指够得着的下半屏。
- 「未确认 / 已确认 / 已关闭」三种状态一眼分得出。未确认时可以慢闪。
- 画面必须大，且标明是实时还是抓拍、是哪只狗哪一路、画面时间。
- 「我来处理」和「开警笛」不能长得一样：前者是常规的主操作，后者是有后果的操作。
- 网络回复晚到时不能把结果显示到别的告警上；警笛只有狗确认开了才显示「已开」。

### E. 查看记录

| 页面 | 功能 | 去哪 |
|---|---|---|
| **E1 巡检记录列表** | 每一趟一行：任务、时间、几张照片、有无异常 | → E2 |
| **E2 一趟的照片** | 这一趟拍的照片列表，每张有系统判读的结论 | → E3 |
| **E3 单张照片** | 大图 + 系统的判断（结论、把握、理由）+ 人的复核（人说了算） | — |
| **E4 事件** | 外部摄像头报来的入侵事件：哪个防区、派了哪只狗、结果如何 | → G4 拦截点；→ E6 摄像头 |
| **E5 排程** | 定时巡检计划：下一轮什么时候、上一次结果 | — |
| **E6 摄像头** | 庄园固定摄像头列表，点开看实时画面 | — |
| **E7 天气** | 当前天气模式（正常 / 下雨 / 雷暴），影响狗的速度和是否出勤；可手动切换 | — |

### F. 地图

| 页面 | 功能 | 去哪 |
|---|---|---|
| **F1 地图列表** | 站点上的地图和版本 | → F2 |
| **F2 地图预览** | 平面图，可缩放；显示狗的位置、待命点、防区、禁行区 | — |

### G. 管理（只有管理员看得到）

| 页面 | 功能 |
|---|---|
| **G1 站点体检** | 站点各项是否正常（证书、磁盘、服务、备份、推送）；各只狗和各台手机在用什么软件版本；**导出诊断包**（保存到手机或分享） |
| **G2 软件版本** | 站点上有哪些版本，每只狗在跑哪版；安装、切换、回退（切换和回退要确认） |
| **G3 待命点** | 增删改狗的待命位置 |
| **G4 拦截点与防区** | 哪个防区对应哪个拦截位置 |
| **G5 录包轨迹、建图日志** | 建图时的轨迹图和日志，调试用 |

```
A1 站点列表 ──添加──▶ A2 添加站点 ──▶ A3 扫码
     │
   登录
     ▼
B1 站点首页 ─┬─▶ B2 值守 ──────────▶ D1 告警现场 ─┬─▶ F2 地图
             │                                    ├─▶ C4 驱离控制
             ├─▶ B3 布防模式                       └─▶ E2 那一趟的记录
             │
             ├─▶ C1 单狗页 ─┬─▶ C2 遥控
             │              ├─▶ C3 录像
             │              ├─▶ C4 驱离控制
             │              └─▶ G3 待命点、G5 调试（管理员）
             │
             ├─▶ E1 巡检记录 ─▶ E2 ─▶ E3
             ├─▶ E4 事件 ─▶ G4 拦截点、E6 摄像头
             ├─▶ E5 排程
             ├─▶ E7 天气
             ├─▶ F1 地图列表 ─▶ F2 地图预览
             └─▶ G1 体检、G2 软件版本（管理员）

推送通知 / 后台值守提醒 ──点击──▶ D1 告警现场（目标；现在还做不到直达）
```

### 三条最常走的路（请优先保证顺畅）

1. **半夜告警**：通知响 → 打开 App → 告警现场页 → 看画面 → 「我来处理」或「误报」。目标是三步以内。
2. **日常看一眼**：打开 App → 一屏内看到「一切正常」或「有几件事要处理」→ 想看哪只狗点进去看画面。
3. **手动出勤**：选一只狗 → 派巡检，或进遥控 → 结束后叫它回待命点。

## 7. 建议重新考虑的地方

以下是现有结构的毛病，欢迎提出更好的组织方式：

- 首页应该回答「现在有没有事」，而不是一个狗的列表加一排图标。考虑把「值守」做成首页。
- 考虑用固定的主导航（比如底部标签栏）分开几件事：值守 / 狗 / 地图 / 记录 / 更多。
- 单狗页的操作要分层：常用的（画面、叫停、派巡检、回待命点）放前面；少用的和管理员才用的收进二级。
- 告警要有一个随时可见的入口和未处理数量，不管用户在哪一页。
- 管理功能集中到一处，普通用户完全看不到。

## 8. 每个页面都要给的状态

- 正常有数据
- 加载中
- 空（没有站点 / 没有狗 / 没有告警 / 没有录像）
- 没连上站点、正在重连
- 数据过期（显示的是多久以前的）
- 没权限（这个角色看不到或不能操作）
- 操作进行中、操作成功、操作失败（说明原因和怎么办）

狗的状态要能表达：在线空闲、在巡检、在驱离、被叫停、离线、电量低、定位不可信、急停中。

## 9. 需要交付什么

1. **设计方向说明**：一页，讲清楚整体思路和为什么。
2. **设计规范**：颜色（含 P1 / P2 的用法）、字体和字号、间距、圆角、图标、按钮和列表等基础组件的各种状态。
3. **信息架构图**：重排后的页面结构和导航。
4. **高保真页面**，至少包括：
   - 站点列表（含空状态）、添加站点
   - 首页 / 值守（平时一切正常、有一条未确认的 P1、有几条 P2 三种情况）
   - **告警现场页**（未确认、已确认、已关闭三种状态；竖屏和横屏）
   - 单狗页（保安看到的、管理员看到的）
   - 遥控页（横屏）
   - 录像时间轴
   - 地图预览
   - 驱离控制
   - 站点体检
5. 关键页面的**英文版和中文版**各一份。
6. 竖屏 390×844 为主；告警现场页和单狗页另给横屏 844×390。

## 10. 不要做的

- 不要用颜色装饰正常状态；不要绿色的「一切正常」大对勾。
- 不要大渐变、玻璃拟态、插画人物、吉祥物。
- 不要把重要操作藏进长按、滑动手势里。
- 不要用纯图标按钮表达危险操作（叫停、警笛必须有文字）。
- 不要为了好看减少信息：保安需要看到编号、时间、距离这些具体数字。
- 不要改动功能或权限规则；有疑问请提出来而不是自行取舍。
