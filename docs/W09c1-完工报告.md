# W09c1 地图版本带先验 · 完工报告（供审核）

> 设计稿：`docs/superpowers/specs/2026-09-27-W09c-prior-in-map-version-design.md`（按推荐）。
> 本张做设计稿决定 1–9、11；决定 10（边走边建）是 W09c2。

## 问题

W09b 的定位器要地图目录里有 `prior.mm` + `frames.json`，只能在开发机上手工做；狗上建图还是 slam_toolbox 出二维图。要让地图版本
自带定位先验、并且规划栅格跟定位报的位置在同一个平面里；建图的狗不用再从站点下回来；几百 MB 的先验下得动；站点不派「图外」的点；
真狗（没有 HAL 载入）也能换图。

## 与设计稿不同的地方

1. **决定 9（站点收图）**：设计稿写「放后台线程校验、搬家、登记」。实现时发现放后台的话，狗在最后一块已经收到 200、删了自己那份，
   后台再出错图就悄悄没了。改成：收完一个文件时把收块算好的整文件哈希（狗也拿它核过）记在收件目录里一个点开头的旁注里（没收完、重传就作废），
   登记时对照它、同一块盘上改名 —— 请求里几乎不花时间，又保留「收不下当场拒、狗隔离留着那份」。设计稿已按实际改写。
2. **栅格加了真射线和挖身子**：设计稿照原型写「用走过的轨迹做 log-odds 射线法」。拿 newdog2 真数据验「哪里有图」时，走过的 247 个点有
   22 个落在「墙」上：跟着狗走的人站过的地方连成一道墙，原型的模拟射线碰到就停、永远清不掉，墙的另一侧全成了「没扫到」。改成逐帧扫描的真射线
   + 狗身子待过的地方一律可通行：0 个被拒，栅格 8 s → 18 s。
3. **「站点存路线 / 巡检点时查」没做**：任务包只写地图号、不写版本，存的时候不知道按哪一版查；只在派单时按狗加载的版本查。

## 已知限制

- 真射线能看穿玻璃：玻璃外面漏出扇形的可通行区。只要玻璃那一侧的墙线连着，规划过不去；墙线断的地方要补（后续：虚拟墙）。真机项 3d.18。
- 逐帧扫描只认 `/front_lidar`（MOLA 跟的就是它的坐标系）；别的话题退回模拟射线。
- 本地库里收养的版本，换成别的图时照样删（狗上只留正在用的那张）；再激活它就从站点下。
- 续传只在一次安装里；代理重启了从头下。
- 换图时定位器换先验是异步的：`map_activated` 发出时定位器可能还在载先验；这段时间定位不可信、狗不走。
