## 交付

### 第一部分：发件箱与证据（决定一到四、六）

- **契约**：
  - 遥测里可选的 `storage`（`StorageFacts`），每 10 s 带一次：发件箱所在盘的已用比例、发件箱字节数与上限、待传文件数与字节数、最老一条待传等了多久；
  - 接收口白名单：狗只传清单、事件、遥测、照片（`d1max_contract.intake`）。
- **代理**：
  - **发件箱** `--outbox`（缺省 `/var/lib/d1max/outbox`，可指到临时硬盘；`D1MAX_OUTBOX_MOUNT` 给了就必须真挂上才起）+ 上限 `--outbox-max-gb`（缺省 20）。分 `runs/`、`bags/`、`maps/` 三块，一条后台线程轮着传；
  - 运行记录直接落发件箱，边跑边传；**站点确认、这一趟安定（任务进终态）、不是引擎正在写的那一趟**，三条都满足才整趟删；没确认的一个字节都不删；
  - 每趟目录带随机后缀：狗钟往回拨撞了名也不会覆盖站点上收齐的一趟；任务名、点位名落盘前做安全处理；
  - 站点永远不收的文件（HTTP 422）：隔离、不再重试，这一趟留在狗上，站点出 `upload_refused` 告警；隔离的**不算积压**；管理员可以让狗把隔离的再传一次（`outbox_retry`）；
  - 水位：盘用到 90% 或发件箱到上限 → 拒新的巡检（`storage_full`），事件派遣的 `goto` 照接；盘量不了按满了报；
  - 事件簿与幂等记录压实（已确认的事件、24 h 以上的幂等记录定期清）；上一个进程没确认的事件带到新 boot 补发（不丢、不重复）；
  - 发件箱一拍限时 5 s；关机先停运行时（停车、放控制权），再停上传线程，不等在途的那一块传完；
  - `--legacy-http` 不许跟 `--outbox` 一起用。
- **站点**：
  - **狗专用接收口**（缺省 8444）：mTLS 必须，跟 MQTT 同一张 CA、同一份吊销表，再按登记表核证书指纹；狗号由站点按证书填，狗 A 写不了狗 B 的路径；TLS 握手在每条连接自己的线程里做；同时连接数有总上限，**每个来源地址另有上限（16）**；
  - 上行：沿用现成的分块续传协议，站点按自己存下的字节算哈希（追加时增量），缺一段不写；单文件上限 8 GiB，站点盘余量不够（< 2 GiB 或 < 2%）不收；
  - 证据库 + `runs`、`run_photos` 表：一趟落 `<站点目录>/evidence/<狗>/<任务>/<时刻>/`；
  - **判读在站点**：一趟跑完、一分钟没有新文件就自动判；**只判收齐的照片**，半张的不判、不当基线（历史照片也一样）；判读开始时先打点，判到一半才收齐的照片下一轮判；没判成的隔 10 分钟再试，最多三轮；没配密钥就都是「待判读」；异常出 `finding` 告警；
  - 复核（管理员、保安）、人点重判（后台跑，回 202）；
  - 导出：管理员按时间段打 zip（原样文件 + 清单 + sha256，哈希按写进 zip 的字节算），后台打、记审计；
  - **站点备份**：每小时一次，`sqlite3 backup` 出库快照（留 7 份），再把证据、**地图、录包、发布包**增量镜像到备份目录；上次成功时刻记在库里；25 h 没成出 `backup_stale`；
  - 盘况告警 `disk_80`、`upload_backlog`（各报一次，回落才重新武装）；值守汇总填上狗的盘况、站点那一行有备份；
  - 告警簿只在事件循环里改：判读、备份、接收口经 `LoopAlerts` 跳回循环（已经在循环里就直接报）；
  - 权限：`review`（管理员、保安）、`export`（管理员）。
- **手机**：记录列表、一趟的照片、判读结论、复核、重判；值守屏有盘水位、积压最老多久、站点备份。
- **部署**：`d1max-agent` 单元用 `--outbox ${D1MAX_OUTBOX}`；`d1max-site` 单元可写 `/var/lib/d1max-site-backup`、读 `/etc/d1max-site/env`（判读密钥）。

### 第二部分：地图（决定五）

- **契约** `d1max_contract.maps`：一张图 = 地图号 + 版本 + 文件清单（大小、sha256）；`map_activate`、`mapping`、`map_build` 的载荷。
- **站点地图目录** `MapCatalog`（`maps`、`bags` 表）：
  - **同一个地图号 + 版本只登记一次，不覆盖**（狗上可能正用着它）；
  - 来路两条：管理员在站点主机上 `d1max-site map-import`；狗重建完传上来 —— **只收站点让这台狗建的那一张**（查命令账里的 `map_build`），收齐 `map.json` 且每个文件的大小、哈希都对上，才搬进目录登记，收件那份删掉；
  - 收不下（版本撞了、清单对不上）回 422：狗隔离、留着那份，站点出告警。不再回 200 让狗删掉、图悄悄没了；
  - 狗下载：`GET /maps/<地图号>/<版本>/<文件>`，只认登记在册的狗、只给清单里的文件。
- **下发**：`POST /api/robots/<id>/map`（管理员）→ `map_activate`：
  - 图里没带 `home.json` 时，站点把**这台狗在这张图上登记的待命点**当原点一起下发；两样都没有就 409，不下发（狗换了坐标系没有原点，之后派什么都过不了起飞前检查）；
  - 代理 `MapKeeper`：经狗专用口（mTLS）下载，边下边核，超长就停，整体最多 30 分钟；对不上整张不装；
  - **下载不挡任务**；下载好之后等狗空下来（最多 10 分钟），只有载入、切坐标系那一小段不接自动任务；
  - 适配器载不进去就扔掉；**提交失败把原来那张载回去**（不留「适配器是新图、代理报老版本」）；成了才记成正在用的（连同原点），别的图都删掉；
  - 能力里的地图版本跟着变，导航桥、原点跟着换；发不出能力不算换图失败（下次重连会再发）；
  - 重启按 `active.json` 接着用，**在连上 MQTT 之前**载好；载不进去发 `map_load_failed`；
  - 再下发正在用的那一版：什么都不删，直接载。
- **录包与重建**（代理 `--mapping`，要 ROS）：
  - `mapping start/stop` 在后台做（起、停 `ros2 bag` 要十几秒，不占命令锁）；盘满了不录；没在录回 `not_recording`；
  - 录包写发件箱 `bags/<包名>-<UTC 时刻>/`，`ros2 bag` 每 2 GiB 切一个文件（站点单文件上限 8 GiB）；停录打 `.done`；
  - 重建 `map_build`：开跑时要狗空闲（吃 CPU），开跑之后不挡出警；上一次同名的产物先删，只收这张图的几个后缀；先在点开头的目录里攒齐，文件就位才写 `map.json`；重建完给包打 `.built`；
  - 起来时收拾：攒到一半的图扔掉，录到一半的包补 `.done`；
  - 重建占着包时发件箱不删它（同一把锁）。
- **站点 API**：`GET /api/maps`；`POST /api/robots/<id>/map|mapping|map_build|outbox_retry`（管理员）；地图号 ≤ 40 字、版本 ≤ 16 字、包名 ≤ 40 字；版本已有或正在建回 409；`map_failed` 告警。
- **仿真适配器**：`load_map`。
- **手机**：地图屏（管理员：下发、拿录包重建），单狗页录包开始、停止。**只列、只显示报了这种能力的狗与按钮**；下发前再确认一次。

### 第三部分：发布（决定七）

- **契约** `d1max_contract.releases`：版本名规矩、`ReleaseRef`（名字、sha256、大小）；`release_install`、`release_activate`、`release_rollback`。
- **站点发布目录** `ReleaseCatalog`（`releases` 表，schema 11）：`d1max-site release-add <包目录>` 核对包内指纹与名字，**带链接（软的、硬的）或特殊文件的包不登记**，打成 tar.gz；狗下载 `GET /releases/<名>.tar.gz`（只认登记在册的狗）。
- **打包**：`release pack … --wheels <轮子目录>` 把离线轮子带进包（算进指纹）；狗上建 venv 见到包里的 `wheels/` 就只从它装（现场的狗上不了网）。
- **代理** `ReleaseOps`：
  - 装：双槽所在的盘要够（包大小的 4 倍加 512 MiB）；下载（边下边核、超长就停）→ 安全解开（只许普通文件与目录、`..` 一律不许、去掉 setuid 位）→ 核包内指纹、落槽 → 建这一版自己的 venv（跟 `install.sh` 4/7 一个做法，哨兵最后落）；装在后台，不挡任务；狗上最多留在跑的、上一版、刚装的这几版；起来时清掉上次装到一半的临时文件；
  - 切：要空闲（不跑任务、不录包、不重建、不在换图）、电量 ≥ 30%、读得到电量；写在途标记 → 换链 → **代理自己好好退出**，systemd 从新的 `current` 起来 → **连上站点才提交**；收下之后到重启前什么都不接（`restarting`）；
  - **启动参数归版本管**：代理单元只指着这一版带的启动脚本 `deploy/d1max-agent-start`，单元装一次不再换；新版起不来、开机守卫退回上一版时，上一版的参数跟着代码一起回来；
  - 退：有在途的那一次升级就退它；已经提交了就切回盘上**上一版**（一样写在途标记、连上才提交）；
  - 开机守卫退回上一版时留一张条子，代理起来连上站点报 `release_rolled_back`，站点出告警；
  - 能力里报在跑哪一版。
- **代理单元**：加开机守卫（`ExecStartPre`）；`ExecStart` 是这一版的启动脚本；适配器从 env 取（`D1MAX_HAL`，缺省 `sim`），其余参数 `D1MAX_AGENT_ARGS`。
- **站点 API**：`GET /api/releases`（每一版、每台狗在跑哪一版）；`POST /api/robots/<id>/release`（管理员）；`release_failed` 告警。
- **手机**：版本屏（管理员装、切、退，切和退要确认；狗没报在跑哪一版就不给按钮）。

## 决策 8 对照：狗上还留什么

| 狗上的东西 | 为什么留 | 什么时候删 |
|---|---|---|
| 发件箱 `runs/` | 断网暂存 | 站点确认 + 这一趟进终态 + 不是正在写的那一趟 → 整趟删 |
| 发件箱 `maps/` | 狗上重建出的图，等上传 | 站点确认即删 |
| 发件箱 `bags/` | 录包：断网暂存，**也是狗上重建的原料** | 站点确认，且（重建过、或录完满 7 天、或盘紧了）才删（见「与设计稿不同」第 1 条） |
| 站点拒收的文件 | 不能悄悄丢证据 | 留着，站点出 `upload_refused`；管理员让它重传 |
| 正在用的那张地图 + `active.json`（含原点） | 工作副本，随时可从站点重下 | 换图成功后别的图都删 |
| 发布槽：在跑的、上一版、刚装还没切的 | 运行必需 + 回滚 | 装完、提交时删多余的版本 |
| 事件簿、幂等记录 | 断线补发、防重 | 压实：已确认的事件、24 h 以上的幂等记录 |

判读、基线、复核、导出、备份、地图目录、发布目录都只在站点。发件箱的位置和上限都可以配（临时硬盘到了改 `D1MAX_OUTBOX`）。

## 与设计稿不同的地方

1. **录包在狗上多留一阵**。设计稿是「传完即删」；但重建在狗上跑（要 ROS），包传完就删的话「拿录包重建」几乎用不上（内部评审第二部分第 3 条）。现在是**传完且（重建过、或录完满 7 天、或盘紧了）**才删；盘紧 = 发件箱过了上限的一半或盘用到八成（第三部分评审的阻断项：留着的包不许把巡检挤成 `storage_full`）。这是决策 8 下的一个口子：录包是建图的原料，按「工作副本」对待，有期限。**请外审确认这样可以**；不行的话改成「传完即删，重建时从站点下回来」（另开工单：狗要从站点下载录包）。外审第一轮建议批准（「受限缓存，不算永久双存」，要求站点副本是权威、正在录或正在重建的不许删 —— 现状就是这样），第二轮明确**批准**（措辞见交接文档 §2）；这是决策 8 的例外，**记进决策表要等用户确认**。
2. **原点随下发走**。设计稿没提原点；自建的图不带 `home.json`，下发后狗没有原点、什么任务都派不出去（第二部分评审的阻断项）。现在站点把这台狗在这张图上登记的待命点当原点一起下发，都没有就不下发。
3. **切版本靠代理自己退出，不装单元**。设计稿写「现成的激活（写 pending、切链接、重启）」。现成的重启走老服务 `d1max-patrol` 的特权助手；代理这里改为：写在途标记、换链、3 秒后给自己发 SIGTERM，`Restart=always` 从新版起来。**切版本不碰单元**（第三部分评审的阻断项：新版单元配老代码，守卫退回之后就再也起不来）：启动参数在这一版带的启动脚本里。于是代理运行时**不需要任何 root 操作**，特权助手在代理这一侧一条都不用（W00c5e 随老服务一起删）。
   **提交的标准是「连上站点」**，没有另跑自检（设计稿写的是「自检过了才算提交」）：新版连得上站点、但发布这条路本身坏了，就只能人上机退。
4. **站点连接数另有按地址的上限**（设计稿没有）。第一部分评审修复加了总连接数上限，第二部分评审指出一个人开空连接就能占满，于是每个来源地址最多 16 条。
5. **判读模块在站点有一份自己的**（`d1max_site.judge`），提示词里的「变电站」改成「安防巡检」。狗上的那份（`src/d1max_patrol/inspect/judge.py`）只有老服务在用，W00c5e 随老服务删。
6. **导出按一趟的开跑时刻（狗的钟）取**，不按站点收到的时刻。评审修复时改的：按收到时刻取，断网补传的那几趟会被分到别的时间段。代价见「已知限制」。
7. **发布的「电量够、盘够」**：切、退要电量 ≥ 30%（读不到电量也不切）；盘量的是**双槽与下载目录所在的盘**（不是发件箱那块，发件箱可能在临时硬盘上）：装要包大小的 4 倍加 512 MiB，切、退要 512 MiB。
8. **站点下发版本要重跑一次 `install.sh`**：代理单元改成指着启动脚本，已经装过的狗要重跑一次装机脚本装新单元（3c.24）。

## 已知限制（没做，列出来）

- **真狗（d1max 适配器）没有「载入一张图」**：能力里不报 `map_activate`，站点不给下发按钮（真机项 3c.22）。真狗要能切图，得先给适配器加载入，另开工单。
- **没有按狗的配额**：站点的盘只有整体余量下限，一台狗传得多会挤占别的狗。
- **录包在站点上没有保留期限**：地图目录、录包只增不删；盘到下限时接收口整体停收（照片也收不了）。要按天数或总量清录包，另开工单。
- **导出按狗的钟**：狗的钟是错的时候（现场已知），导出的时间段对不上。钟的事跟 3c.7、3c.16 一起解决。
- **重启打断的下载、重建不回报**：站点上那条命令停在「狗收下了」。狗起来时会把半截的重建扔掉、半截的录包补完成标记，但不补发失败事件。
- **手机的录包列表**：已经被狗删掉的包照样列着；点重建，狗回 `map_build_failed`（「包不在狗上了」），站点出告警。
- **提交之前不跑自检**：见「与设计稿不同」第 3 条。
- **第一次换图就提交失败**（盘坏了、之前没有正在用的图）：适配器已经是新图，代理报的还是 `--map`，重启后回到 `--map`。有上一张图时会载回上一张。
- **备份只增不删**：备份目录里的证据、地图、录包、发布包不随站点上删除而删（站点本身也还不删），备份盘要按大小选。
- **录包的「满 7 天」按狗的钟**：狗的钟错了会提前或推迟删；盘紧时照样会删，不会撑满。
- **`maps-in` 里的孤儿文件**：狗传最后一块、站点收下但回执丢了，狗重传时站点已经把那张图收进目录；这时收件目录里可能留下一份没人清的。不影响登记，只占盘。
- **每个地址 16 条连接**：手机们在同一个 NAT 后面时算一个地址。现场手机一般直连站点所在的局域网，不受影响。
