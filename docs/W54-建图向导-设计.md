# W54 · 建图向导 · 设计

> 2026-10-31。用户 10-31 定的写在「用户定的」；我替用户定的写在「我定的」，用户可以改。页面草图：https://claude.ai/artifact/Bxc4Gymmjwx5jxCjPnRE6b 。用户 10-31 批了（「没问题」）。
>
> **实现时改的**（见第 11 节）：禁行区挪到原点前面；准备那一步不预先查「站着」「存储够」。

## 1. 为什么

只买设备、没买交付服务的客户，要能自己把第一张图建出来。

建图的功能 App 里其实都有：录包、边走边建、建图预览、重建、下发、标原点、画禁行区、待命点。但它们散在机器人细节页和地图页的七八个按钮里，问题有四个：
- 要自己填包名、地图号、版本号；
- 不教怎么走；
- 建完不说这张图能不能用；
- 少做一步也不提醒，结果机器人派不出去。

## 2. 用户定的（10-31）

- 建图、地图版本管理只给管理员。
- 管理员登录 App，站点上一张图都没有，就弹窗让他开始建图。
- 建图是一个单独的页面，在这一页里做完，再回主页。
- 走一圈既可以用机器人自己的遥控器（手感好），也可以用手机遥控，让客户选。
- 选场地类型（室内、室外、玻璃多），背后换参数，客户不用填参数。

## 3. 我定的（用户可以改）

| # | 定了什么 | 为什么 |
|---|---|---|
| D1 | 工程师（临时账号）也能建图 | 交付工程师上门建图就靠它，到点自动失效 |
| D2 | 「用遥控器」排第一个、默认选中 | 用户说遥控器手感好得多 |
| D3 | 用遥控器时提醒「档位放在低速」 | 10-19 撞玻璃门那次，遥控器档位被改成中速（最高 2 m/s），我们管不到 |
| D4 | 室外、玻璃多这两项先灰掉，写「即将支持，现在请联系交付工程师」 | 这两套参数还没在真场地调过；只有室内那套是实测调好的 |
| D5 | 地图名、版本自动起：地图号 `main`，版本按日期加序号（`20261031-1`）；客户只填一个可选的显示名（比如「一楼」） | 客户不该碰地图号和版本 |
| D6 | 建完给结论，三档，按站点已有的建图记录（`build.json`）判断：<br>- **能用**：回到起点闭合了（回环 ≥ 1 次），而且最大修正 < 0.3 米；<br>- **有问题，建议重走**：没闭合，或修正 ≥ 0.3 米，或走了不到 15 米；<br>- **没建成**：建图出错。<br>「有问题」也能先用。 | 先用最朴素、能解释给人听的几条；阈值等真机多建几张再调 |
| D7 | 向导做到哪一步记在站点上，换手机、关了 App 都能接着做 | 建图要一二十分钟，中途很可能被打断 |
| D8 | 一次只建一台机器人的图；建好先下发给这台，别的机器人在地图管理里一键下发 | 第一张图通常一台就够；多台同时建不了（各自的图坐标不通） |
| D9 | 原点就标在充电桩前；标原点的同时建一个默认待命点（现有做法） | 少一步 |
| D10 | 禁行区一步可以点「这张图没有禁区」，直接确认 | 不是每块地都有水池、楼梯 |

## 4. 流程（一个全屏页面，不显示底部导航）

上面一条进度（第几步 / 共 7 步）；左上角「退出」会先问「先停下吗？做到哪一步记着，下次接着做」。

1. **准备**
   - 选机器人（只有一台就跳过）；
   - 选场地类型（D4）；
   - 起个显示名（可选，D5）；
   - 自动检查：在线、电量 ≥ 50%、站着、没在跑任务、机器人存储够；不过就写原因和怎么办。
   - 提示：「把机器人放在以后要当充电位置的地方（充电桩前）」。
2. **怎么开**：「用机器人遥控器（推荐）」或「用手机遥控」（D2）。
3. **走一圈**
   - 点「开始」，就是现有的「开始录包 + 边走边建」，地图号、版本自动填。
   - 屏幕上是建图预览（正在长的图、走过的路、机器人在哪），旁边一栏提示（第 6 节），下面是「走完了」。
   - 用遥控器时：竖屏，没有摇杆，顶上显示「遥控器在开 / 现在控制权在我们这里」（看机器人报的 `ready.control`）。
   - 用手机时：横屏，跟遥控页一样摇杆加画面，画面角上是小的建图预览。
4. **建图**
   - 「走完了」就是停止录包；边走边建的这时打包出这一版。打包不成就自动从录的包重建（现有的退路）。
   - 页面显示等候中，转圈加已经过了多久。
   - 建完显示图的预览和结论（D6），按钮：
     - 能用：「用这张」；
     - 有问题：「用这张」和「重走一遍」（回到第 3 步，旧的那一版留着）；
     - 没建成：「重走一遍」和「查看原因」（建图日志）。
5. **禁行区**：用现有的看图页，在上面画禁行区（水池、楼梯、陡坡、落差），可以「这张图没有禁区」（D10）；最后「确认禁行区」。
6. **原点**
   - 先把这一版下发给这台机器人（`without_home`），等它换好图。
   - 提示「把机器人开到充电桩前约 1.5 米、正对充电桩、站好」，然后「在这儿标原点」；
   - 机器人核定位，偏差大就不标，并说原因。
7. **完成**
   - 「可以开始巡逻了」。
   - 下一步建议：画巡逻路线（管理 → 巡逻路线）、排日程。
   - 「回主页」。开站清单里地图、禁行区、待命点三项打勾。

## 5. 入口

- **管理员、工程师登录**：站点一张图都没有，进值守页后弹窗：「这个站点还没有地图。机器人要先认识这块地方才能巡逻。现在开始建图？（大约 20–40 分钟）」，按钮是「开始建图 / 稍后」。
  - 「稍后」以后不再每次弹窗，记在账号的向导记录里（`guide.map_later`）。
  - 有没做完的向导就改问「上次建图到第 N 步，接着做？」。
- **开站清单**：「地图」一项的「去做」就是开向导。
- **地图页**右上角「地图管理」：
  - 版本列表：哪一版在用、什么时候建的、谁建的、结论；
  - 新建一张图、重建这一版、下发给哪台机器人、退回上一版。
  - 这些接口站点上都有（`/api/admin/maps…`），App 上补界面。
- **保安、经理、只看**：站点没图时，值守页上一行「站点还没有地图，请管理员先建图」，不弹窗。

## 6. 走的时候的提示（规则，不用模型）

| 什么时候 | 提示 |
|---|---|
| 刚开始 | 慢慢走，像带着人参观：每个房间、走廊都进去，门口停一下 |
| 速度 > 0.6 米 / 秒（遥测） | 慢一点：太快图会糊 |
| 原地转得太快 | 转慢一点 |
| 走了 > 20 米，离起点 > 5 米 | 最后要回到起点，图才能闭合不歪 |
| 回到起点附近（< 1 米），走了 > 15 米 | 回到起点了，可以点「走完了」 |
| 场地类型是「玻璃多」（以后） | 玻璃墙边多走一趟 |
| 遥控器模式 | 遥控器档位放在低速 |
| 录了 > 40 分钟 | 已经很久了，可以先建一版看看 |

## 7. 站点要改的

- **向导状态**：存在 `site_settings` 的 `map_wizard` 键，一个站点同时只有一个向导。
  - 内容：步骤（`prepare` `drive` `walk` `build` `zones` `origin`）、机器人、场地类型、开法、地图号、版本、显示名、谁开的、开始时刻。
  - `GET /api/map-wizard`：要 view 权限，保安能看到「有人在建图」。
  - `POST /api/map-wizard`：要 manage 权限，开始、更新步骤、结束、放弃。
- **下一个地图名**：开始时由站点算（D5），避免撞名。
- **结论**：`GET /api/admin/maps/<图>/<版本>/quality`，按 `build.json` 给出「能用 / 有问题 / 没建成」加原因列表（D6）。
- **地图总览**（现有）多带每一版的结论和显示名。
- 向导记录多一个 `map_later`。

## 8. 手机要改的

- 新的建图向导页（全屏，7 步）。复用现有的建图预览、遥控页、看图页（禁行区）、标原点。
- 登录后的弹窗、开站清单「地图」去做、地图页「地图管理」入口。
- 地图管理页：版本列表加结论、退回上一版、新建。现有的地图列表页补这几样。
- 保安等角色值守页上的「还没有地图」一行。

## 9. 不做

- 室外、玻璃多这两套建图参数：要先在真场地录包调（另开一单，要真机和现场）。
- 自动探索建图（机器人自己走）。
- 多楼层、多张图拼接。
- 网页上的建图向导：建图要在机器人旁边，用手机；网页上照旧是地图管理。

## 10. 怎么验

- **测试**：
  - 站点：向导状态、地图名、结论的三档和边界、权限。
  - 手机：向导每一步、续做、两种开法、退出确认、弹窗只弹一次、`layout_matrix` 加新页。
- **演示站点**：仿真机器人不出雷达数据，录包建不出真图。演示站点加一个假建图：停止录包时把 `--map-dir` 那张图当成新一版，带一份 `build.json`。整个向导在演示站点上能从头走到尾。
- **真机（C40221，要用户在场、批准动机器人）**：
  - 室内建一张图，两种开法各走一次；
  - 看遥控器接管时 `ready.control` 怎么报，结论准不准；
  - 走完标原点、派一趟巡逻。

## 11. 实现时改的（2026-10-31）

- **禁行区排在原点前面**：现有规矩（W10）是禁行区没确认的图下发不了，而标原点要机器人先载上这一版。所以顺序是建图 → 禁行区 → 下发 + 原点。草图上第 5、6 步对调。
- **准备那一步查的**：在线、电量 ≥ 50%、没在跑任务、急停没按、能边走边建。「站着」没有现成的状态可查；「存储够」由机器人开录时拒（`storage_full`），向导把原因说成人话。
- **版本号的日期按站点时区**（跟工程师账号名一个口径）。
- **显示名**存成这一版的备注（地图管理里原来就有备注），用户点「用这张」时写上。
- **地图管理**：管理员、工程师从地图栏右上角进；原来的地图目录（录包、拿录包重建）挪到它最下面一行。
- **手机遥控**：用现有的遥控页，右上角浮一块小的建图预览和「走完了」。
- **演示站点**：`tools/site_demo.py --w54 --map-dir <图>`。站点先没有图；仿真机器人接一个假的建图编排（`--mapping-sim`），录包、打包、上传、站点登记都是真流程，建出的图照搬 `--map-dir`，回环按仿真机器人走过的路算（走一圈回到起点 1.5 米内算闭合）。两套演示站点同时开时用 `--api-port` 和 `--intake-port` 错开。
