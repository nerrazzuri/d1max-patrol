# 装机清单

给现场的人用的单子，逐条能打勾。§7.9 说得很直白：装机是一次性的、要能重复、
要留痕——所以这份清单跟 `deploy/install.sh` 一一对应，脚本能重跑，这份单子
也能重填。出问题按最后一节的三条退路走，不要凭记忆猜。

---

## 一、装机前要准备什么

- [ ] Orin NX 能上网（`curl -sS -m 8 https://pypi.org/simple/` 有响应；
      出不了外网就提前准备好 aarch64 离线 wheel 包，见 `scripts/orin-survey.sh`
      第 5 节）。
- [ ] 一块**备份盘**（不是 U 盘）已经按镜像盘装机的方式初始化过（若这台是
      第一次装，跳过这一条）。
- [ ] 装机用的包已经在这台机器上：`/home/robot/d1max-<日期>-<短哈希>` 这样
      的目录，或者能被 `pip install` 认的路径/归档。
- [ ] 知道这台机器的**机身序列号（SN）**——现场贴在机身上的标签，不是厂商
      SDK 或导航 WebSocket 接口能报出来的字段（它们都不报这个）。
- [ ] 知道这台机器**有没有装上装**（机载上层系统）。这决定装完之后
      `PUT /api/identity/payload` 要填 `true` 还是 `false`。

## 二、装机（对应 `deploy/install.sh` 的七步）

```
sudo bash deploy/install.sh <包目录>
```

- [ ] **1/7 建目录。** 屏幕上看到 `建目录 /opt/d1max`，`/opt/d1max/releases`
      和 `/opt/d1max/bin` 建出来了，属主是 `robot`。
- [ ] **2/7 装版本无关的解释器。** 屏幕上看到
      `装一个跟版本无关的解释器到 /opt/d1max/bin`。第一次装机会新建一个
      venv，重跑不会重建（幂等）。
- [ ] **3/7 把包落进槽里。** 这一步跑的是 `d1max cli release install`，
      屏幕上看到 `落槽了: <名字> (版本 ...)`。只落槽，不切换，不影响正在
      跑的服务（如果有的话）。
- [ ] **4/7 给这一版建自己的 venv。** 屏幕上没有报错。**这是每版一个的
      venv，不是共用根解释器**——回滚要把依赖也一并退回去，这一步就是
      为那件事准备的。第一次给这一版建会花一点时间装依赖，重跑不会重建。
- [ ] **5/7 装 systemd 单元与环境文件。** 屏幕上看到
      `装 systemd 单元与环境文件`。这一步会顺带在 `/etc/d1max/env` 写一份
      模板——**只在这个文件不存在时写**，已经填过 SN 的机器重跑
      `install.sh` 不会被抹掉。
- [ ] **6/7 记上装。** 这一步脚本替不了你（§7.1 纪律 1：只有站在机器旁边
      的人看得见）。照屏幕上给的 `curl` 命令，把这台**有没有装上装**记
      一次。**没记过之前这台机器不许升级**——升级流程不知道该怎么重启它。
- [ ] **在切到这一版之前，先编辑 `/etc/d1max/env`，把 `D1MAX_SN=` 那一行
      填上现场的机身标签。** 这一步不填的后果：命令行 `release activate`
      记进 `pending.json` 的 SN 和重启后 HTTP 服务侧解析出来的 SN 会不
      一致（HTTP 侧会拿兜底的 MAC 值去比），重启后自检第四项
      （`identity`）会假失败，把这一版**好版本判成失败并自动回滚**。
- [ ] **7/7 切到刚装的这一版并起服务。** 屏幕上看到
      `切到 <名字>,上一版 无。重启之后会自检,没过会自己退回去。`，随后
      `systemctl restart d1max-patrol.service` 没有报错。

## 三、装完的验收（三条都要过）

- [ ] `curl http://127.0.0.1:10010/api/release` 返回里 `current`（当前版本）
      有值，不是空。
- [ ] `curl http://127.0.0.1:10010/api/selfcheck` 里四项
      （`process`、`control`、`bridges`、`identity`）全绿
      （`verdict` 不是 `rollback`）。**`identity` 这一项就是靠上一节填好的
      `D1MAX_SN` 才能过。**
- [ ] `curl http://127.0.0.1:10010/api/identity` 里 `payload_recorded` 是
      `true`（第 6 步记过上装了）。

## 四、出错时的三条退路

- [ ] **`sudo /opt/d1max/bin/python -m d1max_patrol.cli release list`**——
      看局面：现在装着哪几版、现在跑的是哪版、有没有在途的升级还没坐实。
- [ ] **`sudo /opt/d1max/bin/python -m d1max_patrol.cli release rollback`**——
      退回上一版。重启生效：`sudo systemctl restart d1max-patrol.service`。
- [ ] **`journalctl -u d1max-patrol -n 100`**——看最近 100 行日志，先看
      服务是不是在无限重启刷屏（`Restart=always` 但 `RestartSec=5`，正常
      情况不该几秒钟就刷一大片）。

## 五、装机之后要留的痕迹

- [ ] 装机的日期、执行人、这台机器的 SN、有没有上装，记进现场的登记表
      （或者机身贴纸旁边）。
- [ ] `docs/真机待验证清单.md` 里跟装机相关的几条，装完之后回来勾掉
      「待测」改成实测结果。
