# W11a 头尾方向闸 · 设计与完工报告

> 用户 2026-10-01：「狗子其实两边都可以是头，所以不能只用一边的雷达」「开始吧，目前暂时没有狗，只能在开发机上做模拟测试」。
> 先堵住（这一单），再做前后雷达合并、两头都能当头（W09i）。小单：设计与报告合一份。分支 `w11a-head` → PR。

## 问题

SDK（0.1.1、0.2.0 都有）能调转头尾（`ReverseHeadTail()`），状态里报 `head_direction`（0 未知、1 狗头为前、2 狗尾为前）。我们整套都没读它：
旁路进程不转、HAL 不报，定位（前雷达）、规划、跟踪、W11 的避障守卫和旁路进程的净空许可**全都按「前雷达那头是前」算**。有人用遥控器 / 厂家 App
调过头尾之后：定位器报的朝向跟「往前走」反着、守卫查的是身后、许可是身后的净空 —— 自己走就是闭着眼睛倒着走。

## 做了什么（按推荐）

| 层 | 改动 | 文件 |
|---|---|---|
| 旁路进程（C++） | `state` 帧带 `head`（SDK 的 `head_direction`）；协议 4 → 5；安全门 `OnHead`：开了 `--require-clearance` 时不是「狗头为前」就不放行前进（许可按前雷达那头算） | `motion/patrol_agent.cpp`、`motion/vel_gate.hpp`、`motion/test_vel_gate.cpp` |
| Python 协议、仿真旁路进程 | `StateFrame.head`（老旁路进程不报 = `unknown`）；仿真照着做 | `src/d1max_patrol/protocol/agent_frames.py`、`src/d1max_sim/agent_server.py` |
| HAL | `Health.head`：`head` / `tail` / `unknown`（默认 `unknown`）；d1max 适配器从状态帧取；`SimRobot` 默认 `head`、`inject_head()` | `packages/contract/.../hal.py`、`adapter-d1max`、`adapter-sim` |
| 导航桥 | 每拍记下头尾；执行中不是「狗头为前」→ 自己停（FAILED），直线桥、规划后端都一样 | `bridges/hal_nav.py` |
| 运行时 | 起来先读一次；不是「狗头为前」→ 不收 goto / 巡检（`head_not_forward`）、跑着的当场中止并停车；变了发事件 `head_changed`、重发能力；能力 `tasks.head.direction`；遥控照常 | `runtime.py` |
| 站点、手机 | 能力里 `head.direction` 不是 `head` → 不派 goto、巡检（排程、事件派遣、回待命点都经过它），遥控照常；单狗页一行「头尾：狗尾为前（前后雷达合并之前不能自己走，遥控照常）」 | `dispatcher.py`；`site_client.dart`、`site_page.dart` |

**「不知道」一律当不是狗头为前**（安全方向）：4 号及更老的旁路进程不报头尾，代理能连、能遥控，但不自己走 —— **真狗上要重编 `motion/patrol_agent` 才能自主走**。

## 测试

- 状态帧解码（0 / 1 / 2、没有、坏值）；d1max 适配器从仿真旁路进程读头尾；仿真旁路进程与 C++ 安全门（开了许可门、调过头尾不放前进；没开门不管）；
  导航桥执行中调头尾自己停；运行时（起来就是狗尾为前不收 goto、能力里报；跑着调过来当场中止、狗停、发事件、调回来又能派）；站点门槛；手机文案。
- 全量 Python 0 失败（`w11a-head` 分支），手机全量 219 条全过（夹具重生成：能力里多了 `head`）。
- 突变 7 条：杀 6 条；活的 1 条是「运行时当场中止」（单个 goto 时导航桥自己也停，测不出来），补了「任务是按 `head_not_forward` 中止的」断言后杀掉 —— 多个点的巡检光靠导航桥停会一个点一个点失败下去。

## 已知限制

- 「调过头尾」只是不许自己走：要两头都能当头，等 W09i（前后雷达合并、机身系与运动系分开、守卫与许可按运动方向）。
- 真狗没验：`head_direction` 在调头时怎么变、里程（`OnMcData`）的正方向跟不跟着翻，都是真机项（W09i 一起）。
