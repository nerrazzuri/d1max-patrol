# W20 角色与模式 · 设计与完工报告

> 工单：「业主/保安账号；布防/在家/访客；操作人实名（挂账 65/73）」。分支 `w20-roles-modes` → PR。设计与报告合一份。

## 用户决定（2026-10-07，决策 35）

用户「W20 按你的意见开始吧」，七条推荐全采纳：

1. **模式只管入侵**：入侵来了派不派狗、响不响铃。排程巡检、狗自己的健康告警在任何模式下都照常。
2. **全站一个当前模式**，加一张「每个防区在家时布不布防」的表；不做每个防区单独一套模式。
3. **谁能切**：业主、管理员随便切；保安只能切到布防，不能撤防（撤防是业主的决定）。
4. **访客必须有结束时间**：默认 4 小时，到点自动回到开访客之前的模式，留审计。
5. **撤防的防区来了入侵**：照样记一条，标「撤防中」，不派狗、不响铃。
6. **实名**：一人一个账号，账号名就是操作人，另加「显示名」；挂账 65/73 作废（已被站点账号取代）。
7. **业主加两样权限**：切模式、确认告警。派单、遥控仍然不给。

## 现状（做之前）

- 角色：W00c3 就有 admin、guard、owner 三个固定角色，权限表在 `permissions.py`。业主只能看、叫停。
- 模式：没有。所有防区的入侵一律派狗、一律响铃（决策 29）。
- 实名：挂账 65/73 说的是老的狗上服务，那里的操作人是自己填的名字、从不核实。W00c5e 已经把老服务删了。
  现在站点上的命令、租约、审计都绑在登录账号上，所以只差「一人一个账号」这条规矩，加一个给人看的名字。

## 怎么做的

### 三种模式

| 模式 | 哪些防区布防 | 谁能切到这个模式 |
|---|---|---|
| `armed` 布防 | 全部 | 保安、业主、管理员（`arm`） |
| `home` 在家 | 除了标了「在家时撤防」的 | 业主、管理员（`set_mode`） |
| `visitor` 访客 | 在「在家」的基础上，再撤这次挑的几个防区 | 业主、管理员（`set_mode`） |

几处要紧的判断：
- **没配过的防区一律布防**。新接的摄像头报了一个没人见过的防区名，宁可多响一次。新站点默认布防。
- 访客必须有结束时间：1 分钟到 24 小时，不填就是 4 小时。到点退回开访客之前的那个模式。
  访客期间再开一次访客（延长、改防区），退回的还是第一次开访客之前的模式，不会退回到「访客」。
- **过了点就按已经退回算**：告警循环每 5 秒才收回一次访客。判断防区的时候不等这一拍，过了结束时间就按退回后的模式判。
- 撤防的入侵记成 `disarmed`，备注写「在家模式：这个防区撤防，只记录」。它不在报告警的那几种去向里，补报时也不会被补上。
- 撤防判断放在「类型认不认」之后、「防区有没有绑拦截点」之前。所以没绑拦截点的防区也能撤防：撤防就只记录，不会再报「没映射」的告警。

### 顺手修的偶发（W31）

`test_site_teleop.py` 的「遥控中钟差变成不知道……」偶发失败。台式机上第一次跑全量就挂了，单跑 5 次挂 1 次。

原因是测试读得太早：站点收掉一趟遥控时，先把它从内存里摘掉，**最后才在库里记结束原因**（`TeleopDesk.close`）。测试一看到内存里没了，马上读库，有时读到的还是空。

改法：等库里记上再断言。产品代码没改。

## 外审第一轮（2026-10-07）：FIX-THEN-APPROVE，2 条阻断、1 条小问题，已修

**阻断 1：撤防之后，首单派失败时仍可能派狗。**
- 原来只在新事件入账时看模式。首单派失败后，会把并进它的第一条「提升」成新的出动，再选一次狗（`_promote_follower`），这条路不看模式。
- 外审的复现：布防时首单在等回执，第二条并了进来 → 业主撤防 → 首单失败 → 第二条变成 `dispatching`，又派了一次狗。

修法：
- 提升也算一次新的出动，要再看一次模式。
- 判断和改账在**同一个事务**里做完。
- 防区已经撤防，就把并进首单的**全部**改记成 `disarmed`（备注写「首条没派成时已是在家模式」），一条都不派，也不占着狗。只有同一个防区才会合并，所以这些都是一起撤的。
- 防区还布防就照旧提升。

**阻断 2：访客挑的防区一多，审计就读不出来。**
- 审计把详情序列化成 JSON 后硬截到 2000 个字符，截完就不是合法 JSON 了。
- 25 个合法的长防区名，切模式本身成功，之后 `AuditLog.list()` 抛 `JSONDecodeError`，审计接口跟着挂掉。

修法：
- 落库前保证是一份完整的 JSON（`encode_detail`）：
  - 放得下就原样存；
  - 放不下先缩：长列表留前 10 项加一句「…共 N 项」，长字符串截到 200 个字符；
  - 还放不下就只留键名，并写上 `truncated`。
- 读的时候扛得住修之前写坏的老行（`decode_detail`）：给 `unreadable` 和原文的前一截，不让整张审计读不出来。
- 访客到点自动退回那条审计走的是同一个 `record`，一起覆盖。
- 访客一次最多撤 64 个防区。

**小问题 3：模式页不随别的手机的操作、访客到期更新。**

修法：
- 模式页订阅站点推送：收到 `mode` 帧就当场换，布防按钮的可按状态跟着变。
- 断线 5 秒后重连并重新拉一次，补上断线期间错过的切换。
- 另外每 30 秒再问一次兜底。

补的测试：
- 站点：
  - 合并之后撤防、首单派失败：并进来的两条都记 `disarmed`，只派过一次，狗不被占着；
  - 访客撤的是别的防区：照样提升、照样派，剩下的那条改并到提升出来的那条；
  - 25 个长防区名的访客，加上它到点退回：审计照样读得出来，每行都是不超过 2000 字符的合法 JSON；
  - 经 HTTP 开这样的访客后，`GET /api/audit` 照样 200；
  - 详情三档（原样、缩、只留键名）；老的坏行读得出来；最多 64 个防区。
- 手机：别的手机撤防，推一帧当场换、布防按钮能按了；断线重连后重新拉一次。
- 先把修复撤掉跑一遍（相当于突变测试）：
  - 撤掉提升时看模式：撤防那条红；
  - 撤掉审计编码：审计 3 条红；
  - 模式页不订阅推送：2 条红；
  - 重连后不重新拉：1 条红。

## 已知限制、要你做的

- **防区名要跟摄像头、NVR 报的一模一样**：模式页列出的防区来自三处——绑过拦截点的、摄像头登记的、配过在家撤防的。客户的院内、外围怎么划，到现场跟业主一起在模式页里点。
- 没有「全部撤防」：用户给的只有布防、在家、访客三种。真要全撤，可以把所有防区标成「在家时撤防」再切到在家。
- 不按时间表自动切（比如每天 23:00 自动布防）。要的话再加，可以走排程那一套。
- 切模式只进审计，不发告警。手机首页那一行实时更新。要是想「业主撤防时通知保安」，再加一种 P3 提示。
- 显示名目前只在登录回包、账号列表里出现。审计、告警上记的仍是账号名（账号名就是操作人，按账号能查到显示名）。
- 账号管理（建账号、改显示名）手机上还没有界面：用站点命令行，或者管理员调接口。
