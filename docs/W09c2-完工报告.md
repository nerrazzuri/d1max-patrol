## 问题

W09c1 之后建图是「录包 → 停 → 站点下 `map_build` → 狗在录包上从头跑 MOLA（4 分半的包要 160 s）→ 打包」。决策 17 要边走边建：走的时候就在建，
停下来尽快有图（目标 ≤ 5 min）。

## 原型（开发机，newdog2 录包在隔离域里放、当实时雷达）

| 做法 | 结果 |
|---|---|
| `ros2 launch` 起 MOLA，停时对进程组 SIGTERM | launch 先退、底下的 `mola-cli` 成了孤儿，**一个文件都没存** |
| 直接起 `mola-cli`，订雷达 best_effort | 存盘 3.5 s，三样都在；但只收到 82% 的帧（本机 DDS 传大点云丢的），图左半边出重影 |
| 直接起 `mola-cli`，订雷达 reliable | **99.5%** 的帧，图跟离线建的一样干净；打包 77 s，走过的 248 个点 0 个被拒 |

厂商前雷达发的就是 reliable（录包 metadata：reliability 1、depth 100）。

## 真实链路（开发机，2026-09-27）

进程管理器 → 建图编排 → `d1max-ros` → `mola-cli` 在线建图 + `ros2 bag record`，newdog2（4 分 35 秒）在隔离域里放、当实时雷达；停下后
`MappingService.finish()` 打包、放进本地库。

| 轮次 | 停录 | 停下到出图 | 建法 | 说明 |

目标 ≤ 5 min（开发机）达到；Orin 真机量（3d.21）。

## 顺带发现并修的

**录包在真狗上多半起不来**：代理的服务（`d1max-agent.service`）里没有 source ROS，建图编排原来直接起 `ros2 bag record`，`ros2` 不在 PATH 上、
`rmw_zenoh_cpp` 也找不到。这条从 W00c5d 起就在，没上过真机。现在录包、在线建图都经 `deploy/d1max-ros`。真机项 3d.20。

## 已知限制

- 在线建图的质量取决于帧收全没有：开发机上 best_effort 丢 18% 就出重影。真狗经 zenoh 收、Orin 算得过来算不过来，都要真机量（3d.22、3d.23）；
  目前没有「丢帧太多就自动退回从录包建」的判据 —— 要真机数据定线。
- 开录前的「盘满」只看发件箱，没算在线建图的中间目录（几百 MB）。
- 站点「这个版本没人在建」先查再发命令，两个并发请求可能都过（`map_build` 原来就这样）。
- 开发机的测试有一处跟真盘挂钩：起飞前检查读真盘的用量，盘过 90% 时一批引擎测试失败（这次踩到，腾了盘就好）。跟本张无关，没改。
- 定位器（W09b 的只定位 MOLA）跟在线建图同时跑时 Orin 的 CPU —— 真机量。
- 在线建图时手机上实时看图是 W09f。
