# W14 任务抢占与待命点 · 设计与完工报告

> 工单原文：「高优先级任务打断巡逻（今天是 `EngineBusy`）；多待命点；随机路线、夜间加密」。按推荐做，小单：设计与报告合一份。分支 `w14-preempt` → PR。没有狗：开发机上做、测。

## 摸底（2026-10-02）：工单那句话大半过时了

- **抢占早就有了**（W00c2b，2026-09-25）：
  - 站点按来源定优先级：回待命点 −10、排程 10–49、手动 60、事件 80、遥控 100；
  - 代理只比数：严格更高的才抢；
  - 被抢的那一趟先停稳、进 `preempted`，抢它的那一趟才起跑。
  - `EngineBusy` 现在只是兜底。
- **多待命点也早有了**（W00c2b + W13a）：每台狗多个命名待命点、一个默认；任务正常做完回默认的。
- **真正缺的**：
  1. **被抢的巡检**：就那么没了。排程那一轮记 `result=preempted`，**连告警都没有**（W00c6c 报告里写着）。
  2. **回哪个待命点**：永远回默认的，没有按排程选的办法。
  3. **随机路线**：任务的巡检点是固定顺序，没有打乱的办法。
  4. **夜间加密**：一条排程一天只有一轮（只有 `at`）；要夜里每小时一趟，得手写一堆条目。

**用户决定（2026-10-02）**：被抢的巡检**维持现状，不续，只告警**（W00c2b 决定 D2A 不变；推荐的是「窗口内续跑没到的点」，用户没选）。另外三样按推荐做。

## 做了什么

| 块 | 内容 | 文件 |
|---|---|---|
| 被打断要告警 | 排程派的那一趟收到 `task_preempted`，当场说一次：新告警 `schedule_interrupted`（P2），「跑到一半被更优先的任务打断了，这一轮没巡完、不续」。一轮只说一次，不续跑 | `scheduler.py`、`alert_sources.py`、`alerts.py` |
| 回哪个待命点 | 排程条目可以写 `standby: <名字>`：这条排程的巡检正常跑完之后回那一个。直线的狗沿来路回到那一个，会规划的狗直接 `goto`。这台狗没有那个点（删了、写错）就回默认的、记日志：停在最后一个巡检点过夜，比回默认的那一个糟。手动派的、事件派的照旧回默认的 | `schedule.py`、`standby.py` |
| 随机路线 | 任务策略加 `order: fixed`（默认）/ `shuffle`。**站点在派之前打乱**，狗收到的永远是固定顺序（`order` 不发给狗，老代理不受影响），每一趟打乱一次。**走直线的狗不打乱**：打乱之后点与点之间的直线没人走过，可能穿墙；照原来的顺序跑。会规划的狗（`goto.path == planned`）才打乱 | `mission.py`、`dispatcher.py` |
| 夜间加密 | 排程条目可以写 `every_min: N` + `until: "HH:MM"`：从 `at` 起每 N 分钟一轮，到 `until` 为止（含）。`until` 早于 `at` 就是跨过午夜到第二天，`days` 看的是第一轮那一天（星期五 22:00–02:00，星期六凌晨那几轮算星期五的）。每一轮各算各的窗口、各记各的账、各报各的告警，排程执行器不用改。约束：`every_min` 10–720；`window_min` 要**小于** `every_min`（不然上一轮还在窗口里下一轮就到了，迟了那一轮的告警会被盖掉）；`until` 不能等于 `at` | `schedule.py`（`offsets_min`、`decide`、`next_run`） |
| 手机 | 排程页说清楚每一条什么时候跑：「22:00–02:00 每 60 分钟」「巡完回 gate」 | `site_client.dart`（`scheduleWhen`）、`site_page.dart` |

例：

```yaml
entries:
  - id: night
    mission: perimeter
    at: "22:00"
    every_min: 60
    until: "05:00"
    days: [mon, tue, wed, thu, fri, sat, sun]
    window_min: 20
    on_missed: alarm
    standby: gate
missions/perimeter.json 的 policy: {"order": "shuffle"}
```

**不做**：
- 被打断的续跑（用户定的）；
- 「回最近的待命点」（W00c2b 决定 3B 否掉了）；
- 排程抢正在跑的活：排程照旧只抢回待命点，狗在忙就等、窗口过了按 `on_missed` 告警；
- 手机上编辑排程：排程照旧从任务包导入。

## 测试

- **契约**：
  - 重复：22:00–02:00 跨午夜的各轮；星期六凌晨的几轮算星期五的；迟了那一轮报 `alarm`；下一轮包括昨天起头、跨过午夜的那几轮；不跨午夜的重复；
  - 不写重复照旧一天一轮、线格式不变；
  - 8 种写错当场报：间隔太小、太大、真假值、没写 `until`、`until` 不合规、`until` 等于 `at`、窗口不小于间隔、`standby` 不是字符串；
  - 只写 `until` 不写 `every_min` 也报；
  - 任务的 `order`：默认 `fixed`、`shuffle`、不认识的报、默认值不进线格式。
- **站点**：
  - 排程巡检被手动派单打断：报一次 `preempted`、不续，下一拍也不再派；
  - 去向到告警的对照表加了 `preempted → schedule_interrupted P2`；
  - 排程写了待命点：直线、会规划的狗都回那一个；写的点这台狗没有就回默认的；手动派的照旧回默认的；
  - 随机路线：会规划的狗每一趟顺序不同、点一个不少、狗收到的没有 `order`；走直线的狗不打乱。
- **手机**：`scheduleWhen` 三种写法。全量 230 条全过。
- **突变 10 条全杀**：跨午夜判据、`until` 回绕、窗口必须小于间隔、下一轮看昨天、只给会规划的狗打乱、真的打乱、不把 `order` 发给狗、打断要告警、按排程选待命点、没有那个点回默认的。
- 全量 Python 0 失败（`w14-preempt` 分支）。

## 已知限制

- 被打断的那一轮不续，靠人看告警决定要不要手动补一趟。
- 打乱是整趟一个顺序，`loops > 1` 的每一圈都按这一个顺序走。
- 重复按墙上时间加：夏令时那一夜可能少一轮或差一小时（马来西亚没有夏令时）。
