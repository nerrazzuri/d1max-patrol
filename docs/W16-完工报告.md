# W16 事件派遣入口 · 设计与完工报告

> 工单：「外部事件 → 选狗 → 去拦截点」。按推荐做，小单：设计与报告合一份。分支 `w16-incidents` → PR。

## 摸底（2026-10-03）：主体在 W00c2c 做完了，缺的是「人知道」

W00c2c（2026-09-25，三轮外审通过）已经做了：
- 签名的 HTTP 回调入口 `POST /api/incidents`（HMAC、时间戳、去重）；
- 拦截点与防区；
- 选离拦截点最近的狗；
- 事件优先级 80，抢占巡检；
- 同一防区 60 s 内合并；
- 账（`incidents` 表）和推送流。

还缺的：

1. **入侵没接进告警**。一条入侵派出去了、没狗可派、防区没映射、派失败，都只在事件页里记一笔：**不响铃，值守的人不知道**。眼下真狗都是「要人监护」，事件派不出去，也就是说每一条入侵都会无声落空。
2. **事件源管理**：密钥不能轮换、不能删，没有限流（W00c2c 取舍 6）。
3. **拦截点、防区只能用命令行、接口配**，手机上没有。

## 做了什么

| 块 | 内容 | 文件 |
|---|---|---|
| 入侵 → 告警 | 一条入侵有了去向就报一次（每条只报一次，结果回写不再报）。<br>- 派出去了、并进已出动的：**P1「防区 X 有入侵：A 已出动去 gate」**，记在那只狗名下；<br>- 没狗、没映射、派失败：**P1「防区 X 有入侵，没狗去：原因」**，记在站点名下；<br>- 同一只狗（或站点）同一种合成一条，标题列上合进来的每个防区；<br>- 重复的、不认的类型不报；<br>- 告警报不出去不带走派遣 | `incidents.py`（`on_outcome`）、`alert_sources.py`（`on_incident`）、`alerts.py`、`main.py` |
| 事件源 | `d1max-site source-rotate NAME`：换密钥，旧的当场作废，新的只显示一次；`source-rm NAME`：删，回调从此验签不过，已入账的事件留着；`source-list`：列出，不带密钥 | `incidents.py`、`main.py` |
| 限流 | 每个事件源每分钟最多 30 条，超了回 **429**；这一分钟里第一下超时报一次 **P2「事件源 X 一分钟内报得太多」**，提示是误报成串还是密钥漏了。限流在验签之后，没登记的源照旧一律 401 | `incidents.py`（`allow`）、`api.py` |
| 拦截点与防区（站点） | `GET /api/intercepts` 列出拦截点与防区（谁都能看）；`POST /api/intercepts {remove}` 删拦截点（**还有防区指着它就不删**：不然那几个防区的入侵会悄悄变成「没映射」）；`POST /api/zones {remove}` 让防区不再派狗（之后的入侵照样报告警）。<br>`POST /api/robots/<id>/intercept/here`：在狗现在的位置设拦截点。位置同 W13a 的「在这儿设待命点」：狗用此刻锚定后的位姿、定位不好就拒，狗上什么都不改；老代理不发。这两个入口的取位置抽成了一个函数 | `api.py`（`_here_pose`、`_intercept_here`） |
| 手机 | 事件页右上「拦截点…」：防区 → 拦截点、拦截点列表。管理员可以：<br>- 「在狗这儿设拦截点」：只有一只能报位置的狗就直接用它；<br>- 「绑防区」；<br>- 取消防区、删拦截点：都先确认。<br>别的角色只看。事件页的去向说人话（「已出动」「没有能派的狗」……） | `site_intercepts.dart`、`site_page.dart`、`site_client.dart` |

另外修了守门测试 `test_site_no_motion.py` 的一个误报：告警代码里的 `kind, robot = "intrusion", …` 被当成了命令种类。现在元组赋值只认 `kind, payload = …` 这种发命令的写法。

**不做**：
- 告警带截图、位姿、地图：W17；
- 拦截点可达性校验：W23；
- 除 `intrusion` 以外的事件类型：等 W19 的 CCTV 接进来再看有哪些；
- 事件源在手机上管理：密钥只该在站点主机上看到。

- 全量 Python：第一遍挂了 1 条 `test_同名待命点在别的图上_409_明说替换才搬`（单独跑 3 次挂 1 次），查出来是 **W13a 留下的一个真竞态**（见下）；修了之后站点测试全过。

### 顺手修的：W13a 标原点的竞态

「在这儿标原点」时，回执（接口线程）和晚到的 `home_marked` 事件（事件循环）会同时调 `StandbyManager.mark`：
- 两边都看见「这张图上还没有待命点」，都去建默认的；
- 后建的那次看见前一次已经设了默认，把同一个点又写成「不是默认」；
- 结果这张图上没有默认待命点，任务做完不回待命点。

修法：「看有没有 → 建」这一段用一把锁做完。加了一条能确定复现的测试：在第一次看完之后让另一个线程把整个 `mark` 跑完。去掉锁 3 次都红，有锁过。

## 外审第一轮（2026-10-03）：FIX-THEN-APPROVE，2 条阻断，已修

**阻断 1：限流挡不住并发请求。** 站点接口是多线程的，`allow()` 对每个事件源最近一分钟的记录是不加锁的「读出、算、写回」。外审用 40 个线程同时调，40 个全放行，存下来的只有 1 笔。

修法：
- 加一把专用锁，「清掉一分钟前的、判断、记一笔」在锁里一次做完；
- 写日志、报限流告警放在锁外，不在锁里碰数据库。

补了测试：40 个线程同时进来，严格只放 30 个、限流告警只报一次。测试里让「读出」和「写回」之间让出 CPU，把并发逼出来；去掉锁，这条测试就红。

**阻断 2：告警报不出去，这条入侵就再也没有告警。** 原来是先记「说过了」再报，告警库一时写不进就永远丢了：
- `no_robot`、`unmapped` 这些结果本来就只推一次，没有第二次机会；
- 站点重启也不补。

这正是 W16 要解决的「入侵无声落空」。

修法，照排程的做法（报成了才记）：
- `incidents` 表加 `told_ms`，库结构升到 17。**告警报成了才写**；报不出去的留着 NULL；
- 站点的告警循环每拍（几秒一次）调 `retell()`，补报最近 24 小时里没报成的。站点重启前没来得及报的也靠它补；
- 同一条事件，接口线程和事件循环可能同时去报：用「正在报」的占位挡住，同一条只报一次。报告警本身不在锁里做；
- 老库升级：历史上的入侵当作已经报过（`told_ms = 0`），免得一升级就把以前的入侵全报一遍。新记的行写 NULL。

补的测试：
- 第一次报告警时抛异常：派遣照常，账里没记说过；下一拍补报出一条；再补是 0 条；狗到了、结果回写也不再报；
- 站点重启：重启前没报成的两条，新的站点补报成一条合并的「没狗去」；一天以前的不补；
- 老库升级：历史行 `told_ms = 0`；
- 告警循环每拍都补报，补报炸了不带走告警那一拍。

突变 8 条全杀：
- 限流去掉锁；
- 报之前就记说过（原来的写法）；
- 不补报；
- 补报不限 24 小时；
- 报成了不记；
- 新行写 0；
- 老库升级写 NULL；
- 告警循环不调补报。

全量 Python 挂了 2 条，都处理了：
- 手机夹具：事件的报文多了 `told_ms`，重新生成了 `site_incidents.json`。别的夹具只是时间戳、随机号变了，没提交；
- `test_halt先收遥控再发_回执超时也已经收了`：单独跑 3 次都过，是测试自己的竞态。零速帧在收尾线程里发，halt 超时后放租在另一条线程里发，谁先谁后不定；测试只等了放租就去看最后一帧。产品行为没问题，两样都会发，哪一样都能让狗停。改成两样都等到。

已知：要是告警报成了、但记 `told_ms` 那一下没写进去，下一拍会再报一次。告警台会把同一只狗同一种告警合并，结果是那条告警的次数加 1，不会多出一条告警。

## 已知限制

- 「入侵、已出动」也是 P1：狗去了，人也得跟上（第一版狗只是去拦截点，不处置）。
- 限流按每个事件源每分钟 30 条，记在内存里：站点重启就清零。
- 真狗眼下都是「要人监护」，事件派不出去，入侵全部落成「没狗去」的 P1；W11 避障真机验收、用户同意改成 `autonomous` 之后才会真出动。
