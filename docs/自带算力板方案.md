# 自带算力板方案（商业化 A5，决策 50）

> 决策 50（2026-10-08）：产品带自己的上装算力板（首选 Jetson Orin NX 16GB），厂商 Orin 只当传感器和运动的网关。先别买：先量板子功耗，先拿别的机器（笔记本顶上）经以太网收狗的雷达，看链路够不够。
>
> 依据：
> - 我们 4 个服务起着时，厂商 Orin 的 CPU 到 69%，还用上了交换区。
> - 厂商自己的 SLAM 跟我们的 MOLA 重复，各算一遍。
> - 竞品的上装就是一台单独的电脑（C40221 上的 192.168.168.19），经狗内网收狗的数据。

## 一、谁跑在哪

| | 厂商 Orin（网关） | 我们的板子 |
|---|---|---|
| 雷达、相机驱动，厂商的 zenoh 路由 | ✔（不动） | |
| 厂商的运动控制（192.168.168.168:8082/UDP） | 在运动控制器上，不在 Orin 上 | |
| **旁路进程** `motion/patrol_agent` | | ✔：它直接用 UDP 连运动控制器，接进狗内网就行 |
| **代理** `d1max-agent` | | ✔ |
| 定位器、感知节点、人员检测、雷达合并 | | ✔：几个进程之间走本机套接字，跟代理在一块板上 |
| **zenoh 路由** `d1max-zenohd`（新） | | ✔：往外连网关的 7447，只在本机听 |
| 对时 | 厂商的 chrony，加一个片段向站点对时（决策 61；厂商那份主配置不改） | 向站点对时（W09d，跟以前一样） |
| RTK 串口（`/dev/ttyTHS3`） | 在网关上 | 要经网络转过来（见「四」） |

**一句话：除了雷达、相机话题要从网关经以太网拉过来，别的都跟装在厂商 Orin 上一样。**

## 二、软件这边做好了的（A5 这一单）

1. **`d1max-zenohd` 单元**：
   - 在 `/etc/d1max/env` 里填了 `D1MAX_GATEWAY=<厂商 Orin 的地址>` 才起（没填就是装在厂商 Orin 上，厂商自己有路由，什么都不起）。
   - 往外只连网关的 zenoh 路由（缺省 7447，`D1MAX_GATEWAY_ZENOH_PORT` 可改），本机的定位器、感知节点照常连本机 7447。
   - **只在 127.0.0.1 听**：狗内网别的机器连不进我们的板子。
   - 装机只装、不 enable（跟定位器那几个单元一样）；排查用 `deploy/d1max-zenohd-start --print` 打出配置。
2. **出厂自检**加一条「网关」：填了 `D1MAX_GATEWAY` 的板子，连不上网关的 zenoh 端口 → FAIL；没填（装在厂商 Orin 上）就不查。
3. **两个量的工具**（板子没到也能先拿笔记本、厂商 Orin 量）：
   - `tools/a5_link_bench.py`：在另一台机器上收狗的雷达话题，量帧率、带宽、延迟、断档、抖动。时间戳跟本机不是一个钟时（两只狗上都是），按抖动判。
   - `tools/a5_power.py`：读 `tegrastats` 的日志，出整板功耗平均 / p95 / 峰值、CPU、内存、交换区、GPU。AGX Orin 没有整板那一路，就把分路加起来，并注明偏小。

## 三、板子到之前要量的（笔记本顶上，真机清单 §3s）

1. **链路**：
   - 笔记本插进狗内网的交换口（**有线**，不是热点）；
   - `deploy/d1max-zenohd-start --print` 那份配置起 `rmw_zenohd`（或者用 `config/zenoh_router.json5`）；
   - `python tools/a5_link_bench.py --seconds 120 /front_lidar /rear_lidar`。
   - 要看：帧率不掉（≥ 标称的 95%）、抖动 p95 < 50 ms（占位）、两台雷达合计多少 Mbit/s（狗内网是百兆还是千兆口要先问清）。
2. **厂商 Orin 现在的负担**：`sudo tegrastats --interval 1000 --logfile …`。
   - 我们的服务全停量 5 分钟；
   - 全起着巡逻量 30 分钟；
   - `python tools/a5_power.py … --json runs/a5/vendor-orin.json`。
   - 两份一减，就是我们的服务要多少算力、多少电。
3. **狗能给上装供多少电**：问厂商上装供电口的电压、电流上限；Orin NX 16GB 的模组是 10 / 15 / 25 W 三档，载板另算。

## 四、板子到了以后的事（不在这一单）

- **买**：Orin NX 16GB + 载板（要两个千兆口：一个接狗内网，一个留给上装的相机或调试）、宽压电源、散热、防水外壳。按「三」量出来的功耗和链路定型号。
- **装**：
  - 我们的板子上跑 `deploy/install.sh`（跟厂商 Orin 上一样），`env` 里填 `D1MAX_GATEWAY`；
  - `systemctl enable --now d1max-zenohd`，再起定位器那几个；
  - 厂商 Orin 上**把我们的服务全停、全关**（`deploy/uninstall.sh`），一只狗只能有一个代理、一个旁路进程。
- **RTK**：接收机串口在厂商 Orin 上。两个办法：
  - 把 RTK 接收机的串口直接接到我们的板子上（首选，少一跳）；
  - 在网关上跑一个串口转 TCP（`ser2net`）。
  - 等 RTK 那一单定。
- **对时**：我们的板子向站点对时。雷达时间戳是网关那边的钟，跟我们的钟本来就对不上（两只狗上都是）；定位器用的是收到的时刻还是时间戳，要在真机上复核。
- **ONNX、视频**：人员检测在我们的板子上，可以用 GPU（Orin NX 有），不用再挤厂商 Orin 的 CPU。

## 五、不改的

- 狗上的服务怎么配、站点怎么管、升级怎么走，**都不变**。站点只认这只狗的证书，不管它装在哪块板子上。
- 厂商 Orin 上原来那套装法照样能用：`D1MAX_GATEWAY` 不填就是老样子。

## 六、2026-10-27 起：板子是 RK3588，人员检测留在厂家 Orin（跨板人员桥）

- **板子换了**：用户 2026-10-27 定买 RK3588（上装 V2 是 ROC-RK3588-RT），替掉上面的 Orin NX 首选；我们的服务全在它上面，上装的线也接到它上面。
- **人员检测例外**（决策 74）：留在厂家 Orin，用它的 GPU（CUDA / onnxruntime-gpu），不移植到 RK3588 的 NPU。它跟代理不在一块板上，人员桥改走狗内网 TCP：
  - **认密钥，双向**：代理在 `D1MAX_PERSONS_LISTEN` 上听。检测节点连上来，先收代理现给的随机数，`hello` 里带 HMAC-SHA256 签名和给代理出的题；代理回的 `hello` 也要带签名，检测节点核对上才算连上（外审 P212-I1：原来谁冒充代理发个挑战就能收截图）。之后两个方向每一行都带签名和递增序号，改过的、重放的、没签名的都不认。签名对不上就断开。还可以用 `D1MAX_PERSONS_PEER` 限定只认厂家 Orin 的 IP。
  - **不加密**（用户 2026-10-30 定，MVP）：截图在机器人内部网线上是明文，只有能接进机器人身体里那段网线的人看得到。记账的残留。
  - 人员桥协议升到 2：两块板要一起升级（老的握手会被拒，代理报「没给代理出题」）。
  - **截图走桥**：两块板不共用盘。检测节点先发截图（≤ 512 KB JPEG）、再发引用它的那一帧；代理写进截图目录，后面跟本机一样（存成归档、传站点）。
  - **外参推过去**：检测节点测距要正在用的那张图的雷达外参。本机时它自己读代理的地图目录；跨板时由代理推过去，连上推一次，换图再推。
- **怎么配**（两块板上的 `/etc/d1max/env`）：
  1. 生成一把共享密钥：`openssl rand -hex 32 > /etc/d1max/persons.key && chmod 600 /etc/d1max/persons.key`，**两块板放同一把**，账号跟跑服务的账号一样。
  2. RK3588（代理）：`D1MAX_PERSONS=bridge`、`D1MAX_PERSONS_LISTEN=<RK3588 狗内网地址>:47010`，可选 `D1MAX_PERSONS_PEER=<厂家 Orin 的 IP>`。
  3. 厂家 Orin（检测）：只装、只起 `d1max-persons`；`D1MAX_PERSONS_CONNECT=<RK3588 狗内网地址>:47010`。
  4. 不填 `LISTEN` / `CONNECT` 就是老样子（同一块板、本机套接字），现在的测试都照这个跑。
- **没做的**：厂家 Orin 上「只装人员检测」的装机角色（现在是整套装上、只起 `d1max-persons`），真机项 3ai.17。
