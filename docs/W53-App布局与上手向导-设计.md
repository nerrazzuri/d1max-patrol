> 2026-10-31。页面草图：https://claude.ai/artifact/QY3k4qPgKRGah5t63cojkd（用户 10-31 看过：「这个就好很多了」）。

## 1. 为什么

用户 10-30 在自己手机上走了一遍，问题有七个：
1. 值守页信息太多、太技术，站点发来的中文夹在英文界面里。
2. 看不到今天的巡逻。「Schedule OK」没有意义。
3. 布防模式切了没反应。
4. 天气在机器人页。
5. 诊断给谁看。
6. 管理页各项不知道是干嘛的。
7. 派巡逻被拒（「区域修订还没做安全确认」）没说清楚怎么办。

10-31 又提了一条：只买设备、没买交付服务的客户要能自己学会用。手机和网页都要有初始设置向导，给管理员、经理、保安各做一次简单的培训。

## 2. 用户定的

- **值守页跟着一台机器人走。** 默认是第一台加入的，能切到别的机器人（名字标签点选，或者在画面上左右滑）。选中那台的这些内容都在值守页：画面、状态、正在做什么、按角色给的按钮、最近事件。诊断不要。
- **画面**：值守的人手动点了才播，能手动关，播的时候全速。
- **机器人页**：只是列表，点一台进细节页，操作更多。
- **保安能派巡逻、能遥控**，这是核心功能。保安派的是临时巡逻：
  - 不存进日程；派了通知经理和管理员。
  - 跟日程撞时间时日程优先，保安派的排到后面，并通知保安。
  - 要估整趟要多久；最后一点不是起点的，走完机器人自己回去，这段也算进时间。
- **经理能派巡逻、能排日程。**
- **初始设置向导 + 按角色的简单培训**，手机和网页都要。

| D11 | 向导里的报警练习只在 App 里模拟：练习报警是假的，不发给站点，不进报警记录，别人看不到。 | 练习不能吵到别人，也不能脏了记录。 |
| D12 | 「看过教程」按账号记在站点上，换手机不用再看一遍；任何时候都能从「我的 / 管理 → 使用教程」重看。 | 一个人一套。 |

## 5. 临时巡逻（站点）

**派单**：`POST /api/robots/<id>/patrol`（`mission_id` 或 `points`）走新流程，`goto` 和 `standby` 不变。

1. 先照旧做全部校验（监护、地图版本、禁行区……），被拒就照旧回 409，加上 `reason_code`。
2. 估时 `estimate_s`（D4）。
3. 看撞不撞日程（D5）：
   - 不撞：立刻派，优先级照旧 `MANUAL`。
   - 撞了：写进排队表，回 `200 {"queued": true, "start_after_ms", "estimate_s", "because": "14:00 日程『外围一圈』"}`。
4. 两种情况都记 P3 提醒 `adhoc_patrol`（给经理和管理员；`alert_audience` 里给 `owner` 那一类）。

**排队表** `adhoc_queue`（库 68）：
- `id`、`robot`
- `mission`（整份 wire，派的那一刻定下来）
- `label`（路线名或「临时路线 3 个点」）
- `by`、`created_ms`、`not_before_ms`、`estimate_s`
- `state`：`queued` / `started` / `expired` / `cancelled` / `failed`
- `task_id`、`note`

**排程执行器每拍**（30 s）：
- 先照旧处理到点的日程，再看排队的临时巡逻。
- 起跑条件：`not_before` 到了；机器人空闲或正在回待命点；后面没有撞上的日程。满足就派（`task_id` 前缀 `adhoc-`），并记一条 `adhoc_started`。
- 后面有日程撞上：`not_before` 推到那趟日程预计走完之后。
- 派单被拒：`failed`，记一条提醒，写明原因。
- 超过 2 小时：`expired`，记一条提醒。

**取消**：`DELETE /api/adhoc/<id>`，派的人、经理、管理员能取消。

**正在跑日程的机器人**：保安点「派巡逻」不再打断它，而是排到它后面（D5）。要立刻去看就用「去这里」或者遥控（D8）。

## 6. 今天的巡逻（站点）

`GET /api/patrols/today`（`view`），按站点时区算今天 0 点到 24 点：

```
{"date":"2026-10-31","timezone":"Asia/Kuala_Lumpur","items":[
  {"at_ms":…, "kind":"schedule"|"adhoc", "label":"外围一圈", "robot":"A"|"",
   "by":"gina"|"",                     // 临时的才有
   "state":"done"|"failed"|"aborted"|"running"|"queued"|"next"|"later"|"missed"|"cancelled"|"expired",
   "reason":"第 3 点被挡住，跳过"|"",    // 中文原话；有代号的另带 reason_code
   "end_ms":…|null,                     // 走完的实际时间，或在跑 / 排队的预计时间
   "schedule_id":"…"|"", "adhoc_id":"…"|"", "task_id":"…"|""}]}
```

- 日程那几行：`occurrences_between(今天)` 每一轮一行；账（`schedule_runs`）有去向的按账显示，没到点的第一轮是 `next`，其余是 `later`。
- 临时那几行：`adhoc_queue` 里今天建的，加上今天手动派的巡逻（`commands` 里 `patrol`、`MANUAL` 那些）。
- App 的值守页、日程页，网页的值守页用的是同一份。

## 7. W52：申请账号（站点）

- `POST /api/account-requests`（不用登录）：`{"display","name","password"}`。
  - 限制：同一地址每分钟 3 次，站点上最多挂 20 条，7 天作废；名字已存在或已在申请中回 409。
  - 密码规则跟建账号一样，站点存的是哈希。
- `GET /api/account-requests`（`manage_accounts`）：返回申请列表。
- `POST /api/account-requests/<id>/approve`（`manage_accounts`，再输一次自己的密码）：`{"role"}`，缺省 `viewer`。批准时用申请时的密码哈希建账号。
- `POST /api/account-requests/<id>/reject`：拒绝申请。
- 有人申请就记一条 P2 提醒 `account_request`（给经理和管理员那一类）：「王小明申请账号，等你批准」。
- 申请人不用另外查结果，批准了直接用那个账号登录；没批准时登录提示「还在等管理员批准」或「申请被拒了」。

## 8. 上手向导（App 和网页）

### 8.1 开站清单（管理员、工程师）

`GET /api/setup`（`manage`）。站点按现在的数据判断每一项做完没有：

| 项 | 怎么算做完 | 去做（App / 网页） |
|---|---|---|
| 改掉初始密码 | 管理员账号不是装机时的初始密码（站点记 `must_change` 标记） | 账号 |
| 加机器人 | 至少一台登记了 | 机器人 → 添加 |
| 地图 | 有一张当前地图 | 地图（建图要工程师工具时，写清楚「请交付工程师做，或看《建图手册》」） |
| 禁行区确认 | 当前地图的区域修订做过安全确认 | 地图 → 确认 |
| 原点、待命点 | 每台机器人在当前地图上有默认待命点 | 机器人细节 → 待命点 |
| 巡逻路线 | 至少一条路线 | 管理 → 巡逻路线 |
| 巡逻日程 | 至少一条日程 | 日程 |
| 布防时间 | 设过布防时间，或者明确「手动切」 | 日程 → 布防时间 |
| 账号 | 除了管理员至少还有一个账号 | 账号 |
| 推送 | 至少一部手机登记了推送 | 我的 → 测试推送 |

- App「管理」页最上面、网页首页最上面，显示一张「开站清单 3/10」卡片，点开看每一项和「去做」按钮。
- 全部做完后，卡片收成一行「开站清单已完成」，可以点开再看。
- 用户可以点「先不管了」把卡片收起来；收起状态按账号记。

### 8.2 上手导览（每个角色都有）

第一次登录（这个账号没看过当前版本的导览）时，进了值守页就开始。做法是在真页面上挡一层半透明，圈出一块，旁边写一两句，按「下一步」往下走。每一步都能「跳过」。

**保安**（7 步，最后做一次报警练习）：
1. 最上面是布防状态和天气。你能切到「布防」；撤防要经理定。
2. 这一排是机器人。点名字切换，或者在画面上左右滑。
3. 点 ▶ 看实时画面，✕ 关掉。
4. 这里写着它在干嘛、电量多少。
5. 派巡逻：选路线。撞上日程会排在日程后面，派了经理会知道。
6. 遥控：手动开着它走。叫停：机器人马上停在原地。
7. 有 P1 报警时会响铃，最上面出红条，点「去处理」。现在练一次 →
   - 弹出一条「演练」报警，照着点：去处理 → 我来处理 → 误报。
   - 练完写「好了，真的来了就这么处理」。

**经理**（5 步）：布防和撤防、机器人标签和画面、派巡逻、日程在第 5 栏、报警和叫停。

**管理员 / 工程师**（6 步）：值守页（同保安的前 4 步合成 2 步）、机器人页（添加、批准）、地图（禁行区要确认）、管理页的「要你处理」和开站清单、账号审批。

**只看**（3 步）：值守页、机器人页、记录页。

网页的值班台一样有，内容按网页的布局写，没有报警练习，改成一句「报警来了：点红条 → 确认 → 写结论」。

重看：App「我的 / 管理 → 使用教程」，网页右上角「?」→ 使用教程。

## 9. App 页面（细节见草图）

- **底部五栏**：值守、机器人、地图、记录，第 5 栏按角色：
  - 管理员、工程师：「管理」
  - 经理：「日程」
  - 保安、只看：「我的」
- **进 App**：第一页是站点列表 + 「加入站点」；站点入口页有登录和「申请账号」。
- **值守**：
  - 布防 + 天气一行（保安只能切到布防）。
  - P1 红条。
  - 机器人标签和画面：默认第一台；用 `PageView` 左右滑；画面默认不播；切台时关掉上一路。
  - 状态和预计走完的时间、按角色的按钮、这台最近事件。
  - 今天的巡逻、其他未处理。
  - 「第一台加入」按机器人的登记时间算；站点没有登记时间就按名字排序。用户在 App 里切过的台记在手机上，下次打开还是那台。
- **派巡逻**：底部弹框；路线列表带估时（站点 `GET /api/robots/<id>/patrol-estimate?mission_id=`）；撞上日程先提示；被拒弹「为什么 + 去处理」。
- **机器人列表 / 机器人细节**：同草图；诊断去掉，放到管理 → 体检里每台机器人下面。
- **地图**：禁行区没确认时显示提示条，按角色显示「去确认」或「管理员还没确认」。
- **记录**：报警 / 巡逻 / 录像三段（原来的「排程」分段去掉，日程到日程页）。
- **管理**：
  - 最上面「要你处理」：禁行区没确认、拦截点没绑防区、账号等批准、机器人等批准。
  - 下面是开站清单卡片，再下面分三组：巡逻、报警联动、人和系统。每项一句说明。
  - 「体检」是原来的站点体检页。
- **日程页**（经理、管理员）：今天 / 每周；加一条时显示估时和冲突。
- **账号页**（管理员）：等批准（权限下拉，默认只看）+ 现有账号。
- **我的**（保安、只看）：账号、语言、使用教程、帮助、测试推送、退出。
- **弹框**：被拒原因 + 去处理；连热点失败的提示等系统框结束再弹，说「没找到」，给手动连的办法。

## 11. 不做

- 建图向导：建图现在要工程师的工具，自己摸索的客户先看《建图手册》。以后另开单。
- 告警、事件全部双语：只做派单拒绝原因（D10）。
- 报警练习进站点：只在 App 里模拟（D11）。
- 临时巡逻保存成路线：保安要常用的路线，找管理员存。
