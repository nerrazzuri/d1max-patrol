### 狗

- `goto` 收 `photo`（相机名），只认 `front`、`back`。到了就像巡检点位那样拍一张，进这一趟的归档，传到站点。
- **拍不成不算没到**：新加内部策略 `Policy.photo_optional`，不进线格式，任务包里写不了。拍照失败只记一笔 `photo_failed`；巡检的拍照点照旧按失败算。
- 能力报文报 `goto_photo`，只报配了取流的相机。**真狗目前没有取流**（`main.py`：「RTSP 取图归后面的工单」），所以真狗不报、站点也不带，**真狗到了还不会拍**。仿真狗会。

## 外审第一轮（2026-10-04）：FIX-THEN-APPROVE，2 条阻断，已修

**阻断 1：值守令牌读得到整个站点的事件流。** 白名单放行了通用的 `/api/events`：
- 首帧是全部狗的视图；
- 之后是狗的状态、任务事件、命令回执、对账、入侵账。

偷到一个 30 天的值守令牌，就能一直看整个站点，不是「只能看告警」。

修法：
- 新开 `GET /api/watch/events`：首帧是没解决的告警（不带狗的视图），之后只转告警帧和心跳；断流重补时也是告警首帧。
- 值守令牌的白名单只剩它和注销。`/api/events`、告警名单、值守汇总都不再放行（汇总里有狗的状态）。
- 普通会话照旧走全量流。
- 后台值守服务改连这条流，首帧代替了原来的「连上补读告警名单」。

补了真连 SSE 的测试：
- 用值守令牌连上，首帧没有 `robots`，有那条没解决的告警；
- 往推送流里注入 status、event、ack、reconcile、incident、snapshot 六种帧，再报一条告警，下一帧就是那条告警；
- 值守令牌访问 `/api/events`、告警名单、值守汇总、狗列表，都回 403；
- 普通会话照旧收到 `robots`。

突变 3 条全杀：不过滤、首帧给全量、白名单放回 `/api/events`。

**阻断 2：响铃通知被划掉或点开之后，再也不响。** 原来先记「这一档弹过了」再弹，通知又是点开就消失、能划掉的：
- 一被点开或划掉，声音停；
- 之后同一档的帧、重连补读都因为「弹过了」跳过；
- 告警还没人确认，手机却再也不响，跟「响到有人确认」正相反。

修法：
- 「该弹、该收、该重弹」抽成纯判断 `AlertBell.kt`（不碰 Android），**只有站点推来确认、解决才收**。
- 响铃档的通知常驻、点开不消失（点开只是打开 app，不算确认）。Android 14 起常驻通知也划得掉，所以挂了删除回调：划掉了、告警还没确认，就当场重弹、接着响。
- 别的档照旧可以点掉、划掉，之后升档或重连的首帧会再弹。

补了 JUnit 测试 5 条（`src/test/.../AlertBellTest.kt`，CI 的 android 作业也跑）：
- 响铃档弹一次，同一档的帧不重弹；
- 划掉了没确认就重弹（连划两次都重弹），确认了才收，确认之后划掉就是划掉；
- 屏幕档划掉随它，重连首帧里还挂着就补弹；
- 升档再弹，首帧里没了的、确认了的收掉；
- 不是 P1 的不弹，停值守全收。

突变 3 条全杀：划掉不重弹、划掉后还记着「弹过了」、首帧里没了的不收。

修完之后 release APK 照样编得过；全量 Python 0 失败。

CI 上 `test_手机读的站点夹具跟真站点同形` 挂了一次：「告警帧」那条告警发出时，狗有时已经在跑任务（`context` 带 `task_id`），有时还没有（空的），时序决定。`context` 跟事件的 `data` 一样是按情况带不同键的自由对象，比形状时按一个整体对象算，不比里面的键。

## 已知限制、要你做的

- **手机真机没试过**：后台值守是原生代码，这台机器没有接手机、没有模拟器。拿到包（CI 产物或这台机器编的）装到保安的 Android 手机上，要试这几样：
  1. 登录后通知栏出现「值守中」；
  2. 锁屏、把 app 划掉，在站点上造一条入侵（`tools/site_demo.py` 加一个事件源发一条），闹钟声响；点开、划掉都不停，在 app 里确认了才停；
  3. 关掉站点，两分钟后弹「值守断了」；
  4. 点「停止值守」，令牌作废。
  
  省电要设「不限制」。各家手机（小米、华为、OPPO 等）还有自己的「自启动」「后台运行」开关，可能要手动打开。
- **真狗到了不拍照**：狗上还没有 RTSP 取图（后面的工单）。现场页的「现场照片」在真狗上会说「记录里没有照片」。告警的现场位姿、拦截点、在图上看不依赖这个，真狗也有。
- iPhone 不做：项目只有 Android 和桌面版。iOS 不许后台长连接，要苹果推送，那得走外网（决策 27 不做）。
- 后台值守和 app 内的连接是两条：app 开着时手机跟站点连两条事件流，多一点流量，可以不管。
- 「推送」那一档（2 分钟没人确认）在后台值守里是弹一条有声的通知；第 0 档（屏幕）也弹通知，只是不响铃。
