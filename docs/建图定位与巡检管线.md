# D1 Max 建图 / 实时定位 / 巡检 管线（2026-09-02 现场跑通）

全程 **WiFi**（狗热点 `XG2WIFI_C40221`，RK3588=`192.168.234.1`，Orin NX=`192.168.168.100`）。
ROS2 走 **zenoh 桥**：本机起 `rmw_zenohd` 连 Orin，即可订阅厂商话题。

> 约定：`<REPO>` = 本仓库绝对路径。注意本机路径含空格（`D1 Max`），

## 1. 抢控制权 + 常驻会话

```bash
bash field-agent.sh          # 保持连热点 + 抢开机窗口 TakeControl + 握住不放 + 跨重启重抢
# 命令：echo 'stand' > runs/d1max-agent.fifo   （FIFO 空格格式）
# 转向等带 yaw 的走 TCP JSON 口 127.0.0.1:8090（见 motion/patrol_agent.cpp）
```

**Ctrl+C 只退这个脚本，`patrol_agent` 继续跑、控制权继续握着。** 控制权交不回来
（#46/#47），松手就只能重启 RK3588 重抢窗口，所以它跑在自己的 session 里，
Ctrl+C 和关终端都碰不到它。退出后停的只是保活：热点掉线不再自动重连、机器重启
不再自动重抢。重跑 `bash field-agent.sh` 会认出它并接管，不会起第二个。

真要交还控制权（不可逆）：`echo 'shutdown' > runs/d1max-agent.fifo`。

### 用 app 跑（第 2 ~ 6 节的全部内容）

**抢完控制权之后，剩下的每一步都在 app 里点。** 下面第 2 ~ 6 节保留的是
底下真正跑的命令——出事时照着它一条条手动复现，平时不用敲。

```bash
pip install -e .            # 装一次，得到 d1max-app 命令
d1max-app --nav vendor      # 甲路线：厂商导航。乙路线用 --nav local
# 浏览器开 http://127.0.0.1:8095
```

想让**手机**也开得了这个页面，就得绑到局域网上，而绑局域网**必须给 PIN**，
不给它拒绝启动：

```bash
D1MAX_PIN=428913 d1max-app --nav vendor --host 0.0.0.0
```

狗热点的密码是 `12345678`、还印在这份文档里（第 1 节），射程之内谁都能连
上来；而这个页面能让机器狗走起来、能把现场照片整包拉走。所以这里不是提醒，
是硬拦。PIN 走环境变量给，别写命令行——命令行参数在 `ps` 里是明文的。

### 多只狗怎么分得清

**每只 D1 Max 的内网地址是同一套**——Orin NX 永远 `192.168.168.100`、RK3588
永远 `192.168.168.168`。这是机身内部固定的，不是我们配的，所以**靠地址分不
出谁是谁**：手机上今天连的和昨天连的，在网址上长得一模一样。

管理按**机身序列号（SN）**走，MAC 一并记下：

```bash
D1MAX_SN=C40221 D1MAX_NICKNAME=三号 d1max-app --nav vendor
```

麻烦在于**厂商没给 SN 这个字段**——SDK 开发指南和导航 WebSocket API 里都
没有。所以程序按这个顺序找，找不到就明说找不到，不编一个出来：

1. `--sn` / `D1MAX_SN`（人填的，权威。现场贴的标签才认数）
2. `/proc/device-tree/serial-number` 那几个只读文件（标识的是**模组**不是
   整机，换过主板就变，所以排在人填的后面）
3. 都没有 → 记成 `mac:<主网卡MAC>`，同时把来源标成 `mac`，页面上显示成橙色

**为什么不能编。** 主板厂出货时常把序列号填成 `To be filled by O.E.M.` 这类
占位串，而它在每一台机器上都是同一个值——真拿它当 SN，一整批机器会被认成
同一只狗，归档全混到一起，事后没法分开。所以这类值一律当成"没有"。

身份进两个地方：`GET /api/identity`（要先解锁）给手机认狗；每次运行的
`manifest.json` 的 `fingerprint` 里写着 `robot_sn`，报告上直接看得见。

**归档目录不按机器分层。** 一台狗上只会有它自己的数据，多一层机器目录，
下面永远只有一个兄弟。日后真要把几只狗的归档倒到一处，认的是 `manifest.json`
里那个字段，不是目录名。

五个页签就是五步：**建图**（录包 / 重建 / 存图）、**地图与点位**（在图上点、
存点位）、**任务**（编巡检任务）、**运行**（起飞检查 / 跑 / 急停）、
**判读与报告**（VLM 判读 + 人复核 + 出报告）。

**app 关掉不影响 `patrol_agent`。** 它不是 app 起的，收尾时也不碰它——控制权
交不回来（#46/#47），app 每关一次就带走它，等于每关一次 app 都要重启一次
RK3588。app 只收自己起的那些 ROS 进程。

`--host` 默认只听本机。这些接口没有任何认证，而且能让机器狗走起来，
换成别的地址前先想清楚这个网段上还有谁。

## 2. 建图（3D 速腾雷达 → 2D 占据图）

厂商 `/laser_scan` 用 **Livox（窄视场）+ 图像分割过滤**，桌椅扫不全；
改用 **速腾前雷达 `/front_lidar`（360°）** 压平，桌椅墙都进来。

> **这一节的命令已经编码进 `src/d1max_patrol/app/mapping.py`**（页面上的
> 「录包 / 重建 / 存图」走的就是它）。两处必须一字不差：改了这里要同步改
> 那里，反之亦然。`tests/app/test_mapping.py` 逐条比对生成出来的命令行与
> 环境变量，改漏一处那组测试就会红。

```bash
# (a) 录一段带平移的走动（3D 点云流到笔记本，机器不占内存）
ros2 bag record -s mcap -o runs/bags/d1max-walk3d-<ts> \
  /front_lidar /tf /tf_static /odom/mc_odom /odom/current_pose
# 你用 field-agent / 看板按钮驱动机器走一圈，最后绕回起点（回环闭合）

# (b) 离线重建（隔离域 + FastDDS，纯本地回放）
export ROS_DOMAIN_ID=93 RMW_IMPLEMENTATION=rmw_fastrtps_cpp ROS_LOCALHOST_ONLY=1
cp config/params/mapper_3d.yaml /tmp/; sed -i 's#<REPO>#'"$PWD"'#' /tmp/mapper_3d.yaml
ros2 run slam_toolbox async_slam_toolbox_node --ros-args --params-file /tmp/mapper_3d.yaml -p use_sim_time:=true &
# 估计雷达外参（速腾大概朝后装；yaw 影响见第6节）
ros2 run tf2_ros static_transform_publisher --x 0.2 --y 0 --z 0.18 --roll 0 --pitch 0 --yaw 0 \
  --frame-id base_link --child-frame-id rslidar_head &
# 点云→2D激光（取 0.1–1.5m 高度带，含桌面 0.73m）
ros2 run pointcloud_to_laserscan pointcloud_to_laserscan_node --ros-args \
  -r cloud_in:=/front_lidar -r scan:=/scan_3d -p target_frame:=base_link \
  -p min_height:=0.1 -p max_height:=1.5 -p range_min:=0.3 -p range_max:=20.0 \
  -p angle_min:=-3.14159 -p angle_max:=3.14159 -p angle_increment:=0.0087 -p use_sim_time:=true &
ros2 bag play runs/bags/d1max-walk3d-<ts> --clock --delay 4 --topics /front_lidar /tf /tf_static
# (c) 存图 + 序列化（localization 要 .posegraph）
ros2 run nav2_map_server map_saver_cli -f runs/slam/d1max_map_3d_b --ros-args -p save_map_timeout:=15.0
ros2 service call /slam_toolbox/serialize_map slam_toolbox/srv/SerializePoseGraph "{filename: '$PWD/runs/slam/d1max_map_3d_b'}"
```

## 现场踩到的坑 / 已知项

- **路由不持久**：机器重启 / WiFi 重连后，第 0 节那条路由要重加（否则 Orin 不可达、`/tf` `/laser_scan` 全进不来）。
- **雷达朝向**：速腾前雷达疑似朝后装，建出的图内部朝向差 **180°**。矩形对称所以图/位置看着没差，但机器**头朝向反了**——根治是把 `static_transform_publisher` 的 `--yaw` 设 `3.14159` 重建图。app 里**不做显示端修正**：摆歪的外参在显示端兜住，只会让下一个人以为它是对的。
- **2D 建图的局限**：家具密集区（桌腿细、椅子乱）2D scan 匹配差，走进去反而更乱；家具级完整图要走全 3D SLAM（FAST-LIO2 / 厂商 LIO，`/opt/runtime/config/nx_zg.yaml`）。
- **zenoh 毛病**：`map_server` 的 latched `/map` 在 zenoh 上传播不出去 → **AMCL 定位 pgm 走不通**（所以用 slam_toolbox 从文件读图）。多个本机 ROS 节点互相发现偶发失败。
- **看板启动**：这个受限 shell 后台起 python 反复秒退；**用前台方式起**（会阻塞后转常驻）最稳。
- **雷达外参**来源：`/opt/robot/robot-driver/install/laser_scan/share/laser_scan/config/config.yaml`（Livox 的 `ext_T=[0.205,-0.023,0.176]`、高度带 0.1–1.0）；速腾外参在 LIO 配置里。
