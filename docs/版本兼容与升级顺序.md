# 版本兼容与升级顺序（商业化 A7）

一套系统有四样东西，各自升级：**站点**、**狗上的代理**、**旁路进程**（`motion/patrol_agent`，狗上的 C++ 程序）、**手机 App**。这份文档说清楚哪些版本能配在一起、升级按什么顺序。

## 一、各自的「版本号」

| 东西 | 看哪个数 | 现在 | 谁检查、配不上怎样 |
|---|---|---|---|
| 站点 ↔ 狗的报文 | `schema` 主版本（`d1max_contract.SCHEMA`） | 1.0 | 两头都查，主版本不同的报文直接丢 |
| 狗上的代理 | **代理兼容级别**（`compat.AGENT_LEVEL`，能力里 `tasks.compat.level`） | 2 | 站点查，认 2–2。太老报 P2「狗上的代理太老」，太新报 P2「站点比狗老」；**升级包级别不在这个范围的，站点不登记** |
| 旁路进程 | 协议号（`agent_frames.PROTO_VERSION`） | 8（代理认 3–8） | 代理连旁路进程时查，配不上代理不起（日志写「重编 motion/patrol_agent」）。站点版本一览里能看到每只狗的协议号 |
| 任务包 | `requires_mission_schema` | 1 | 狗上查，包比狗新就不升 |
| 站点库结构 | `SCHEMA_VERSION`（库里 `meta.schema`） | 48 | 站点程序开库时查：**库比程序新就不开**（防回滚把库弄乱）。库比程序老，自动补表补列 |
| 手机 App ↔ 站点接口 | 站点接口级别（`compat.SITE_API_LEVEL`）、站点要的 App 最低级别（`MIN_APP_API_LEVEL`）；App 里有自己的级别和要站点的最低级别 | 1 / 1 | App 登录时查，配不上不登录，提示「升级 App」或「先升级站点」 |

在哪里看：
- 站点和每只狗：`GET /api/versions`（能登录就能看），或者 `d1max-site versions`（只看站点自己）。
- 每只狗另外在手机「版本」屏里看。

## 二、能配在一起的（兼容矩阵）

| 站点 | 代理级别 1（PR #88 以前的狗） | 代理级别 2（现在） |
|---|---|---|
| PR #88 以前的站点 | 能配 | 能配（新代理认的回执老站点不发，没事） |
| PR #88 以后、A7 以前 | **不配**：站点删过的证据，老代理会一直重传（这就是 SR1 时说的「狗和站点要一起升」） | 能配 |
| A7 及以后（现在） | **不配**：站点报 P2「狗上的代理太老」，带升级办法 | 能配 |

| 代理 | 旁路进程协议 3–7 | 旁路进程协议 8 |
|---|---|---|
| 现在的代理 | 能配（代理只用到 `vel`） | 能配 |

| App | 站点接口级别 1 |
|---|---|
| 现在的 App（级别 1，要站点 ≥1） | 能配；不带级别的老站点也算 1 |

## 三、升级顺序

**先站点，再狗；旁路进程跟着狗；App 随时。**

1. **先备份站点**：`d1max-site backup-verify` 看一眼最近一份备份是好的（`docs/备份恢复与灾备演练.md`）。
2. **升站点**：按站点的安装文档重装新版。库结构自动往前升；**升了就回不去**，新库老程序不开。要退回老版本，只能用升级前的备份恢复。
3. **看版本一览**：每只狗是 `ok` 还是「狗上的代理太老」。
4. **升狗**：在站点上登记新的升级包（级别不配的站点不收），一只一只下发。
   - 狗上自己核签名、核任务包结构，切换以后起不来会自动回滚（`docs/装机清单.md` 四）。
   - **先升一只看半小时**，再升剩下的。
5. **旁路进程**：升级包里带着旁路进程，跟狗一起升。协议号只往上加，代理一直认老的（现在认 3–8），所以先后无所谓。
6. **App**：随时升。站点升了接口级别，老 App 登录时会被提示升级。

**不要做的：**
- 先升狗、后升站点：新代理的级别老站点不认。站点报「站点比狗老」，那就先把站点升上去。
- 老站点程序配新库（回滚站点程序）：程序不开库。用升级前的备份恢复。

## 四、什么时候加级别（给开发）

只有**两头都得会**的东西改了才加，新加的可有可无的字段不算。

- **代理级别**（`d1max_contract/compat.py` 的 `AGENT_LEVEL`）：站点开始发老代理处理不了的东西。加了以后：
  - 把 `SITE_MAX_AGENT_LEVEL` 跟上；
  - 站点确实要求了，才抬 `SITE_MIN_AGENT_LEVEL`；
  - 在这份文档的矩阵和 `compat.py` 的注释里写一行为什么。
- **站点接口级别**：接口改得老 App 用不了了。加了以后看是否要抬 `MIN_APP_API_LEVEL`；App 里的 `minSiteApiLevel` 同理。
- **旁路进程协议号**：已经有自己的规矩（`agent_frames.py`），代理认一个范围。
- **站点库结构**：每次加表加列都加一，老库会自动补。
