# 版本兼容与升级顺序（商业化 A7）

一套系统有四样东西，各自升级：**站点**、**狗上的代理**、**旁路进程**（`motion/patrol_agent`，狗上的 C++ 程序）、**手机 App**。这份文档说清楚哪些版本能配在一起、升级按什么顺序。

## 一、各自的「版本号」

| 东西 | 看哪个数 | 现在 | 谁检查、配不上怎样 |
|---|---|---|---|
| 站点 ↔ 狗的报文 | `schema` 主版本（`d1max_contract.SCHEMA`） | 1.0 | 两头都查，主版本不同的报文直接丢 |
| 狗上的代理 | **代理兼容级别**（`compat.AGENT_LEVEL`，能力里 `tasks.compat.level`） | 3 | 站点查，认 2–3。太老报 P2「狗上的代理太老」，太新报 P2「站点比狗老」；**升级包级别不在这个范围的，站点不登记** |
| 旁路进程 | 协议号（`agent_frames.PROTO_VERSION`） | 9（代理认 3–9） | 代理连旁路进程时查，配不上代理不起（日志写「重编 motion/patrol_agent」）。站点版本一览里能看到每只狗的协议号。9 起只收认证过的连接的运动命令（S11，令牌见 `docs/真机联调手册.md`） |
| 任务包 | `requires_mission_schema` | 1（任务包本身现在打出来是 schema 2：每个任务都绑地图版本，R1） | 狗上查，包比狗新就不升；站点不导入任务没绑版本的老包（`docs/任务包格式.md`） |
| 站点库结构 | `SCHEMA_VERSION`（库里 `meta.schema`） | 57（区域确认内容、待核对的提议，决策 66、R2） | 站点程序开库时查：**库比程序新就不开**（防回滚把库弄乱）。库比程序老，自动补表补列 |
| 手机 App ↔ 站点接口 | 站点接口级别（`compat.SITE_API_LEVEL`）、站点要的 App 最低级别（`MIN_APP_API_LEVEL`）；App 里有自己的级别和要站点的最低级别 | 1 / 1 | App 登录时查，配不上不登录，提示「升级 App」或「先升级站点」 |

在哪里看：
- 站点和每只狗：`GET /api/versions`（能登录就能看），或者 `d1max-site versions`（只看站点自己）。
- 每只狗另外在手机「版本」屏里看。

## 二、能配在一起的（兼容矩阵）

| 站点 | 代理级别 1（PR #88 以前的狗） | 代理级别 2 | 代理级别 3（现在，R1） |
|---|---|---|---|
| PR #88 以前的站点 | 能配 | 能配（新代理认的回执老站点不发，没事） | **不配**（同下一格） |
| PR #88 以后、A7 以前 | **不配**：站点删过的证据，老代理会一直重传（这就是 SR1 时说的「狗和站点要一起升」） | 能配 | **不配**（同下一格） |
| A7 以后、R1 以前 | **不配**：站点报 P2「狗上的代理太老」，带升级办法 | 能配 | **不配**：老站点派的巡检任务没绑地图版本，3 级的狗全拒；站点报 P2「站点比狗老」、不登记 3 级的升级包 —— 先升站点 |
| R1 及以后（现在） | **不配**（同上） | 能配：站点把**任务的**地图版本放进命令，老狗本来就核这个键 | 能配 |

| 代理 | 旁路进程协议 3–8 | 旁路进程协议 9（现在，S11） |
|---|---|---|
| S11 以前的代理（认 3–8） | 能配（代理只用到 `vel`） | **不配**：老代理不发令牌，握手就拒（「协议版本对不上」） |
| 现在的代理（认 3–9） | 能配，但老旁路进程**不核令牌**：本机任何进程都能让狗动，代理日志记一条警告 —— 重编 `motion/patrol_agent` | 能配：代理连上先用令牌认证（缺省读 `~/.d1max/sidecar.token`，读不了、不对就不起） |

| App | 站点接口级别 1 |
|---|---|
| 现在的 App（级别 1，要站点 ≥1） | 能配；不带级别的老站点也算 1 |

**区域的两个新字段（2026-10-14，决策 65、66）没加级别**：`hard`（硬禁区）、`until_ms`（临时区到期）只在用到时才上线，
老的区域集线上一字不差。老代理不认 `hard`，照普通禁行区守（规划照样绕），**遥控时不守硬禁区** —— 新代理在能力里报
`zones_set.teleop_hard`，站点开遥控时发现图上有硬禁区、狗没报这一项，就告诉手机「这台狗遥控时不守硬禁区，看着画面开」。
到期由站点删、出新修订，老代理照收。**App**：确认一个区域都没有的那一版，站点（2026-10-14 起）要 `empty_ok`，老 App 不会带，
确认时站点回 409 说清楚 —— 换新 App 再确认；新 App 配老站点：多带的 `empty_ok`、`adopt` 老站点不认，照常确认。

**抹掉区（区域种类 `erase`，2026-10-14，地图台账 44）也没加级别**：老代理不认这个种类，整份区域集会被它拒掉（修订号对不上、
派单一直拒「区域没同步」）。新代理在能力里报 `zones_set.erase`；站点发给**没报这一项**的狗时把抹掉区换成**同一块禁行区**
（id、名字、几何、硬、到期都不变，修订号不变）—— 对狗一样严，狗照收照守，只是它不知道站点画图时要抹掉那一块。站点一个人兜住了，
所以不用两头一起升。老 App 看到抹掉区会当成「限速」显示（种类不认），存、删别的区域时原样带回去，不丢；画抹掉区要新 App 或网页。
**地图文件 `seen.pbm`（「看到过、狗没走过」，只管显示）**：可选文件，老狗按清单逐个下、逐个核，多一个文件不出事；老站点不画它。

**运行配置的三样新东西（2026-10-15，地图管理 R3、R4、R5）也没加级别**（都是可有可无的字段，老的一头不认就当没有）：

| 新东西 | 谁发、谁看 | 老的一头怎样 |
|---|---|---|
| 能力里的 `running_config`：狗**实际在跑**的图号版本、**图内容摘要**（`map_digest`，由 `active.json` 里的清单算）、区域修订与**区域内容摘要**（`zones_digest`，不含修订号）、上一张 / 本地留着哪几版、换图靠谁确认（`confirms`）、最近一趟巡检命令带的任务修订 | 新狗发、新站点看 | **老狗没有**：站点退回只比区域修订号（派单闸原样），网页「每只狗」那张表标「老代理：只比区域修订号」；**老站点不看**这一项，新狗照常能配 |
| 事件 `map_activated` 多一个 `confirmed`（`localizer`＝定位器确认收下了新图的先验；`load`＝没有定位器，载入成功就算） | 新狗发、新站点看 | **老狗没有**：站点显示「老代理：没等定位器确认」，别的照旧；老站点忽略这个字段。新狗在定位器**不收**这张图时发 `map_activate_failed`（原因里写「已退回原来的 X:Y」），老站点本来就会把它报成 P2「换图没成」 |
| 巡检命令多一个 `mission_rev`（任务定义的内容摘要） | 新站点发、新狗记 | 老狗不看这个键；新狗收到没带的（老站点）自己按收到的任务定义算 |

派单闸（`goto`、`patrol`、`standoff`）新增两条，**只在两头都报了摘要时才比**：狗报的图摘要 ≠ 站点登记的这一版的清单摘要 → 拒（「狗上的内容跟站点登记的不一样」，重新下发这一版）；区域修订号一样但内容摘要不一样 → 拒（站点多半从旧备份恢复过又改了一次；再保存一次区域出新修订就发给狗了）。站点不认识的版本、狗没报摘要的（命令行指定的图），查不了、不挡。

狗上的地图目录（`<store>/maps/`）以前只留正在用的一张，现在**最多三张**：正在用的、上一张（`previous.json` 记着，回退不用重新下载）、最近一次自己建的。升级到新代理以后第一次换图才开始多留一张；**退回老代理**：老代理看不懂 `previous.json`，会把别的版本一律删掉（只丢一份缓存，需要时站点再下发）。站点库结构这一单**没动**（仍是 57）：每只狗的换图状态（等狗换 / 已确认 / 没成 / 太久没动静）是从命令账和事件里推的。

## 三、升级顺序

**先站点，再狗；旁路进程跟着狗；App 随时。**

1. **先备份站点**：`d1max-site backup-verify` 看一眼最近一份备份是好的（`docs/备份恢复与灾备演练.md`）。
2. **升站点**：按站点的安装文档重装新版。库结构自动往前升；**升了就回不去**，新库老程序不开。要退回老版本，只能用升级前的备份恢复。
3. **看版本一览**：每只狗是 `ok` 还是「狗上的代理太老」。
4. **升狗**：在站点上登记新的升级包（级别不配的站点不收），一只一只下发。
   - 狗上自己核签名、核任务包结构，切换以后起不来会自动回滚（`docs/装机清单.md` 四）。
   - **先升一只看半小时**，再升剩下的。
5. **旁路进程**：升级包里带着旁路进程，跟狗一起升。协议号只往上加，代理一直认老的（现在认 3–9）。**9 号要新代理**（老代理认 3–8、握手就拒），所以先升代理、再重编旁路进程（重起旁路进程要重启 RK3588 抢窗口）；代理和旁路进程要用**同一个账号**跑（代理读旁路进程写的令牌）。
6. **App**：随时升。站点升了接口级别，老 App 登录时会被提示升级。

**不要做的：**
- 先升狗、后升站点：新代理的级别老站点不认。站点报「站点比狗老」，那就先把站点升上去。
- 老站点程序配新库（回滚站点程序）：程序不开库。用升级前的备份恢复。

## 四、什么时候加级别（给开发）

只有**两头都得会**的东西改了才加，新加的可有可无的字段不算。

- **代理级别**（`d1max_contract/compat.py` 的 `AGENT_LEVEL`）：站点开始发老代理处理不了的东西。加了以后：
  - 把 `SITE_MAX_AGENT_LEVEL` 跟上；
  - 站点确实要求了，才抬 `SITE_MIN_AGENT_LEVEL`；
  - 在这份文档的矩阵和 `compat.py` 的注释里写一行为什么。
- **站点接口级别**：接口改得老 App 用不了了。加了以后看是否要抬 `MIN_APP_API_LEVEL`；App 里的 `minSiteApiLevel` 同理。
- **旁路进程协议号**：已经有自己的规矩（`agent_frames.py`），代理认一个范围。
- **站点库结构**：每次加表加列都加一，老库会自动补。
