# 商业化 B3a：值班台录像页 完工报告

2026-10-11。台账 C-B3a。鸿蒙样品按用户决定先放下（要华为账号和设备），先做剩余项；这是第一项。

## 做了什么

值班台顶栏的 **Recordings** 页签原来是灰的，现在能用。

- **选**：机器狗、前 / 后摄像头、日期（当地的一天）。右上角写这一天录了多久、几段、留着几段。
- **时间轴**：一条 24 小时的轴。有录像的地方是实的，没录的是空的；这台狗这一天的 P1（红）、P2（琥珀）告警在轴上各有一条竖线；标了「留着」的段下面有一道蓝线；白线是现在放到哪儿。
  - 点哪儿从哪儿放；点在空档上就从后面最近的一段放起，后面也没有就说一声。
  - 键盘：轴得到焦点后左右键各挪一分钟。
  - 「Go to time」填几点几分几秒直接跳。
- **放**：一段（60 秒）放完自动接下一段；上一段 / 下一段；1× / 2× / 4×（换段保持）；正在放时换前后，接着同一刻放另一路。
- **画面上的字**：上沿是「狗 摄像头」和**录像里的时刻**（日期 + 时分秒，跟着播放走），下沿标 `Recorded`，跟实时画面的 `Live` 分得清。
- **留着**：管理员、保安能把正在放的这一段标成留着（过了留存期也不删），再点一次取消；业主没有这个按钮（跟站点的 review 权限一致）。
- **从告警过来**：报警队列每一行（狗的告警）多一个 `Recording` 链接，直达那台狗、告警前 10 秒；录像页下面也列出这一天的告警，每条能「从前 10 秒放」。地址形如 `#/recordings?robot=A&t=<毫秒>`，能收藏、能发给别人。
- **状态说清楚**：没开录像的站点、列表没读到、这一天没有录像、这一段放不了（可能删了），各有一句话，不留一块黑屏。

站点：

- `/api/recordings/<id>/video` 认 `Range: bytes=…`：只发要的那一段（206，带 `Content-Range`、`Accept-Ranges`），够不着回 416；不带、看不懂、一次要好几段都照旧整份发。浏览器拖进度靠它。照片、导出包不变。
- `tools/site_demo.py --recordings N`：往演示站点放 N 分钟的假录像（ffmpeg 测试图，前后两路，中间留 5 分钟空档），看录像页用。

界面上没有用内联样式（站点的内容安全策略不许），时间轴是 SVG。

## 验证

- 网页 32 条通过（新增 7 条：一天的范围、排序、并段与总时长、哪一段盖住哪一刻、上下段、轴坐标与告警链接、谁能标留着）。
- 站点：`Range` 解析 17 种写法、真 HTTP 取段（跨 64 KB 块、最后几个字节、够不着 416、多段整份发）。
- 浏览器实测（演示站点 + 90 分钟假录像，Chromium）：列表 85 段；点时间轴从那一刻放；深链接放到指定时刻（差 3 秒以内，是页面加载的时间）；换前后接着同一刻；4× 下自动接下一段；标留着后按钮变成「Stop keeping」；1440 和 800 宽都看过。
- Python 本地只跑了受影响的几个文件（录像、W30、网页静态文件、设计常量），全部通过。**本地全量没跑完**：两次跑到一半开发机都重启了（原因没查清，不确定跟测试有没有关系），所以全量以 CI 为准。

## 没做的

- **报表页（Reports）**还是灰的：内容要先定。
- **真录像没验**：狗上录的 H.264 分段在浏览器里能不能放、拖动顺不顺，只用 ffmpeg 生成的测试片验过。
- 多路同步回放（前后并排）、导出一个片段、逐帧、缩放时间轴（现在固定一天一屏，一段 60 秒在 1440 宽的屏上是 1 像素）。
- 告警记号只取站点最近 500 条告警里这一天的；更早的日子可能没有记号。
- 手机 App 的录像页没动。

## 升级注意

库结构没变（53）。只升站点即可；老 App 不受影响。

# 第二部分 · B3b：值班台报表页（值班日报）

2026-10-11。台账 C-B3b。内容是用户定的：**值班日报**（选一天或一个班次，一页看完，能打印、能导出 CSV）。

## 做了什么

值班台顶栏的 **Reports** 页签能用了。

- **选时间段**：日期 + 起止钟点（24 小时制的文字框，不跟着系统变成上午下午）。结束不比开始晚就算到第二天，所以 `00:00 → 00:00` 是一整天，`20:00 → 08:00` 是夜班。最长 31 天。
- **告警**：P1 / P2 / P3 各多少；还没人确认的；没人确认就自己消除的；P1 从报出来到有人确认的中位数和最长；谁确认了几条、关了几条；按种类多少；全部告警的明细（时刻、级别、事件、哪台狗、哪个防区、谁确认 · 过了多久、几点谁关的）。
- **入侵事件**：一共几起，各种处置各几起（已出动、并入前一起、没布防、授权访客、没有可派的狗……），明细。
- **排程巡逻**：该跑几趟，出发、跳过、没派出去各几趟；出发的里面完成、失败、被叫停、被打断、还在跑各几趟；收到的巡逻记录几趟、照片几张；明细带备注（为什么跳过）。
- **打印**：点 Print，白底黑字，只印报表（顶栏、报警队列、筛选条不印），表格行不跨页断开。
- **导出**：告警、入侵事件、巡逻三张 CSV。带 BOM（Excel 打开中文不乱）；以 `= + - @` 开头的文字前面垫撇号（表格软件不当公式算）。
- 报表抬头写站点名、时间段、谁在几点生成的。
- 颜色只给 P1 / P2 的数（不为零时）和级别标记，别的数都是中性的。
- 页脚写明这份报表里**没有**什么。

站点：`GET /api/reports/daily?since=<毫秒>&until=<毫秒>`（新模块 `d1max_site/reports.py`）。

- 能看的都能看（保安交班、业主）。只读库。
- 归到哪一段：告警按第一次报的时刻，入侵事件按站点收到的时刻，排程按该跑的时刻，巡逻记录按第一个文件到站点的时刻；都是含头不含尾。
- **数是 SQL 数出来的，不截**；明细每样最多 1000 行，截了回包里写明，页面上也写「只列了前 N 行；上面的数是全的」。
- 时间段不对（倒着、超过 31 天、不是整数）回 400。

顺带修了录像页一个日期校验漏洞（`2026-13-01` 被当成 2027 年 1 月），是写报表测试时抓到的。录像页的「跳到几点」也改成了 24 小时制文字框（回车跳）。

## 验证

- 站点 17 条：空的一天、归段的边界、各级计数、确认用时（中位数、钟差当 0）、谁处理的、明细截断写明而计数不截、入侵事件与排程各种结果、巡逻记录、9 种不对的时间段、正好 31 天、真 HTTP（业主能看、没登录 401、7 种坏参数 400、POST 405）。
- 网页 40 条（新增 8 条：钟点、时间段含跨夜、秒数写法、CSV 引号与防公式、三张 CSV 的列、处置文字中英都有、跳到几点、日期校验）。
- 浏览器实测（演示站点里放了几条告警、事件、排程）：英文 1440 宽、中文 820 宽、打印版各看过一遍；CSV 真下载下来看过内容。
- Python 本地只跑了受影响的文件；全量以 CI 为准（原因同第一部分）。

## 没做的

- **每台狗在线了多久**：站点不记在线历史，要加一张表才有。
- **误报率**：值班台的「误报」和「解决了」在库里是同一个动作，分不出来；要给关闭加原因才有。
- 周 / 月趋势图、PDF 文件（现在用浏览器的打印另存为 PDF）、按狗 / 按防区筛选、自动每天发报表。
- 入侵事件的处置、巡逻的备注里，站点写的原因文字仍是中文。
- 手机 App 没有报表页。

## 升级注意

库结构没变（53）。只升站点即可。
