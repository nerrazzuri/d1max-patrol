# 商业化 B3a：值班台录像页 完工报告

2026-10-11。台账 C-B3a。鸿蒙样品按用户决定先放下（要华为账号和设备），先做剩余项；这是第一项。

## 做了什么

值班台顶栏的 **Recordings** 页签原来是灰的，现在能用。

- **选**：机器狗、前 / 后摄像头、日期（当地的一天）。右上角写这一天录了多久、几段、留着几段。
- **时间轴**：一条 24 小时的轴。有录像的地方是实的，没录的是空的；这台狗这一天的 P1（红）、P2（琥珀）告警在轴上各有一条竖线；标了「留着」的段下面有一道蓝线；白线是现在放到哪儿。
  - 点哪儿从哪儿放；点在空档上就从后面最近的一段放起，后面也没有就说一声。
  - 键盘：轴得到焦点后左右键各挪一分钟。
  - 「Go to time」填几点几分几秒直接跳。
- **放**：一段（60 秒）放完自动接下一段；上一段 / 下一段；1× / 2× / 4×（换段保持）；正在放时换前后，接着同一刻放另一路。
- **画面上的字**：上沿是「狗 摄像头」和**录像里的时刻**（日期 + 时分秒，跟着播放走），下沿标 `Recorded`，跟实时画面的 `Live` 分得清。
- **留着**：管理员、保安能把正在放的这一段标成留着（过了留存期也不删），再点一次取消；业主没有这个按钮（跟站点的 review 权限一致）。
- **从告警过来**：报警队列每一行（狗的告警）多一个 `Recording` 链接，直达那台狗、告警前 10 秒；录像页下面也列出这一天的告警，每条能「从前 10 秒放」。地址形如 `#/recordings?robot=A&t=<毫秒>`，能收藏、能发给别人。
- **状态说清楚**：没开录像的站点、列表没读到、这一天没有录像、这一段放不了（可能删了），各有一句话，不留一块黑屏。

站点：

- `/api/recordings/<id>/video` 认 `Range: bytes=…`：只发要的那一段（206，带 `Content-Range`、`Accept-Ranges`），够不着回 416；不带、看不懂、一次要好几段都照旧整份发。浏览器拖进度靠它。照片、导出包不变。
- `tools/site_demo.py --recordings N`：往演示站点放 N 分钟的假录像（ffmpeg 测试图，前后两路，中间留 5 分钟空档），看录像页用。

界面上没有用内联样式（站点的内容安全策略不许），时间轴是 SVG。

## 验证

- 网页 32 条通过（新增 7 条：一天的范围、排序、并段与总时长、哪一段盖住哪一刻、上下段、轴坐标与告警链接、谁能标留着）。
- 站点：`Range` 解析 17 种写法、真 HTTP 取段（跨 64 KB 块、最后几个字节、够不着 416、多段整份发）。
- 浏览器实测（演示站点 + 90 分钟假录像，Chromium）：列表 85 段；点时间轴从那一刻放；深链接放到指定时刻（差 3 秒以内，是页面加载的时间）；换前后接着同一刻；4× 下自动接下一段；标留着后按钮变成「Stop keeping」；1440 和 800 宽都看过。
- Python 本地只跑了受影响的几个文件（录像、W30、网页静态文件、设计常量），全部通过。**本地全量没跑完**：两次跑到一半开发机都重启了（原因没查清，不确定跟测试有没有关系），所以全量以 CI 为准。

## 没做的

- **报表页（Reports）**还是灰的：内容要先定。
- **真录像没验**：狗上录的 H.264 分段在浏览器里能不能放、拖动顺不顺，只用 ffmpeg 生成的测试片验过。
- 多路同步回放（前后并排）、导出一个片段、逐帧、缩放时间轴（现在固定一天一屏，一段 60 秒在 1440 宽的屏上是 1 像素）。
- 告警记号只取站点最近 500 条告警里这一天的；更早的日子可能没有记号。
- 手机 App 的录像页没动。

## 升级注意

库结构没变（53）。只升站点即可；老 App 不受影响。
