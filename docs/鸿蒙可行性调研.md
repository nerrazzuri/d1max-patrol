# 鸿蒙版手机 App 可行性调研（RC 加固 H14，2026-10-14）

> 范围：只做调研，**没有鸿蒙工程、没装 DevEco / ohpm / hvigor、没登录华为账号、没有鸿蒙手机**。
> 网上查的都是公开资料，每条后面带出处；没查实的写「未确认」，自己推的写「推断」。
> 本机实测的（第二节）是在桌面机上做的：克隆了鸿蒙版 Flutter，在**副本**上跑了 `pub get`、`analyze`、`test`，
> 仓库里钉的 Flutter（3.47.5）和 `mobile/` 都没动。

## 一、结论先说

- **能做，但不是「再编一个包」**：鸿蒙 NEXT（HarmonyOS 5 起）不跑安卓包，要用社区维护的鸿蒙版 Flutter
  （OpenHarmony 的 Flutter 分支）重新编出 HAP，插件要换成有鸿蒙实现的版本，原生那一块（后台值守、推送）要用
  ArkTS 重写。纯 Dart 的部分（界面、网络、证书钉扎、MJPEG 解帧）基本能原样用。
- **版本差一截**：鸿蒙版 Flutter 最新的正式标签是 3.41.10（Dart 3.11.5），我们钉的是 3.47.5（Dart 3.13）。
  实测：把 `sdk` 放到 `^3.11.0`、`video_player` 退到 `^2.10.0` 之后，**整个 App 用鸿蒙版 Flutter 能解依赖、
  `flutter analyze` 零问题、测试除两条跟副本有关的都过**（第二节）。也就是 Dart 代码这一层没有挡路的东西。
- **难点在插件和原生**：扫码（`mobile_scanner`）没有可靠的鸿蒙版；分享、另存只有个人维护、很久没更新的移植；
  后台常连站点（安卓的前台服务 `WatchService`）在鸿蒙上**很可能不被允许**，P1 告警要靠推送（Push Kit / 极光鸿蒙版）。
- **要先有的东西**：华为开发者账号（实名）、一台 HarmonyOS 5+ 的真机、AppGallery Connect 里的应用和签名材料。
  这些没有之前，只能做到「编得过」，验不了扫码、视频、推送、后台。
- **一周样品**：有账号和真机以后，**5–7 个工作日**做出能登录、看告警、看视频、扫码配对、收推送的样品
  （第八节）；后台值守那一块只做「推送兜底」，不做常连。
- **市场提醒**：鸿蒙 NEXT 目前主要在中国大陆的华为手机上；马来西亚首个客户用的华为手机大概率还是能跑安卓包的
  老系统或海外版（推断，见第九节）。先确认客户手里是什么系统，再决定要不要真开鸿蒙版。

`jpush_flutter` 的鸿蒙实现看的是本机 pub 缓存里 3.5.8 的源码。

**Dart 这边要改的地方（推断，按现在的代码）**：`Platform.isAndroid` 在鸿蒙上是假，下面几处要多认一个鸿蒙：

- `lib/net/push.dart`：`JPushRegistrar.supported`、`defaultPush()` 现在只认安卓（H13 刚改的），鸿蒙要加上；
  `platform` 报 `harmony`（站点那头的平台名注释里已经留了 `harmony`）。
- `lib/ui/site_add.dart`：能不能扫码只认安卓、iOS。
- `lib/ui/site_health.dart`：「分享」按钮只在安卓、iOS 显示。
- `lib/net/background_watch.dart`：只认安卓（鸿蒙先不做，见第五节）。

怎么判断是鸿蒙：社区文章说鸿蒙版 Dart 的 `Platform.operatingSystem` 是 `'ohos'`；`Platform.isOhos` 只有鸿蒙版
Flutter 才有，用了别的 Flutter 就编不过；建议用 `defaultTargetPlatform == TargetPlatform.ohos` 或比字符串
（<https://juejin.cn/post/7521004625387028516>）。主线还要能用官方 Flutter 编，所以**只用比字符串**
（`Platform.operatingSystem == 'ohos'`）。未在真机上确认。

## 五、安卓原生代码和鸿蒙的对应

`mobile/android/app/src/main/kotlin/` 里的东西：

| 安卓 | 干什么 | 鸿蒙上怎么办 |
|---|---|---|
| `MainActivity.kt` 的 `d1max/watch` 通道 + `WatchService.kt`（前台服务）+ `AlertBell.kt` | 后台值守：App 被划掉也常连站点告警流，P1 弹通知，响铃那一档闹钟声响到站点说确认 | 鸿蒙的应用退后台会被挂起，挂起后用不了网络；能常驻的「长时任务」要在 `module.json5` 声明类型、申请 `KEEP_BACKGROUND_RUNNING`，给的是音频、定位、蓝牙这类用户看得见的业务（<https://bbs.huaweicloud.com/blogs/479604>、<https://bbs.huaweicloud.com/blogs/448674>）。**「常连一个网络服务等告警」不在这些类型里**（推断，官方类型表没查全）。所以鸿蒙版**不做后台常连**，P1 靠推送；`AlertBell` 的判断逻辑（只有站点说确认了才收）要在推送那头重想 |
| `MainActivity.kt` 的 `d1max/push` 通道 + `FcmToken.kt` | FCM 推送号 | 鸿蒙没有 Google 服务，FCM 用不了。用华为 **Push Kit**：`pushService.getToken()`（`@kit.PushKit`），前提是在 AppGallery Connect 开通推送服务（<https://help.aliyun.com/zh/document_detail/2803626.html>、<https://www.tencentcloud.com/document/product/1047/72237>）。或者直接用极光鸿蒙版（底层也是走 Push Kit）。站点那头要么加一个「华为推送」通道，要么只走极光（推荐后者：站点已经能推极光） |
| `MainActivity.shouldHandleDeeplinking` | 点推送拉起 App 时别当深链接 | 极光鸿蒙版要在 `EntryAbility.ets` 的 `onCreate` / `onNewWant` 里调 `setClickWant`（`jpush_flutter` 的 `README_Harmony.md`） |
| 通知权限、省电白名单（`askOnce`） | 弹通知、别被省电杀 | 鸿蒙要请求通知授权；没有「省电白名单」这回事（推断） |

**推送的分类要注意**：华为推送按消息分类管，没申请「自分类权益」的应用，通知默认算「资讯营销」，有每日条数上限；
可选的分类里有「设备提醒」「工作提醒」等，**没有「紧急 / 报警」类**（<https://help.aliyun.com/zh/document_detail/2835878.html>，
第三方文档转述；华为原文未查到）。入侵告警算哪一类、能不能响铃到确认，要申请权益时跟华为确认。

## 六、网络、证书钉扎、视频

- **证书钉扎**：我们连站点全走 `dart:io` 的 `HttpClient(context: SecurityContext(withTrustedRoots: false))`，
  每张证书都过 `badCertificateCallback` 比 SHA-256（`lib/net/site_client.dart`）。这一层是 Dart 运行时自带的
  TLS，不走系统网络库，所以鸿蒙上**应该照样工作**（推断；第二节的测试在 Linux 上跑过，真机没验）。
- **鸿蒙的网络权限**：要在 `module.json5` 里声明 `ohos.permission.INTERNET`（推断，按鸿蒙应用的常规；未逐条查）。
  是否像 iOS 那样有「本地网络」弹窗：**未确认**。
- **实时画面**：MJPEG 是我们自己在 Dart 里分帧、`Image.memory` 逐帧画（`lib/ui/widget/live_video.dart`），
  不依赖平台播放器，应该能用（推断）。
- **录像**：下到本地再用 `video_player` 放 MP4（H.264）。鸿蒙版 `video_player` 底层换成鸿蒙的播放器，H.264 本地文件
  能不能放、拖动准不准，要真机验（未确认）。
- **SSE 告警流、遥控**：纯 Dart 的长连接，前台时应该没问题（推断）；退后台被挂起后会断（见第五节）。
- **字体**：我们打包了 Space Grotesk / Inter / JetBrains Mono，中文落到系统字体；鸿蒙系统中文字体是 HarmonyOS Sans
  （推断），排版要过一遍。

## 九、风险

1. **鸿蒙版 Flutter 落后主线**：现在差 3.41 → 3.47 两个大版本，以后每次升 Flutter 都要等它跟上；鸿蒙分支要长期维护。
   维护方刚从 openharmony-tpc 换到 CPF-Flutter（第三节），**社区项目，不是 Google 也不是华为官方产品**。
2. **插件移植质量**：扫码、分享、另存都只有个人 / 久未更新的移植，样品里要自己写原生小插件（ArkTS），以后多一份要维护的代码。
3. **后台告警**：没有安卓那样的前台服务常连，P1 只能靠推送；推送有分类和条数限制、没有「报警」类（第五节），
   能不能像安卓那样响到有人确认，**不确定**。这是值守 App 的核心功能，是最大的风险。
4. **账号和合规**：华为开发者实名、AGC 建应用受名单管控、上架审核；全在用户手里，时间不可控。
5. **市场**：鸿蒙 NEXT 不再兼容安卓应用，目前重心在中国大陆，海外推广没有确定时间
   （<https://www.scmp.com/tech/tech-war/article/3288398/huawei-has-global-ambitions-pure-blood-os-china-focus-now>）。
   首个客户在马来西亚，客户的华为手机多半还能装安卓包（推断）——**先问客户再投入**。
6. **下载源在国内**：鸿蒙版 Flutter 的 Dart SDK、引擎从华为云 OBS（华南）下（第二节实测），海外 CI 上可能慢；
   鸿蒙 SDK 要登录下，**没法放进 GitHub Actions 公开跑**（推断）。
