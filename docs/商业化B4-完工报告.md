# 商业化 B4：手机体检页、诊断包、App 版本号上报 完工报告

2026-10-11。台账 C-B4。这三项是 A 阶段（A1 体检、A7 版本兼容）在手机上留下的尾巴。

## 做了什么

### App 版本号上报

- App 登录时多带一段 `client`：`{kind: "app", version, api_level, platform}`。版本号是 App 里的常量 `appVersion`，测试核着它跟 `pubspec.yaml` 一致。
- 站点把它记在这次会话上（`sessions.client`，**库结构 54**，老库自动补列）。只认四样：类别（app / web）、版本和系统（字母数字和 `.+_-`，最长 32）、接口级别（0–9999 的整数）；别的丢掉。看不懂的不记，**不挡登录**（老 App 不报，照样登）。
- 网页登录（种 cookie 的那种）一律记成 web，不看它自己报什么；App 的登录报成 web 的不记。
- 这是客户端自己报的，**只拿来给人看**，站点不拿它做任何判断（配不配仍然是登录时那两个接口级别说了算）。
- 哪里看：`GET /api/versions` 多一段 `clients`（带账号名，**只给管理员**）—— 还有效的登录各是谁、哪一版、最后用的时刻；退出了、过期了、账号停用了的不列。值班台 System 页和手机体检页都列出来，App 报的接口级别比站点要的低就标「太老」。

### 手机上的站点体检页

管理员的菜单里多一项「站点体检 / Site health」（保安、业主没有）。

- 整体一句话：各项都正常 / 有几项要看一下 / 站点有要紧的问题，下面是站点版本。
- 每一项检查：名字、过没过、站点给的明细。没过的排前面，要紧的（库、事件循环、消息服务、盘）最前；要紧的没过用 P1 的形状和颜色，别的没过用 P2，过了的不上色。不认得的检查项原样摆。
- 狗上的软件：每台狗的代理版本、兼容级别、在不在线、跟站点配不配。
- 登录着的 App（同上）。
- 读不到就说读不到，**不拿上一次读到的当现在的**；先发的查询后到会丢掉。

### 手机保存诊断包

体检页最下面「保存诊断包」：从站点取 `.tar.gz`，按当地时间起名（`d1max-support-20261011-020409.tar.gz`），存到下载目录（安卓上是这个 App 自己的外部文件目录；没有下载目录的平台存到文档目录），页面上写存到哪儿了、多大（路径能长按复制）。取不到、存不下都说出来。

## 验证

- 站点 27 条（`test_site_clients.py` 26 条 + 网页登录 1 条）：收拾 `client` 的 21 种写法；最近用过的在前；退出、过期（含正好到期那一刻）、停用；库里那一格坏了跳过；53 → 54 老库补列且老会话照样能用；真 HTTP 下管理员看得到名单、保安看不到、冒充 web 的不记、乱报的照样登录。
- 手机 475 条通过（新增 12 条：版本号跟 pubspec 一致、登录报文、文件名、都正常、要紧项没过的排序与形状、只有不要紧的没过、狗太老 / App 太老、读不到、读到过后来读不到、保存、取不到 / 存不下、入口按角色）；体检页进了版面矩阵（竖屏 / 横屏 × 英文 / 中文不溢出）。
- 网页 60 条通过，构建产物已更新。
- 本地 Python 只跑了受影响的文件，全量以 CI 为准（开发机此前两次在全量中途重启，原因没查清）。

## 没做的

- **真机没验**：安卓上那个下载目录在文件管理器里好不好找、要不要权限，只在开发机上验过。
- 没接系统的分享面板（存完直接发微信 / 邮件）：要加插件，另说。
- iOS 没有工程。
- 站点给的体检明细是中文，英文界面会夹着中文。
- 老 App（这一版之前的）不报版本，名单里看不到它们 —— 名单是「报了的」，不是「全部登录」。

## 升级注意

- **库结构 53 → 54**（`sessions` 多一列）。站点升级时自动补；升了之后老版本站点程序打不开这个库（防回滚的老规矩），回退要用升级前的备份。
- 站点和 App 没有先后要求：新 App 连老站点，多带的 `client` 老站点不看；老 App 连新站点照样登录，只是名单里没有它。
