# P1 告警推送（极光）配置

> 商业化 A6（决策 53）。给交付、运维的人看。技术细节见 `docs/商业化A6-完工报告.md`。

## 推什么

- **只推 P1**：入侵、狗看见人了、狗翻倒了、狗被抱起来了……。P2 只在 App 里看。
- **只推标题**：通知上是「<站点名> · P1」加告警标题，**不带照片和位置**。点开通知进 App 看详情。
- 新起一条推一次；**没人确认、升档**时再推一次。有人确认或解决了就不推了。
- 推给**进了这个站点**的手机：手机登录站点就登记，离开站点（退出登录）就注销。

推送跟 App 的后台值守（W17）是两条路，互为兜底：
- **后台值守**：App 自己连着站点；
- **推送**：站点经极光推过来。手机厂商的省电管理把 App 杀掉时，推送还能到。

## 一、注册极光（一次）

1. 在 [极光官网](https://www.jiguang.cn/) 注册开发者账号，建一个应用：
   - 应用包名填 `com.d1max.d1max_patrol`；
   - 拿到 **AppKey** 和 **Master Secret**。
2. **厂商通道**（App 被清掉以后也收得到，强烈建议配）。要**两头都配**：
   - 在小米、华为、荣耀、OPPO、vivo 各自的开发者平台注册，建应用，拿到推送参数；
   - 把参数填进极光控制台的「厂商通道」；
   - **打包时也要给**（见第三节）：App 里要带上那一家的极光厂商插件和参数，光填控制台不够。
   - 首批支持这五家。没配厂商通道时，只有极光自己的长连接：App 在后台活着能收到，被系统清掉以后**不保证**收到。系统设置里「强行停止」的 App 任何推送都收不到，这是系统规定。

## 二、站点上配（每个站点）

1. Master Secret 放到站点主机上：

   ```sh
   echo '<Master Secret>' | sudo tee /etc/d1max-site/jpush.secret >/dev/null
   sudo chown root:d1max-site /etc/d1max-site/jpush.secret
   sudo chmod 0440 /etc/d1max-site/jpush.secret
   ```

   跟另外三把密钥一样，**离线另存一份**。它不在备份里，恢复到新主机时要放回去。
2. 在 `/var/lib/d1max-site/site.json` 里加：

   ```json
   "push": {"provider": "jpush", "app_key": "<AppKey>"},
   "site_name": "翠湖庄园"
   ```

   `site_name` 是通知上显示的站点名，不写就用站点号。
3. 重启站点：`sudo systemctl restart d1max-site`。
4. 看手机上的值守汇总：「推送」那一项是**已配**，有几台手机登记了。

站点要**能上外网**（访问 `api.jpush.cn`）。上不了外网时推送发不出去：
- 连续 10 分钟发不出去，报 **P2「P1 告警推送发不出去」**；
- 发出去一条，自动解决；
- 一个小时还没发出去的推送作废（那时再推已经没意义）。

## 三、App 打包（每个版本）

AppKey 打包时给，**不进仓库**：

```sh
flutter build apk --release -PjpushAppKey=<AppKey> --dart-define=JPUSH_APPKEY=<AppKey> \
    -PjpushXiaomiAppId=<小米 AppID> -PjpushXiaomiAppKey=<小米 AppKey> \
    -PjpushOppoAppKey=<OPPO AppKey> -PjpushOppoAppId=<OPPO AppID> -PjpushOppoAppSecret=<OPPO AppSecret> \
    -PjpushVivoAppKey=<vivo AppKey> -PjpushVivoAppId=<vivo AppID> \
    -PjpushHonorAppId=<荣耀 AppID>
```

- 华为：把华为开发者平台下载的 `agconnect-services.json` 放到 `mobile/android/app/` 下（**不进仓库**）。有这个文件才接华为的插件和构建插件。
- 给了哪一家的参数才带哪一家的插件；没给的那家不带。小米的值前面要加的 `MI-`、OPPO 的 `OP-`，打包脚本会自己加，不用手写。
- 这些参数也可以写进打包机的 `~/.gradle/gradle.properties`（`jpushAppKey=…`、`jpushXiaomiAppId=…` 等）。
- 没给 AppKey 打出来的包照常能用，只是收不到推送。

App 进了站点以后，标题栏上有一个推送的小图标：
- 绿色：P1 推送已就绪；
- 橙色：还没就绪，按住能看到原因，比如没配极光、还在注册、登记没成。

没就绪时 App 会自己一直重试（最长一分钟一次），不用退出重登。

## 四、验收

1. 手机装上带 AppKey 的包，登录站点。
2. 站点上制造一条 P1，比如在测试环境里让狗报一次「看见人」。
3. 看三种情况都收到通知：
   - App 在前台；
   - App 在后台；
   - 把 App 划掉。没配厂商通道时，这一种收不到。
4. 确认告警后再制造一条，升档时那一次推送不该再来。
5. 退出站点后再制造一条，这部手机不该再收到。
6. **每家厂商各拿一台手机**：分别在前台、后台、划掉（或被系统回收）三种情况下各收一次。
7. 打出来的包里查一下带上了哪几家：解开 APK 的 `AndroidManifest.xml`，看有没有对应厂商的组件和参数。
