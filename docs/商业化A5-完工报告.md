# 商业化 A5 · 自带算力板（软件准备）· 设计与完工报告

> 决策 50：产品带自己的上装算力板（首选 Orin NX 16GB），厂商 Orin 只当传感器和运动的网关。**板子还没买**，先量功耗、量链路。这一单把板子到之前**能做的软件**做完。板子到了以后的采购、装机、RTK 接线不在这一单。方案见 `docs/自带算力板方案.md`。

## 结论先说

我们的东西搬到自己的板子上，**只有一样要跨机器：雷达、相机话题**。其余几样都跟着我们的板子走，不用改：
- **旁路进程**：本来就是用 UDP 直连运动控制器（192.168.168.168:8082），不经厂商 Orin；
- **代理和定位器那几个**：之间走的是本机套接字。

竞品的上装就是这么接的：一台单独的电脑，经狗内网收狗的数据。

## 做了什么

1. **`d1max-zenohd`**（`deploy/d1max-zenohd-start` + 单元）：
   - `/etc/d1max/env` 填了 `D1MAX_GATEWAY` 才起（`ExecCondition`），往外只连网关的 zenoh 路由；
   - **只在 127.0.0.1 听**，狗内网别的机器连不进来；
   - 值按字面量读、不 source，不干净就拒（跟对时脚本一个规矩）；
   - 装机只装不 enable，卸载删干净；定位器、感知、人员检测、雷达合并都排在它后面起；
   - 没填网关，就是装在厂商 Orin 上的老样子，什么都不变。
2. **出厂自检加「网关」**：填了网关的板子，连不上网关的 zenoh 端口 → FAIL；没填不查。
3. **`tools/a5_link_bench.py`**：在另一台机器上收狗的雷达话题，量帧率、带宽、延迟、断档。
   - 两只狗上雷达的时间戳跟 Orin 的钟都差了两百多天，所以钟对不上时自动改看**抖动**：每帧延迟减最快那一帧。
4. **`tools/a5_power.py`**：读 `tegrastats` 日志，出整板功耗平均 / p95 / 峰值、CPU（关掉的核不算）、最忙的核、内存、交换区、GPU。
   - AGX Orin 没有整板那一路，就把分路加起来，并注明偏小；
   - 给了预算，超了退出码 1。
5. 方案文档 `docs/自带算力板方案.md`：谁跑在哪、板子到之前量什么、到了以后做什么。真机清单加 §3s（5 项，不用控制狗）。

## 测试

- **路由**：
  - 没填网关不起；填了起，配置里连网关、端口可改；
  - 只在本机听（不出现 `[::]`）；
  - 网关地址、端口值不干净 → 退出码 4。
- **单元**：有条件才起；只装不启用；四个吃话题的单元排在它后面。装机、卸载声明的路径对得上，卸载时先停吃话题的，再停路由。
- **自检**：没填网关不探；填了探的是网关的 7447；连不上 FAIL，并带上原因。
- **链路**：帧率、带宽、断档的计数；帧率门槛、延迟门槛；时间戳差两百天时按抖动判（抖得多 FAIL，放宽门槛 PASS）；一帧没收到 FAIL。
- **功耗**：Orin NX 的整板那一路、AGX 的分路相加；关掉的核不算；非 tegrastats 的行跳过；预算判定；用了交换区有提示。
- **突变**：9 条全抓住：没填也起、听所有网卡、值不查、网关不查、钟差不认、断档不数、不加分路、关的核算 0、预算不判。

## 没做的（等板子、等真机）

- 买板子、载板、电源、外壳：等 §3s 量出来的功耗和链路。
- RTK 串口怎么到我们的板子上：直接接线（首选）或者网关上转 TCP，等 RTK 那一单。
- 定位器用的是收到的时刻还是报文时间戳：两台机器分开以后要在真机上复核。
- 人员检测改用 Orin NX 的 GPU：板子到了再做。
