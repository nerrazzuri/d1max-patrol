## 交付

- **三个角色**（`permissions.py`）：admin（一切）、guard（看、派单、叫停）、owner（看、叫停）。站点 API 每条路由声明所需权限，不够回 403；SSE 按周期重查令牌与角色。
- **账号管理**：API `GET/POST /api/accounts`、`POST /api/accounts/<name>`（`role`/`disabled`/`password` 一次改多项，**先全部校验、一个事务提交**）、`POST /api/me/password`（要旧口令）；CLI `add-account --role`、`set-role`、`disable`、`enable`（`add-admin` 保留）。每次改动吊销这个账号的全部会话；**最后一个启用的 admin 不能停用、不能降级**；停用账号的令牌立刻作废、登录与错口令同一个说法。
- **审计**（`audit.py`、`GET /api/audit`，admin）：登录成功与失败、注销、每一次改动类请求：谁、动作、对象、结果、来源地址、净化过的细节（派单带 `command_id`；账号改动带改成了什么；**从不带口令**）。

## 设计取舍

1. **遥控转发不在这一张**（决定二 A，不代拍）：待人拍板第 7 条确认后另开。
2. **审计不记未登录的乱请求**（任何人都能发，记下来只会把表撑满）；登录失败与事件回调照记。审计没有保留期限（单站点、量小），没有防篡改链（决定三 A）。
3. **按账号名锁定**（W00c1 起）：连错 5 次锁 5 分钟，猜旧口令也计入。代价：任何人都能把某个管理员锁 5 分钟；恢复办法是等 5 分钟或重启 `d1max-site`（锁在内存里）。按「名字 + 来源地址」锁会让分布式猜口令变容易，没改。
4. **管理员不能从账号接口重设自己的口令**，要走 `/api/me/password`（要旧口令）：偷到管理员令牌的人不能靠它把账号永久改走。
5. **`Principal` 是 `str` 的子类**（名字 + 角色）：老调用把它当名字用不受影响；派单的 `issued_by` 存的是纯字符串。

## 测试与突变

`test_site_roles.py`（14 条）、`test_site_accounts.py`、`test_site_cli.py`（账号命令行 1 条）。突变 14 条全红：业主能派单、保安能管待命点、改角色不吊销会话、停用了令牌还能用、最后一个 admin 能停用、不记审计、改口令不验旧口令、停用的还能登录、逐项提交、审计不写细节、能从账号接口改自己口令、旧口令不计锁、未登录也记、Principal 不能 pickle。其中「停用了令牌还能用」起初活了（停用时也删会话，两道都在），加了「直接改库停用、会话还在」的测试后红；「未登录也记」起初活了（测试查的演员名写错了），改正后红。
