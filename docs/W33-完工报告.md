## 第一个 PR

### 只许手动派（停用开关，决策 49）

C40221 现场：入侵派遣把笔记本上的**真狗代理**（新登记的测试身份 `C40221L`）当成离得最近的狗派走了，真狗没经确认走了约 1 m、掉了头。站点当时分不清哪台是测试狗。

- 站点给每台狗一个「只许手动派」标记（`robot_service` 表，库结构 36 版）。打上以后，**站点自己发起的动作一律不派**：
  - 排程巡检：记 `supervised`，理由写「站点设成只许手动派」；
  - 入侵派遣：理由同上；
  - 自动回充；
  - 任务完了自动回待命点：安静地不回，不报「没回去」。
- **人手动派的照常**：goto、回待命点、遥控。要不要人在现场监护，还是按狗自己报的自主级别算，跟以前一样。
- **新登记的狗默认打上**：站点命令行 `enroll` 时打上，标记写「新登记：确认之前只许手动派」。
- 怎么改：
  - 命令行：`robot-auto <狗>` 接自动派遣，`robot-manual <狗> [--note …]` 设成只许手动；都记审计。
  - 接口：`POST /api/robots/<id>/service {manual_only, note?}`。
    - 设成只许手动要 `dispatch`：保安能关，往安全那边走；
    - 接自动派遣要 `manage`：管理员确认。
- `GET /api/robots` 每台狗多一项 `manual_only`（`{by, at_ms, note}` 或 `null`）。

### W32 退版不能退成起不来（决策 47）

`/etc/d1max/env` 的 `D1MAX_AGENT_ARGS` 是整机的，不跟版本走。新版加的参数，退回老版时老版不认，狗就一直崩。

- 启动脚本不再把这串摊在命令行上，改成整串交给代理：`--env-args=<串>`。
- 代理逐个参数过一遍：
  - 这一版认识的照用，接在命令行最后：写在后面的盖前面的，跟以前一样；
  - **不认识的连同后面跟着的值一起跳过**，日志警告；起来以后记一条事件 `agent_args_skipped`，站点报 **P2**「狗上的代理有几个启动参数这一版不认识，跳过了」。
- **命令行上直接给的不认识参数照旧拒**：那是人刚敲的，要当场知道。
- 顺手修了一个老问题：横线开头的值（`--home -1,2,0`）以前 argparse 会当成参数、起不来。现在拆的时候合成 `--home=-1,2,0`。
- 只对带这段逻辑的版本有效：**从这一版往后退，都退得起来**。已经装在狗上的老版本还是老脚本。

## 第一个 PR 外审（2026-10-08）：FIX-THEN-APPROVE，1 条阻断，已修

**已有流程会绕过「只许手动派」。** 回充只在起新一轮时看开关；已经走到桩前（`arrived`）、被打断待接着充（`resume`）的，照样自动派对桩、去桩。雷暴撤巡检后的回程也不看开关。

修法：站点自己发起的动作，**发之前一律再问一次**（派遣器加 `check_auto`）：
- 回充：去桩、对桩发之前都看开关。只许手动时这一轮的进度留着，改回接自动派遣再接着办；狗上正在跑的对桩、出桩不受影响，出桩是狗自己的事。
- 雷暴回程：只许手动的回不得，狗原地等，报「没回待命点」，跟原来「不能安全回」一样。
- 顺手查了别的站点自己发起的动作，一并补上：
  - 事件派遣：占位之后、发之前改了开关，也拦下，记派失败、提升排着的事件；
  - 驱离：不再新派保持距离；收场后不自动回待命点。
- **撤、停照旧**：驱离收场撤保持距离、人点的中止都不经过这道开关。

补的测试：
- 走到桩前之后改成只许手动：不续派对桩，改回来接着派；
- 被打断待接着充时改成只许手动：不再去桩；
- 只许手动的狗，雷暴回程也不派；
- 事件占位之后、发之前改了开关：不派，记派失败；
- 驱离中改成只许手动：不再新派保持距离，收场照撤，但不自动回待命点。

突变 6 条全抓住：回充续去桩不查、续对桩不查、雷暴回程不查、收场回程不查、新派保持距离不查、事件发之前不查。

## 第一个 PR 外审复查（2026-10-08）：FIX-THEN-APPROVE，剩 1 条，已修

**自动回待命点的重试仍会绕过「只许手动派」。** 任务结束后自动回程，碰上状态不新鲜、钟差还不知道之类暂时派不了，等 2 秒再试；等的时候保安改成只许手动，下一次照样发出回程。`_auto` 只在入口查了一次，`_dispatch_back` 每次重试没再查。

修法：`_dispatch_back` 每次（包括等了再试的）发之前再看开关。只许手动了就安静地不回，跟入口一样，不报「没回去」；人手动叫回照收。

另外查了站点别的重试路径：雷暴回程、回充重发、保持距离补派、事件派遣，每次都经过已经加了检查的那几个函数，这是唯一一处漏的。

补的测试：回程等着重试的时候改成只许手动，下一次不发、也不报没回去，人手动叫回照收。改之前同一个场景发了两次 goto。
