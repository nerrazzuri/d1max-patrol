# 第一部分 · 友商上装（anbot，ROS1）

查法：上装开着 ROS1 的 master（`11311`），只读问了它「有哪些节点、话题、服务」（XML-RPC `getSystemState`、
`getTopicTypes`），没有登录，也没有往它上面注册任何东西。另外它开着 SSH、网页（80/443）、RTSP（554）、9090。

**怎么拿到狗的传感器**：Orin 上有人放了 `~/bridge_start.sh`，用 `ros1_bridge` 把 ROS2 的 `/front_lidar`、`/rear_lidar`
及雷达 IMU 桥到上装的 ROS1（`ROS_MASTER_URI=http://192.168.113.203:11311`）。上装自己也跑着 `rslidar_sdk_node`、
`gnw_imu_node`（它自己的 IMU，`/imu/data_can`），还留着 `/livox/lidar`（没有发布者）。

**节点（23 个）里跟定位、建图有关的**：

| 节点 | 发什么 | 是什么 |
|---|---|---|
| `lio_node` | `/lio/odom/body`、`/odom`、`/lio/global_map`、`/lio/cloud_registered`，消息包叫 `super_lio` | **激光惯导里程计**（推断：Super-LIO 一类，FAST-LIO 系的改进版），兼建点云地图 |
| `map_manage` | `/map`（2D 栅格）、`/mapcloud`（3D 点云）、`/mapvoxel`、`/elevation_map`（高程图） | 地图管理：**同一张图出 2D 栅格 + 3D 点云 + 高程图** |
| `oneway_amcl` | `/amcl_pose`、`/localscore`、`/amcl/lost`、`/oneway_amcl/matched`·`unmatched`（点云） | **粒子滤波定位（AMCL），在 3D 点云上匹配**；有匹配分、「丢了」信号；`/amcl/odom_mode` 能切里程来源 |
| `loc_refine` | `/initialpose`、`/loc_refine/request`·`response` | 定位精修 / 重定位：给个大概位置，它配准后回一个准的 |
| `ground_segment` | `/cloudGroundNav`、`/cloudNonGroundLoc`、`/ground_segment/fall_detected`、`fall_zone/*` | 地面分割；**自动检测「落差」（台阶下沿、坑）**；`lidar_tag_filtered` 推断是用雷达反射率认充电桩上的反光标 |
| `core_local_planner` | NavfnROS 全局 + **TEB** 局部规划、代价图 | ROS1 `move_base` 那一套 |
| `nmea_gps_driver` | `/gps/navsatfix` | **RTK/GNSS 走 NMEA**（推断：上装自带接收机） |

**RTK 怎么用**：
- `nmea_gps_driver` 出 `/gps/navsatfix`；`/gps/map_calibration` 加 `/gps/map_calibration_return` 是**地图跟经纬度对齐**
  （标定一次，地图就有了地理坐标）；`/gpsPara` 是参数；`/odometry/gps`、`/gnssStatus` 有话题、此刻没有发布者。
- 推断：RTK 用来**给地图做地理标定**，必要时当定位源（`/amcl/odom_mode` 能切）；不是像厂家那样塞进位姿图。

**建图流程（推断）**：手机 App（`/android/makemap_return`、`/android/uploadmap`）发起；`lio_node` 边走边出点云
地图；`map_manage` 存成 2D、3D 和高程；定位时用 `oneway_amcl` 在这张图上做粒子滤波。

**值得借鉴的**：
1. **定位用「粒子滤波 + 3D 点云匹配」，再加匹配分和「丢了」信号**：玻璃、对称场地里比单次 ICP 稳。
   2026-09-21 展厅的结论就是「产品级要粒子滤波 + 标记纠偏」。
2. **落差自动检测**（`fall_detected`）：我们现在靠人在图上画落差禁行区（W10），可以加一层实时的。
3. **一张图出三种**（2D 栅格、3D 点云、高程）：规划用 2D、定位用 3D、过坎用高程。
4. **RTK 做地图地理标定**：跟我们 W09e 的方向接近，可以对照。

# 第二部分 · 狗厂家（智元）自带的导航模块（Orin 上的 `/opt/robot`）

## 一、在跑的东西

| 进程 | 是什么 |
|---|---|
| `robot_slam` | 建图（SLAM）主程序，`/opt/robot/robot_slam` |
| `robot_localization` | 同一套算法的**定位模式**（在建好的图上匹配），参数文件跟建图几乎一样 |
| `arc_mapping` | 建图任务的编排层：订前后雷达、IMU、相机、RTK、充电桩，出「电子地图」 |
| `apriltag_localization_node` | **AprilTag 二维码定位**（配置 `apriltag_localization_pc_config_middle_dog.yaml`） |
| `sixents_gps_driver`、`gpsd` | 六分 RTK 模块（LK1220D）的驱动，发 `/gps/rtk` |
| `navigo_*`（`/opt/robot/robot_nav`） | 导航：Nav2 改的一套，规划器、控制器、代价图、碰撞监控、行为树 |

参数文件名叫 `nx_zg_rtk.yaml`（推断：NX = Orin NX，zg = 智元/中光之类的缩写，rtk = 带 RTK 的那一版配置）。

## 二、建图算法：激光惯导里程计 + 关键帧位姿图 + 回环

**前端（逐帧）**：参数名跟 FAST-LIO 一模一样（`filter_size_surf` 0.2 m 体素降采样、`max_iters` 2 次迭代卡尔曼、
`estimate_extrinsic_flag`、`recontruct_kdtree_flag` 增量 kd 树、`use_undistort_flag` 运动去畸变），IMU 用的是
雷达自带的 `/front_lidar/imu`。**推断：前端是 FAST-LIO 一类的「激光 + IMU 紧耦合」里程计。**

**后端（全局一致）**：
- 关键帧：每走 0.2 m 或转 0.2 rad 存一帧。
- 位姿图：链接了 `libgtsam`，库里有 `isam2` 的符号 —— **GTSAM iSAM2 增量优化**（LIO-SAM 的做法）。
- 回环：`loop_closure_flag: true`，在历史 25 个关键帧里找候选（分数过 0.8），ICP 精配（最多 300 次迭代）。
  `arc_mapping` 还有 `/manual_loop` 话题 —— **可以人工指定回环**。
- 库里有 DBoW（词袋）、`arc_mapping` 订相机图像且 `save_image_flag: true` —— **推断：关键帧带图像，
  用视觉词袋做回环候选或重定位**。
- 支持 Livox 和速腾（RoboSense）两种雷达；`arc_mapping` 前后两个雷达都订。

**定位**：`robot_localization` 在先验图上做同样的匹配；有「重定位管理器」（`RelocalizationManager`）和
`/relocalization` 话题 —— 开机或跟丢后能自己找回位置（推断：靠词袋/二维码出初值，再 ICP 精配）。

## 三、RTK：架子搭了，这台上没真用上

- **用了的部分**：六分 RTK 驱动、`gpsd` 都在跑；`arc_mapping` 订 `/gps/rtk`；SLAM 参数里有一整套 GNSS 因子
  （`gnss_noise`、`gnss_prior_noise`、`use_gnss_elevation_flag: true`、`gnss_factor_count_threshold: 4`、
  `gnss_distance_threshold: 0.3`）—— 设计上是 **把 RTK 当成位姿图里的 GNSS 因子**（LIO-SAM 的做法），
  用 RTK 把图「钉」到经纬度上、压住长距离漂移。
- **但是**：加因子的两个门槛 `add_gnss_factor_time_threshold`、`add_gnss_factor_distance_threshold` 设成了
  1e10、2.5e10，**实际上等于不加**（推断：这一版默认关着，开要改这两个数）。
- 这台狗**没装 RTK 天线**（2026-09-22 勘察：`/rtk_pvh` 有话题没数据），所以眼下怎么配都没有 RTK 解。

## 四、二维码与充电桩

- AprilTag：`tag36h11` 家族，单独一个定位节点在跑；`arc_mapping` 里 `use_dock: true`、`is_use_dock: true`。
- 推断：**充电桩上贴着二维码**，回充对准和「在桩前重定位」都靠它；场地里也可以多贴几张当地标。
- 这正好对上我们 2026-09-21 在玻璃展厅的结论：纯激光在玻璃、对称的地方会跳，**产品级要二维码/反光标纠偏**。

# 第三部分 · 跟 MOLA 比（待讨论）

## 狗厂家这套 vs MOLA

| | 厂家这套 | MOLA（我们现在的路线，3.2.0） |
|---|---|---|
| 前端 | 激光 + IMU 紧耦合（FAST-LIO 类） | 纯激光 ICP 里程计（IMU 可选） |
| 后端 | 关键帧 + iSAM2 位姿图 + 回环（自动 + 人工） | 建图主要是里程计 + 地图；回环/位姿图要另加 |
| RTK | 有 GNSS 因子的架子（这台默认关） | MOLA 3.x 有 GNSS 融合与地理参考 |
| 重定位 | 有重定位管理器、词袋、二维码 | 要我们自己做（人给初值，W09b） |
| 二维码 | 有 | 没有 |
| 开放 | 闭源，只有二进制和参数 | 开源（BSD），我们能改、能调 |
| 跟我们系统 | 输出 `/slam_odom`、电子地图格式未知 | 已经接好（W09b/W09c），有回放测试 |

几个要一起想的问题：

1. **能不能直接用厂家的定位**（订它的 `/odom/localization_odom` 或 `/slam_odom`），我们只做上层？省掉 MOLA，
   但地图格式、建图流程、出错时的诊断都在黑盒里；换一家狗就没了（我们的产品要能跨品牌）。
2. **借鉴而不换**：给 MOLA 这条线补上 IMU（四足晃动大，纯激光在快转时容易丢）、位姿图回环、二维码纠偏、
   开机自动重定位。
3. **RTK 怎么进**：厂家是「GNSS 因子进位姿图」；我们 W09e 的设计是什么样、要不要照这个改。
4. **对比实验**：同一只狗、同一条路线录一包，厂家建图 vs MOLA 建图，比回环处的误差和玻璃区的跳变。
5. **友商上装那套**（第一部分）跟 MOLA 的分工更像：它也是「LIO 里程计 + 在图上做定位」，只是定位用的是粒子滤波。
   我们的 W09b 用 MOLA 只定位，要不要换成或补上粒子滤波，是这次讨论的重点。
