# W45 站点 VPN（决策 71）

> 决策 71（2026-10-27 用户）：站点会联网（除非客户要求只在局域网），用**站点装 VPN**（WireGuard，不经公司服务器，画面不出家门）；断网不影响看家。
> 上装 V2 的路由器（USR-G806w-G）不支持 WireGuard，所以 WireGuard 客户端跑在机器人的 RK3588 上（W46 对照「三」）。
> 下面「我定的」是用户把细节交给我以后的取舍（2026-10-29）。

## 一、为什么要

- 机器人在 4G 上（WiFi 断了、在院子边上）连不回家里的站点：4G 没有公网地址，站点在家里的路由器后面。
- 业主、保安在外面用手机看站点：同样连不进来。
- WiFi 和 4G 来回切时，路由器的外网地址会变。WireGuard 会自己重新握手；**隧道里的地址不变**，代理的连接和视频都走隧道，所以不断。

## 二、怎么搭（我定的）

| 项 | 定的 |
|---|---|
| 隧道网段 | `172.29.70.0/24`（跟上装的 172.29.66/67 一个系列，避开现场 WiFi 常见的 192.168.0/1.x、10.0.0.x） |
| 站点 | `.1`；监听 UDP 51820（可改）；家里的路由器只把这一个 UDP 端口转发到站点主机 |
| 机器人 | `.10` 起，每台一个固定地址；只把隧道网段走隧道（上网、厂家的东西照旧走路由器）；每 25 秒保活一次（4G 的 NAT 不掐断） |
| 手机 | `.100` 起；WireGuard 应用导入配置 |
| 密钥 | 纯 Python 的 X25519 生成（RFC 7748，测试核着），每个机器人、手机还有一把预共享密钥；都在 `<站点目录>/vpn/`（目录 700、文件 600） |
| 站点证书 | 总带上 `172.29.70.1`（新站点初始化时自动带）；老站点要明着重签（见「四」） |

**站点的网页、登录页不直接对外**：路由器只转发 VPN 的 UDP 端口，外面的人看到的只有一个不回应的 UDP 端口（WireGuard 不认识的包一律不回）。

**只在局域网的站点照样完整可用**：VPN 是额外的一条路，不装、不开都不影响局域网里的机器人和手机。

## 三、装

### 站点主机（一次）

1. `sudo apt install wireguard-tools`
2. `d1max-site vpn init --endpoint <家里的域名或公网 IP>`（打出站点公钥；家里没有固定公网 IP 就配一个动态域名）
3. 家里的路由器：UDP 51820 → 站点主机。
4. `d1max-site vpn server-conf > /tmp/d1max.conf && sudo install -m 600 /tmp/d1max.conf /etc/wireguard/d1max.conf && rm /tmp/d1max.conf && sudo systemctl enable --now wg-quick@d1max`

### 每台机器人（RK3588）

1. 站点上 `d1max-site vpn add robot <机器人号>`，写出 `<站点目录>/vpn/peers/<机器人号>.conf`。
2. 拷到机器人上 `/etc/wireguard/d1max.conf`（`chmod 600`），`sudo apt install wireguard-tools`，`sudo systemctl enable --now wg-quick@d1max`。
3. `/etc/d1max/env` 里 `D1MAX_SITE_MQTT=mqtts://172.29.70.1:8883`、`D1MAX_SITE_NTP=172.29.70.1`（走隧道），重启代理。
4. 站点上重新装一遍站点配置（同「站点主机」第 4 步，换成 `restart`）。
5. **所有**机器人都走隧道以后，`site.json` 的 `video.srt_host` 改成 `172.29.70.1`，重启站点：画面也走隧道，WiFi、4G 切换时不断。站点只有这一个推流地址，所以不自动改：还有没装 WireGuard 的机器人时改了，它的画面就出不来。

### 每部手机

1. 站点上 `d1max-site vpn add phone <名字>`；`qrencode -t ansiutf8 < <站点目录>/vpn/peers/<名字>.conf` 出二维码，手机 WireGuard 应用扫。
2. 手机应用里的站点地址用 `172.29.70.1`。
3. 站点上重新装一遍站点配置。

### 删

`d1max-site vpn remove <名字>`，再重新装一遍站点配置。删掉的地址不马上给新来的，免得旧配置还在谁手里时撞上。

## 四、老站点的证书

手机钉的是**站点证书本身**的指纹。老站点的证书里没有 `172.29.70.1`，走隧道连会被拒，所以要重签；但重签以后每部手机都要重新添加站点。因此不悄悄重签：`vpn init` 发现证书里没有隧道地址时会提示，要人明着跑 `d1max-site vpn reissue-cert`。它会打出新指纹，并重启 `d1max-mosquitto`、`d1max-site`。机器人不用动，因为 CA 没变。

## 五、注意

- **家里路由器的「回环」**：机器人在家里 WiFi 上时，也是连 `--endpoint` 那个公网地址。家里的路由器要支持从里面连自己的公网地址（NAT 回环，多数家用路由器支持）。不支持的话，在路由器的 DNS 里把那个域名指到站点主机的局域网地址（`--endpoint` 用域名），里外各解析各的。真机项 3am.2 会测到。
- 运营商 NAT 后面（没有公网地址、做不了端口转发）的家：这一单不管，见「六」。

## 六、没做的

- 站点网页上看哪台机器人、哪部手机的隧道通着（`wg show` 要 root；先用命令行看 `sudo wg show d1max`）。
- 机器人装机脚本自动装 WireGuard（现在按上面手动装，配置文件里有私钥，要人拷）。
- 家里没有公网地址、也做不了端口转发的（运营商 NAT 后面）：要另想办法（比如租一台中转），不在这一单。
