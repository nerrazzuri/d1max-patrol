> **这份文档是写给"另一台笔记本上的那个 Claude 实例"的。**

## 0. 你（笔记本上的 Claude）需要先知道的七件事

1. **机器在客户现场，窗口只有 1 天、最多 2 天。**
   现场时间只用来采**采不到就永远补不回来**的东西：原始报文、真实响应字段、
   真实时序、SDK 真实数据流。代码可以回家再改，报文回家补不了。

2. **默认全程只读。** D 阶段（导航一致性巡检）和 S 阶段（SDK 侦察）都不会
   让机器动。任何会让机器移动的命令，必须先问人"周围清空了吗？可以动吗？"，
   得到明确答复再发。**人没回答就不要发。**

3. **每条链路的原始帧都在自动录制**，落在 `runs/frames/nav-<UTC时间>.jsonl`。
   这是本次现场最重要的产出物。**不要加 `--no-record`。**

4. **Ubuntu 22.04 正好是厂商 SDK 的官方指定平台。**
   `RobotSDK-0.2.0/README_zh.md` 白纸黑字写着：Ubuntu 22.04 / GCC 11.4 /
   CMake 3.8+ / Boost 1.74。库文件 `lib/x86_64/librobot_sdk.so.0.2.0` 只依赖
   libc、libgcc_s、libstdc++（Boost 是静态进去的），最高要 `GLIBC_2.34` 和
   `GLIBCXX_3.4.30` —— Ubuntu 22.04 的 glibc 2.35 / libstdc++ 3.4.30 都够。
   **所以这次能顺带把 SDK 也侦察了**，见 S 阶段。

5. **仓库是私有的**，里面有厂商私有协议文档的逐字转录。不要 push 到别的地方，
   不要贴到任何在线服务上。

6. **接线之前先看 C 阶段第一段。** D1 Max 机身上**没有 RJ45 网口** ——
   以太网走的是扩展仓面板上的 M12 12 针航插，要厂商配的转接线束才能插网线。
   没有线束就走 WiFi（AP: `XG2WIFI_xxxxxx` / `12345678`），一样能干完全部活。

7. **导航地址厂商两份文档说法不一致，现场实测为准。**

   | 用途 | 候选地址 | 出处 |
   |---|---|---|
   | 导航 WebSocket | `192.168.144.100:10010` | 导航 API 文档第 9 行（注释写 `#D1 Max`） |
   | 导航 WebSocket | `192.168.168.100:10010` | SDK 开发指南 5.2 的 control 例子 |
   | SDK（有线） | `192.168.168.168:8081` | SDK 开发指南 2.7 |
   | SDK（WiFi） | `192.168.234.1:8081` | SDK 开发指南 2.7 |
   | 摄像头 RTSP | `rtsp://192.168.234.1:8554/{front,back}` | SDK 开发指南 4.1 |

   `conform` 已经改成**四条候选一次全扫**，报告里会写清楚哪条通。
   **这张实测结果是本次最要紧的产出之一。**

## A 阶段 · 笔记本环境准备（出发**前**在家做完）

现场可能没网、也没时间装东西。这一段必须提前跑通。

### A1. 装系统包

```bash
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip \
                    build-essential cmake libboost-all-dev
```

- `python3-venv` Ubuntu 默认没装，少了这个 `python -m venv` 会失败。
- `build-essential cmake libboost-all-dev` 是 S 阶段编 SDK 例子用的。
  没打算跑 S 阶段也建议装上 —— 现场想装就来不及了。

确认 Python 版本（本项目要 **3.10+**，Ubuntu 22.04 自带的就是 3.10，正好）：

```bash
python3 --version
```

### A2. 拉仓库

仓库地址：`https://github.com/nerrazzuri/d1max-patrol` （**Private**，需要登录）

```bash
git clone https://github.com/nerrazzuri/d1max-patrol.git
cd d1max-patrol
```

要密码的话：GitHub 不收密码了，用 Personal Access Token，或者装 `gh` 然后
`gh auth login`。**这一步必须在出发前解决。**

### A3. 建虚拟环境并安装

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

> 以后每开一个新终端都要先 `source .venv/bin/activate`，否则命令找不到。

### A4. 跑一遍测试，确认环境是好的

```bash
python -m pytest --tb=short
```

**期望：`513 passed`，约 90 秒。** 有红的就先别去现场——环境有问题。

（Ubuntu 默认是 UTF-8 locale，不用像 Windows 那样设 `PYTHONIOENCODING`。）

### A5. 确认 refs/ 是全的（不用拷，只是核对）

### B4. 提前把 SDK 例子编一遍（**在家编，别到现场编**）

编译不需要机器在场。现场再发现少个包就完了。

**两个版本都编** —— 现场才知道机器该配哪个，到时候没时间编：

```bash
for V in 0.2.0 0.1.1; do
  cd "refs/robot-sdk/RobotSDK-$V/example"
  mkdir -p build && cd build && cmake .. && make -j6
  ls        # 应该有 data / control / sync / async / take_control ...
  cd -
done
```

（0.1.1 没有 `recharge`，这是正常的，它是 0.2.0 才加的。）

**⚠️ 厂商 CMakeLists 有个坑，会让编出来的程序跑不起来。**
它写的是 `BUILD_RPATH "${SDK_ROOT}/lib/${ARCH_DIR}"`，但 `ARCH_DIR`
**这个变量他们从头到尾没定义过**，所以 RPATH 会少掉 `x86_64` 那一层，
运行时报 `error while loading shared libraries: librobot_sdk.so.0.2.0`。

不要去改他们的 CMakeLists（改了回家还要对差异），运行前设一下环境变量就行：

```bash
# 在哪个版本的 build 目录里，就指哪个版本的 lib
export LD_LIBRARY_PATH=$(cd ../../lib/x86_64 && pwd):$LD_LIBRARY_PATH
./data                 # 不带参数，应该打印 Usage 就退出 —— 这就说明链接是好的
```

看到 `Usage: ./data <ip> <port>` 就成功了。**两个版本都做到这一步。**

## C 阶段 · 现场硬件：怎么把笔记本接上机器狗

> 这一节的每一条都来自厂商《智元四足机器人 D1 Max SDK 开发指南 V0.1.0》，
> 仓库里就有：`refs/hardware/D1Max-SDK开发指南V0.1.0-正文提取.txt`
> （2.5 设备登录 / 5.7 连接 WiFi 的情况下访问有线网口 / 1.5 电气拓展接口）。
> 现场有疑问就去翻那份文本，别猜。

### C0. 先看清楚：这机器上**没有 RJ45 网口**

这是最容易翻车的地方，出发前必须搞定。

D1 Max 的以太网**不是**普通网口，而是机身**扩展仓电气接口面板**上的
**M12 12 针航空插头**（板端型号 `M12-P12A-GPFM12`），而且是**网口 + 电源**
合在一个航插里。面板上一共两个这种航插：

| 面板序号 | 接口名称 | 说明 |
|---|---|---|
| 3 | `24V(3A) + 网口` | 网口 A/B/C/D 四对差分 + 24V + GND |
| 4 | `12V(5A) + 网口` | 同上，供电是 12V |

**所以一根普通网线插不上去。** 要接线必须有厂商配的**对插线束**
（M12 12 针 → RJ45 的转接线）。

**这件事出发前必须问客户/厂商：「那根 M12 转 RJ45 的网口线束在不在现场？」**

- **在** → 走 C1（有线），带宽稳，首选。
- **不在 / 问不到** → **走 C2（WiFi）**，一样能干完 D 阶段和 S 阶段的全部活。
  别在现场硬凑，凑不出来。

> 顺带记着：航插不用时要盖防护盖（整机 IP67）；接扩展仓的线之前
> **先按扩展仓按键把扩展接口断电**。这两条是厂商的硬性要求。

### C1. 路线甲：有线（需要 M12 → RJ45 线束）

接法：M12 线束一头拧上机器扩展仓的网口航插（3 或 4 号都行），另一头 RJ45
插笔记本网口。笔记本没有网口就用 **USB 转以太网**转接头——**提前确认带了**。

机器那边有线网段的固定地址（厂商文档 2.5）：

| 主机 | 地址 | 上面跑什么 |
|---|---|---|
| RK3588（运控主机） | `192.168.168.168` | SDK 服务端、RTSP 推流 |
| Orin NX（导航主机） | `192.168.168.100` | 导航、ROS2 |

**笔记本要配成 `192.168.168.x`，x 不能是 100、168、255。** 推荐
`192.168.168.50/24`，不设网关。

先拿网卡名（通常 `enp0s31f6` / `eth0` / 插 USB 网卡后的 `enx....`）：

```bash
ip -br link
```

**做法一：`nmcli`（推荐）。** Ubuntu 22.04 桌面默认由 NetworkManager 托管网卡，
用裸 `ip addr add` 配的地址**可能几秒后被它抹掉**（它会去跑 DHCP）：

```bash
IFACE=<你的网卡名>
sudo nmcli con add type ethernet ifname $IFACE con-name d1max \
     ipv4.method manual ipv4.addresses 192.168.168.50/24
sudo nmcli con up d1max
```

> 收工恢复：`sudo nmcli con down d1max && sudo nmcli con delete d1max`

**做法二：裸 `ip`**（server 版 / `nmcli` 报 `NetworkManager is not running`）：

```bash
IFACE=<你的网卡名>
sudo ip link set $IFACE up
sudo ip addr add 192.168.168.50/24 dev $IFACE
```

> 收工恢复：`sudo ip addr del 192.168.168.50/24 dev $IFACE`

确认（**等 10 秒再看一次，确认没被 NetworkManager 抹掉**）：

```bash
ip -br addr show $IFACE     # 应该看到 192.168.168.50/24
ping -c 3 192.168.168.168   # RK3588
ping -c 3 192.168.168.100   # Orin NX
```

### C2. 路线乙：WiFi（**没有线束时走这条，一样够用**）

机器狗自己开了一个 AP 热点（厂商文档 2.5）：

- **SSID：`XG2WIFI_xxxxxx`**（后面 6 位是机器序列号，现场扫一下就看见了）
- **密码：`12345678`**

笔记本连上这个热点之后：

```bash
ping -c 3 192.168.234.1     # RK3588 的 AP 侧地址
```

**关键一步：连了 WiFi 也能访问有线网段**（厂商文档 5.7）。加一条路由，
`192.168.168.0/24` 就从 AP 走过去了：

```bash
sudo ip route add 192.168.168.0/24 via 192.168.234.1
ping -c 3 192.168.168.168
ping -c 3 192.168.168.100
```

> 收工恢复：`sudo ip route del 192.168.168.0/24 via 192.168.234.1`

**这条路由是走 WiFi 路线时的必做项**——不加它，导航主机（Orin NX）够不着。

### C3. 导航到底在哪个地址？——**厂商两份文档说法不一致，现场必须实测**

这是本次要带回去的**头号答案**：

| 出处 | 说的导航地址 |
|---|---|
| `refs/nav-api/自主导航_WEBSOCKET_API.md:9` | `192.168.144.100:10010`（注释写着 `#D1 Max`） |
| `refs/hardware/...正文提取.txt` 5.2 的 control 例子 | `192.168.168.100:10010` |

两份都是厂商写的，都点名 D1 Max。可能是同一台 Orin NX 的两块网卡，也可能是
文档版本差。**不要选一个信，两个都试**：

```bash
ping -c 2 192.168.168.100
ping -c 2 192.168.144.100
```

`conform` 已经改成**四条候选地址一次全扫**（`192.168.144.100:10010`、
`192.168.168.100:10010`、`192.168.168.168:8081`、`192.168.234.1:8081`），
报告里会写清楚哪条通、哪条不通。**这张表就是要带回去的东西。**

哪条通就用哪条跑 D 阶段：

```bash
d1max --url ws://192.168.168.100:10010 status     # 或 144.100
```

> ping 不通**不代表连不上**（有的设备禁 ICMP）。ping 失败也直接试一次
> `status`，TCP 探一次比 ICMP 准。

### C4. 顺手记下来：SSH 和版本号（S 阶段要用）

### C5. 摄像头：RTSP 地址（本卷不实现，但**务必确认一下能不能拉到流**）

第二卷的定点拍照就靠这两条流，现在确认一次，回家就能直接写：

```bash
ffplay rtsp://192.168.234.1:8554/front
ffplay rtsp://192.168.234.1:8554/back
```

没装 ffplay 就 `sudo apt install -y ffmpeg`（**在家装好**）。
能出画面就记一句"能拉到"，顺手记下分辨率和延迟感受。拉不到也记一句。

### C6. 连不上时的速查

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 网线插不进机器 | 机器上是 M12 航插，不是 RJ45 | 找厂商线束；找不到就改走 C2 的 WiFi |
| 网口灯不亮 / `ip link` 一直 DOWN | 线 / 转接头 / 航插没拧到位 | 换线换口；确认扩展仓已上电 |
| 地址配上了几秒后没了 | NetworkManager 抢着跑 DHCP | 改用 C1 做法一的 `nmcli` |
| 找不到 `XG2WIFI_` 热点 | 机器没开机 / AP 被关过 | 问现场的人；或走有线 |
| WiFi 通但 `192.168.168.100` 不通 | **忘了加 C2 的那条路由** | `sudo ip route add 192.168.168.0/24 via 192.168.234.1` |
| 地址在但 ping 全不通 | 防火墙 | `sudo ufw status`，active 就 `sudo ufw disable` 试一下 |
| 两个导航地址都不通 | 这台机器被改过网段 | **问现场的人**，或让他们在厂商 App 里看设备 IP |
| 有线 + WiFi 同时开着，路由乱 | 走错网卡 | `ip route get 192.168.168.100` 看走哪块卡，必要时关掉另一路 |

## S 阶段 · SDK 侦察（仍然不动机器）

> 这一段能做，是因为笔记本是 Ubuntu 22.04 —— 正好是厂商 SDK 的指定平台。

### S0. 先确认两件事

1. **平台版本对不对得上 SDK 版本**（见"前置"那一节的表）。
   - 平台 `0.3.0(V4)` → 用 **SDK 0.2.0**
   - 平台 `0.1.0-C` ~ `0.2.4(V4)` → 用 **SDK 0.1.1**
   - 版本配错会直接连不上，而且报错未必说得清楚。

2. **控制权规则**（`docs/zh/sdk_control_ownership_zh.md`）：
   > **App 可以抢 SDK 的控制权；SDK 不能抢 App 的控制权。**

   所以现场最安全的姿势是：**让厂商 App 保持连着**。App 先连上时，SDK 端
   就拿不到控制权，只能读数据 —— 这正是我们今天想要的。

   **请人确认 App 是连着的，再往下走。**

   > ⚠️ 但厂商《SDK 开发指南》2.7 写着"运行 demo 前务必使遥控器 App 退出
   > 后台程序"。两条要求打架。**处理办法：先在 App 连着的情况下跑 `data`。**
   > 如果能吐出数据，皆大欢喜，安全性还保住了。如果连不上或一条数据都没有，
   > **先问人**"能不能退出 App？退了机器就只受 SDK 管了"，得到明确同意
   > 再退。**人没同意就不要退，把"App 连着时 data 拿不到数据"这条结论
   > 记下来带回去，本身就是答案。**

### S1. 只跑 `data`，绝不跑 `control` / `take_control`

端口是 **8081**，有线和 WiFi 都是（厂商《SDK 开发指南》2.7 的两条示例命令
用的都是 8081）。地址按你走的路线选：

```bash
cd refs/robot-sdk/RobotSDK-0.2.0/example/build     # 版本按 S0 挑
export LD_LIBRARY_PATH=$(cd ../../lib/x86_64 && pwd):$LD_LIBRARY_PATH

./data 192.168.168.168 8081 2>&1 | tee ~/sdk-data.log   # 有线
# 或
./data 192.168.234.1   8081 2>&1 | tee ~/sdk-data.log   # WiFi
```

`data` 这个例子做的是**订阅传感数据**：依次开关运控数据、20Hz 速度数据、
关节状态数据，每种开两秒再关掉，然后退出。它**不发任何运动指令**。

`example/` 里另外那些 —— `control`、`take_control`、`recharge` —— 
**这次一个都不要跑**。`control` 会让机器动，`recharge` 会让它去找充电桩。

### S2. 要从输出里捞的东西

把 `~/sdk-data.log` 完整带回来。重点看：

- 连上了没有？连不上的话报的什么错（**版本不匹配 vs 网络不通，错误信息不一样**）
- 三类数据（运控 / 速度 / 关节）各自**真的有数据吐出来吗**，还是只有日志没有数据
- 数据结构长什么样、字段叫什么、数值范围大概多少
- 20Hz 是真 20Hz 吗（数一下两秒里出了多少条）

这些决定了以后"上装 + 巡检"要不要走 SDK 这条路、值不值得做那个 C++ 旁路进程。

### S3. 失败了也没关系

S 阶段**不是今天的必答题**，D 阶段才是。如果：
- SDK 的两个地址（`192.168.168.168` / `192.168.234.1`）都 ping 不通 →
  记一句"哪条线上都不通"，收工
- 版本配不上、两个 SDK 版本都连不上 → 把两次的报错原文都留下，收工
- 编译当时没编（忘了 B4）→ 别在现场编，直接跳过

**任何一种失败，写下来带回去，就是这一趟的收获。**

## G · 失败处置速查

| 出什么事 | 怎么办 |
|---|---|
| 网线插不进机器 | 机器上是 M12 航插不是 RJ45，见 C0。没线束就改走 C2 的 WiFi |
| 两个导航地址都连不上 | 回 C6 排查表。**不要**改代码去"适配"，先确认物理链路 |
| WiFi 通但 168 网段不通 | 忘了加路由：`sudo ip route add 192.168.168.0/24 via 192.168.234.1` |
| IP 配上几秒就没了 | NetworkManager 在抢，改用 C1 做法一的 `nmcli` |
| 连上了但报文解析失败 | **原样保存报错和那一帧**，继续跑别的命令。这是好数据不是坏消息 |
| 某个接口返回 error | `conform` 会记下来继续跑，不用管，报告里有 |
| `get_pgm_map` 卡死/超时 | Ctrl+C，记下"多久卡的、有没有部分数据"。这条本来就是测极限的 |
| `./data` 报 `librobot_sdk.so.0.2.0` 找不到 | 厂商 CMakeLists 的 RPATH bug，`export LD_LIBRARY_PATH=.../lib/x86_64`（见 B4） |
| SDK 连不上 8081 | 先确认平台版本 vs SDK 版本（两个版本都试）；再确认网段通不通。两次报错都留下 |
| 机器动作不对劲 | **先按急停**，再 Ctrl+C。安全永远优先于采数据 |
| 命令行崩了 | 录像已经落盘了（每写一行都 flush，就是为了这个）。捡起 jsonl 继续 |
| 时间不够 | 优先级：**D2 `conform`** > E2 走一个点 > S1 SDK 侦察 > E3 走完整路线 > E4 建图。**D2 一定要做完** |
