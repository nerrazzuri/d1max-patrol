# D1 Max 真机联调手册（笔记本 = Ubuntu 22.04）

> **这份文档是写给"另一台笔记本上的那个 Claude 实例"的。**
> 请那个实例从头到尾读完再动手，然后**一步一步带着人做**：
> 每一步先说"现在做什么、为什么"，让人做完、把看到的东西贴回来，
> 再走下一步。不要一次抛十条命令。
>
> 出门的笔记本是 **Ubuntu 22.04 x86_64**。本手册只写 Ubuntu 的做法。

---

## 0. 你（笔记本上的 Claude）需要先知道的六件事

1. **机器在客户现场，窗口只有 1 天、最多 2 天。**
   现场时间只用来采**采不到就永远补不回来**的东西：原始报文、真实响应字段、
   真实时序、SDK 真实数据流。代码可以回家再改，报文回家补不了。

2. **默认全程只读。** D 阶段（导航一致性巡检）和 S 阶段（SDK 侦察）都不会
   让机器动。任何会让机器移动的命令，必须先问人"周围清空了吗？可以动吗？"，
   得到明确答复再发。**人没回答就不要发。**

3. **每条链路的原始帧都在自动录制**，落在 `runs/frames/nav-<UTC时间>.jsonl`。
   这是本次现场最重要的产出物。**不要加 `--no-record`。**

4. **Ubuntu 22.04 正好是厂商 SDK 的官方指定平台。**
   `RobotSDK-0.2.0/README_zh.md` 白纸黑字写着：Ubuntu 22.04 / GCC 11.4 /
   CMake 3.8+ / Boost 1.74。库文件 `lib/x86_64/librobot_sdk.so.0.2.0` 只依赖
   libc、libgcc_s、libstdc++（Boost 是静态进去的），最高要 `GLIBC_2.34` 和
   `GLIBCXX_3.4.30` —— Ubuntu 22.04 的 glibc 2.35 / libstdc++ 3.4.30 都够。
   **所以这次能顺带把 SDK 也侦察了**，见 S 阶段。

5. **仓库是私有的**，里面有厂商私有协议文档的逐字转录。不要 push 到别的地方，
   不要贴到任何在线服务上。

6. **两条网段是分开的，别搞混：**

   | 用途 | 地址 | 协议 | 本次要做的 |
   |---|---|---|---|
   | 导航（建图/定位/巡检） | `192.168.144.100:10010` | WebSocket | D 阶段，主力 |
   | SDK（运控/传感器/回充） | `192.168.234.1:8082` | UDP | S 阶段，侦察 |
   | SDK 的 WebSocket 变体 | `192.168.234.1:8081` | WebSocket | `conform` 只探这条的可达性 |

   > `conform` 探的是 **8081**，不是笔误。它探的是 TCP，而 8082 是 UDP —— 
   > 用 TCP 去连 UDP 端口必然失败，探了只会得到一条假阴性。真正验 8082 的
   > 是 S 阶段跑厂商自己的 `data` 例子。

**不是随便配的**：

的"关于/系统信息"里看）。**两个版本的 SDK 都带上**，现场按版本挑。

## A 阶段 · 笔记本环境准备（出发**前**在家做完）

现场可能没网、也没时间装东西。这一段必须提前跑通。

### A1. 装系统包

```bash
sudo apt update
sudo apt install -y git python3 python3-venv python3-pip \
                    build-essential cmake libboost-all-dev
```

- `python3-venv` Ubuntu 默认没装，少了这个 `python -m venv` 会失败。
- `build-essential cmake libboost-all-dev` 是 S 阶段编 SDK 例子用的。
  没打算跑 S 阶段也建议装上 —— 现场想装就来不及了。

确认 Python 版本（本项目要 **3.10+**，Ubuntu 22.04 自带的就是 3.10，正好）：

```bash
python3 --version
```

### A2. 拉仓库

仓库地址：`https://github.com/nerrazzuri/d1max-patrol` （**Private**，需要登录）

```bash
git clone https://github.com/nerrazzuri/d1max-patrol.git
cd d1max-patrol
```

要密码的话：GitHub 不收密码了，用 Personal Access Token，或者装 `gh` 然后
`gh auth login`。**这一步必须在出发前解决。**

### A3. 建虚拟环境并安装

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

> 以后每开一个新终端都要先 `source .venv/bin/activate`，否则命令找不到。

### A4. 跑一遍测试，确认环境是好的

```bash
python -m pytest --tb=short
```

**期望：`513 passed`，约 90 秒。** 有红的就先别去现场——环境有问题。

（Ubuntu 默认是 UTF-8 locale，不用像 Windows 那样设 `PYTHONIOENCODING`。）

### A5. 把 refs/ 补齐

按上面"前置"那一节，把 SDK 和 API 文档拷进 `refs/`。检查：

```bash
ls refs/robot-sdk/RobotSDK-0.2.0/lib/x86_64/     # 应该看到 librobot_sdk.so.0.2.0
```

把那个 `conformance-report.md` 打开看一眼，知道它长什么样。

### B4. 提前把 SDK 例子编一遍（**在家编，别到现场编**）

编译不需要机器在场。现场再发现少个包就完了。

```bash
cd refs/robot-sdk/RobotSDK-0.2.0/example
mkdir -p build && cd build
cmake ..
make -j6
ls        # 应该有 data / control / sync / async / take_control / recharge ...
```

**⚠️ 厂商 CMakeLists 有个坑，会让编出来的程序跑不起来。**
它写的是 `BUILD_RPATH "${SDK_ROOT}/lib/${ARCH_DIR}"`，但 `ARCH_DIR`
**这个变量他们从头到尾没定义过**，所以 RPATH 会少掉 `x86_64` 那一层，
运行时报 `error while loading shared libraries: librobot_sdk.so.0.2.0`。

不要去改他们的 CMakeLists（改了回家还要对差异），运行前设一下环境变量就行：

```bash
export LD_LIBRARY_PATH=$(cd ../../lib/x86_64 && pwd):$LD_LIBRARY_PATH
./data                 # 不带参数，应该打印 Usage 就退出 —— 这就说明链接是好的
```

看到 `Usage: ./data <ip> <port>` 就成功了。**在家做到这一步。**

- B2 所有命令都跑出了对得上的输出

- `runs/frames/` 下有 jsonl，随便打开一个能看到一行行 JSON
- B4 的 `./data` 能打出 Usage
- `refs/` 里 SDK 和 API 文档都在，**两个版本的 SDK 都带了**

**这五条做完，才算可以出发。**

## C 阶段 · 现场硬件：接线与配 IP

### C1. 接线

D1 Max 机身上有网口。用一根**普通网线**，一头插机器狗的网口，一头插笔记本网口。

- 笔记本没有网口 → 需要 **USB 转以太网** 转接头。**提前确认带了**，现场买不到。
- 不要走客户的路由器/交换机 —— 直连最省事，也避免和客户网段撞车。
- 机器狗那边已有的线保持原样，我们只加一根。

接好后先看**网口指示灯亮不亮**，同时：

```bash
ip link                    # 找到那块网卡，状态应该从 DOWN 变成 UP
```

灯不亮 / 一直 DOWN = 线或转接头的问题，先解决物理层。

### C2. 配笔记本的 IP

导航服务在 `192.168.144.100`。笔记本要配到 **`192.168.144.x`**（x 不能是 100）。
推荐 **`192.168.144.50/24`，不设网关**。

先拿到网卡名（通常是 `enp0s31f6` / `eth0` / 插 USB 网卡后的 `enx....`）：

```bash
ip -br link
```

#### 做法一：`nmcli`（**推荐**，Ubuntu 桌面版默认跑 NetworkManager）

Ubuntu 22.04 桌面默认由 NetworkManager 托管网卡。这种情况下用裸 `ip addr add`
配的地址**可能会被 NetworkManager 在几秒后抹掉**（它会去跑 DHCP）。所以优先：

```bash
IFACE=<你的网卡名>
sudo nmcli con add type ethernet ifname $IFACE con-name d1max \
     ipv4.method manual ipv4.addresses 192.168.144.50/24
sudo nmcli con up d1max
```

> 收工恢复：`sudo nmcli con down d1max && sudo nmcli con delete d1max`

如果 `nmcli` 说 `NetworkManager is not running`（比如是 server 版），那就用做法二。

#### 做法二：裸 `ip`（server 版 / 没有 NetworkManager 时）

```bash
IFACE=<你的网卡名>
sudo ip link set $IFACE up
sudo ip addr add 192.168.144.50/24 dev $IFACE
```

> 收工恢复：`sudo ip addr del 192.168.144.50/24 dev $IFACE`

#### 确认真的配上了

```bash
ip -br addr show $IFACE     # 应该看到 192.168.144.50/24
```

**看到地址还在（等 10 秒再看一次，确认没被 NetworkManager 抹掉）才往下走。**

### C3. 验证通不通

```bash
ping -c 3 192.168.144.100
```

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 网口灯不亮 / `ip link` 一直 DOWN | 线 / 转接头 / 网口 | 换线、换口，先解决物理层 |
| 地址配上了几秒后没了 | NetworkManager 抢着跑 DHCP | 改用 C2 做法一的 `nmcli` |
| 地址在但 ping 不通 | 防火墙 | `sudo ufw status`，如果是 active 就 `sudo ufw disable` 试一下 |
| 还是不通 | 机器狗 IP 不是 144.100 | **问现场的人**，或让他们在厂商 App 里看设备 IP。这台机器可能被改过网段 |
| WiFi 也开着 | 路由走错网卡 | `ip route get 192.168.144.100` 看走哪块卡；必要时关 WiFi |

> **ping 不通不代表一定连不上**（有的设备禁 ICMP）。
> ping 失败也可以直接试 D1 的 `status`，用 TCP 探一次更准。

### C4. SDK 网段 `192.168.234.1`

S 阶段要用。多数情况下这个网段走的是**同一根线**（机内两台主机各占一个网段），
所以给同一块网卡**再加一个地址**就行：

```bash
# nmcli 方式：给刚才那条连接追加第二个地址
sudo nmcli con mod d1max +ipv4.addresses 192.168.234.50/24
sudo nmcli con up d1max

# 或裸 ip 方式
sudo ip addr add 192.168.234.50/24 dev $IFACE
```

然后 `ping -c 3 192.168.234.1`。

**如果 ping 不通，也不要在这上面耗时间** —— 有可能 SDK 那台主机要走另一个
物理口，或者需要接 WiFi。**先把 D 阶段做完**，S 阶段有时间再回来弄。
`conform` 会自动记下 8081 的可达性，那条记录本身就是要带回去的数据。

## D 阶段 · 导航只读采集（不动机器，先做这个）

### D1. 第一条命令

```bash
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 status
```

**这一条通了，就说明协议对上了 —— 今天最大的风险已经过去。**

连接失败 → 回 C3 的排查表。连上了但解析报错 → **把完整报错原样保存下来**，
这本身就是重要信息（说明真机报文和文档不一样）。

### D2. 跑一致性巡检（现场的核心动作）

```bash
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 -v conform
```

`-v` 会把每一帧打到屏幕上，方便肉眼确认。

这条命令会：
- 探两个网段的 TCP 可达性
- 依次调用**全部只读导航接口**：导航状态、定位状态、建图状态、速度、列地图，
  再对前两张地图列路线、取地图栅格
- 单条接口失败**不会**掐断后面的（特意设计的——现场只有一次机会）
- 把录像回读，跟厂商文档的 61 条样本逐字段对拍
- 出 `conformance.json` + `conformance-report.md`

**跑完把屏幕汇总和报告文件内容一起贴给人看。**

### D3. 重点盯这几件事

这三个接口厂商文档没给响应样本，**它们的真实响应是本次现场的头号目标**：

- `get_all_pgm_map`（列地图）
- `get_all_paths_by_mapid`（列路线）
- `get_pgm_map`（取地图栅格）

特别是 `get_pgm_map`：文档里的样例地图是 1000×1000，也就是**上百万个整数、
好几 MB 的 JSON**。仿真器只发 20×20。**真机上这一条会不会把连接撑爆、要多久，
是必须实测的。** 如果卡住超过一分钟，Ctrl+C 掉，把现象记下来 ——
"撑不住"本身就是结论。

### D4. 顺手抄回来的东西

让人在**厂商 App** 里看一眼并抄下来：

- **机器软件平台版本号**（S 阶段挑 SDK 版本要用，**这条别忘**）
- 设备上现有的地图名 / 地图 id 长什么样
- 每张图上有哪些路线、路线里的点叫什么

`docs/真机待验证清单.md` 里 18 条待验证假设中，**1、2、10、11、12、13**
这些时序类的，看录像 jsonl 的时间戳回家就能算 —— 现场**不用**专门测。

## S 阶段 · SDK 侦察（仍然不动机器）

> 这一段能做，是因为笔记本是 Ubuntu 22.04 —— 正好是厂商 SDK 的指定平台。

### S0. 先确认两件事

1. **平台版本对不对得上 SDK 版本**（见"前置"那一节的表）。
   - 平台 `0.3.0(V4)` → 用 **SDK 0.2.0**
   - 平台 `0.1.0-C` ~ `0.2.4(V4)` → 用 **SDK 0.1.1**
   - 版本配错会直接连不上，而且报错未必说得清楚。

2. **控制权规则**（`docs/zh/sdk_control_ownership_zh.md`）：
   > **App 可以抢 SDK 的控制权；SDK 不能抢 App 的控制权。**

   所以现场最安全的姿势是：**让厂商 App 保持连着**。App 先连上时，SDK 端
   就拿不到控制权，只能读数据 —— 这正是我们今天想要的。

   **请人确认 App 是连着的，再往下走。**

### S1. 只跑 `data`，绝不跑 `control` / `take_control`

```bash
cd refs/robot-sdk/RobotSDK-0.2.0/example/build
export LD_LIBRARY_PATH=$(cd ../../lib/x86_64 && pwd):$LD_LIBRARY_PATH
./data 192.168.234.1 8082 2>&1 | tee ~/sdk-data.log
```

`data` 这个例子做的是**订阅传感数据**：依次开关运控数据、20Hz 速度数据、
关节状态数据，每种开两秒再关掉，然后退出。它**不发任何运动指令**。

`example/` 里另外那些 —— `control`、`take_control`、`recharge` —— 
**这次一个都不要跑**。`control` 会让机器动，`recharge` 会让它去找充电桩。

### S2. 要从输出里捞的东西

把 `~/sdk-data.log` 完整带回来。重点看：

## G · 失败处置速查

| 出什么事 | 怎么办 |
|---|---|
| 连不上 `192.168.144.100:10010` | 回 C3 排查表。**不要**改代码去"适配"，先确认物理链路 |
| IP 配上几秒就没了 | NetworkManager 在抢，改用 C2 的 `nmcli` 做法 |
| 连上了但报文解析失败 | **原样保存报错和那一帧**，继续跑别的命令。这是好数据不是坏消息 |
| 某个接口返回 error | `conform` 会记下来继续跑，不用管，报告里有 |
| `get_pgm_map` 卡死/超时 | Ctrl+C，记下"多久卡的、有没有部分数据"。这条本来就是测极限的 |
| `./data` 报 `librobot_sdk.so.0.2.0` 找不到 | 厂商 CMakeLists 的 RPATH bug，`export LD_LIBRARY_PATH=.../lib/x86_64`（见 B4） |
| SDK 连不上 `192.168.234.1:8082` | 先确认平台版本 vs SDK 版本；再确认那个网段通不通。两次报错都留下 |
| 机器动作不对劲 | **先按急停**，再 Ctrl+C。安全永远优先于采数据 |
| 命令行崩了 | 录像已经落盘了（每写一行都 flush，就是为了这个）。捡起 jsonl 继续 |
| 时间不够 | 优先级：**D2 `conform`** > E2 走一个点 > S1 SDK 侦察 > E3 走完整路线 > E4 建图。**D2 一定要做完** |
