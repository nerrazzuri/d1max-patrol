# D1 Max 真机联调手册

> **这份文档是写给"另一台笔记本上的那个 Claude 实例"的。**
> 请那个实例从头到尾读完再动手，然后**一步一步带着人做**：
> 每一步先说"现在做什么、为什么"，让人做完、把看到的东西贴回来，
> 再走下一步。不要一次抛十条命令。

## 0. 你（笔记本上的 Claude）需要先知道的五件事

1. **机器在客户现场，窗口只有 1 天、最多 2 天。**
   现场时间只用来采**采不到就永远补不回来**的东西：原始报文、真实响应字段、
   真实时序。代码可以回家再改，报文回家补不了。

2. **默认全程只读。** 本手册第 D 阶段（`conform`）不会让机器动一下。
   任何会让机器移动的命令，必须先口头问人一句"周围清空了吗？可以动吗？"，
   得到明确答复再发。**人没回答就不要发。**

3. **每条链路的原始帧都在自动录制**，落在 `runs/frames/nav-<UTC时间>.jsonl`。
   这是本次现场最重要的产出物，比任何截图和总结都重要。**不要加 `--no-record`。**

4. **不要试图跑 C++ SDK。** 厂商 RobotSDK 只发布了 Linux 的
   `librobot_sdk.so`（x86_64 / aarch64），没有 Windows 版、没有 Python 绑定。
   本次现场是**纯导航 WebSocket**。`conform` 仍会探一下 SDK 那个网段
   （`192.168.234.1:8081`）—— 探到通不通，本身就是要带回去的数据。

5. **仓库是私有的**，里面有厂商私有协议文档的逐字转录。不要 push 到别的地方，
   不要贴到任何在线服务上。

## A 阶段 · 笔记本环境准备（出发**前**在家做完）

现场没有网、没有时间装环境。这一段必须提前跑通。

### A1. 装 Python

需要 **Python 3.10 或更高**。检查：

```
python --version
```

- Windows 没装的话去 python.org 装 3.10+，安装时**勾上 "Add python.exe to PATH"**。
- Ubuntu：`sudo apt install python3 python3-venv python3-pip`

### A2. 拉仓库

仓库地址：`https://github.com/nerrazzuri/d1max-patrol` （**Private**，需要登录）

```
git clone https://github.com/nerrazzuri/d1max-patrol.git
cd d1max-patrol
```

如果 `git clone` 要密码：GitHub 现在不收密码，要用 Personal Access Token，
或者提前装好 `gh` 然后 `gh auth login`。**这一步必须在出发前解决。**

### A3. 建虚拟环境并安装

Windows（PowerShell）：
```
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Ubuntu / macOS：
```
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

> 以后每开一个新终端，都要先 `Activate.ps1` / `source .venv/bin/activate`，
> 否则命令找不到。

### A4. 跑一遍测试，确认环境是好的

Windows 上先设编码，否则中文输出会炸：
```
$env:PYTHONIOENCODING="utf-8"; $env:PYTHONUTF8="1"
```

然后：
```
python -m pytest --tb=short
```

**期望：`513 passed`，约 90 秒。** 如果有红的，先别去现场——环境有问题。

### A5. 知道 `refs/` 是空的

仓库的 `.gitignore` 故意排除了 `refs/`（厂商原始资料不入库）。所以你 clone 下来
**不会**有厂商的《自主导航 WEBSOCKET API》文档。

现场基本用不到它。**但如果你需要**（比如要查某个接口的参数），请让人从原始
资料压缩包里解出来，放到 `refs/nav-api/`。协议的关键结论已经写在
`docs/第1卷决策记录.md` 和 `docs/真机待验证清单.md` 里，先查这两个。

## C 阶段 · 现场硬件：接线与配 IP

### C1. 接线

D1 Max 机身上有网口。用一根**普通网线**，一头插机器狗的网口，一头插笔记本网口。

- 笔记本没有网口（很多轻薄本没有）→ 需要一个 **USB 转以太网** 转接头。
  **这个东西一定要提前确认带了**，现场买不到。
- 不要走客户的路由器/交换机 —— 直连最省事，也避免和客户网络的网段撞车。
- 如果机器狗那边已经接了别的线，保持原样，我们只加一根。

接好后先看**网口指示灯亮不亮**。不亮 = 线或转接头的问题，先解决物理层。

### C2. 配笔记本的 IP

机器狗的导航服务在 **`192.168.144.100`**，端口 `10010`。
所以笔记本要配到 **`192.168.144.x`** 网段（x 不能是 100）。

推荐：**IP `192.168.144.50`，掩码 `255.255.255.0`，网关留空。**

#### Windows 做法（图形界面，最稳）

1. 右下角网络图标右键 → **打开"网络和 Internet"设置**
2. 左边选 **以太网** → 点那块刚插上线的网卡
3. 找到 **IP 分配** → 点 **编辑**
4. 把 **自动 (DHCP)** 改成 **手动**
5. 打开 **IPv4** 开关，填：
   - IP 地址：`192.168.144.50`
   - 子网掩码：`255.255.255.0`
   - 网关：**留空**
   - DNS：**留空**
6. 保存

#### Windows 做法（命令行，需要管理员 PowerShell）

先看网卡叫什么名字：
```
Get-NetAdapter
```
找到状态是 `Up` 的那块以太网卡，记下 `Name`（通常是 `以太网` 或 `Ethernet`）。然后：
```
New-NetIPAddress -InterfaceAlias "以太网" -IPAddress 192.168.144.50 -PrefixLength 24
```

> 之后要恢复成自动获取：
> `Remove-NetIPAddress -InterfaceAlias "以太网" -Confirm:$false`
> 再 `Set-NetIPInterface -InterfaceAlias "以太网" -Dhcp Enabled`

#### Ubuntu 做法

```
ip link                 # 看网卡名，通常 enp0s31f6 / eth0
sudo ip addr add 192.168.144.50/24 dev <网卡名>
sudo ip link set <网卡名> up
```

> 恢复：`sudo ip addr del 192.168.144.50/24 dev <网卡名>`

### C3. 验证通不通

```
ping 192.168.144.100
```

**ping 通了就往下走。ping 不通，按这个顺序排查：**

| 现象 | 多半是 | 怎么办 |
|---|---|---|
| 网口灯不亮 | 线 / 转接头 / 网口坏 | 换线、换口，先解决物理层 |
| 灯亮但 ping 不通 | 笔记本 IP 没配上 | Windows 跑 `ipconfig`，确认那块网卡真的显示 `192.168.144.50` |
| IP 对但还是不通 | 防火墙 | Windows 上临时关掉"专用网络"的防火墙试一下 |
| 还是不通 | 机器狗 IP 不是 144.100 | **问现场的人**，或让他们在厂商 App 里看设备 IP。这台机器可能被改过网段 |
| 有多块网卡（WiFi 也开着） | 路由走错网卡 | 把 WiFi 关掉再试 |

> **`ping` 不通不代表一定连不上**（有的设备禁 ICMP）。
> ping 失败也可以直接试下一步的 `status`，用 TCP 探一次更准。

### C4. 关于 SDK 网段 `192.168.234.1`

本次现场**不用**它（SDK 只有 Linux 的 .so，Windows 上跑不了）。
但如果时间有富余，可以顺手多配一个 IP（比如 `192.168.234.50/24`）看看那个网段
通不通 —— `conform` 会自动探它，探到的结果是有价值的数据。**不通也没关系，
不要为了它耽误时间。**

## D 阶段 · 只读采集（不动机器，先做这个）

### D1. 第一条命令

```
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 status
```

**这一条通了，就说明协议对上了 —— 今天最大的风险已经过去。**

如果报连接失败，回 C3 的排查表。如果连上了但解析报错，**把完整报错原样保存下来**，
这本身就是重要信息（说明真机报文和文档不一样）。

### D2. 跑一致性巡检（现场的核心动作）

```
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 -v conform
```

`-v` 会把每一帧都打到屏幕上，方便现场肉眼确认。

这条命令会：
- 探两个网段的 TCP 可达性
- 依次调用**全部只读接口**：导航状态、定位状态、建图状态、速度、列地图，
  再对前两张地图列路线、取地图栅格
- 单条接口失败**不会**掐断后面的（这是特意设计的——现场只有一次机会）
- 把录像回读，跟厂商文档的 61 条样本逐字段对拍
- 出 `conformance.json` + `conformance-report.md`

**跑完把屏幕上那段汇总，和报告文件的内容，一起贴给人看。**

### D3. 重点盯这几件事

这三个接口厂商文档没给响应样本，**它们的真实响应是本次现场的头号目标**：

- `get_all_pgm_map`（列地图）
- `get_all_paths_by_mapid`（列路线）
- `get_pgm_map`（取地图栅格）

特别是 `get_pgm_map`：文档里的样例地图是 1000×1000，也就是**上百万个整数、
好几 MB 的 JSON**。仿真器只发 20×20。**真机上这一条会不会把连接撑爆、要多久，
是必须实测的。** 如果这条卡住超过一分钟，Ctrl+C 掉，把现象记下来 ——
"撑不住"本身就是结论。

### D4. 顺手抄回来的东西

跑完 `conform` 后，如果时间允许，让人在**厂商 App** 里看一眼并抄下来：

- 设备上现有的地图名 / 地图 id 长什么样
- 每张图上有哪些路线、路线里的点叫什么
- 机器的固件 / 软件版本号

`docs/真机待验证清单.md` 里有 18 条待验证的假设，其中 **1、2、10、11、12、13**
这些时序类的，看录像 jsonl 里的时间戳就能回家慢慢算 —— 现场**不用**专门测。

## E 阶段 · 运动测试（**必须先问人**）

> **在发任何会让机器动的命令之前，你必须先说这句话并等到回答：**
> "下一步会让机器狗真的走起来。请确认：周围清空了吗？有人在旁边看着吗？
> 急停按钮在手边吗？确认了我再发。"
>
> **人没明确回答，不要发。**

### E1. 加载地图、等定位就绪（这一步机器不动）

```
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 load <真实map_id>
```

`<真实map_id>` 用 D2 里列出来的那个。

期望：`定位就绪: ContinuousLoc`。
**定位没就绪就绝对不要往下走** —— 定位不准的时候让它走，是要撞东西的。

### E2. 走一个点（先走一个近的）

```
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 goto <x> <y> <yaw>
```

**第一个点选一个离当前位置一米以内、周围空旷的坐标。**
坐标从 `paths` 列出来的现有航点里挑一个最近的，不要自己编。

期望：`导航结束: Succeed`。

这一条能验证清单里的第 1、2、11、12 条（终态回落时机、拒绝条件、运动参数）。

### E3. 走完一条完整路线（**时间够、且前面都顺**才做）

```
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 walk <map_id> <path_id>
```

注意：本项目是**全逐点执行** —— `walk` 是一个点一个点地发单点导航，
不用厂商的多点接口。这是刻意的设计，不是缺失。

### E4. 建图（**最低优先级，前面全做完还有时间才碰**）

```
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 map-start
# ... 人牵着/遥控着机器走一圈 ...
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 map-stop
python -m d1max_patrol.cli --url ws://192.168.144.100:10010 maps
```

要采的是：**保存后新地图的 id 长什么样**（清单第 15 条。文档样例写 `map_id_1`，
仿真器发 `map_1`，真机是啥不知道）。

## G · 失败处置速查

| 出什么事 | 怎么办 |
|---|---|
| 连不上 `192.168.144.100:10010` | 回 C3 排查表。**不要**改代码去"适配"，先确认物理链路 |
| 连上了但报文解析失败 | **原样保存报错和那一帧**，然后继续跑别的命令。这是好数据不是坏消息 |
| 某个接口返回 error | `conform` 会记下来继续跑，不用管。报告里会有 |
| `get_pgm_map` 卡死/超时 | Ctrl+C，记下"多久卡的、有没有部分数据"。这条本来就是要测极限的 |
| 机器动作不对劲 | **先按急停**。然后 Ctrl+C 掉命令。安全永远优先于采数据 |
| 命令行崩了 | 录像已经落盘了（每写一行都 flush，就是为了这个）。捡起 jsonl 继续 |
| 时间不够了 | 优先级：D2 `conform` > E2 走一个点 > E3 走完整路线 > E4 建图。**D2 一定要做完** |

## I · 给人的一句话开场白（可以直接用）

> 我看完手册了。今天分四步：**先接线配 IP**（10 分钟），
> **再跑一次只读巡检**（机器不会动，5 分钟，这是今天最重要的），
> **然后如果一切正常，我们让它走一个点**（要你确认周围安全），
> **最后有时间再走完整路线**。
> 我们从第一步开始 —— 网线带了吗？笔记本有网口还是需要转接头？
