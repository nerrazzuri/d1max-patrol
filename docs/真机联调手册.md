## 0. 你（笔记本上的 Claude）需要先知道的七件事

1. **机器在客户现场，窗口只有 1 天、最多 2 天。**
   现场时间只用来采**采不到就永远补不回来**的东西：原始报文、真实响应字段、
   真实时序、SDK 真实数据流。代码可以回家再改，报文回家补不了。

2. **默认全程只读。** D 阶段（导航一致性巡检）和 S 阶段（SDK 侦察）都不会
   让机器动。任何会让机器移动的命令，必须先问人"周围清空了吗？可以动吗？"，
   得到明确答复再发。**人没回答就不要发。**

3. **每条链路的原始帧都在自动录制**，落在 `runs/frames/nav-<UTC时间>.jsonl`。
   这是本次现场最重要的产出物。**不要加 `--no-record`。**

4. **Ubuntu 22.04 正好是厂商 SDK 的官方指定平台。**
   `RobotSDK-0.2.0/README_zh.md` 白纸黑字写着：Ubuntu 22.04 / GCC 11.4 /
   CMake 3.8+ / Boost 1.74。库文件 `lib/x86_64/librobot_sdk.so.0.2.0` 只依赖
   libc、libgcc_s、libstdc++（Boost 是静态进去的），最高要 `GLIBC_2.34` 和
   `GLIBCXX_3.4.30` —— Ubuntu 22.04 的 glibc 2.35 / libstdc++ 3.4.30 都够。
   **所以这次能顺带把 SDK 也侦察了**，见 S 阶段。

5. **仓库是私有的**，里面有厂商私有协议文档的逐字转录。不要 push 到别的地方，
   不要贴到任何在线服务上。

6. **接线之前先看 C 阶段第一段。** D1 Max 机身上**没有 RJ45 网口** ——
   以太网走的是扩展仓面板上的 M12 12 针航插，要厂商配的转接线束才能插网线。
   没有线束就走 WiFi（AP: `XG2WIFI_xxxxxx` / `12345678`），一样能干完全部活。

7. **地址表（2026-09-01 现场已实测，四条全通）。**

   | 用途 | 地址 | 现场实测 |
   |---|---|---|
   | 导航 WebSocket | `192.168.168.100:10010` | 通 ✅ **实际用这条** |
   | 导航 WebSocket | `192.168.144.100:10010` | 通 ✅（同一台 Orin NX 的另一块网卡） |
   | SDK 主机（有线） | `192.168.168.168` | 网段通 ✅ |
   | SDK 主机（WiFi） | `192.168.234.1` | 网段通 ✅ |
   | **SDK 控制口** | **`8082 / UDP`** | ✅ 实测；**不是 8081**，8081 恒 `ShakeHand failed` |
   | 摄像头 RTSP | `rtsp://192.168.234.1:8554/{front,back}` | 未验 |

   `conform` 四条候选一次全扫，但注意它探的是 **TCP**：`sdk-wired` /
   `sdk-wifi` 那两行显示"通"只说明 **SDK 主机网段可达**，不代表 SDK 能用
   —— 真正的控制口 8082 是 UDP，TCP 探不到（清单 #34）。

## 前置 · 资料全在 git 里，clone 就有，不用拷任何东西

以前这份手册要求手工拷 SDK 和 API 文档。**现在不用了。** 厂商资料已经全部
入库（`refs/urdf/` 除外，那 252 MB 现场用不到）：

    refs/nav-api/自主导航_WEBSOCKET_API.md      # 导航 WebSocket 协议
    refs/robot-sdk/RobotSDK-0.2.0/              # SDK 新版
    refs/robot-sdk/RobotSDK-0.1.1/              # SDK 老版（见下面的版本坑）
    refs/hardware/D1Max-SDK开发指南V0.1.0-正文提取.txt   # 接线/IP/RTSP 都在这
    refs/hardware/智元四足机器人D1 Max SDK开发指南V0.1.0_20260721.pdf

`refs/hardware/` 里那份**正文提取的 txt 是主用的那份**——多数机器没装
poppler，PDF 读不了，txt 随时能 grep。

### ⚠️ SDK 版本对不上会直接连不上 —— 这是最容易踩的一个坑

`RobotSDK-0.2.0/README_zh.md` 里有一张"SDK 版本 × 机器软件平台版本"对照表，
**不是随便配的**：

- 机器平台 **0.3.0(V4)** → 只能用 **SDK 0.2.0**
- 机器平台 **0.1.0-C 到 0.2.4(V4)** → 只能用 **SDK 0.1.1**（或更低）
- 两者**互不兼容**

两个版本仓库里都有了，现场按机器的平台版本挑。**版本号怎么查：见 C4。**

> **2026-09-01 现场结论：这台机器用 `0.1.1`，而且 0.1.1 是全面更好的选择。**
> 不只是"能连上"——0.1.1 能自激活站起（`TakeControl → SetMode(1) → StandUp`）
> **并且遥测正常**；0.2.0 的遥测直接抛 `key 'current_state' not found`，
> 所有数据回调都不触发。**除非机器平台确实是 0.3.0(V4)，否则一律用 0.1.1。**
> 详见清单 #39 / #45。

**⚠️ 厂商 CMakeLists 有个坑，会让编出来的程序跑不起来。**
它写的是 `BUILD_RPATH "${SDK_ROOT}/lib/${ARCH_DIR}"`，但 `ARCH_DIR`
**这个变量他们从头到尾没定义过**，所以 RPATH 会少掉 `x86_64` 那一层，
运行时报 `error while loading shared libraries: librobot_sdk.so.0.2.0`。

不要去改他们的 CMakeLists（改了回家还要对差异），运行前设一下环境变量就行：

```bash
# 在哪个版本的 build 目录里，就指哪个版本的 lib
export LD_LIBRARY_PATH=$(cd ../../lib/x86_64 && pwd):$LD_LIBRARY_PATH
./data                 # 不带参数，应该打印 Usage 就退出 —— 这就说明链接是好的
```

看到 `Usage: ./data <ip> <port>` 就成功了。0.1.1 做到这一步就够。

### C0. 先看清楚：这机器上**没有 RJ45 网口**

这是最容易翻车的地方，出发前必须搞定。

D1 Max 的以太网**不是**普通网口，而是机身**扩展仓电气接口面板**上的
**M12 12 针 A 型（A-coded）航空插头**，板端型号 `M12-P12A-GPFM12`，
而且是**网口 + 电源**合在一个航插里。面板上一共两个这种航插：

| 面板序号 | 接口名称 | 说明 |
|---|---|---|
| 3 | `24V(3A) + 网口` | 网口 A/B/C/D 四对差分 + 24V + GND |
| 4 | `12V(5A) + 网口` | 同上，供电是 12V |

12 针的线序（两个航插一样，只有供电电压不同）：

| 针 | 定义 | 针 | 定义 |
|---|---|---|---|
| 1（棕） | GND | 7（黑） | 网口 B- |
| 2（蓝） | 24V / 12V | 8（灰） | 网口 C+ |
| 3（白） | 24V / 12V | 9（红） | 网口 C- |
| 4（绿） | 网口 A+ | 10（紫） | GND |
| 5（粉） | 网口 A- | 11（橙） | 网口 D+ |
| 6（黄） | 网口 B+ | 12（浅绿） | 网口 D- |

四对差分全都引出来了，所以是**千兆**（整机规格表也写"千兆网口*2"）。

> ⚠️ **别去买通用的工业以太网 M12 转接线。** 市面上标准的工业以太网 M12
> 只有两种：**4 针 D 型**（百兆，2 对）和 **8 针 X 型**（千兆，4 对）。
> 这台机器用的**两种都不是** —— 是 12 针 A 型的"网口+电源"混合航插。
> 买 D 型或 X 型的线插不上，针数和键位都对不上。
>
> 所以只有两条路：**要到厂商原配的那根对插线束**，或者按上面的线序找人
> **定做**（M12 12 针 A 型公头 → RJ45，4/5、6/7、8/9、11/12 四对分别对到
> RJ45 的四对，电源那几针空着不接）。定做来不及的话就走 WiFi。

**总之，一根普通网线插不上去。**

#### 自己买/定做时的完整规格

淘宝上"M12 转 RJ45 连接器"这类工业连接器店能配到，参考规格：

| 项 | 要选什么 | 为什么 |
|---|---|---|
| 产品芯数 | **12 芯 - A 型** | 和 `M12-P12A-GPFM12` 对上 |
| M12 规格 | **直式【公头】** | 机器板端是**母头**（文档 1.5.3/1.5.4 标题写明"航插母头"），线要公头 |
| RJ45 端 | **母头**（RJ45 插座） | 做成 30cm 短尾巴，再接一根普通网线，比整根定长灵活 |
| 线长 | 30cm 够（当 pigtail 用） | 长度靠后面那根普通网线补 |

> 💥 **下单前必须问卖家一件事：12 根芯具体怎么映射到 RJ45 的 8 芯？**
>
> RJ45 只有 8 个触点，12 芯必然要挑 8 根。**卖家默认多半是"M12 的 1~8
> 直通到 RJ45 的 1~8"** —— 对这台机器是灾难：
> - M12 的 **2、3 针是 24V/12V**，会被直接送进笔记本网口；
> - 而且 4/5、6/7 这两对会被拆散（RJ45 的线对是 1-2、3-6、4-5、7-8）。
>
> 正确映射（按机器线序推出来的）：
>
> | 机器 M12 针 | 信号 | 接 RJ45 针 |
> |---|---|---|
> | 4（绿）/ 5（粉） | 网口 A± | 1 / 2 |
> | 6（黄）/ 7（黑） | 网口 B± | 3 / 6 |
> | 8（灰）/ 9（红） | 网口 C± | 4 / 5 |
> | 11（橙）/ 12（浅绿） | 网口 D± | 7 / 8 |
> | 1（棕）、10（紫） | GND | **不接** |
> | 2（蓝）、3（白） | 24V / 12V | **绝对不接** |
>
> 千兆 PHY 自带 auto-MDI/MDI-X 和自动对交换、极性纠正，所以**四对之间的
> 先后顺序换了一般也能通**；但**每对必须保持成对**落在 RJ45 的线对上，
> 电源针**一根都不能上 RJ45**。
>
> 页面上一般有"线长可定制/弯式可定制"，说明能按图定做 —— 把上面这张表
> 直接发给卖家最稳妥。

> ✅ **到货先验，再插笔记本。** 机器上电、M12 插上、RJ45 那头悬空，用万用表
> 量 RJ45 8 个触点对地电压，**必须全是 0 V**。有电压说明电源针串进来了，
> 那根线直接扔，别插笔记本网口。



**这件事出发前必须问客户/厂商：「那根 M12 转 RJ45 的网口线束在不在现场？」**

- **在** → 走 C1（有线），带宽稳，首选。
- **不在 / 问不到** → **走 C2（WiFi）**，一样能干完 D 阶段和 S 阶段的全部活。
  别在现场硬凑，凑不出来。

> 顺带记着：航插不用时要盖防护盖（整机 IP67）；接扩展仓的线之前
> **先按扩展仓按键把扩展接口断电**。这两条是厂商的硬性要求。

### C1. 路线甲：有线（需要 M12 → RJ45 线束）

接法：M12 线束一头拧上机器扩展仓的网口航插（3 或 4 号都行），另一头 RJ45
插笔记本网口。笔记本没有网口就用 **USB 转以太网**转接头——**提前确认带了**。

机器那边有线网段的固定地址（厂商文档 2.5）：

| 主机 | 地址 | 上面跑什么 |
|---|---|---|
| RK3588（运控主机） | `192.168.168.168` | SDK 服务端、RTSP 推流 |
| Orin NX（导航主机） | `192.168.168.100` | 导航、ROS2 |

**笔记本要配成 `192.168.168.x`，x 不能是 100、168、255。** 推荐
`192.168.168.50/24`，不设网关。

先拿网卡名（通常 `enp0s31f6` / `eth0` / 插 USB 网卡后的 `enx....`）：

```bash
ip -br link
```

**做法一：`nmcli`（推荐）。** Ubuntu 22.04 桌面默认由 NetworkManager 托管网卡，
用裸 `ip addr add` 配的地址**可能几秒后被它抹掉**（它会去跑 DHCP）：

```bash
IFACE=<你的网卡名>
sudo nmcli con add type ethernet ifname $IFACE con-name d1max \
     ipv4.method manual ipv4.addresses 192.168.168.50/24
sudo nmcli con up d1max
```

> 收工恢复：`sudo nmcli con down d1max && sudo nmcli con delete d1max`

**做法二：裸 `ip`**（server 版 / `nmcli` 报 `NetworkManager is not running`）：

```bash
IFACE=<你的网卡名>
sudo ip link set $IFACE up
sudo ip addr add 192.168.168.50/24 dev $IFACE
```

> 收工恢复：`sudo ip addr del 192.168.168.50/24 dev $IFACE`

确认（**等 10 秒再看一次，确认没被 NetworkManager 抹掉**）：

```bash
ip -br addr show $IFACE     # 应该看到 192.168.168.50/24
ping -c 3 192.168.168.168   # RK3588
ping -c 3 192.168.168.100   # Orin NX
```

### C2. 路线乙：WiFi（**没有线束时走这条，一样够用**）

机器狗自己开了一个 AP 热点（厂商文档 2.5）：

- **SSID：`XG2WIFI_xxxxxx`**（后面 6 位是机器序列号，现场扫一下就看见了）
- **密码：`12345678`**

```bash

```


**这条路由是走 WiFi 路线时的必做项**——不加它，导航主机（Orin NX）够不着。

## S 阶段 · SDK 会话（2026-09-01 现场实测重写）

> 这一段能做，是因为笔记本是 Ubuntu 22.04 —— 正好是厂商 SDK 的指定平台。
>
> **本节在 2026-09-01 现场被整段推翻重写。** 原来写的"用 0.2.0、连 8081、
> 让 App 连着当安全垫、只跑 `data` 不跑 `control`"——四条里错了四条。
> 下面是实测结论，证据在 `runs/field-logs/` 和 `docs/真机待验证清单.md` #34–#48。

### S0. 三条硬事实（先读完再动手）

1. **端口是 `8082`，协议是 UDP。**（清单 #34）
   连 8081 会连上、然后 `ShakeHand failed`，恒定失败。`conform` 里 8081
   显示"通"只代表主机网段可达，别读成"SDK 可用"。

2. **SDK 版本用 `0.1.1`。**（清单 #45，推翻旧的 #35）
   0.1.1 能自激活站起（`TakeControl → SetMode(1) → StandUp`），**而且遥测
   正常**。0.2.0 遥测直接抛 `key 'current_state' not found`，`OnRobotStateData`
   等回调压根不触发 —— 能控制但看不见状态，没法用。

3. **SDK 资源是独占的，开机后默认被上装占着。**（清单 #46 / #47）
   这是目前最大的障碍。不持有会话时，连**只读**都进不去，报
   `Controlled denial of service`。一旦释放，上装立刻收回，你再也进不去。

   **推论：不存在"先侦察一下、回头再正式连"这种玩法。** 一旦连上，就得
   一直握住。所以 S 阶段和 E 阶段其实是同一条会话的两段。

### S1. 抢开机窗口，起常驻会话

唯一已验证的进入方式：**在机器刚开机、上装还没占住 SDK 之前抢进去。**
高频重试连接，抢到就永不释放。

现场那天用的是 `motion/hold02`。之后它被产品化成
**`motion/patrol_agent`**——同一套抢窗口 + 常驻逻辑，多了一条给 Python
巡检程序用的 TCP 口。**新的联调一律用 `patrol_agent`**，`hold02` 留着只
是为了对照现场日志。

```bash
cd motion && make patrol_agent      # 默认编 0.1.1 / x86_64
mkfifo /tmp/d1max.cmd               # 人工命令管道，只需建一次
./patrol_agent 192.168.168.168 8082 --listen 127.0.0.1:8090 --fifo /tmp/d1max.cmd     2>&1 | tee ~/agent.log
```

**先起 `patrol_agent`，再给机器上电。** 它会一直刷"第 N 次未抢到"，直到打印：

```
[agent] ★★★ 抢到窗口，已连上（第 N 次）★★★
[CTRL] TakeControlAck: SUCCESS
[agent] 监听 127.0.0.1:8090，等巡检程序接进来
```

抢到之后 Python 那头就可以随连随断了：

```python
from d1max_patrol.backends.sidecar_device import SidecarDeviceBackend
backend = SidecarDeviceBackend("127.0.0.1", 8090)
await backend.connect()          # 只是接上旁路进程，不碰 SDK 会话
await backend.acquire_control()  # 核对"旁路进程真握着控制权"
```

`backend.close()`、程序崩、Ctrl+C —— 都不会碰到 SDK 会话。这正是要的：
**巡检程序可以随便重启，控制权不会在缝隙里被上装收回。**

> **`patrol_agent` 和 `hold02` 的一处关键差别：没有 `quit`。**
> `hold02` 的 `quit` 会 `ReleaseControl`，那是当天最贵的一条误操作路径。
> 新程序里改叫 `shutdown`，而且 Ctrl+C / SIGTERM **也不会**释放控制权。

抢到之后它就常驻了：同一条连接里既订阅遥测（`[STATE*]` 行会实时刷
`motion=` / `batt=`），又接收命令。

> **热交接**：如果已经有一条会话在跑、你想换程序，**先起新客户端去抢，
> 抢到了再停旧的**。反过来先停旧的，上装会在缝隙里收回控制权，你就进不去了。

### S2. 通过命令管道发指令（**动机器的命令要先问人**，见 E 阶段）

在**另一个**终端里往 FIFO 里写一行就是一条命令：

```bash
echo status >  /tmp/d1max.cmd     # 只打印状态，不动机器 —— 先跑这条
echo stand  >  /tmp/d1max.cmd     # 站起（会动！先问人）
echo "walk 2 0.4" > /tmp/d1max.cmd  # 前进 2 秒（会动！先问人）
echo lie    >  /tmp/d1max.cmd     # 趴下
echo estop  >  /tmp/d1max.cmd     # 软急停 ON
echo clear  >  /tmp/d1max.cmd     # 软急停 OFF
echo shutdown > /tmp/d1max.cmd    # 释放控制权并退出（**不可逆，之后要重启 RK3588**）
```

（`patrol_agent` 里 `quit` 是停用的：敲它只会打印一句提醒，不会释放控制权。）

TCP 那条口收的是换行分隔的 JSON，跟 FIFO 走同一条会话、同一把锁：

```bash
# 不装 Python 也能戳一下，确认口是通的
printf '{"id":1,"cmd":"hold"}
' | nc 127.0.0.1 8090
```

`Move` 的量级是关键（清单 #37/#38）：`fwd=0.11` 几乎不动，**`0.3~0.5` 才
真的走**。单位是百分比、受 `SpeedLevel` 限速，一条 `Move` 维持 1 秒；
`fwd≈0.5` 大约 0.5–0.6 m/s，和只读接口的 `get_speed x=0.6` 对得上。

### S3. 盯着电量

**白灯转黄灯 = 低电量告警**（清单 #43，厂商文档没写这条）。一天能从 71%
掉到 17%。`hold02` 的 `[STATE*]` 行里有 `batt=`，隔一会儿看一眼。

**四足断电会当场瘫倒。** 低电量还很可能就是建图被拒（#42）的原因。

### S4. 已知进不去的情况

| 现象 | 说明 |
|---|---|
| `Controlled denial of service` | 上装占着。只能重启 RK3588 再抢窗口（#40/#46/#47） |
| 连上但 `ShakeHand failed` | 端口连错了，八成写成了 8081。改 8082 |
| 站不起来 | 是不是漏了 `SetMode(1)`？只 `StandUp` 不行（#45） |
| 站起来但不走 | 是不是 `fwd` 给太小？0.11 不够，给 0.4（#37） |
| 遥测一片空白 | 是不是用了 0.2.0？换 0.1.1（#39） |

## E 阶段 · 运动测试（**必须先问人**）

> **在发任何会让机器动的命令之前，你必须先说这句话并等到回答：**
> "下一步会让机器狗真的走起来。请确认：周围清空了吗？有人在旁边看着吗？
> 急停按钮在手边吗？确认了我再发。"
>
> **人没明确回答，不要发。**

### E1. 加载地图、等定位就绪（这一步机器不动）

```bash
python -m d1max_patrol.cli --url $U load <真实map_id>
```

`<真实map_id>` 用 D2 里列出来的那个。期望：`定位就绪: ContinuousLoc`。

**定位没就绪就绝对不要往下走** —— 定位不准的时候让它走，是要撞东西的。

### E2. 走一个点（先走一个近的）

```bash
python -m d1max_patrol.cli --url $U goto <x> <y> <yaw>
```

**第一个点选一个离当前位置一米以内、周围空旷的坐标。**
坐标从 `paths` 列出来的现有航点里挑最近的，**不要自己编**。

期望：`导航结束: Succeed`。
这一条能验证清单里的第 1、2、11、12 条（终态回落时机、拒绝条件、运动参数）。

### E3. 走完一条完整路线（**时间够、且前面都顺**才做）

```bash
python -m d1max_patrol.cli --url $U walk <map_id> <path_id>
```

注意：本项目是**全逐点执行** —— `walk` 是一个点一个点地发单点导航，
不用厂商的多点接口。这是刻意的设计，不是缺失。

### E4. 建图（**最低优先级，前面全做完还有时间才碰**）

```bash
python -m d1max_patrol.cli --url $U map-start
# ... 人牵着 / 遥控着机器走一圈 ...
python -m d1max_patrol.cli --url $U map-stop
python -m d1max_patrol.cli --url $U maps
```

要采的是：**保存后新地图的 id 长什么样**（清单第 15 条。文档样例写 `map_id_1`，
仿真器发 `map_1`，真机是啥不知道）。

## G · 失败处置速查

| 出什么事 | 怎么办 |
|---|---|
| 网线插不进机器 | 机器上是 M12 航插不是 RJ45，见 C0。没线束就改走 C2 的 WiFi |
| 两个导航地址都连不上 | 回 C6 排查表。**不要**改代码去"适配"，先确认物理链路 |
| WiFi 通但 168 网段不通 | 忘了加路由：`sudo ip route add 192.168.168.0/24 via 192.168.234.1` |
| IP 配上几秒就没了 | NetworkManager 在抢，改用 C1 做法一的 `nmcli` |
| 连上了但报文解析失败 | **原样保存报错和那一帧**，继续跑别的命令。这是好数据不是坏消息 |
| 某个接口返回 error | `conform` 会记下来继续跑，不用管，报告里有 |
| `get_pgm_map` 卡死/超时 | Ctrl+C，记下"多久卡的、有没有部分数据"。这条本来就是测极限的 |
| `./data` 报 `librobot_sdk.so.0.2.0` 找不到 | 厂商 CMakeLists 的 RPATH bug，`export LD_LIBRARY_PATH=.../lib/x86_64`（见 B4） |
| SDK `ShakeHand failed` | 端口写成 8081 了。控制口是 **8082/UDP**（清单 #34） |
| SDK `Controlled denial of service` | 上装占着 SDK 资源。重启 RK3588，用 `hold02` 抢开机窗口（#46/#47） |
| 站起来了但不走 | `Move` 的 `fwd` 给太小。0.11 不够，给 0.3~0.5（#37） |
| 遥测全空、回调不触发 | 用了 SDK 0.2.0。换 0.1.1（#39/#45） |
| 机器动作不对劲 | **先按急停**，再 Ctrl+C。安全永远优先于采数据 |
| 命令行崩了 | 录像已经落盘了（每写一行都 flush，就是为了这个）。捡起 jsonl 继续 |
| 时间不够 | 优先级：**D2 `conform`** > E2 走一个点 > S1 SDK 侦察 > E3 走完整路线 > E4 建图。**D2 一定要做完** |

## H · 绝对不要做的事

- 不要加 `--no-record`。录像没了就补不回来。
- 不要跑 SDK 例子里的 `recharge` —— 它会让机器自己去找充电桩。
- 不要在没问人的情况下发任何会让机器移动的命令（`stand` / `walk` / `lie`）。
- **不要在 `hold02` 里发 `quit`，除非确定今天不再用了。** 释放控制权 = 上装
  立刻收回 = 你再也进不去，只能重启机器抢窗口（清单 #47）。
- **不要"先停旧会话再起新的"。** 要换程序就先起新的去抢，抢到再停旧的。
- 不要在现场改产品代码去"绕过"报错。把报错带回来，回家改。
- 不要在现场编译 SDK 例子（B4 在家做完）。
- 不要把这个仓库、或厂商协议文档，push / 贴到任何公开的地方。
- 不要一次给人贴十条命令。一步一步来，等人回话。
