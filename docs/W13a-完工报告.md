# W13a 原点与待命点拆开 · 设计与完工报告

> 决策 16（用户 2026-09-26 认可）：原点是安全返航、回充的语义，一张图通常一个；待命点是运营调度的语义，可以多个、可调。迁移时用现有原点初始化一个默认待命点。
> 按推荐做，小单：设计与报告合一份。分支 `w13a-standby` → PR。没有狗：开发机上做、测；真机项见 `docs/庄园场景待真机测试.md` §3i。

## 摸底（2026-10-02）

- **站点上根本没有「原点」**：
  - 「在这儿标原点」把狗报的位置登记成**默认待命点**；
  - 下发地图时，拿这张图上的待命点（默认的优先、再按名字）当原点发给狗；
  - 任务做完自动回的也是这个默认待命点。
  - 一个点兼两职：改待命点就是改原点，反过来也一样。
- 狗上的原点（`homes.json`、低电量返航、起飞前检查）是单独的，站点下发什么它就用什么。
- 手机只能「回待命点」（默认那个）、「在这儿标原点」，没有管理待命点的界面；地图预览上只画了待命点。

## 做了什么（按推荐）

| 层 | 改动 | 文件 |
|---|---|---|
| 站点：原点表 | 新表 `homes`：每台狗、每张图、每个版本一个原点。**迁移**：老库打开时，照以前下发地图的挑法（这张图上的待命点，默认的优先、再按名字）抄成原点；待命点原样留着，默认待命点还是它（决策 16 的「用原点初始化默认待命点」，起步两边一样）。只在建表那一次抄，删掉的原点不会复活 | `db.py`（schema 16） |
| 站点：标原点 | 「在这儿标原点」只改原点。这台狗在这张图这个版本上还没有待命点时，顺手用它建一个（这台狗没有默认的、或默认的在别的图上，就设成默认）。已有的待命点不动。晚到的 `home_marked` 事件也只补登记原点 | `standby.py`、`api.py` |
| 站点：下发地图 | **只发原点表里的点**（外审阻断后改：待命点不顶替原点，见下文「外审」）；没有原点、图里也没带 `home.json` 时 409 `no_home`，管理员明说 `without_home` 才照样下发 | `api.py` `_home_on` |
| 站点：待命点 | 新接口 `POST /api/robots/<id>/standby/here`（管理员）：在狗现在的位置设待命点，**不动原点**，可以带 `default`。`standby/return` 可以带 `name`，回指定的那一个。`GET …/standby` 带上原点（`homes`）；地图预览也单独带原点 | `api.py`、`standby.py` |
| 狗 | `mark_home` 认 `target: "standby"`：检查一样（停着、不忙、定位好），回位置，但**狗上的原点、`homes.json` 都不改**。能力里报 `mark_home.standby`：**老代理不认 `target`，会当成标原点把原点冲掉**，所以站点只对报了的狗发，回执里没有 `target: standby` 也不登记 | `runtime.py` |
| 手机 | 单狗页加「待命点…」，进一页列出原点和待命点：<br>- 能派单的人可以「回这儿」（回指定的那一个）；<br>- 管理员可以「在这儿设待命点」（名字、要不要设默认）、「设默认」、「删」（先确认）。<br>「在这儿标原点」的对话框改口：改的是原点、待命点不动。地图预览上原点画蓝方块、待命点画橙圆点，右栏分开列 | `site_standby.dart`、`site_page.dart`、`site_mapping.dart`、`site_client.dart` |
| 注释 | 狗上把原点叫「待命位」的几处改掉 | `homing.py`、`preflight.py`、`assembly.py`、`maps.py` |

**不做**：
- 「回原点」按钮：原点的用处是低电量返航、回充，狗自己按原点走；运营上要狗回去，用待命点。
- 在地图上点一下设待命点：这一单只做「在狗现在的位置设」，坐标有狗的定位背书；站点命令行、接口照旧能按坐标登记。

## 外审第一轮（2026-10-02）：FIX-THEN-APPROVE，1 条阻断，已修

**阻断：没有原点时永久退回用待命点当原点，原点和待命点并没有真拆开。** 新图（或新版本）只登记了运营待命点，下发地图时站点就把待命点当原点发给狗，低电量返航、安全返航都会去那个随时会挪、会删的运营点。老库的兼容 schema 16 那一次迁移就够了，不需要运行时一直退回。

修法：
- `_home_on()` **只读原点表**，没有就是没有；schema 16 的一次性迁移保留，老库升级后的行为不变。
- 没有原点（图里也没带 `home.json`）时下发地图回 409，`reason: no_home`，原因写清楚：下发之后狗不接 goto、巡检，要先把狗开到原点、设好位置、「在这儿标原点」。不再提示「先登记待命点」。
- **跟评审的建议不一样的一处**：评审建议没有原点就一律拒。但「在这儿标原点」要狗先载上这张图（狗用这张图上的定位位姿），新建的图、新版本一律拒的话就永远标不了原点。所以管理员明说 `without_home: true` 才照样下发（审计里记 `without_home`）：狗上没有原点，起飞前检查拒 goto、巡检（狗上本来就这么做，补了端到端测试），遥控、设位置、标原点照常。这还是失败即关闭：默认拒，放行要人明确确认，而且放行之后狗也不会自己走。
- 手机：下发被拒 `no_home` 时弹框说清楚后果，点「照样下发」才带上 `without_home` 再发一次。

补的测试（站点）：
- 只有待命点、没有原点：不下发、不给狗发命令；
- 标了原点才下发，狗拿到的是原点；
- 新版本不继承旧版本的原点；
- 挪、删待命点不动原点；
- 图里带了 `home.json`、这张图上有待命点：按 `home.json`，不按待命点；
- 明说 `without_home` 才下发，狗上没有原点，派 goto 狗报失败、原因说原点；审计带 `without_home`；`without_home` 不是真假值 400；
- 老库升级：迁移把旧的默认待命点抄成原点（`test_site_db.py`），有原点就照常下发（上面那条）；这两段分开测，没有一条从老库文件一路测到下发。

手机：没有原点时说后果、点「算了」不发、确认了带 `without_home` 再发。

突变 5 条全杀（退回用待命点、去掉确认门、审计不记、`without_home` 不核类型、不分版本）；全量 Python 0 失败，手机 229 条全过。

评审的非阻断备注（标原点时同名待命点在别的图上要 `replace`）：记下，`mark_home` 顺带建待命点的语义以后跟 W14 的多待命点一起拆清楚。

## 已知限制

- 原点是每台狗每张图每个版本一个。地图重建出新版本之后要重新标原点：先 `without_home` 下发、把狗开到原点、设位置、标原点，这之前狗不接 goto、巡检。
- 待命点的默认是每台狗一个，不分图；默认的那个不在狗现在用的图上时，自动回程不派、推 `standby_failed`，跟以前一样。
