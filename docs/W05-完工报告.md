## 一、问题（修之前，D4）

- `LocalNavBackend.set_speed()` 只把数存进 `self._speed`；`_advance`/`_turn` 直接用 `params.max_fwd/max_yaw` 饱和，**从不读它**。复现过：`set_speed(0,0,0)` 回显全零，随后 `goto` 照样以 `fwd=0.5` 走，`get_speed` 仍报零。
- 单位不一致：基类契约 `get_speed` 说 m/s、rad/s，这里存的是控制量百分比。
- 后果：方案里「靠近人员自动降速」（5.4）无从实现；上层看到零速、底层在动，是 RobotHAL 规格明令禁止的「静默改写」。

## 二、做了什么

| 改动 | 位置 |
|---|---|
| 内部改存 `_fwd_cap`/`_yaw_cap`（控制量），默认 `max_fwd`/`max_yaw`；`_advance` 饱和上限用 `_fwd_cap`，`_turn` 用 `_yaw_cap`。下限（死区）不动——精细逼近仍靠缩短脉冲，不靠降量 | `backends/local_nav.py` |
| `set_speed(x, y, z)`：按基类契约收 m/s、rad/s，除以 `fwd_speed_mps`/`yaw_speed_rps` 换算成控制量；**超过 `max_*` 夹住并回报夹住后的真实值**；**低于死区抛 `NavRequestError`**（0 也拒——要停用 `stop`）；`y` 非 0 拒绝（本后端不侧移） | 同上 |
| `get_speed()` 回 `{x: cap·fwd_speed_mps, y: 0, z: yaw_cap·yaw_speed_rps}`（m/s、rad/s） | 同上 |

与架构规格 2.2「速度命令返回真实应用值与 clamped/rejected 原因，禁止静默改写」一致：能做的回真值，做不到的明确拒绝。

唯一调用方是 CLI `d1max speed`（`cli.py`），它把 `NavBackendError` 族当错误打印；`NavRequestError` 是其子类，行为不变。HTTP 服务没有设速度的路由。

## 三、测试（4 条新增，先红后绿）

`tests/backends/test_local_nav.py`（仿真旁路进程 + 仿真定位桥，真跑运动循环）：
- `限速是上限_每一拍的前进量都不超过它`：设 0.36·`fwd_speed_mps` m/s → 走 1.5 m，每拍 `fwd ∈ [0.30, 0.36]`
- `限速低于死区_拒绝而不是回显`：0、0.1、-1 都 `NavRequestError`（匹配「死区」），`get_speed` 不变
- `速度按基类契约用米每秒_超过上限就封顶并回报真实值`：默认值 = `max·rate`；`set_speed(5.0, 0, 9.0)` 回报 `max_fwd·fwd_speed_mps`、`max_yaw·yaw_speed_rps`；`y=0.3` 拒绝
- `限速也管转向`：转向上限 0.36 → 每拍 `|yaw| ≤ 0.36`

`tests/backends/test_local_nav.py`、`test_base.py`、`test_ports.py` 全绿；既有断言未改；ruff 干净。

## 四、已知边界

- 上限**只对自建导航**生效。厂商导航的 `set_speed` 走厂商 WebSocket（`nav_speed set`），本单未动；D1 Max 的 SDK 速度档位（`SetSpeed(1/2/3)`）在 W12 接入。
- 死区值 `min_fwd=0.30`、`min_yaw=0.30` 仍是「待真机验证」的假设（#37/#56）；换算系数 `fwd_speed_mps=1.2`、`yaw_speed_rps=1.5` 同样未量。上限的**语义**不依赖这些数，但「0.42 m/s」到底对应多快要上机量。
- 「近人降速」的触发（人员检测）不在本单；本单只保证降速命令**真的生效**。
