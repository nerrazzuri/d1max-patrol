## 2. 外审经过

**第一轮（`f0f037c`）：先修再批准（FIX-THEN-APPROVE），两组阻断，修复在 `eaf34df`。**
- **W00d 速度目标可能越过停车或急停继续生效**（vel 与 halt/estop 的代次竞争；二次检查漏了姿态与急停；C++ 只有源码字符串测试）。
  - 修法：新增运动安全门 `motion/vel_gate.hpp`：检查与登记同一把锁；急停先闩本地、再跟 SDK 说；状态变坏立刻作废，恢复也不复活；驱动在拿锁后、`Gait` 后、每次 `Move` 前现查。
  - 测试：新增 `motion/test_vel_gate.cpp`，用假 SDK 的 C++ 行为测试，含外审描述的交错。
- **W00c2c 同防区合并与事件幂等不是原子的**。修法：占位在一个事务里一步做完；唯一约束冲突转 `duplicate`；等回执的也算合并目标；首条失败就提升后续事件。
- **决策 7**：用户批准；外审随后正式批准。

**第二轮（`eaf34df`）：事件并发阻断通过；运动安全门主体通过，还剩两条阻断，修复在本文档所在提交。**
- **C++ 安全门把急停 Unknown 当成可运行**：改成两路都**明确** Recover 才安全，Unknown、Stop 和没见过的值一样拒，并作废目标；仿真旁路同一语义。
- **控制权丢失后旧速度目标可能复活**：
  - `OnControlLost` 作废速度目标与排队的 walk；
  - 安全门在速度线程看到没控制权时也作废目标，回调漏了也兜得住；
  - 仿真旁路同步。
  - 重新拿到控制权之后，要一条新的 vel 才动。
- **非阻断，也修了**：
  - 站点收尾时被取消的提升派单，落成 `dispatch_failed`（写明狗可能已在路上），不再挂在 `dispatching`；
  - 站点重启时遗留的 `dispatching` 同样收掉，不再占住狗和防区 30 分钟；
  - 本文档正文已统一。
