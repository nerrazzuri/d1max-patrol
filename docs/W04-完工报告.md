## 一、问题（修之前）

- `engine/machine.py::_go_home` 只调 `self._nav.return_home()`；`backends/base.py` 的默认实现是**明确拒绝**（`NavRequestError("该后端不支持返航")`），`LocalNavBackend` 与 `d1max_sim` 都没覆盖。
- 拒绝被 `except NavBackendError` 接住 → `_do_abort("返航失败: …")`：**低电时狗原地停下**（此前用真实 `MissionEngine` + 拒绝的假后端复现为 `ABORTED`）。
- 引擎手里其实有回家所需的一切：`self._home`（原点位姿，spec §1.3 "换电位=待命位=返航目标"）、`live.mission.waypoints`、`live.index`。

## 二、做了什么

| 改动 | 位置 |
|---|---|
| `_go_home` 里 `return_home()` 外包一层：`NavRequestError` → 记日志、`_retrace_home()`、`break`（成功即 DONE）；其他异常路径不变 | `engine/machine.py` |
| 新增 `_retrace_home()`：`legs = waypoints[:live.index]` 倒序 + 原点；每段 `_stop_nav_quietly` → `_await_nav_standby` → `goto` → `_wait_nav_terminal(RETURN_TIMEOUT_S)`。原点为 None 抛 `_FailWaypoint`（走既有"返航失败"中止） | 同上 |
| import `NavRequestError` | 同上 |

**为什么在引擎不在后端**：回溯来路是品牌无关的任务逻辑（架构规格：策略在代理，适配器只碰硬件原语）；在 `LocalNavBackend` 里实现只能直线回家，会穿墙。厂商后端支持 `return_home` 的照旧用厂商的。

**为什么倒序走已到过的点**：那是狗刚走过、已知可通行的路径；`live.index` 是正在去的点，前面的都到过（或试过）。一个点都没到过 → 只剩"原点"一段。

**接管/暂停**：每段都是普通 `goto` + 终态等待，`_ResumeReturnHome`/`_RetryWaypoint` 从 `_wait_nav_terminal` 抛出、一路到 `_go_home` 的循环 → `continue` → 重新进入 `_retrace_home`，按当时 `live.index` 重算。

## 三、测试（3 条新增，先红后绿；前两条红的原因是 `ABORTED is not DONE`）

`tests/engine/test_machine.py`：
- `后端不支持返航_引擎沿来路倒着回原点`：P1 到（index→1）、P2 卡住、电量到返航线 → 断言 `goto_calls[2:] == [P1, 原点]`、`home_calls == 0`、终态 `DONE`、经过 `RETURNING`。用按调用次序的脚本控制每次 `goto` 推什么事件（到/卡/到/到）。
- `后端不支持返航_一个点都没到过就直接回原点`：P1 卡住就返航 → `goto_calls[1:] == [原点]`。
- `后端不支持返航_到过两个点就倒着走两段再回原点`（`964c416`，内部评审抓出来补的）：三个点，P1、P2 到、P3 卡 → 回程必须是 `[P2, P1, 原点]`。**只有这一条真正钉住倒序**——第一条到过的点只有一个，倒不倒序看不出来。

`tests/engine` + `tests/backends` 全绿；ruff 干净。既有断言未改。

## 四、已知边界

- **返航途中接管/暂停再继续，回路从头重走**：`continue` 后重新 `return_home()`（再次被拒）→ 重新 `_retrace_home()`，按当时 `live.index` 重算，而 `live.index` 在回溯期间不变，所以是整条倒序列表从第一段重来，不是从被打断的那一段继续。安全上是重走已验证过的地面，但比「从当前位置继续」多走路。没有测试覆盖这条（`test_machine_suspend.py` 里没有回溯中接管的用例），记为后续账。
- **多圈任务**（`policy.loops > 1`）：`live.index` 每圈从 0 重数，回溯只按本圈进度算；圈首离原点近，这个假设与单圈一致，但未验证。

- 每段超时沿用 `RETURN_TIMEOUT_S = 300 s`（不是 `goto` 的 120 s）；自建导航单段 120 s 的限制在后端内部仍然存在，长腿（>~50 m）会被后端判超时 → `_FailWaypoint` → 整趟按返航失败中止。这是自建导航本身的限制（W10/W12 处理），本单不改。
- 回溯的是**点位**不是轨迹：两点之间后端仍是直线；若去程两点之间本就绕过了障碍（自建导航今天不会绕），回程也绕不了。W10/W11 之前，来路回溯是能拿到的最安全的近似。
- 已到过但**失败**的点（到不了的）也在回溯列表里——它是"试过"而非"到过"；保守起见没有剔除，因为剔除后两点间距变长、穿墙风险更高。
- 电量：回溯路程可能比直线长，`homing.estimate_cost_pct` 的返航线是按 `route_length_m` 估的（本来就按航点路程算），未改。
