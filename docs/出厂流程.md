# 出厂流程（W63）

每块上装板出厂时烧写绑定码、热点、配网证书（W42），并装一张**出厂证书**（W63）。站点只让有出厂证书、
而且现场答得上题的机器人加入（`docs/W63-设备身份-设计.md`）。

## 一、准备（一次）

- 公司台式机上有出厂钥匙、解绑公钥：`~/nexus-keys/factory.key`、`~/nexus-keys/unbind-pub.pem`
  （`docs/钥匙生成与保管.md`）。出厂私钥**只在这台机器上**，不拷到上装板、不发给生产线。
- 上装板已刷好系统、装好我们的软件（`deploy/install.sh`）；台式机能 SSH 上去，账号能免密 sudo。

## 二、一条命令烧一台

台式机上，仓库目录里：

```bash
.venv/bin/python tools/factory.py --board 192.168.1.2=D1M-000123 --out ~/factory-labels
```

- 几块板一起：`--board` 写几次（依次烧，哪块没成会说清楚，其它照做）。
- SSH 账号不是 `robot`：加 `--user <账号>`；钥匙不在 `~/nexus-keys`：加 `--keys <目录>`。

它依次做：

1. 送解绑公钥过去，板子上烧写（`factory burn`）：绑定码、热点、配网证书、设备钥匙（私钥只在这块板上，
   只有 root 能读）、读芯片编号、出厂申请。**读不到芯片编号就不烧**；
2. 取回出厂申请，在台式机上用出厂钥匙签，出厂台账 `~/nexus-keys/出厂台账.csv` 记一行；
3. 证书送回板子装上（`factory install-cert`：序列号、芯片编号、设备钥匙都要是这块板的）；
4. 贴纸打印文件拿回台式机 `~/factory-labels/<序列号>.txt`（权限 600）；
5. 出厂检验（`factory check`）；
6. 删掉板子上的临时目录（失败了也删）。

打完贴纸：`python tools/sticker_label.py ~/factory-labels/<序列号>.txt` 出二维码图，打印、贴好，
**扫一遍实物贴纸**再跑一次检验（板子上 `sudo /opt/d1max/bin/python -m d1max_patrol.cli factory check --scan '<扫到的那串>'`），
然后把 `~/factory-labels` 里这台的文件删掉（里面有绑定码、热点密码）。

## 三、开发样机、老机器：只补设备身份

没走过出厂烧写的机器（C40221、C40011 这类，跑在厂家 Orin 上）不烧绑定码、热点，只补设备身份：

```bash
.venv/bin/python tools/factory.py --board <机器人地址>=<它在站点上的编号> --identity-only --out /tmp/x
```

序列号一定写它**在站点上的编号**（站点核的是这个）。补完以后用开通码重新开通一次
（站点 `d1max-site enroll-code <编号>`，机器人 `provision --code`），站点记下它的设备身份，之后证书才能续签。

台式机连不到机器人时，分三步手工做（申请和证书都不含机密，可以拷来拷去）：

1. 机器人上：`sudo /opt/d1max/bin/python -m d1max_patrol.cli factory device-init --serial <编号>`，
   把 `/etc/d1max/device/device-request.json` 拷到台式机；
2. 台式机上：`.venv/bin/python -m d1max_patrol.cli factory sign-device device-request.json --key ~/nexus-keys/factory.key --out-dir certs --ledger ~/nexus-keys/出厂台账.csv`；
3. 把 `certs/<编号>.json` 和 `~/nexus-keys/factory-pub.pem` 拷回机器人：
   `sudo /opt/d1max/bin/python -m d1max_patrol.cli factory install-cert <编号>.json --factory-pub factory-pub.pem`
   （机器人上已经装了发行包里的出厂公钥，`--factory-pub` 可以不给）。

## 四、被站点拒了怎么查

机器人或手机只会看到「此设备无法加入站点，请联系供应商」，站点网页上什么都没有（故意的）。
站点主机上 `d1max-site company-reports` 导出给公司的记录，每条有原因（没有出厂证书、芯片编号不对、
同一序列号换了设备钥匙……）。公司后台（W43）做好以后由站点自动上传。

常见原因：

- 开发样机没补设备身份 → 按第三节补；
- 换过主板（芯片编号变了）→ 这块新板按第二节重新出厂，旧序列号在站点上先解绑；
- 站点没装出厂公钥（`/etc/d1max-site/factory-pub.pem`）→ 用正式发行包装站点（发行脚本要求包里有它）。
