# 内部安全说明（**不随机器交付**）

> **这一份不在 `交付文件()` 名单上，不发到客户现场，不进工单，不贴群里。**
> 护栏在 `tests/test_deploy_files.py` 的 `test_内部安全说明不在交付名单上` 上钉着。

## 这一份是干什么的

交付面那几份文件里，每一份单独读都是一段负责任的安全披露。**但摞在一起，就可能成为一份
从头到尾的可利用性分析**：哪儿是单点、凑到什么程度能让现场按不了软件叫停、哪一种冒用在记录上
看不出来。所以交付面只留「现场要做的事」，「为什么做得到」写在这里。

**这一份同样不许写真口令、真证书指纹、SSID、厂商私有协议样例。** 它写的是
「我们这一版有哪些已知弱点」，不是「怎么打进去」的操作指南。

> **2026-09-26（W00c5e）整份重写。** 以前这里讲的是狗上老服务那一套（设备 PIN 的离线穷举、
> 热点口令等于公开、同名顶替、名额闸堵住软件急停）。老服务、PIN、手机直连随 W00c5e 一起
> 退役，那些弱点跟着没了；下面是站点这一套的。

---

## 一、站点是单点

站点是唯一权威（决策 8）：账号、派单、遥控、证据、地图、版本都在它上面。**拿下站点主机
就等于拿下这个站点的每一只狗**——能派它们去哪儿、能给它们装一版自己做的代码（版本要经站点
登记、狗核包内指纹，但登记本身就在站点上做）。

所以站点主机本身的安全是这一版的前提：谁有它的 root、谁能登上去、站点目录（CA 私钥、库、
证据）有没有备份到别的盘上、备份盘放在哪儿。这些不是软件能兜住的。

## 二、叫停要两段网络都通

软件叫停走的是「手机 → 站点 → 狗」。任何一段断了，软件叫停都到不了狗那儿。狗自己的兜底是：
遥控帧 300 毫秒过期就停、断线时按任务的断线策略停住等待。**但一只正在自动巡检、断线策略是
「安全时继续」的狗，在网络被切断的那段时间里会接着走完它手上这一趟**——这是设计，不是缺陷；
能让它当场停下的只剩机身上的硬件急停。

凑出「按不了软件叫停」不需要攻破任何东西：把站点和狗之间的网络弄断就够了（拔网线、干扰
无线、把站点主机弄宕）。

## 三、连接数上限可以被人占满

站点的手机 API 与狗专用口都有同时连接数上限，另有**每个来源地址 16 条**的上限（W00c5d 内部
评审加的）。一个能连到站点端口的人，用 16 条空连接就能占满自己那个地址的名额；**用很多个
地址**（或者跟现场手机在同一个 NAT 后面）就能把总名额占满——这时候手机连不上站点，叫停也
按不下去。

TLS 握手在每条连接自己的线程里做，一条不说话的连接挡不住别的连接；但名额是实打实占着的，
直到超时才还回来。

## 四、捡到一台已登录的手机

手机上存着站点的会话令牌。**闲置 30 分钟内**捡到一台没锁屏、已登录的手机，就能按这个账号的
角色操作（保安的账号能派单、能遥控）。记录上看到的是那个账号本人。

现场能做的：手机设锁屏；换班换账号；丢了手机让管理员 `d1max-site disable <账号>`（这个账号
所有会话当场作废）。

## 五、狗的证书在狗的盘上

狗的私钥在 `/etc/d1max/tls/`。**狗被拆走，证书就可能被拷出来**，拿去冒充这只狗连站点：
上传假证据、报假状态。吊销（`d1max-site revoke`）之后狗专用口立刻不认它；broker 那一侧要重启
`d1max-mosquitto` 才重新读吊销表——**吊销和重启之间那段时间，broker 还认这张证书**。

## 六、帧和租约按狗的钟判过期

遥控的帧和租约在狗上按单调钟判（墙钟往回拨不会让狗多走），但站点发下来的续租命令带着站点
写的过期时刻，狗按自己的墙钟判它过没过期。**钟差大了，遥控就开不起来或者几秒就断**——这是
可用性问题，不是安全问题（出错的方向是「停」）。现场真机项 3c.16 专门量它。

## 七、摞起来是什么样

最省事的一条路不是攻破哪一层，而是**把站点和狗之间的网络弄断**：软件叫停到不了，自动巡检中
的狗按断线策略可能继续走。对应的处置只有一条，而且必须写进现场培训：**值守的人要知道机身
硬件急停在哪儿，并且离得够近。**
