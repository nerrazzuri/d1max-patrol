# iOS App：差距与方案（W58 调研，2026-10-31）

用户 2026-10-31：客户手机**安卓和 iOS 都要**。现在只有安卓版。App 是 Flutter 写的，界面和业务代码大部分能直接跑在 iOS 上；差距在下面这些**原生功能**和**苹果的分发、权限规矩**。

## 一、先要你定的（不定就做不了）

| # | 事 | 说明 |
|---|---|---|
| 1 | 苹果开发者账号 | 用公司名义注册 Apple Developer Program（每年 99 美元，要邓白氏编码 D-U-N-S）。个人账号也能上架，但开发者名称显示个人 |
| 2 | 一台 Mac | 编译、签名 iOS 包必须用 macOS + Xcode。也可以用 GitHub Actions 的 macOS 机器（按 10 倍分钟计费），但第一次配证书、调真机仍要一台 Mac |
| 3 | 一部 iPhone | 真机调试；推送、热点、后台行为模拟器上测不了 |
| 4 | 分发方式 | ① App Store 公开上架（要过审核）；② App Store「不公开列出」；③ Apple Business Manager 定制 App（只给指定客户）。**iOS 不允许像安卓那样由站点分发安装包** |

## 二、安卓原生功能在 iOS 上的对应

| 安卓模块 | 做什么 | iOS 怎么做 | 难度 |
|---|---|---|---|
| `FcmToken.kt` | 取推送号 | Firebase iOS SDK 拿 FCM 号（底下走 APNs），站点那边不用改；要在 Firebase 后台上传 APNs 密钥。极光也有 iOS SDK | 中 |
| `AlertBell.kt` | P1 一直响铃到确认 | iOS 不能一直响。可选：①「时效性通知」+ 自带 30 秒内的提示音，没确认就每分钟再推一次；② 向苹果申请「重要提醒」（Critical Alerts）权限，静音模式下也响——只批给医疗、安防等，要写申请 | 中（②要苹果批） |
| `WatchService.kt` | 后台值守（前台服务常驻） | iOS 不允许常驻后台。改为**完全靠推送**：App 在后台时不连站点，报警全靠推送送达 | 中 |
| `RobotHotspot.kt` | 配网时连机器人热点 | **已有降级**（W42）：iOS 上 App 显示热点名和密码，教人去「设置」里手动连。自动连要用 `NEHotspotConfiguration`，并在开发者后台开「Hotspot Configuration」权限 | 低 |
| `ApkInstaller.kt` | 从站点更新 App | iOS 不可能。改为提示「请在 App Store 更新」；站点的「App 分发」只给安卓用 | 低 |
| `MainActivity.kt` | 方法通道注册 | 写在 `AppDelegate.swift` | 低 |

## 三、要验证的风险

1. **站点的自签证书**：App 自己的网络请求（Dart）按证书指纹认站点，iOS 上照样能用；但**视频播放器（AVPlayer）走苹果的网络栈**，不认自签证书，实时画面、录像可能放不出来。方案：①视频改走 App 内的本地转发（Dart 连站点、播放器连本机）；②或站点视频改用 App 自己解码的方式。要在真机上先试。
2. **本地网络权限**：iOS 14 起访问局域网要弹「本地网络」权限，`Info.plist` 要写用途说明；用户拒绝了就连不上站点。
3. **相机、通知权限说明**：`Info.plist` 要写用途文字（中英文）。
4. **审核**：App Store 审核会要求演示账号或演示视频（我们的 App 要连现场站点才能用）；隐私说明（`docs/客户/隐私说明.md`）要放在网上可访问的地址。

## 四、建议的做法和工作量（粗估）

1. 你准备好账号、Mac、iPhone 后，第一周：iOS 工程配置（包名、签名、权限说明）、推送（FCM iOS）、热点（先做手动连）、去掉安卓专属功能入口，真机跑通「添加站点 → 值守 → 收报警 → 处置」。
2. 第二周：视频（自签证书问题）、P1 提醒（时效性通知 + 重复推送）、TestFlight 内测。
3. 之后：重要提醒权限申请、App Store 或定制 App 上架。

在账号和 Mac 到位之前，我能先做的：把安卓专属功能在 iOS 上的降级处理写好（没有后台值守时的提示、更新入口改为 App Store、热点手动连的引导），保证 iOS 编译通过所需的 Dart 侧改动；这些在 Linux 上能写、能跑单元测试，但**编不出 iOS 包、也测不了真机**。
