## 第一个 PR

### 旁路进程丢了控制权自己定期重抢

C40221：用厂家遥控器挪过狗、遥控器退出以后，SDK **不发**「控制权可用」（厂家 App 退出会发）。旁路只等那条通知，一直 `held=0`，收工连趴下都发不了。

- 现在旁路心跳里发现没握着控制权，就**每 6 秒 `TakeControl` 一次**。
  - 成了：走 `SetHeld`，广播握手帧，代理马上知道；
  - 没成：遥控器、App 还拿着时，SDK 回「another master exists」，不会抢走人手上的控制权。同一个原因只记一次日志，6 秒后再试。
- 要在真狗上生效得换旁路进程，换就要重抢开机窗口：下次重启狗时一起换（跟 PR #61 一样）。

### 任务失败原因写清楚

C40221：急停、看不见、定位不收敛，都写成「到不了下一个点（导航回了 Failed）」。

- 两个导航后端（直线、规划）每次进 Failed 之前，都把原因记进 `fail_reason`；引擎写失败原因时带上，例如「到不了下一个点：急停按下了」。
- 记下的原因有：
  - 急停按下了；
  - 没控制权（遥控器或厂家 App 拿着）；
  - 狗报故障；
  - 被挡 N 秒还没走成（扫过区有挡 a 处、看不见 b 处）；
  - 定位不可信：具体原因，比如定位偏差、没设位置、里程不新鲜；
  - 重规划没成；
  - 狗进了禁行区；
  - 障碍数据断了 / 不新鲜；
  - 头尾方向不让走。
- 新的一段开始时清空。

### σ 线收到 0.5 m

C40221 3d.8：杀掉 MOLA 让它自己重定位时，σ 从 1.5 m 往下降，降到 1.0 m 代理就认定位可用了，对导航太松。代理认可定位的线（`BridgeLocalizer.SIGMA_LOST_M`）从 1.0 改成 **0.5 m**。点云匹配正常在 0.1–0.3 m，标原点本来就要 ≤ 0.5 m。

### 定位器：同一张图重新载先验时，自己按最后可信的位置找回来

C40221：代理每次重启（装新版也会），定位器都要人重新给初始位置。查到的问题：

- 定位器载先验时（`prior_loading`），不管是不是同一张图，都把「最后可信的位置」清掉了。注释写的是「别的图才作废」。
- 比较先验是不是同一份时，比的是路径字面。代理经 `active` 链接给的路径和上次字面不同，就会重启 MOLA。

现在：
- 同一张图重新载，「最后可信的位置」留着，MOLA 起来以后按它自己重定位，跟 MOLA 崩了重启时一样；
- 换了别的图照旧作废、等人给；
- 判同一份先验时解开链接再比：同一个文件不重启 MOLA。

**这是从代码里查出来的可能原因，现场到底是哪一路要看笔记本的 `3d7/3d8-loc.txt` 确认。** 回真机要验：代理重启后不用人给位置。

### 定位器监管写对退出码

C40221：罩住前雷达，MOLA 段错误，日志却写「退出码 0」。0 是外层 `ros2 launch` 的退出码。

- 监管现在读 `ros2 launch` 的输出，原样进日志（`mola` 日志器）。
- 认出「底下哪个进程死了、退出码多少」，就写成「定位程序退出了（mola-1 退出码 -11，被信号 SIGSEGV 杀了）」。
- 认不出又是 0 的，写「外层 ros2 launch 退出码 0；底下的 MOLA 可能是被杀或崩了，看日志」，不再像正常退出。

### 注释写反了

`d1max-obstacles-start` 和感知节点里写着「后雷达没标定之前只用来看见『空』」。代码是**没标定只用它的「挡」**、不拿它的「空」放行，标过两样都用。注释改成跟代码一致。

## 测试（第一个 PR）

- 监管：底下节点段错误、外层退 0 → 写明 mola-1 退出码 -11、SIGSEGV；外层退 0、没说谁死了 → 不写成正常退出。
