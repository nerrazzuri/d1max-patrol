# W63 设备身份：只有原厂上装能加入站点（设计）

用户 2026-11-01：平台和上装要牢牢绑在我们手里。要防的是：客户买了一台，逆向上装、自己组装，再把仿制的机器人加入我们的平台管理。

用户定的三条：
1. 新增第四把**出厂钥匙**，跟发行钥匙、解绑令钥匙分开。
2. 这一版**先用纯软件**，安全芯片下一版硬件再加。
3. 没有出厂证书的机器人**一律拒绝加入，不惊动站点和管理员**；把这次尝试记下来，等公司后台（W43）做好推给公司。

## 一、出厂：每块上装板一张出厂证书

1. 出厂烧写（`factory burn`，在上装板上以 root 跑）新增：
   - 生成一对**设备钥匙**（Ed25519），私钥存 `/etc/d1max/device/device.key`，只有 root 能读，永不离开这块板；
   - 读**芯片唯一编号**，取它的 SHA-256 作 `hw_id`：
     - RK3588 读 OTP / eFuse 里的芯片序号；
     - Orin 读设备树里的序号；
     - 都读不到就拒绝烧写，不用 machine-id 之类可随意改的值凑数。
   - 写一份**出厂申请** `device-request.json`：序列号、型号、设备公钥、`hw_id`。
2. 公司在台式机上用出厂钥匙签：`d1max factory sign-device <申请> --key ~/nexus-keys/factory.key` → `device-cert.json`。
   - 证书内容：序列号、型号、设备公钥、`hw_id`、签发时间、出厂钥匙编号，加上签名。
   - 每签一台记一行出厂台账（CSV，公司内部，不进仓库）。
3. 回到上装板装上：`factory install-cert device-cert.json`。装之前核对证书确实属于这块板：公钥、`hw_id`、序列号都要对得上。
4. 出厂检验 `factory check` 加一项：证书在、能验过、私钥跟证书配对。

现有的开发样机（C40221、C40011，跑在厂家 Orin 上）也用正式出厂钥匙签一张证书，**不留任何"跳过检查"的开关**。

## 二、站点：领证书之前先核设备身份

机器人加入站点最后都要经过"领证书"这一步（正常配网之后，或者工程师开通码），**核对就放在这一步**，哪条路都绕不过去。配网申请时也先核一次，假机器人连"待批准"列表都进不去。

1. 站点出题：`GET /api/attest/challenge` 回一个随机数。这个随机数用站点自己的密钥签过、带时间，5 分钟内有效、只能用一次，站点不用另存状态。
2. 机器人答题：配网服务（root，读得到设备私钥）用设备私钥签"用途 | 站点编号 | 随机数 | 序列号 | 要申请的证书指纹"，连同出厂证书、现场读到的 `hw_id` 一起发上来。
3. 站点核对：
   - 出厂证书是我们出厂钥匙签的；认哪几把出厂公钥随发行包下发，跟解绑公钥一样支持更换、作废；
   - 证书里的序列号就是来申请的序列号；
   - 答题签名能用证书里的设备公钥验过（证明真的拿着那把私钥），随机数没过期、没用过；
   - 现场 `hw_id` 跟证书一致；
   - 这个序列号已经在站点登记过、而设备公钥不同，判为仿冒；相同但原机在线，判为整盘克隆。
4. 核过了才继续：配网申请进入"待批准"，或者发证书。登记表记下设备公钥指纹，以后续签证书也要再核一次。

## 三、核不过：悄悄拒，记给公司

- **对机器人和手机**：只回一句中性的话"此设备无法加入站点，请联系供应商"，不说哪一项没过。
- **对站点**：不报警，不进"待批准"列表，不在管理员看得到的地方出现。
- **记给公司**：在站点库里新加一张"给公司的记录"表，记下时间、来源地址、声称的序列号和型号、设备公钥指纹、`hw_id`、没过的是哪一项、站点编号。
  - 网页和手机都不显示这张表；
  - 公司后台（W43）做好后由站点上传；在那之前，工程师可以用命令行导出。
  - 同一来源一分钟内只记一条，防止被刷满。

## 四、出厂钥匙

- `tools/make_keys.py` 加生成第四把 `factory.key` / `factory-pub.pem`；你本人在台式机上运行一次，跟另外三把放在一起（`~/nexus-keys`）。
- 出厂公钥提交进仓库 `deploy/factory-pub.pem`，随发行包装到站点。
- 丢失或泄露时，处理办法跟解绑钥匙一样：新公钥随发行下发，旧钥匙写进作废名单。
- 《钥匙生成与保管》加上这一把。

## 五、这一版拦得住什么、拦不住什么

| 情形 | 结果 |
|---|---|
| 仿制的上装板，没有出厂证书 | 拦住 |
| 把正品的证书文件拷到仿制板上 | 拦住：没有私钥，答不了题；芯片编号也不对 |
| 把正品整盘（连私钥）拷到另一块板 | 多半拦住：芯片编号对不上。但懂行的人能改程序伪造编号读数（纯软件的局限，下一版用安全芯片补） |
| 有站点主机 root 权限的人改站点代码跳过检查 | 拦不住（纯软件的局限）。靠发版后仓库转私有、这部分编译成机器码发布、合同条款 |

## 六、要做的事（实现顺序）

1. 出厂签名、证书格式、验签（共用契约包）+ 测试；
2. 出厂烧写：生成设备钥匙、读芯片编号、出厂申请、装证书、出厂检验；
3. 站点：出题、核对（配网申请、领证书、续签证书三处）、给公司的记录表、命令行导出；
4. 机器人配网服务、开通码领证书：答题；
5. 钥匙脚本加出厂钥匙、文档（钥匙保管、出厂流程、真机测试卡）；
6. 演示站点和测试用临时的出厂钥匙走完整流程（不用跳过开关）。

## 七、我替你做的决定（可以改）

- 被拒时手机上给一句中性提示，否则装机的人会一直卡在"等待批准"。站点和管理员那边什么都看不到。
- 设备钥匙用 Ed25519，跟发行签名、解绑令同一套代码，不引入新的加密库。
- 已经在跑的机器人（开发样机）升级到这一版后，要先补签出厂证书才能续签站点证书；在那之前，旧证书照常用到期。
