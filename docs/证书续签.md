# 机器人证书续签（工单 9）

机器人连站点用的证书是站点 `enroll` 时签的，有效期由 `--days` 决定（C40221、C40221L 在 2026-10-08 签的是 30 天，**约 2026-11-07 到期**）。到期前 14 天站点会报 P2「证书快到期了」。

## 自动续签（W55 起，平时不用管）

机器人和站点都升到 W55 以后：证书剩 45 天以内，站点自动续（一年一签；体检在剩 30 天时才告警，所以正常情况下看不到告警）。机器人生成新私钥和申请（私钥不出机器人）→ 站点签 → 机器人核对新证书跟私钥是一对、编号对、由站点 CA 签的，换上并重启代理（旧证书留 `.prev`）。

- 失败报 P2「证书自动续签失败」，第二天自动重试；网页「诊断」页该机器人「远程运维 → 立即续签证书」、手机机器人页「管理 → 远程运维」可手动触发。
- 机器人要在线、并且报了 `cert_csr` 能力（W55 以前的代理没有，只能用下面的手动办法）。

## 手动续签（老机器人、自动续签不成时）

1. 在站点主机上（站点账号）：
   ```
   d1max-site --home <站点目录> renew <机器人编号> --days 365
   ```
   打印出新证书包的目录。**旧证书不吊销**，到期之前机器人照样连得上，所以续签和换证书之间不会断线。
2. 把新证书包里的这几样拷到机器人上（覆盖旧的；`ca.crt` 没变，不用拷）：
   - `robot.crt`、`robot.key` → `/etc/d1max/tls/`（`robot.key` 权限 0600，属主跟原来一样）
   - `registration.json` → `/etc/d1max/`
   - 包里有 `evidence-pub.key` 的话一起拷到 `/etc/d1max/`（跟原来的一样，覆盖无妨）
3. 重启代理：`sudo systemctl restart d1max-agent`，看站点上它重新在线。
4. 核：站点「体检」里这台不再报「在用的证书还有 N 天到期」（代理会把在用证书的到期时间报给站点；只续了站点这边、没拷到机器人上，告警会写「新证书已签发、机器人未换上」）。

## 注意

- 已经吊销的机器人不能续签，要重新 `enroll`（会换控制代次之外的登记信息）。
- `revoke` 会把这台机器人名下**所有**还有效的证书（续签前那张也算）一起吊销。
- 证书私钥只在站点主机和机器人上，不要发到网上、不要进 Git。
