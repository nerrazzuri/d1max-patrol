# 仓库与知识产权审计（2026-10-12，RC 加固 H4）

> 只审计、不动仓库。怎么处理要用户定（决策 54 当时定的是「暂时不动」）。文末有我的建议和每条路的代价。
> 数字都是 2026-10-12 在 master 上查的。**这不是法律意见**：厂商资料能不能公开、能不能随产品分发，要看跟厂商的合同，我看不到合同。

## 一、现状

| 项 | 查到的 |
|---|---|
| 仓库可见性 | GitHub `nerrazzuri/d1max-patrol`，**公开** |
| 许可证 | 没有 `LICENSE`、`NOTICE`。没写许可证不等于「保留全部权利」之外的任何东西，别人照样看得到、克隆得走 |
| 历史体积 | `.git` 打包后约 44 MB |
| 密钥扫描 | CI 里的 GitGuardian 一直是过的；仓库里没查到我们自己的私钥、令牌 |

## 二、不是我们的东西

### 1. 厂商资料 `refs/`（104 个文件，23 MB）

第一次提交（`97511f4`）就进了仓库，历史里一直有。

| 路径 | 内容 |
|---|---|
| `refs/robot-sdk/RobotSDK-0.1.1/`、`RobotSDK-0.2.0/` | 厂商 C++ SDK：头文件、示例、中英文文档、协议 PDF，**编译好的库**（`librobot_sdk.so`，x86_64 和 aarch64 各两份） |
| `refs/hardware/` | 《D1 Max SDK 开发指南 V0.1.0》PDF 和提取出的正文 |
| `refs/nav-api/` | 厂商自主导航 WebSocket 协议文档 |

- SDK 的说明文件和头文件里**没有许可证条款**（没写能不能再分发）。没写就是没授权。
- **谁在用它**：
  - 现场脚本 `field-sdk.sh`、`field-sdk2.sh` 用里面的示例程序和库（笔记本上跑）；
  - `scripts/extract_refs.sh`、`scripts/extract_doc_samples.py` 从里面抽协议样例；
  - `tests/protocol/`、`src/d1max_sim/`、`src/d1max_patrol/protocol/` 只在注释里引用文档的章节号，**不读这些文件**；
  - `motion/*.cpp`（真机动作小程序）要 SDK 的头文件和库才编得出来。
- **发给客户的包里没有它**：打包白名单只收 `pyproject.toml`、`src`、`config`、`deploy`、`packages`。所以问题在「公开的仓库」，不在「交付物」。

### 2. 文档里的厂商默认口令

`docs/真机验证.md（§6）`、`docs/R阶段-ROS2与建图手册.md`、`docs/RTK-室外定位-调研.md` 里写着狗的热点口令、两台机载电脑的 SSH 账号和口令。这些是厂商出厂默认值，不是我们的密钥，所以密钥扫描不报。但它们在公开仓库里，等于告诉所有人：站在任何一台没改过口令的同型号狗旁边怎么登进去。

### 3. `dist/`（67 MB）

| 文件 | 说明 |
|---|---|
| `dist/app-release.apk`（50 MB） | 2026-09 的旧安装包，直连模式那一版。文档里已经写明「不能用」，但它仍是一个带旧包名、调试签名的可安装文件，放在公开仓库里 |
| `dist/wheels-aarch64-py310/`（8 个轮子，17 MB） | 狗上离线装依赖用的第三方包（numpy、PyYAML、websockets、paho-mqtt、pip、setuptools、wheel、tzdata）。**这个要留**：打包、发行闸都用它，包指纹里有它 |

### 4. `runs/`（59 个文件）

现场日志、取证、抽帧。里面有狗的内网地址、序列号、话题清单，没有客户的东西（还没有客户）。有了客户以后，现场日志不能再进这个仓库。

## 三、第三方依赖的许可证

都是宽松许可证，没有 GPL 一类要求开源我们代码的。

| 部分 | 依赖 | 许可证 |
|---|---|---|
| 站点、狗（Python） | PyYAML、websockets、numpy、paho-mqtt、tzdata | MIT、BSD-3、BSD、EPL-2.0 或 BSD-3（二选一）、Apache-2.0 |
| 值班台（运行时） | preact、@preact/signals、qrcode-generator | MIT |
| 值班台和手机的字体 | Atkinson Hyperlegible Next / Mono | SIL OFL 1.1（可以随产品分发，不能单独卖字体） |
| 手机（Flutter） | Flutter 自带插件、crypto、mobile_scanner、share_plus、file_picker | BSD-3、MIT |
| 手机推送 | jpush_flutter（MIT 的壳）+ **极光 SDK**、firebase-messaging | 极光 SDK 是商业服务条款，不是开源许可证；Firebase 是 Apache-2.0 加 Google 的服务条款 |
| 系统程序（不随包带，装机时装） | mosquitto、ffmpeg、openssl、chrony | EPL / EDL、LGPL / GPL（看发行版怎么编的）、Apache-2.0、GPL-2.0 |

要注意的三点：

1. **宽松许可证也要求带着版权声明**。现在发给客户的包里没有一份「第三方软件声明」。Flutter 会自动把手机依赖的声明收进 App，但我们没有页面把它显示出来；站点、值班台没有。
2. **ffmpeg 是我们调用的外部程序**，由系统包管理器装，不是我们分发的，这样用没有问题。要是以后做成一体机镜像、把 ffmpeg 一起烧进去，就变成我们在分发，要按它的许可证办。
3. **极光 SDK 给安卓包带进了这些权限**：定位（含后台定位）、读手机状态、查询全部应用、读写外部存储。我们自己的功能用不到。上 Google Play 时「查询全部应用」「后台定位」要单独过审；对海外客户，隐私说明里也得解释。只走 FCM 的包可以不带极光。

## 四、我们自己的东西，缺什么

- 没有许可证文件、没有版权声明：代码的归属（个人还是 Nexus Dynamic）没有写在任何地方。
- 仓库在个人账号下，不在公司的组织下。
- 没有第三方软件声明（见上）。
- 没有隐私说明（App 收集什么：账号名、推送号、App 版本；站点上存什么：照片、录像、位置）。

## 五、怎么办：三条路

| | 做什么 | 好处 | 代价 |
|---|---|---|---|
| **甲（建议）** | 仓库**改成私有**；`refs/`、旧安装包先原样留着 | 一步止住继续公开；什么都不用改，CI、现场脚本照旧 | ① 已经被人克隆、被搜索引擎和存档站收走的收不回来；② 私有仓库的 GitHub Actions 按分钟计费，有免费额度，macOS 机器按 10 倍算（现在只有 `experimental` 用）；③ 免费个人账号的私有仓库**没有分支保护**，要 Pro 或者放到付费的组织下，否则「必过检查才能合」这条规矩在 GitHub 上失效 |
| 乙 | 保持公开，把 `refs/`、`dist/app-release.apk`、文档里的口令从**当前版本和全部历史**里清掉 | 可以继续公开 | ① 要改写历史、强推受保护的分支，所有克隆都要重来；② `motion/`、现场脚本要改成从仓库外面找 SDK；③ 清不掉别人已经拿走的；④ 既然公开，还得补许可证，决定是开源还是「公开可看、保留全部权利」 |
| 丙 | 维持现状 | 不花时间 | 厂商的库和文档持续由我们公开分发；第一个客户、厂商、对手都看得到全部代码和文档 |

**我的建议：甲，而且在出第一套正式包之前做。** 理由：

- 这是商业产品，代码和三十多份设计、外审文档现在谁都能看；
- 厂商的库没有再分发的授权，公开分发的是我们；
- 甲是唯一能在几分钟里做完、而且可以撤回的；乙的改写历史随时可以在私有以后慢慢做。

做甲之前要先定的两件事：分支保护怎么保住（升 Pro，还是建一个 Nexus Dynamic 的组织）、Actions 的额度够不够（现在一次 CI 约 60 机器分钟，一次发行闸再加约 80）。

## 六、不管选哪条路都该做的（都不急，按顺序）

1. **问厂商**：SDK 的库、头文件、文档能不能放在我们的私有仓库里，能不能把动作小程序（链了他们的库）装到客户的狗上。拿到书面答复。
2. 删掉 `dist/app-release.apk`（已经不能用，留着只会被人误装）。
3. 文档里的出厂默认口令改成「见现场记录」，口令本身放到仓库外面；装机清单加一条「改掉出厂默认口令」。
4. 加版权声明和许可证文件（闭源就写「版权所有，保留全部权利」，写明权利人）。
5. 出一份第三方软件声明，随站点包和 App 带着；值班台和 App 里各加一个看得到它的地方。
6. 写隐私说明（上应用商店、给海外客户都要）。
7. 有了客户以后：现场日志、客户的地图和录像不进这个仓库。

第 2、3、4 条我可以直接做；第 1、6 条要你；第 5 条我可以先出清单。
