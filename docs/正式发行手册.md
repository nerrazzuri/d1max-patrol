# 正式发行手册

> 商业化 RC0-3，决策 54：**正式包在离线的发行机上签，钥匙不进 GitHub**。
> CI 的 `android` 作业出的包是调试签名的，只给开发、测试用，**不能发给客户**。发给客户的只能是按这份手册出来的。

## 一、两把钥匙

| 钥匙 | 签什么 | 丢了 | 泄露了 |
|---|---|---|---|
| 发行私钥（Ed25519，一个 PEM 文件） | 站点和狗的软件包（`release.json` 的签名） | 再也签不出狗和站点认的包。只能生成新的一把，把新公钥**人到现场**装到每台狗、每个站点上 | 按 `docs/商业化A3-完工报告.md` 的轮换流程换：新公钥放进 `deploy/release-pub.d/`，下一版用旧钥匙签着发下去，再下一版起用新钥匙签，最后把旧公钥从仓库删掉 |
| 安卓 keystore（一个 `.jks` 文件和两个口令） | 安卓安装包 | 已经装了的手机**升不了级**，只能卸了重装（登录信息要重填） | 别人能签出手机认的升级包。只能换钥匙，所有手机卸了重装 |

两把都只存在发行机之外的介质上（建议两个 U 盘，分开放，其中一个进保险柜）。口令不跟 U 盘放一起。**不放进仓库、GitHub、网盘、聊天记录。**

## 二、只做一次：生成钥匙

在发行机上（一台你自己管的电脑；装好这个仓库和 `.venv`，编安卓包还要 Flutter、JDK 17、Android SDK，见 `docs/手机app.md`）。

1. 发行私钥：

   ```bash
   .venv/bin/python -m d1max_patrol.cli release keygen /media/<U盘>/d1max-release.key deploy/release-pub.pem
   ```

   私钥在 U 盘上（权限 600），公钥在仓库里。**把 `deploy/release-pub.pem` 提交进仓库**（走 PR）。从这一版起，包里带着公钥，装机脚本会把它装到狗上、站点上；装了公钥的狗和站点不再接受没签名的包。

2. 安卓 keystore：

   ```bash
   keytool -genkeypair -keystore /media/<U盘>/d1max-android.jks -alias d1max \
       -keyalg RSA -keysize 4096 -validity 10000
   ```

   问到的名字、单位填正式的（装到手机上以后改不了）。然后写 `mobile/android/key.properties`（这个文件不进仓库）：

   ```
   storeFile=/media/<U盘>/d1max-android.jks
   storePassword=<口令>
   keyAlias=d1max
   keyPassword=<口令>
   ```

3. 两把钥匙各复制一份到第二个 U 盘，拿第二个 U 盘按第三节出一次包，确认备份是好的。

> **产品名和包名定下来之前不要做第 2 步之后的正式发行**（决策 54）：包名一改，手机上就是另一个 App。

## 三、每次发行

1. 要发的代码已经合进 master。**先过发行闸**：GitHub 上手动跑 `release-gate` 工作流（或者推一个 `v*` / `rc*` 标签）。它把整套测试跑一遍（集成层在这儿必过），把恢复、升级、回退、兼容那几组点名再跑一遍，最后出一份 `gate.json`（产物 `d1max-release-gate`，留 90 天），里面是提交和包指纹。闸是红的就不发。
2. 发行机上 `git checkout <过了闸的那个提交>`，工作区干净；把 `gate.json` 下到发行机上。插上放钥匙的 U 盘。
3. 一条命令：

   ```bash
   export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ANDROID_HOME=$HOME/Android/Sdk
   .venv/bin/python tools/make_release.py --key /media/<U盘>/d1max-release.key \
       --out ~/d1max-release-out --wheels dist/wheels-aarch64-py310 --build-number <上一次加一> \
       --gate ~/gate.json
   ```

   它先把条件全查一遍，有一条不过就什么都不写：

   - 仓库里没有没提交的改动、没进仓库的文件；
   - 仓库里有提交过的 `deploy/release-pub.pem`，手里这把私钥跟它（或 `deploy/release-pub.d/` 里的某一把）是一对；
   - 私钥只有自己读得到、不在仓库目录里；输出目录不在仓库里；
   - 有 `key.properties`，它写的 keystore 在；给了构建号；
   - 给了发行闸的记录，闸过的就是现在这个提交。

   打完包再对一次：**包指纹跟闸记的不一样就不发**（这台机器上的代码或轮子跟闸测的不是同一份），半成品删掉。

   然后打包、签名、拿仓库里的公钥验一遍；编安卓包（带 `-Pd1max.requireReleaseKey=true`），用 `apksigner` 核它正好一个签名人、不是调试证书。

4. 输出目录里有：

   | 文件 | 给谁 |
   |---|---|
   | `<日期>-<提交>/`（包目录） | 站点主机（`install-site.sh`、`d1max-site release-add`）和狗（`install.sh`） |
   | `<包名>-android-<版本>+<构建号>.apk` | 手机 |
   | `<包名>-android-<版本>+<构建号>.apk.manifest.json` | 站点分发 App 用的签名清单（W55）：网页「软件升级 → App 安装包」连 APK 一起上传 |
   | `<包名>.release-record.json` | 留档：提交、包指纹、发行钥匙编号、安卓证书指纹 |
   | `<包名>.SHA256SUMS.txt` | 拷到 U 盘、发给现场之后对一遍 |

5. **第一次发行时把屏幕上的「安卓证书」那一行抄下来**；以后每次发行都跟它对，不一样就是签错了钥匙，不要发。
6. 拔掉 U 盘，放回去。`key.properties` 里有口令：发行机不是只有你用的话，发完把它删掉。
7. 升级顺序按 `docs/版本兼容与升级顺序.md`：先站点、后狗、最后手机。远程升级（W55）：把包目录打成 `.tar.gz`（`tar czf <包名>.tar.gz -C <输出目录> <包名>`），
   在网页「软件升级」上传，站点用「升级站点」、机器人用上传升级包；App 用上面的 APK 加清单。见 `docs/远程运维手册.md` 第四节。
   单独给桌面版等别的安装包签清单：`d1max release sign-app <文件> --version <主.次.修+构建号> --key <私钥>`。

只出站点和狗的包、不编安卓：加 `--skip-android`（不用 keystore、不用构建号）。

明知没过闸也要出包（比如现场救急）：`--no-gate`。屏幕上和发行记录里都会写明「没过闸」，这样的包不算正式发行。

**钥匙为什么不放 GitHub**（决策 54）：闸只回答「这份代码测过了」；签名只在你手里的机器上做。仓库权限被人拿到，也出不了狗、站点、手机认的包。

## 四、限制

- 发行机第一次编安卓包要上网下 Gradle 依赖；下过以后可以断网编。发行私钥那一步本来就不用网。
- 脚本只认「不是调试证书、正好一个签名人」，**不知道哪一张才是你的正式证书**，所以要有第三节第 5 步的人工对指纹。
- 没有 iOS、鸿蒙的发行流程。iOS 只有基础工程（H13，`mobile/ios/`，只在 experimental 工作流里手动验「不签名编得过」，
  没有签名、没有 APNs 推送）；鸿蒙只做了调研（H14，`docs/鸿蒙可行性调研.md`），没有工程。
- 极光、FCM 的参数（`docs/告警推送配置.md`）这个脚本不传：等账号注册了、加 FCM 的时候一起接进来（决策 54）。现在出的安卓包没有推送，靠后台值守收告警。
