## 交付

`.github/workflows/ci.yml`：推 `master`、开 PR 时跑；同一分支的新提交把旧的那次取消掉；只读权限；官方的 `actions/checkout`、`actions/setup-python`
按提交哈希钉死；Flutter 按标签（3.47.5）从官方仓库拉，不用第三方 action。

## 分支保护（决策 20、22）

**2026-10-01 已开**（用户「你帮我开」）：`lint`、`py-contract`、`py-agent`、`py-site`、`py-core`、`flutter` 必过（`strict`：合并前要跟 master 同步），`integration` 不设，`enforce_admins=false` 保留管理员紧急处置。从 W11 起改走短分支 → PR → 必过检查通过 → 合并。下面是当时给的开法，留档。

### 原来的说明

CI 在几次提交上都稳了之后开 `master` 的分支保护，把 `lint`、`py-contract`、`py-agent`、`py-site`、`py-core` 设成必过（`flutter` 再稳几次加进去；`integration` 不加），
保留管理员紧急处置。网页上：仓库 Settings → Branches → Add branch ruleset（或 classic 的 branch protection rule）→ `master` → Require status checks to pass →
勾上面五个。或者用命令（仓库管理员账号）：

```bash
gh api -X PUT repos/nerrazzuri/d1max-patrol/branches/master/protection \
  -H "Accept: application/vnd.github+json" \
  -F required_status_checks[strict]=true \
  -f 'required_status_checks[contexts][]=lint' \
  -f 'required_status_checks[contexts][]=py-contract' \
  -f 'required_status_checks[contexts][]=py-agent' \
  -f 'required_status_checks[contexts][]=py-site' \
  -f 'required_status_checks[contexts][]=py-core' \
  -F enforce_admins=false -F required_pull_request_reviews=null -F restrictions=null
```

（`enforce_admins=false` 就是保留管理员紧急处置。）开了之后我这边改走「分支 → PR → CI 过了再合」，不再直推 `master`。
