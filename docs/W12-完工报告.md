## 摸底（2026-10-01）

- SDK 的 `Move` 收比例值，换成 m/s **全看档位**（`sdk_client_api_zh.md` 的 `SetSpeed`）：
  - 低速（默认）：前进 ±1.0 = ±1.0 m/s，转向 ±1.0 = ±1.5 rad/s；
  - 中速：前进 ±1.0 = ±2.0 m/s。
- 我们从没调过 `SetSpeed`，也没读过 `RobotState.speed_level`。有人在厂家 App 上换了档，同样的比例就快一倍，没人知道。
- **换算系数是猜的，而且猜错了**：默认「比例 1.0 = 0.4 m/s」（`--mps-per-unit 0.4`），可文档和 #38 的粗测都是约 1.0–1.1 m/s。后果：
  - 代理以为自己最快只有 0.5 × 0.4 = 0.2 m/s，实际约 0.5 m/s；
  - **W10 的限速区限不住**：限 0.3 m/s，换算成比例 0.75，被比例上限 0.5 夹住，实际跑 0.5 m/s；
  - 遥控「能力的一半」也是按错的数算的。工单里「有效约 0.42 m/s」就是这么来的。
- 死区 0.05 m/s 按错的系数折算成比例 0.125。#37 实测：比例 0.11 几乎不动、0.3 明显走。

## 做了什么（按推荐）

| 块 | 内容 | 文件 |
|---|---|---|
| 档位（旁路进程协议 7） | 参数 `--speed-level`（默认 1 低速，0 不管）。拿到控制权就 `SetSpeed`；档位被换掉就每秒再设一次；**档位不对的时候运动安全门不放行任何运动**。`state` 带 `speed_level`，`hello` 带 `speed_level_want` | `motion/vel_gate.hpp`、`patrol_agent.cpp`、`test_vel_gate.cpp` |
| 档位（代理） | 档位不对时 HAL 拒速度命令（`speed_level`），旁路进程设回去之后照常。老旁路进程（≤ 6）不报档位，不核 | `adapter-d1max/hal.py`、`agent_frames.py`、`d1max_sim/agent_server.py` |
| 换算默认值 | 按 SDK 文档的低速档：`--mps-per-unit` 0.4 → **1.0**，`--radps-per-unit` 1.0 → **1.5**，`--deadband` 0.05 → **0.2** m/s（#37）。比例上限 0.5 不动，**实际最快仍约 0.5 m/s**，只是代理对速度的认知对了 —— 限速区、遥控限速、规划的速度从此按真的算 | `main.py`、`adapter-d1max/hal.py`、`install.sh`（模板；env 里照抄了老模板 `0.4` 的只提示、不改） |
| 近障降速（人也是障碍，认不出人） | 行进方向前面、机身两边各多 0.5 m 的带子里，最近的「挡」在 2 m 以内开始降，0.5 m 处降到 0.25 m/s（线性）。只看「挡」不看「看不见」，不然侧面盲带会让狗一直慢。刹停仍归守卫（按实测速度） | `robot-agent/obstacles.py`（`near_ahead`）、`bridges/planned_nav.py`（`_near_cap`） |
| 限速区 | W10 已经有（规划按区限速）；这一单之后才真的限得住 | — |

**最高速度**：第一版上限 ≤ 0.6 m/s（W08）。现在比例上限 0.5 × 1.0 m/s = 0.5 m/s，在上限以内，**不往上调**：要到 0.6 得把旁路进程的比例上限从 0.5 放到 0.6，等真机量过换算、停车距离再说（§3h.4）。

**一个看得见的变化**：限速低于前进死区的限速区，W10 内审起就按禁行处理（再慢狗就不走了）。死区从 0.05 改成 0.2 之后，**限速 < 0.2 m/s 的限速区在真狗上会变成禁行**。以前这种区其实也没限住（代理以为 0.15，实际约 0.375 m/s）。手机画限速区时请 ≥ 0.2 m/s。

## 测试

- 新增：
  - 协议：档位字段，老旁路进程不报是 None；
  - C++ 门：要了档位，没收到过、被换成中速都不走，对了才走，速度线程那一拍不发非零 `Move`；不管档位时照旧；
  - 仿真旁路进程：档位被换掉不走，1 s 后自己设回去；不管档位时不核；
  - d1max 适配器：档位不对拒、设回去后照常；不管档位不核；默认换算；
  - 近障：只看行进方向前面带子里的「挡」，狗尾为前看身后，带子外、看不见的都不算；仿真世界里前面偏一点有人，狗慢下来（不低于 0.25 m/s），之后照常走到；
  - 装机脚本的提示。
- 改了的：
  - 协议版本断言（6 → 7）；
  - `test_hal_d1max的参数` 的默认值；
  - 「挡的东西挪走了」：近障降速后狗慢慢靠过去，被挡得晚一点，改成等到被挡为止，最多 5 s。
- 突变 7 条全杀：HAL 档位检查、默认换算、仿真档位门、仿真设回档位、近障限速、近障看行进方向、近障带宽。
- C++ `test_vel_gate` 全过、`make patrol_agent` 编过；全量 Python 0 失败（`w12-speed` 分支）。

## 已知限制

- 档位换算、死区、停车距离都还是文档值和粗测值，真机要用 `tools/w00d_motion_check.py` 量（§3h.2）。
- 档位被换掉之后的那一秒里不放行运动：正在走的任务会被 HAL 拒、按失败收尾。有人在 App 上换档，本来就算人在干预。
- 近障降速认不出人，箱子、墙角一样降；墙边窄道里会一直偏慢（两边 0.5 m 带子），真机看要不要收窄。
- 遥控不受近障降速（遥控本来就只有能力的一半，约 0.25 m/s）。
