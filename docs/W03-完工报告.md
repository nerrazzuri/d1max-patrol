## 一、问题（修之前）

1. `engine/upload_queue.py::_EXACT` 是白名单（不是黑名单），`findings.json`（模型判读）、`review.json`（人工复核）、`report.html` 不在其中，`classify()` 回 `None`，**从不入队**。这三份只在狗上有一份；保留策略按水位 `rmtree` 整趟时随之消失。W02 已把它们列进 `REWRITTEN_IN_PLACE`，但"判得出改写却根本不入队"。
2. `.uploaded` 标记**永不撤销**：`app/server.py::_该打可删了吗` 见标记即返回。W02 之后同大改写的报告会重新入队，此时标记若已挂上，`/api/storage/sweep` 会在重传完成前删掉整趟——改过的结论两头都没了。两轮评审都指向这条。

## 二、做了什么

| 改动 | 位置 |
|---|---|
| `_EXACT` += `report.html`（三级，同 report.md）、`findings.json`、`review.json`（二级，同 events/manifest：小、是结论） | `engine/upload_queue.py` |
| 新增 `retention.unmark_uploaded(run_dir) -> bool`：撤标，幂等 | `engine/retention.py` |
| `_该打可删了吗` 判序调整：**先**查该趟在队列里有没有未 `done` 的——有就 `unmark_uploaded` 并返回；没有再看标记/收工/打标。撤了之后全传完会经原路打回 | `app/server.py` |
| 新增 `_mask_uploaded_by_queue(runs, runs_root, queue)`：把活队列里仍有未 `done` 条目的趟的 `RunInfo.uploaded` 遮成 `False`；清盘路由 `_sweep` 在 `plan_sweep` 之前调它（`ctx.upload` 存在时）。这是第二道闸：`scan()` 重开条目到 `_补打可删` 撤标之间隔一拍，清盘请求落在窗里时盘上的标记还是旧的 | `app/server.py` |
| `UploadPump.queue` 只读属性，给路由拿活队列 | `app/upload_pump.py` |

分层：`upload_queue`/`retention` 仍互不知道对方；"标记跟着队列走"只在 `app/server.py` 这一层接线，与仓库既有规矩一致。

## 四、已知边界

- 遮罩只在**清盘路由**生效；`/api/storage` 的盘况/预告显示的 `uploaded` 仍读盘上标记，撤标那一拍之前可能短暂显示"已传"。只影响显示，不影响删除。
- `unmark` 与 `mark` 由同一条回调路径写，无并发写者；`_补打可删` 与 sweep 之间的互斥仍靠 sweep 自己的 `_sync_lock`，本单未改。
- 单机档（无服务器）下 `uploaded` 永远不会被打上，本单对它无影响；`exported` 路径未动。
