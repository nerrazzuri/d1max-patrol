# W55 远程运维（设计）

> 用户 2026-10-31：重新把维护部分查一遍，**要确保整套系统能让工程师远程定位大部分问题、解决绝大部分事情**。
> 本文先盘点现状（每一项都核过代码），再列缺口和补法。最后一节是要用户定的事。

## 一、目标

工程师不到现场，能做到：

1. **连得上**：从公司或家里连进客户站点（站点网页、站点主机、机器人）。
2. **看得见**：出了问题能从日志、状态里看出是哪一块、为什么。
3. **动得了**：重启服务、重启机器人、调日志级别、续证书、清磁盘、重新对时。
4. **升得动**：机器人、站点、App 都能远程升级，坏了能退回。

不在范围：厂家的运动控制固件、操作系统本身的升级（仍要现场或厂家）；公司后台（W43）。

## 三、补法（一张单子做完）

### A. 连得上

- **A1 工程师接入**：VPN 加第三种角色「工程师」（`d1max-site vpn add engineer <名字> --hours 24`）。到点自动从站点配置里删掉（站点每分钟查一次、重新装配置）。网页「用户」页开工程师账号时可以顺手勾「同时给 VPN 配置」，出二维码 / 配置文件。
- **A2 工程师到机器人**：工程师的隧道地址可以 SSH 到机器人和站点主机（站点开转发，**只放行工程师地址 → 机器人 22 端口、站点主机 22 端口**）。**要用户定**（见第五节）。
- **A3 装机就装好 VPN**：`install-site.sh` 和机器人 `install.sh` 默认装 WireGuard、写好配置（客户要求只在局域网的，加参数跳过）。体检里加「VPN」一项：隧道是否起来、每个机器人 / 工程师最后一次握手时间。

### B. 看得见

- **B1 机器人日志远程取**：代理新命令 `journal`：取我们自己的服务（`d1max-*`，白名单）最近 N 小时日志，打码（令牌、长十六进制）、限大小（单次 ≤ 2 MB）。站点 `/api/robots/<id>/journal?unit=&hours=`；网页、App 机器人页「日志」可选服务、时间段、下载。
- **B2 机器人日志保留**：`install.sh` 写 `/etc/systemd/journald.conf.d/d1max.conf`：`Storage=persistent`、`SystemMaxUse=500M`、`MaxRetentionSec=14day`。
- **B3 机器人诊断快照**：代理新命令 `diag`：我们每个服务的状态（在跑 / 失败 / 重启次数 / 起了多久）、各服务版本、内存、CPU、温度、磁盘、开机时长、网络（WiFi 名、信号、4G）、对时状态、证书到期、`/etc/d1max/env`（打码）、最近 20 条起飞前检查结果。网页机器人页「诊断」一屏显示，可下载。
- **B4 诊断包补全**：站点诊断包加：每台在线机器人的诊断快照 + 最近 6 小时日志（B1、B3）、7 天机器人事件、7 天命令回执、7 天操作记录、30 天运行指标、VPN / 对时 / 消息服务日志、App 与网页的错误记录（B5）。下载时选时间段（默认 24 小时，最长 7 天）。
- **B5 App、网页错误记录**：App 本地留最近 500 条错误（接口报错、异常、Flutter 报错，带时间、页面、版本），登录着时每 10 分钟传给站点；网页同样传。站点存 14 天，进诊断包。不传画面、不传密码。
- **B6 运行指标看图**：网页「系统」页加 30 天曲线：磁盘、机器人在线、待传证据、事件循环延迟。

### C. 动得了

- **C1 远程重启**：
  - 机器人上的服务：代理新命令 `service_restart`（白名单里的我们的服务；代理自己也行）。
  - 整台机器人重启：代理新命令 `reboot`，**只在空闲（没任务、没遥控、没在充电对桩）时**，要二次输入密码，进操作记录。
  - 站点服务：网页「系统」页「重启站点服务」，站点自己退出由 systemd 拉起（同样要密码）。
  - 权限：管理员、工程师。
- **C2 证书自动续签**：站点在证书剩 30 天时自动续签，通过命令 `cert_install` 把新证书发给机器人（加密信道里，机器人核验链、核编号、换上、重启代理）。失败报 P2 并保留手工办法。
- **C3 临时详细日志**：机器人页「详细日志 1 小时」：代理和各服务把日志级别调到 DEBUG，到点自动恢复。
- **C4 远程清理**：机器人磁盘页列出可清的东西（已上传的录包、旧版本、旧日志），勾选清理；正在用的、没传完的不让删。
- **C5 立即对时**：机器人页「重新对时」，代理调 `chronyc makestep`（或对应命令）。
- **C6 推送测试**：网页「系统」页「发一条测试推送」到指定账号的手机。
- **C7 网页恢复备份**：网页「系统」页列出备份，选一份恢复（要密码；先自动再备份一次当前的；恢复后站点重启）。

### D. 升得动

- **D1 机器人升级修三处**：① 切换后重启**所有**我们的服务（按包里清单），不只代理；起不来按现有规则整版回退；② 包里带 systemd 单元文件，切换时更新（有特权的小助手 `d1max-units-apply`，只认包里白名单里的单元）；③ 旁路进程源码进包，安装时在机器人上编译（编不过 = 装失败，不切换）；文档改正。
- **D2 网页升级站点**：上传公司签名的站点包（`.tar.gz`）→ 验签 → 自动备份 → 装新版 → 体检 → 不过就用刚才的备份自动恢复老版本。由一个独立的小服务 `d1max-site-updater`（systemd 一次性单元）执行，站点自己不替换自己。
- **D3 App 更新**：站点存每个平台最新的 App 安装包（跟机器人包一样上传、验签）。App 登录后问站点有没有更新，有就提示，点了下载安装（安卓直接装；桌面版下载后打开安装）。
- **D4 发行钥匙**：用户生成（`d1max release keygen`、Android keystore），这张单子只写操作说明，不碰钥匙。

## 六、实现要点（我定的）

### 特权执行器（机器人、站点各一份）

要 root 的事（重启服务、重启机器人、对时、换证书、装服务单元、清日志、站点升级、站点恢复备份、装 VPN 配置、读 VPN 状态）
都不让代理、站点进程自己做（代理是 `robot` 用户；站点单元带 `NoNewPrivileges=yes`，也提不了权）。做法：

- 普通进程往**请求目录**写一个 JSON（`/var/lib/d1max-ops/req/`，属主是代理或站点用户、0700），
  systemd 路径单元 `d1max-ops.path` 看见就拉起一次性单元 `d1max-ops.service`（root），它逐个处理、把结果写进
  **结果目录**（root 属主、请求方可读），请求方等结果（有超时）。
- 执行器是装机脚本拷到 `/usr/local/lib/d1max/ops-runner` 的**独立脚本**（root 属主、只用标准库），
  **不从机器人可写的版本目录里跑任何代码**（版本目录属主是 `robot`，root 跑那里的代码等于把 root 交出去）。
- 只认白名单动作，参数逐个校验（服务名在白名单里、路径固定、文件按 O_NOFOLLOW 打开、请求文件属主必须是请求方）。
- 换服务单元、站点升级要先**验发行签名**（执行器自带一份验签代码、用 root 属主的公钥），验不过不装。
- 测试、演示站点、仿真机器人没有 root：用同一个接口的「本机模拟」实现，动作记下来、不真做。

### 机器人这边（新命令，都走「地图类命令」那条路：站点发、代理回执里带数据）

| 命令 | 做什么 |
|---|---|
| `ops_journal` | 我们的服务（白名单）+ `sshd`、`wg-quick@d1max`、`chrony` 最近 N 小时日志，打码，单次 ≤ 2 MB（代理用户加进 `systemd-journal` 组，直接读，不经执行器） |
| `ops_diag` | 诊断快照（见三 B3） |
| `ops_restart` | 重启一个我们的服务（执行器） |
| `ops_reboot` | 空闲才重启整机（执行器，3 秒后） |
| `ops_debug` | 详细日志 N 分钟（≤ 120）：写一个到点文件，我们的 Python 服务每 10 秒看一次、调日志级别 |
| `ops_cleanup` | 列出 / 清理：多余的旧版本（留当前和上一版）、日志（`journalctl --vacuum-size`）、已上传且超过保留天数的录包 |
| `ops_timesync` | 立即对时（执行器：chrony `makestep`，没有 chrony 就重启 timesyncd） |
| `cert_csr` / `cert_install` | 机器人自己生成新私钥和证书申请（私钥不出机器人），站点签好发回，机器人核对（公钥对得上私钥、CN 是自己、链到站点 CA）后由执行器换上、重启代理 |

### 站点这边

- 机器人运维接口 `/api/robots/<id>/ops/<动作>`：管理员、工程师；重启整机、重启站点、恢复备份要再输密码；全部进操作记录。
- 证书自动续签：每天看一次，剩 30 天以内的在线机器人自动走 `cert_csr` → 签 → `cert_install`；失败报 P2、下一天再试。
- 诊断包：按时间段（默认 24 小时、最长 7 天）带上三 B4 列的东西。
- App、网页错误记录：新表 `client_errors`（库结构加一），留 14 天。
- 站点升级、App 安装包：站点包、App 包都用公司发行钥匙签名；站点包交给执行器（先备份、装、体检，不过就用刚才的备份恢复）；App 包存在站点目录 `apps/`，App 登录后查更新、提示、下载安装（安卓弹系统安装界面；桌面版下载后打开所在文件夹）。
- VPN：新角色「工程师」带到期时间；站点每分钟清一次到期的、通过执行器重装 VPN 配置；站点 VPN 配置里加转发规则：只放行工程师地址 → 机器人地址和站点隧道地址的 TCP 22。

### 升级修复

- 机器人换版本后，执行器重启我们所有已启用的服务（不只代理）。
- 包里带服务单元，执行器验签后更新有变化的单元、`daemon-reload`。
- 旁路进程源码（`motion/`）进包，安装新版本时在机器人上编译（编不过 = 装失败，不切换）；`d1max-sidecar-start` 用这一版编出来的程序。
