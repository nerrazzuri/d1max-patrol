## 一、问题（修之前）

`app/server.py::_schedule` 路由的 docstring 原话：「**到点自动出发这件事,整个仓库里没有人做。**」`engine/schedule.py` 的 `decide()`/`pick()` 是纯判据，只有那条只读路由调它们、把结论写进响应给值守屏看；`last_started_ms` 一律传 `None`。要让一趟任务出发，唯一的办法是有人 `POST /api/missions/<id>/run`。方案的 R5「按时段自动巡逻、夜间加密」因此今天不成立。

## 二、做了什么

| 改动 | 位置 |
|---|---|
| `_StateHub._schedule_runner`：`while True: sleep(_SCHEDULE_PERIOD_S=30) → _schedule_once()`；兜 `OSError/ValueError/BundleError/MissionError/HomeError/EngineBusy` 记进 `last_error`；别的异常掀翻协程，`_执行器塌了` 记 `watchdog_died` P1（与租约看门狗同一套） | `app/server.py` |
| `_schedule_once`：`active_bundle` → `read_bundle_schedule` → 包里时区的 `now` → 每条 `decide(entry, now, last_started_ms=_last_started(entry))` → `pick(decisions, running=…)`；**引擎在跑**（`running` 传本进程起的那条 id 或 `"manual"`）或 **有人握着控制权**（`ControlDesk.sweep()` 后 `holder` 非空）就不起并记 `last_skip`；任务从**当前任务包** `missions/<id>.json` 取，包里没有再退到 `missions_dir/<id>.yaml`；原点 `load_home(map_id)`；起飞检查走与手动路由同一个 `_preflight_with_scan`，没过记 `last_skip`；过了 `engine.start`，记 `_sched_started[entry.id]=now` | 同上 |
| `_last_started(entry)`：内存记录与 `_last_run_started_ms(runs_root, mission)`（`runs/<任务>/` 下最新目录名按 `STAMP_FMT` 解成 UTC 毫秒）取晚者——**重启后靠归档回查**，这是工单原话"两条必须一起补"的那另一条 | 同上 |
| `/api/schedule`：`decision` 用真实 `last_started_ms`；新增 `executor` 块（`period_s`、`last_tick_ms`、`last_started`、`running`、`last_skip`、`last_error`） | 同上 |
| `_StateHub.start` 挂协程 + `add_done_callback(_执行器塌了)`；`stop` 沿用统一取消 | 同上 |

**不做的**：排程**不打断**正在跑的任务（`pick` 的 §3.3 第 3 条），抢占是 W14；`on_missed: alarm` 的告警没有登记过的 kind，本单只记进 `last_skip`/日志（W17 一起做）；多个待命点、随机路线也是 W14。

### 二之二、内部评审修复（`0af1066`）

评审 FIX-THEN-APPROVE，两条必修 + 一条风险，都做了：

| 发现 | 改法 |
|---|---|
| 执行器崩溃告警复用 `watchdog_died`；`AlertBook` 按 robot/kind 聚合，租约看门狗和执行器各死一次会合成一条、后死的盖掉先死的诊断 | 登记独立 kind `schedule_died`（P1） |
| `pick()` 返回的 `displaced`/`alarms` 被静默丢弃，值守屏看不到"到点了但没轮到" | 记 `executor.last_displaced` + WARNING 日志（正式告警随 W17） |
| 没有钟偏闸：真机钟差半年，执行器会按错钟出发 | 有时间参照且偏差 > `CLOCK_SKEW_ALARM_S`（60 s）→ 不起，`last_skip` 说明；没有参照（单机档）照常 |

评审另指出的窄边界（如实记）：`engine.start()` 若在建好归档目录之后、返回之前抛错，下一拍的归档回查会把这一轮当"起过"——静默跳过一轮、无告警；`MissionEngine.start` 内没有 await 点，窗口极窄，未处理。

## 三、测试（8 条新增，全部先红后绿）

`tests/app/test_api_bundle.py`（真服务、真引擎、假导航；执行器周期拨到 0.3 s；包里任务的图 `floor1` 先标原点，否则起飞检查拦住）：
- `到点了执行器自己把任务起跑`：钟 22:10、排程 22:00±45 → 引擎跑起来、`snapshot.mission == "night"`、`executor.last_started["night-1"] > 0`、这条排程随即判 `not_yet`
- `起过一次就不再起_哪怕这趟跑完了`：中止这趟后再过几拍不重复起
- `重启后靠归档回查_已经起过的那一轮不重复起`：预置 `runs/night/20260907T140500Z/`（22:05 吉隆坡）→ 22:10 起来的执行器不起、判 `not_yet`
- `还没到点就不起`：钟 21:00
- `有人握着控制权就不自动起跑`：设 PIN 的服务、真 token、真取控制权 → 不起、`last_skip` 含"控制权"；还了之后起。（用租约簿直接记是不行的：`sweep()` 会把没有活会话的租约当场释放——这是对的）

第二轮新增：`到点了但引擎在跑_记成没轮到而不是静默丢掉`（人手起的任务在跑，到点后 `last_displaced` 含该排程，且没打断）· `钟不可信就不按钟出发`（`time_reference` 指本地钟快 3 小时 → 不起、`last_skip` 提到钟）· `tests/engine/test_alerts.py` 断言 `schedule_died` 是独立 P1。

`tests/app` 整组 + 排程单元测试 + CLI 测试全绿（除 W07 已记的 `test_static` 环境项）；ruff 干净。

## 四、已知边界

- 周期 30 s、窗口分钟级：最坏晚 30 s 出发。**未在真机验证**。
- `running="manual"` 只是占位：人手起的任务在跑时，排程到点会被 `pick` 判为 `displaced`，窗口过了就按 `on_missed` 处理；这符合 §3.3「正在跑的不许被排程打断」。
- 归档回查按**任务名**：同一任务被两条排程引用时，任一条起跑都算另一条这一轮"起过"（`decide` 本来就按任务算 `last_started`）。
- 起飞检查没过时每拍重试直到窗口关闭；失败原因只在 `executor.last_skip`，没有告警（W17）。
- `_SCHEDULE_PERIOD_S` 是模块常量，测试用 `monkeypatch` 拨小；协程读的是模块名字，所以拨得动。
