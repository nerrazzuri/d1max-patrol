# 商业化 A6 · P1 告警推送 · 设计与完工报告

> 决策 53：推送用聚合推送，选**极光**；**只推 P1、只推标题**，不带照片和位置。先把站点、手机两头做好，极光账号你注册以后再配（`docs/告警推送配置.md`）。

## 为什么要

App 的后台值守（W17）是 App 自己连着站点；手机厂商的省电管理把 App 杀掉以后，P1 就到不了手机。推送走手机厂商的系统通道，App 被杀也收得到。极光把华为、小米、OPPO、vivo、荣耀的通道接好了，站点只调极光一个接口。

## 站点

- **排队跟告警同一个事务**：告警写库时，没确认、没解决的 P1 排进 `push_outbox`（库结构 45）。
  - 新起一条排一次；没人确认、升到下一档再排一次；同一条同一档只排一次。
  - 记下了就一定会推，站点重启也不丢。
- **单独一条道往外发**（`PushDesk.tick`，放在线程里跑，不卡事件循环）：
  - 推给登记了的手机，停用的账号不推；一次最多 1000 台；
  - 已经有人确认、解决了的，不推；
  - 一个小时还没发出去的，作废；
  - 没有登记的手机，作废；
  - 发不出去就退避（10 秒起，翻倍，最多 5 分钟）。
- **发不出去报 P2**：连续 10 分钟报「P1 告警推送发不出去」，发出去一条就自动解决。按当前的队列每拍对账；这条 P2 自己不推。
- **极光接口**：REST v3，`Basic` 鉴权（AppKey、Master Secret）。只推标题，`extras` 里只有告警的键（App 以后用来跳转）。
- **配置**：`site.json` 里 `push.app_key`；Master Secret 放 `/etc/d1max-site/jpush.secret`，不进 `site.json`。没配就不推，值守汇总里明说为什么。
- **手机登记**：
  - `POST /api/push/devices` 登记推送号，`POST /api/push/devices/remove` 注销，都记在当前账号名下；
  - **值守令牌也能登记**：值守令牌就是为收 P1 发的；
  - 站点的 HTTP 服务不收 DELETE，所以注销跟别的接口一样用 POST。
- 值守汇总带上推送的状态：配没配、几台手机、在排队的、上一个错误。

## 手机

- 接极光官方 Flutter 插件 `jpush_flutter` 3.5.8。这个插件也支持鸿蒙，后面做鸿蒙样品时用得上。
- **进了站点（登录）就登记**这台手机的推送号，**离开站点**时先注销推送号、再注销会话。跟后台值守「登录进来就开、离开就停」一样。
  - 登记不上不挡进站点，后台值守照旧。
  - 桌面版、测试里不推。
- 推送号的获取包在 `PushRegistrar` 后面，测试换成假的。
- **AppKey 打包时给**，不进仓库：Android `-PjpushAppKey=…`，iOS `--dart-define=JPUSH_APPKEY=…`。没给照常能用，只是收不到推送。
- 按极光插件的说明，`MainActivity` 关掉 Flutter 的深链接处理：Flutter 3.29 起，App 被杀后点厂商通道的通知会白屏。我们不用深链接。

## 测试

- **站点**：
  - P1 新起排一条，同一条再来不重排，升档再排一条，P2 不排；
  - 只推标题给登记了的手机，停用的账号不推，`extras` 只有告警的键，推过的不再推；
  - 已经确认的不推；一小时没发出去作废；没有手机作废；
  - 发不出去退避，退避期内不重发，连续 10 分钟报 P2，发出去了自动解决，P2 自己不推；
  - 极光报文：鉴权头、受众、标题、正文；连不上、401 都抛错；
  - 配置：没配、没密钥文件、配好了；没配推送时告警不排队，值守汇总说没配；
  - 接口：登录的手机、值守令牌都能登记，记在自己名下；空推送号 400；注销；没登录 401。
- **手机**：进了站点报推送号，离开时先注销推送号再注销会话；不支持推送的平台什么都不报。手机端全部 312 条过，`flutter build apk --debug` 打得出包。
- **突变**：10 条全抓住：P2 也排、升档不重推、确认了照推、不作废、停用照推、不退避、发不出去不报、推了带位置、没配也排、值守令牌不能登记。

## 没做的、要你做的

- **注册极光、配厂商通道**：见 `docs/告警推送配置.md`。没有账号，这台机器上验不了真的推送，只验到极光的报文和鉴权。
- **点通知跳到那一条告警**：现在点开只是打开 App。`extras` 里已经带了告警的键，以后加跳转。
- **iOS、鸿蒙**：站点报文已经带了 iOS 的字段；手机这边等 B 阶段做 iOS 工程、鸿蒙样品时再接。

## 全量测试时抓到的

- 推送要在线程里发（同步、要等网络）。起先把告警循环的「道」改成「不是协程函数就放线程里」，太宽：测试替身的天气是返回协程的普通函数，被扔进了线程。现在只有推送明说要线程（`thread=True`），别的照原样（直接调、返回可等待的再等）。另加了一条测试：推送那条道卡住，事件循环照转。
- 系统审查 S06 那条测试的替身 `_lane` 不认新加的参数：每拍报错、记日志，循环永远等不到驱离，日志越攒越多，最后把内存吃光、进程被杀。替身改成把参数原样传过去。产品代码没有这个问题。
- 台式机硬盘满了（96%），巡检引擎的保护线是 95%，一大批引擎测试因此中止。删掉安卓的构建产物、Gradle 缓存之后恢复正常，跟这单的代码无关。
