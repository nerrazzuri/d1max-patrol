# 商业化 B1（第一部分）· 网页值班台：值班组 · 设计与完工报告

> B 阶段第一单。站点以前没有网页界面，值班只能用手机 App。这一单做的是**值班组**：
> - Live（视频墙）
> - Map
> - Alarms
>
> **管理组**（机器狗与摄像头、地图与防区、用户、名单、系统）是下一部分。
>
> 视觉按 B0 专业版（`docs/视觉规范.md`）；技术用 TypeScript + Preact + Vite（用户选）。

## 用户定的

- **以视频为主**：所有狗的前后两路在一页，可滚动；地图放另一个页签。
- **专业而不是漂亮**：设计助手按 frontend-design 技能和控制室规范（ISA-101、ISO 11064、ISA-18.2、VMS 惯例）评审后出的专业版。用户同意四条：
  1. 专业版；
  2. 第一版就做 P2 搁置；
  3. P2 不闪；
  4. 字体用 Atkinson Hyperlegible。
- **英文为主，中文可选**。
- 管理组排在后面。名单第一版做「时段 / 人员授权」；人脸、车牌另行立项。

## 做了什么

### 站点（`packages/site-node`）

- **网页静态文件**（`webui.py`）：
  - `/` 回值班台，`/assets/<文件>` 回构建产物（文件名带哈希，长缓存）；只认一层文件名，走不出 `web/`。
  - 每个回复都带严格的安全头：
    - CSP：只许本站的脚本、样式、图片、连接；不许内联；不许被嵌进别的页面；
    - `nosniff`、`X-Frame-Options`、`Referrer-Policy`。
  - 构建产物随站点包装（`package-data`），站点安装不用装 Node，离线可用。
- **浏览器登录用 cookie**：
  - `POST /api/login` 带 `"web": true` 时，种 `HttpOnly; Secure; SameSite=Strict` 的 cookie，**回复里不给令牌**，页面脚本拿不到。
  - 退出时清 cookie。手机、命令行仍用 `Authorization` 头，不受影响。
- **防跨站伪造**：靠 cookie 认人的改动请求必须带 `X-D1Max-Web: 1`，退出也要。
- **`GET /api/me`**：网页刷新后靠 cookie 认出是谁、什么角色、站点叫什么（`site.json` 的 `site_name`，没有就用 `site_id`）。
- **告警搁置**（ISA-18.2 shelving，库结构 50）：
  - `POST /api/alerts/{key}/shelve {until_ms, reason}` 和 `/unshelve`；
  - 只有 P2 能搁置，P1 不行；要有人、有原因；最多 12 小时；
  - 到点自动回来（不用谁去改）；再触发不打断搁置；写进库、记审计。

### 网页（`web/console`，构建到 `packages/site-node/src/d1max_site/web`）

- **Live = 视频墙**：
  - 每只狗一个外壳：铭牌条（编号、状态、电量、任务、Map），下面是前后两路画面，两只一行，按编号固定。
  - 每路画面上沿是「`D1-01 Front 02:15:08`」，下沿是 Live / Paused at … / Reconnecting…，可全屏（全屏里可切前后）。
  - **看得见才拉流**：可见面积 ≥25% 才拉；离开视口 2 秒后停，停之前把最后一帧压暗留着；浏览器页签藏起来也停。
  - **有 P1 的狗置顶成「报警画面」**：
    - 整行宽、3px 报警框，未确认时框闪；
    - 头条写「Person detected / East wall, 6.2 m ahead of D1-02 / Unacknowledged for 0:42」；
    - 前后两路一直实时；
    - 操作条：I'll handle it（中性主按钮）、Sound siren (level 2)、False alarm（要确认）、Show on map、Talk 暂未开通，以及驱离和人数。
  - 离线的狗收成一条斜纹窄条，不拉流；狗多于 4 只时顶上有跳转条。
- **报警队列**（底部常驻，ISA-18.2）：
  - 分 Active / Shelved / History 三页；
  - 状态分 Unacknowledged / New / Acknowledged / Shelved / Resolved；
  - 未确认的在前；只有未确认的 P1 闪；
  - P2 可确认、可搁置（1 小时 / 到 08:00 / 原因必填）；P3 不进队列。
- **Map 页**：
  - 地图铺满；正常的狗是中性灰白圆加朝向，异常的用形状 + 颜色；P1 位置是菱形加报警圈；
  - 右侧栏只给选中的狗拉前后两路小画面；
  - Live 以外的页签顶上都有全站 P1 条，可以直接「我来处理」。
- **顶栏**：
  - 页签：Live / Map / Alarms，Recordings、Reports 标「即将推出」；
  - P1 / P2 计数（形状 + 数字）；
  - 模式三段：Armed / Home / Visitor，切换要确认；
  - 时钟、EN / 中文、账号、退出；
  - **Stop all**：唯一的红色控件，带外框达到对比度要求，确认后逐只停车，停不了的点名说用遥控器。
- **中英文**：
  - 界面词条英文为主、中文完整；
  - 第一次打开按系统语言，选过就记住；
  - 告警标题按种类取 `design/i18n/alerts.json`（67 种，测试保证跟站点的告警表一致），不认识的种类用站点原文。
- **视觉数值**：全部来自 `design/tokens.json`（运行时挂成 CSS 变量）；字体 Atkinson Hyperlegible Next / Mono 自托管（latin 子集，OFL）。

## 测试

- **站点**：
  - 静态文件和安全头、走不出 `web/`（5 种路径）、没构建时 404；
  - cookie 登录、防伪造头、退出清 cookie、手机照旧；
  - `/api/me`；
  - 包里带的网页没有内联脚本和样式；
  - 搁置：规矩、到点回来、再触发不打断、重启还在、接口权限和坏参数。
- **网页**（Vitest 18 条）：
  - 词条齐全；第一次语言选择；告警标题按种类；
  - 狗的状态优先级；报警状态；队列排序；视频墙排序；正常状态不着色；
  - 坐标换算；请求头和 cookie；401 回登录页（开页时的「我是谁」不算过期）。
- **真跑**：本机演示站点（真站点 + 仿真狗）+ 无头浏览器截图：登录、Live、Map、中文、手机宽度、P1（拦截假告警）。
  - 截图时抓到并修了两个问题：
    - 一打开就提示「会话过期」；
    - 地图侧栏小画面的叠字挤在一起。
- **CI**：新增 `web` 任务：类型检查、测试、构建，再对比构建产物跟仓库里的一致。

# 第二部分：管理组（2026-10-11）

只有管理员看得到。顶栏上只占一个「Admin」页签，进去以后是子页签：
- 机器狗与摄像头
- 地图与防区
- 用户
- 名单
- 系统

## 站点新加的

- **网页上登记、出码、吊销机器狗**（`/api/admin/robots`，`manage`）：跟命令行 `enroll --code` / `enroll-code` / `revoke` 用同一套函数，证书、注册表、CRL 都一样。
  - **登记**：签证书，出一次性开通码（24 小时），默认「只许手动派」。
  - **重出开通码**：旧码作废。
  - **吊销**：注册表立刻生效，站点不再派它；CRL 也会更新，但消息服务（broker）要重启才断开这只狗的连接，回复里给出重启命令。
- **防区画在地图上**（`zone_areas` 表，`/api/maps/{map}/{version}/areas`，看要 `view`，改要 `manage`）：
  - 每张图每个版本，一个防区一个多边形，地图坐标，3–64 个角；
  - `zone_at` 按狗的位置算出它在哪个防区。
- **名单第一版：时段 / 人员授权**（`authorizations` 表，`/api/lists/authorizations`）：
  - 字段：谁、在哪（几个防区，或全站）、星期、几点到几点（站点本地时间，可以跨午夜，星期按开始那天算）、有效到哪天。
  - 授权生效时：
    - 摄像头那个防区的入侵事件只记录、不派狗，结果写「授权在场：园丁」；
    - 狗看见人、而且狗在授权的防区里（或者授权是全站的）：不报 P1，记一条 P3「授权在场」（新告警种类 `authorized_person`），这一回只记一次。
  - 人脸名单、车牌名单另行立项；页面上写明了「暂未开通」。
- 库结构 51。

## 网页新加的

- **机器狗与摄像头**：
  - 每只狗一行：在线与否、软件版本、兼容级别、自动 / 只许手动、证书到期；
  - 操作：切换自动派遣、重出开通码、吊销（要确认）；
  - 「添加机器狗」后直接弹出开通码，可以复制，并提醒别贴到工单、截图里；
  - 固定摄像头列表（添加还是在站点主机上用命令行）。
- **地图与防区**：选一张图，「画防区」以后在图上点出各个角，可以撤销一个点，画完起名、保存；可以删除。禁行区一起画出来做参照。
  - 值班的地图页也会淡淡地显示防区和名字，不能改。
- **用户**：
  - 列表；改角色、停用 / 启用、重设口令（自己的不能在这里改）；添加用户；
  - 最近 100 条操作审计。
- **名单**：授权列表和「添加授权」（谁、全站或选防区、星期、从几点到几点、有效到、备注），带跨午夜的说明。
- **系统**：
  - 体检每一项（关键项标出来），没过的用 P2 / P1 的形状加颜色标出；
  - 各狗的兼容情况；
  - 下载诊断包。

## 测试

- **站点**：
  - 网页登记、出码、吊销：只有管理员能做；重出以后旧码作废；吊销以后领不到码，也不能再出码；坏参数回 400。
  - 防区多边形：校验，按位置算防区，改和删。
  - 授权：
    - 星期、时段（结束那一分钟不含）、跨午夜（第二天早上按开始那天的星期算）；
    - 有效期；防区或全站；说不清在哪个防区时只认全站授权。
  - 联动：摄像头入侵有授权时只记录；狗在授权防区里记 P3、只记一回，走出去照报 P1。
  - 接口权限。
- **突变**：14 条全抓住：跨午夜不认、星期不看、防区不看、有效期不看、结束那一分钟也算、点在多边形里判反、小多边形照收、入侵不看授权、狗不看授权、授权不记一回、防区谁都能改、名单谁都能改、登记狗谁都能做、P1 也能搁置。
  - 「授权不记一回」第一次没抓住：测试里的假告警台会把重复的合并，掩盖了问题。已经加上直接检查记录。
- **网页**：Vitest 20 条，新增坐标来回换算、星期显示。
- **真跑**：演示站点接上 C40221 现场的真地图，无头浏览器走完整条流程：
  - 添加机器狗，拿到开通码；
  - 在地图上画「Back garden」并保存；
  - 加「Gardener，Back garden，工作日 09:00–11:00」；
  - 看用户、审计、系统体检。
  - 截图时发现并修了两个问题：
    - 管理组页签让顶栏挤成两行，改成一个「Admin」加子页签；
    - 摄像头空列表没有提示，「失败」的字样也写错了。
