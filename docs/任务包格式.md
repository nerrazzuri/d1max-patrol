# 任务包格式

> **2026-10-14 起：站点存的路线、排程是唯一真理源。** 路线在网页「Routes／巡检路线」页和手机 App 里
> 直接画、改（只有管理员能存，看是谁都能看）；派遣器、排程执行器读的就是站点库里这份。任务包
> **仍然能导入**（同一个库、同一套规矩），站点也能把库里的路线和排程**导出成任务包**做备份、搬站点。
> 下面讲的是包本身的格式，没有变。
>
> - **导入是「并进」，不是「整包替换」。** 按名字：包里的任务和站点上同名的路线 → 内容一样算没变
>   （不动修订号），不一样就替换；站点上原有、包里没有的路线和排程**留着**，**绝不悄悄丢排程**。导入回的摘要
>   写明新加、替换、没变、留着的各是哪几条。要让某条排程消失，在站点上删它。
> - **排程时区整个站点一个。** 包里有 `schedule.yaml` 时它的时区算数；跟站点现在的不同、而站点上还有包里
>   没有的排程时拒收（换时区它们的钟点会悄悄换了意思）。包里没有 `schedule.yaml` 就是排程、时区都不动。
> - **每条排程自己记「从什么时候起算数」**：新加、改了钟点、导入替换、换时区的那一刻起。那之前到点的轮次
>   不跑、不补记、不告警（原来是按「包导入的那一刻」整包算，意思一样）。
> - **导出**：`d1max-site export-bundle OUT_DIR`，或管理员 `POST /api/route-export`（落在站点主机的
>   `route-exports/`）。包 id 是 `site-routes`，版本号取「库修订号、已导入过的同 id 最大版本」里大的再加一，
>   `import-bundle` 收得下（版本号只许往上走）。没绑地图版本的路线打不成包，先在路线页选版本。
> - **每条路线必须绑 `map_version`**，存的时候逐点校验（在这一版图的可通行格子上、离建图走过的路不超过
>   5 m、不超过 500 个点和 200000 字节）。路线名和排程 id 只许 ASCII 字母、数字、`.`、`_`、`-`。
> - 升级到库结构 58 时，原来的「当前包」里的任务和排程原样抄进库里（排程从那次导入起算），派遣、排程
>   照旧。老包留作导入记录。

一个任务包就是一个目录。**里头全是数据，没有一行可执行的东西。**

判据是这一句：**断网 72 小时，这只狗还能不能照常上岗？** 答案是「不能」的
东西，都得进包（设计 spec §3.1）。

## 目录长什么样

```
site-kl-7/
  bundle.yaml          # 这个包是谁、第几版、内容指纹
  schedule.yaml        # 什么时候跑什么
  missions/            # 每个任务一个 .json
    night.json
  maps/                # 地图
    floor1.pgm
```

## bundle.yaml

| 键 | 类型 | 说明 |
|---|---|---|
| `bundle_id` | 字符串 | 2–48 个小写字母／数字／连字符。**会被拼进路径。** |
| `version` | 整数 | 1 到 999999。**不许用时间戳**，见下。 |
| `schema` | 整数 | 任务格式的版本。当前是 2（2：每个任务都绑地图版本，见下面 missions/）。**打包器自己盖，不用手写。** |
| `content_sha256` | 字符串 | 整包指纹。**打包器自己算，不用手写。** |
| `built_at` | 字符串 | ISO8601，**必须带时区**。 |
| `built_by` | 字符串 | 谁编的。可以不写。 |
| `targets` | 字符串列表 | 这份包发给哪几台机器的 SN。**不写就是不限。** |

**`targets` 空着是常态。** 站点的当前包对站点上的每一只狗都有效，**站点这一版不看
`targets`**：它是给狗上落包那一套用的（狗上落包随 W00c5e 退役），格式里留着这个字段，
只是为了老包照样导得进来。要让某只狗只跑某几条任务，在排程里指定狗。

**为什么版本号不许用时间戳。** 版本号要回答的是「哪一版更新」，而这个问题
必须有一个确定的答案。两台机器的钟可以差几分钟甚至几个月（RTC 电池没电、
刚刷完机），拿时间戳当版本号，「更新」这件事就跟着钟一起漂了。上界 999999
就是拿来拦时间戳的：报错会点名说它看着像时间戳。

**同一个版本号不许换内容。** 站点导入那一步会拒。改了包就升版号。

**时区不在这份文件里。** 它在 `schedule.yaml`。写两份就是两个真理源，
两份不一致的那天没人说得清该信哪个。

## schedule.yaml

| 键 | 说明 |
|---|---|
| `timezone` | IANA 时区名，比如 `Asia/Kuala_Lumpur`。**必填。** |
| `entries` | 排程条目的列表。可以是空的。 |

**时区写在包里，绝不读系统时区**（§3.3 第 1 条）。刷机、OTA、换主板 ——
这几件事都会让一台机器的系统时区悄悄变回 UTC，而没有任何一条告警会响：
狗会一脸认真地在错误的时间去巡逻。所以「没写时区」是个当场就炸的错，
不是一个兜底。

每条 entry：

| 键 | 说明 |
|---|---|
| `id` | 这条排程的名字。同一份包里不许重名。 |
| `mission` | 跑哪个任务，对应 `missions/<mission>.json` |
| `at` | `HH:MM`，24 小时制 |
| `days` | `[mon, tue, wed, thu, fri, sat, sun]` 里挑，至少一个 |
| `window_min` | **必填。** 迟到多少分钟以内还算数。 |
| `on_missed` | **必填。** `skip` ／ `run_late` ／ `alarm` |
| `priority` | 撞车的时候谁先跑。默认 0，越大越优先。 |

**`window_min` 是核心，不是装饰**（§3.3 第 2 条）。22:00 那一轮，狗 22:40 才
从充电桩上醒过来 —— 该跑还是不该跑？这个问题必须由写包的人回答，代码不猜。

**`on_missed` 也没有默认值。** 「没赶上」这件事的后果只有现场的人知道：有的
点位晚跑两小时照样有用，有的点位过了时间跑等于白跑还费一次电。

**跨午夜是算数的。** 23:30 那一轮配 60 分钟窗口，到第二天 00:15 还在窗口里。

**补跑窗口到午夜为止。** `on_missed: run_late` 能不能把「昨天那一轮」当成候选
补跑，只在排程的窗口**真的跨了午夜**（即 `at` 加上 `window_min` 到达或超过当天
24:00）时才成立。不跨午夜的排程，比如 `at: "08:00"` 配 `window_min: 30`，
补跑机会只到当天午夜为止 —— 过了午夜，昨天那一轮就当没发生过，不会被今天
补上。写窗口的时候要把这一点算进去：真正需要「隔夜也能补」的排程，窗口本身
就得跨过午夜。

一份例子：

```yaml
timezone: Asia/Kuala_Lumpur
entries:
  - id: night-1
    mission: perimeter-full
    at: "22:00"
    days: [mon, tue, wed, thu, fri, sat, sun]
    window_min: 45
    on_missed: skip
    priority: 10
```

## 撞车怎么办

**同一时刻只跑一个**（§3.3 第 3 条）。两条排程同一分钟到点：

1. `priority` 大的先跑
2. 一样大，到点时刻早的先跑
3. 还一样，按 `id` 的字典序

没轮上的那些，各自按自己的 `on_missed` 处理。**正在跑的任务不会被排程打断。**

## missions/

每个任务一个 `.json`，格式跟契约里 `d1max_contract.mission` 的任务定义一样。打包器（`d1max_contract.bundle_format.build_bundle`）会把
每一个都过一遍解析 —— **打包的时候发现坏任务，比半夜出发之后发现要好** ——
然后重写成规范形式并盖上 `schema`。

`schema` 是打包器盖的，不用手写。它记的是这份任务用的是第几版任务格式，
格式哪天升级了，靠它分辨新旧。

### 每个任务都要写 `map_version`（R1，2026-10-14）

```json
{"mission": "perimeter-full", "map_id": "estate-1", "map_version": "7", "waypoints": [...]}
```

**`map_version` 是这些点在哪一版图上量的。** 地图号加版本才是一个坐标系：每次建图原点都不一样，
第 7 版上的 (3, 2) 落到第 8 版上，可能是一个能走、但不对的地方（离建图路线 5 m 以内、落在能走的格子上
这道检查挡不住它）。所以：

- 写成字符串（`"7"`，不是 `7`），1–64 个字符；版本号在站点地图页（`GET /api/maps`）里看。
- **打包器不收没写的任务**：报错点名是哪个文件。**站点也不导入**没写的老包（schema 1），报错列出站点上
  这张图有哪几版 —— **只列，不替人挑**：哪一版是这些点量的，只有画点的人知道。核过点再写，重新打包。
- 换了图（重建出新版本）之后，老任务**不会**自动跟过去：站点不派（见下面「狗上没有任务包」），要在新图上
  核过点、改 `map_version`、升包的版本号、重新导入。

## 哪些东西不进包

* **固件和代码。** 包是纯数据。
* **VLM 权重和 API key。**

「纯数据」这条界靠**四道互相独立的闸**挡着。任何一道没过，包都编不出来，
也落不了盘：

| 闸 | 拦的是 |
|---|---|
| 后缀白名单 | 只认 `.yaml` `.yml` `.json` `.md` `.txt` `.csv` `.pgm` `.png` `.jpg`。别的一律拒，**连没有后缀的也拒**。 |
| 符号链接 | 一条指向 `/etc/shadow` 的链接，光是算哈希就会把它读出来。 |
| 可执行位 | `chmod +x` 过的文件。 |
| shebang | 头两个字节是 `#!` 的文件。这道抓的是「改成 `.txt` 的脚本」—— 白名单放行了后缀，它拦住内容。 |

**一道后缀名闸永远不够** —— 后缀是可以随手改的。四道全要。

## 狗上没有任务包

**任务包导进站点，不落到狗上**（W00c5e 起；决策 8：信息都在站点上）：

- 管理员在站点主机上 `d1max-site import-bundle <任务包目录>`（或者站点接口
  `POST /api/bundles`，管理员）。站点先把上面那四道闸和整包指纹核一遍，过了才收，
  **这一份成为站点的当前包**。
- **排程在站点上跑。** 站点每 30 秒按当前包里的 `schedule.yaml` 判一次，到点了给这条排程指定
  的那只狗（排程里的 `robot`）下一条巡检命令。**站点上不止一只能派的狗、排程又没指定 `robot`，
  站点挑一只**（W28，决策 46）：电量最高的先，一样就定位质量高的；挑了谁、为什么写在这一轮的记录里。
  （W28 之前是记一笔 `ambiguous`、不派。）**巡检命令里带着这一趟的任务（`missions/` 里那一个）
  和任务绑的地图版本**（R1）：
  - **站点先核**：任务的 `map_id` 和 `map_version` 要跟狗加载的那一张图、那一版一模一样，不一样不派
    （手动派单回 409，说清楚任务是第几版、狗是第几版）。排程挑狗时版本不对的狗不算能派的，挑别的；
    都不行记 `no_robot`（备注写着哪只狗是第几版），过宽限期报「这一轮没跑」。
  - **任务没绑版本**（站点升级前导入的老包）：哪只狗都不派，排程这一轮记 `dispatch_failed`、当场报；
    `GET /api/schedule` 的 `unbound_missions` 列着这几个任务。**站点绝不拿狗现在用的那一版去补。**
  - **狗再核一遍**：命令里的 `map_version` 是**任务的**（以前填的是狗自己的，狗的核对等于空转），
    任务自己带的版本、命令的版本、狗加载的版本三样都得一样，不然拒收（`map_mismatch`，或者
    `payload: …`），站点记一笔 `dispatch_failed`。
  - 版本兼容：不收没绑版本巡检的代理是**代理级别 3**；老站点不认 3 级，所以**先升站点、再升狗**
    （`docs/版本兼容与升级顺序.md`）。新站点照样能派 2 级的老狗：老狗本来就核命令里的版本。
- **换包不打断正在跑的一趟**：正在跑的那一趟用的是它那条命令里带下去的任务，跟站点换没换包
  没有关系；新包从下一轮排程起生效。站点挑狗时跳过正忙着的狗。
- **狗离线时站点不替它补跑。** 到点了没有能派的狗，站点记一笔 `no_robot`；过了窗口，按排程的
  `on_missed` 判跳过还是报警。
- 狗上没有任务包，也就没有「狗手上这一版和站点那一版的落差」：值守屏那一格写着
  「任务随命令下发，狗上没有任务包」。

**想让一只正在跑的狗停下来**：手机上的「叫停」（中止这一趟）或「停」（halt，当场停车），
业主也能按；还有一条不经过任何软件的：**机身上的物理急停**。

## 接口

| 在哪儿 | 怎么做 | 干什么 |
|---|---|---|
| 笔记本 | `python -m d1max_patrol.cli bundle pack <源目录> <放包的父目录> --id <包 id> --version <版本>` | 造包：四道闸、盖 schema、算指纹、写 `bundle.yaml` |
| 站点主机 | `d1max-site import-bundle <目录>` | 导入一个任务包，成为当前包 |
| 站点接口 | `POST /api/bundles`，体是 `{"path": "<站点主机上的目录>"}`（管理员） | 同上 |
| 站点接口 | `GET /api/schedule` | 当前包、每条排程此刻的决定、下一轮、最近几轮的去向 |
| 站点接口 | `POST /api/robots/<狗>/patrol`，体是 `{"mission_id": "..."}`（管理员、保安） | 手动派一趟当前包里的任务 |
