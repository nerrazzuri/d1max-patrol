# 任务包格式

一个任务包就是一个目录。**里头全是数据，没有一行可执行的东西。**

判据是这一句：**断网 72 小时，这只狗还能不能照常上岗？** 答案是「不能」的
东西，都得进包（设计 spec §3.1）。

## 目录长什么样

```
site-kl-7/
  bundle.yaml          # 这个包是谁、第几版、内容指纹
  schedule.yaml        # 什么时候跑什么
  missions/            # 每个任务一个 .json
    night.json
  maps/                # 地图
    floor1.pgm
```

## bundle.yaml

| 键 | 类型 | 说明 |
|---|---|---|
| `bundle_id` | 字符串 | 2–48 个小写字母／数字／连字符。**会被拼进路径。** |
| `version` | 整数 | 1 到 999999。**不许用时间戳**，见下。 |
| `schema` | 整数 | 任务格式的版本。当前是 1。**打包器自己盖，不用手写。** |
| `content_sha256` | 字符串 | 整包指纹。**打包器自己算，不用手写。** |
| `built_at` | 字符串 | ISO8601，**必须带时区**。 |
| `built_by` | 字符串 | 谁编的。可以不写。 |
| `targets` | 字符串列表 | 这份包发给哪几台机器的 SN。**不写就是不限。** |

**`targets` 空着是常态。** 单机站点、以及打给一整批狗的通用包，都不用列。
列了之后，**不在名单上的机器换不上这份包** —— 它照样落得下来（拿一块备份盘
给五台狗分发同一堆目录是正常操作），但换链那一步会拒。

SN 得跟机器自己报的那个字**逐字相同**：大小写、连字符，一个都不能差。
包这一层不做「聪明的」匹配，因为那会让「为什么这台换不上去」变成一个要读
两处代码才答得出的问题。机器自己是哪个 SN，`GET /api/identity` 里看得到。

**为什么版本号不许用时间戳。** 版本号要回答的是「哪一版更新」，而这个问题
必须有一个确定的答案。两台机器的钟可以差几分钟甚至几个月（RTC 电池没电、
刚刷完机），拿时间戳当版本号，「更新」这件事就跟着钟一起漂了。上界 999999
就是拿来拦时间戳的：报错会点名说它看着像时间戳。

**同一个版本号不许换内容。** 落盘那一步会拒。改了包就升版号。

**时区不在这份文件里。** 它在 `schedule.yaml`。写两份就是两个真理源，
两份不一致的那天没人说得清该信哪个。

## schedule.yaml

| 键 | 说明 |
|---|---|
| `timezone` | IANA 时区名，比如 `Asia/Kuala_Lumpur`。**必填。** |
| `entries` | 排程条目的列表。可以是空的。 |

**时区写在包里，绝不读系统时区**（§3.3 第 1 条）。刷机、OTA、换主板 ——
这几件事都会让一台机器的系统时区悄悄变回 UTC，而没有任何一条告警会响：
狗会一脸认真地在错误的时间去巡逻。所以「没写时区」是个当场就炸的错，
不是一个兜底。

每条 entry：

| 键 | 说明 |
|---|---|
| `id` | 这条排程的名字。同一份包里不许重名。 |
| `mission` | 跑哪个任务，对应 `missions/<mission>.json` |
| `at` | `HH:MM`，24 小时制 |
| `days` | `[mon, tue, wed, thu, fri, sat, sun]` 里挑，至少一个 |
| `window_min` | **必填。** 迟到多少分钟以内还算数。 |
| `on_missed` | **必填。** `skip` ／ `run_late` ／ `alarm` |
| `priority` | 撞车的时候谁先跑。默认 0，越大越优先。 |

**`window_min` 是核心，不是装饰**（§3.3 第 2 条）。22:00 那一轮，狗 22:40 才
从充电桩上醒过来 —— 该跑还是不该跑？这个问题必须由写包的人回答，代码不猜。

**`on_missed` 也没有默认值。** 「没赶上」这件事的后果只有现场的人知道：有的
点位晚跑两小时照样有用，有的点位过了时间跑等于白跑还费一次电。

**跨午夜是算数的。** 23:30 那一轮配 60 分钟窗口，到第二天 00:15 还在窗口里。

**补跑窗口到午夜为止。** `on_missed: run_late` 能不能把「昨天那一轮」当成候选
补跑，只在排程的窗口**真的跨了午夜**（即 `at` 加上 `window_min` 到达或超过当天
24:00）时才成立。不跨午夜的排程，比如 `at: "08:00"` 配 `window_min: 30`，
补跑机会只到当天午夜为止 —— 过了午夜，昨天那一轮就当没发生过，不会被今天
补上。写窗口的时候要把这一点算进去：真正需要「隔夜也能补」的排程，窗口本身
就得跨过午夜。

一份例子：

```yaml
timezone: Asia/Kuala_Lumpur
entries:
  - id: night-1
    mission: perimeter-full
    at: "22:00"
    days: [mon, tue, wed, thu, fri, sat, sun]
    window_min: 45
    on_missed: skip
    priority: 10
```

## 撞车怎么办

**同一时刻只跑一个**（§3.3 第 3 条）。两条排程同一分钟到点：

1. `priority` 大的先跑
2. 一样大，到点时刻早的先跑
3. 还一样，按 `id` 的字典序

没轮上的那些，各自按自己的 `on_missed` 处理。**正在跑的任务不会被排程打断。**

## missions/

每个任务一个 `.json`，格式跟 `engine/mission.py` 的任务定义一样。打包器会把
每一个都过一遍解析 —— **打包的时候发现坏任务，比半夜出发之后发现要好** ——
然后重写成规范形式并盖上 `schema`。

`schema` 是打包器盖的，不用手写。它对应装机那一头的
`requires_mission_schema`（§7.2）：一份用了新格式的包，装到一台老固件的狗上
会被拒，而不是被将就着跑。

## 哪些东西不进包

* **固件和代码。** 包是纯数据。
* **VLM 权重和 API key。**

「纯数据」这条界靠**四道互相独立的闸**挡着。任何一道没过，包都编不出来，
也落不了盘：

| 闸 | 拦的是 |
|---|---|
| 后缀白名单 | 只认 `.yaml` `.yml` `.json` `.md` `.txt` `.csv` `.pgm` `.png` `.jpg`。别的一律拒，**连没有后缀的也拒**。 |
| 符号链接 | 一条指向 `/etc/shadow` 的链接，光是算哈希就会把它读出来。 |
| 可执行位 | `chmod +x` 过的文件。 |
| shebang | 头两个字节是 `#!` 的文件。这道抓的是「改成 `.txt` 的脚本」—— 白名单放行了后缀，它拦住内容。 |

**一道后缀名闸永远不够** —— 后缀是可以随手改的。四道全要。

## 狗上是什么局面

```
/opt/d1max/bundles/
  site-kl-6/
  site-kl-7/
  current  -> site-kl-7      # 正在跑的
  previous -> site-kl-6      # 退得回去的
  landed.json                # 证没证过、退过哪些
```

**永远留两份**（§3.2）。新包首次执行就崩，自动退回 `previous` 并上报；
**退过的那一版默认不许再上**，除非人明确强推 —— 不拦的话就是一个安静的
死循环，现场看到的是「狗一直在重启」。

**那两条符号链接是「在跑哪一版」的唯一真理源。** `landed.json` 只记两件事：
哪一个槽被证过、退过哪些（只增，清磁盘也不清）。

## 服务器那一版和狗手上这一版

**狗手上那一版是「执行」的唯一真理源；服务器那一版是「意图」的唯一真理源**
（§3.4）。两边不一致是常态，不是异常 —— 狗断网了、推送还没到、包落好了还
没生效。**值守屏必须显式显示这个落差**（画屏那一半在第 9 卷；判断这一半
已经是 `engine/bundle.py` 里的 `divergence()` 了）。

落差分五种：

| 值 | 意思 |
|---|---|
| `in_sync` | 两边同一版，内容指纹也一样 |
| `behind` | 狗落后。服务器已到 v9，狗还在 v7 |
| `ahead` | **狗超前。** 服务器被回滚过，狗手上那一版已经被撤回了 |
| `never_synced` | 从没对过话。两边碰巧同号也不算一致 |
| `conflict` | 同号不同内容，或者压根不是同一个 `bundle_id` |

**`ahead` 和 `conflict` 是这张表里最要紧的两行。** 它们看起来都像「已同步」，
而实际上一台狗正带着一份已经被撤回、或者根本不属于这个站点的包在上岗。

推送不打断正在跑的任务。停机指令走独立的实时通道，不走这条路（第 8 卷）。

## 接口

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/bundle` | 现在是哪一版、证没证过、退过哪些 |
| POST | `/api/bundle/apply` | 让某一版生效，体是 `{"slot": "site-kl-7"}` |
| POST | `/api/bundle/rollback` | 退回上一版，体是 `{"reason": "..."}` |
| GET | `/api/schedule` | 排程、每条此刻的决定、下一轮、时钟漂移 |

回滚记录里的时刻是**服务端盖的**，请求里带的 `at` 一律不收。
