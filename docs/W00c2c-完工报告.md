## 交付

- **入口**：签名的 HTTP 回调 `POST /api/incidents`（不要登录）。每个事件源 `d1max-site source-add NAME` 登记，拿到一个只显示一次的共享密钥；请求头 `X-D1MAX-Source`、`X-D1MAX-Timestamp`（十进制毫秒）、`X-D1MAX-Signature = hex(HMAC-SHA256(密钥, 原样时间戳头 + "." + 原始请求体))`。时间差超 5 分钟拒；同一 `(source, event_id)` 只处理一次。
- **拦截点与防区**：`d1max-site intercept NAME --map M:VER --pose x,y,yaw`、`zone ZONE INTERCEPT`（也有 API）。拦截点记地图与版本，版本对不上的狗不派。
- **选狗**：在线、新鲜、就绪、地图与版本对得上、没在处理别的事件的狗里，按最近一次遥测位姿离拦截点最近的一台（契约 `DispatchClient` 因此订上遥测）。正在跑巡检或回程的可以派（事件优先级 80 抢占它们）。
- **派什么**：`goto` 去拦截点，优先级 80；到了之后由 W00c2b 自动回待命点。**同一防区 60 s 内的后续事件合并**到已出动的那条。
- **账**：`incidents` 表，去向 `dispatched / merged / duplicate / unmapped / ignored_type / no_robot / dispatch_failed`（发送中是 `dispatching`），结果由事件回写；每一条与每次回写都推 SSE（`kind: incident`）。`GET /api/incidents`（要登录）。

## 设计取舍

1. **只认 `intrusion`**，别的类型记账不派（`ignored_type`）。
2. **两个事件同时到不派给同一台狗**（内部评审阻断）：派单前先把这一行记成 `dispatching`，账上「派了、没结果」的狗算忙（30 min 上限，防丢了终态的任务永远占着）。原来只看狗自己报的 status，回执等待期间它还没跟上。
3. **401 一律「验签没过」**，具体原因只进站点日志；未登记的源也照算一次 HMAC。不让人探出哪些源登记过。
4. **签的是原样的时间戳头**；时间戳只认十进制纯数字、签名只认 64 位十六进制（非 ASCII 的签名头原来会 500）。
5. **只并入真出动了的那条**：派单失败的不吸收后续事件；回执超时按「可能在路上」算出动。派单时任何意外异常都记 `dispatch_failed`，不留半截。
6. **事件源密钥明文存在站点库里**（HMAC 需要原密钥）；`site.db` 收紧到 0600。密钥轮换、删源、限流没做。
7. **狗那边**：同优先级的第二条 goto 如果在第一条还在 `pending`（没起跑）时到，代理会收下排队（资源账本只看正在跑的）。站点这边已经用账挡住；代理侧的这个语义记在这里，W00d 之后再看要不要收紧。

## 测试与突变

`test_site_incidents.py`（15 条）、`test_site_api.py`（事件回调 1 条）、`test_site_cli.py`（1 条）。突变 19 条全红（不验签名、不查时间戳、不去重、不合并、挑最远的、不查拦截点版本、事件优先级降级、结果不回写、不避开在处理事件的狗、防区没映射也派、类型不挑、不看账上占着的狗、签名头不检查格式、时间戳宽松、401 说原因、失败的也吸收、意外异常不收、只推派出去的、库不收紧权限）。「时间戳宽松」起初活了（签名覆盖原样时间戳头，挡住了），加了「按怪写法签好的也不收」后红。
