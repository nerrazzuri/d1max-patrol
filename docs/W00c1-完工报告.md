## 工单与交付

> `packages/site-node`；Mosquitto + mTLS + 按 `robot_id` 的 ACL；站点自建 CA（openssl）签发狗证书、吊销；最小派遣（`goto`/`abort` 经 `DispatchClient`，落 SQLite）；最小站点 API（登录、机器人列表与状态、派单、事件流）。

- 新包 `packages/site-node`（`d1max_site`），**只依赖契约包**，不依赖根包、代理、适配器（工作区测试守住）。
- 站点 → broker → 狗整条链路已用真进程跑通：`d1max-site` 命令行建站点、签证书、加账号 → 真 Mosquitto（mTLS + ACL）→ `d1max-site serve` 子进程 → `d1max-agent` 子进程（sim，带证书）→ 站点 API 派 `goto`/`abort`。
- 契约与代理侧配套：`PahoTransport` 支持客户端证书；**连接被拒不再当成已连上**（原先 CONNACK 带失败码也会走「已连接」分支）；`d1max-agent` 加 `--tls-*`；代理正常退出时自己发 retained 的 offline status。
- 站点主机部署文件：`deploy/site/{d1max-mosquitto.service, d1max-site.service, install-site.sh}`。狗上的 `install.sh` 不碰站点，站点脚本不碰狗（有测试）。

## 设计取舍（审核请重点看）

1. **事件流用 SSE，不用设计稿写的 WebSocket。** 老服务端的 `/api/events` 就是 SSE，手机端现成会接；W00c4 迁手机时少改一层。站点 → 客户端是单向推送，SSE 够用。第一帧是全量快照；订阅者队列满了就标 `lagged`，下一帧补全量快照，不悄悄丢。
2. **连接被拒要抛错。** 原来 `PahoTransport._on_connect` 不看 reason code，broker 回「未授权」也会把连接标成已连上、`connect()` 正常返回。W00c1 上了 mTLS 后这就是「证书被吊销的狗以为自己连上了」。改为 CONNACK 失败、连接失败回调、CONNACK 前断开（TLS 1.3 下服务端拒客户端证书的样子）都让 `connect()` 抛 `ConnectionError`。
3. **吊销要重启 broker 才对 broker 生效。** Mosquitto 只在启动时读 CRL。`revoke` 先改注册表（派遣器立刻不再给它派单），再更新 CRL；命令行提示 `systemctl restart d1max-mosquitto`。已连着的被吊销狗在 broker 重启前不会被踢。
4. **站点在 broker 上的身份是保留名 `site:<site_id>`。** CA 与注册表都拒绝以 `site:` 开头的 `robot_id`，狗不可能拿到站点的 ACL。
5. **站点 API 绑到非本机地址必须 HTTPS。** 用站点服务证书；只绑 `127.0.0.1` 时允许 HTTP。`serve` 按绑定地址自动选。令牌只认 `Authorization: Bearer`（SSE 也是）；手机信任站点 CA、SSE 的查询串令牌等归 W00c4。
6. **每条命令都绑在已认证账号上。** `issued_by` 只从令牌解析出的账号名来，请求体里没有这个字段；派遣器拒绝空的 `issued_by`。
7. **代理正常退出自己发 offline。** LWT 只在异常断线时由 broker 代发；原来 SIGTERM 之后站点要等 90 s 的新鲜度过期才知道狗不在了。派遣器测试里发现的。
8. **`control_epoch` 在 c1 固定为 1**（注册表持久化，吊销后重登不倒退）。代次的推进与租约归 W00c3。
9. **站点不依赖根包。** 自带一个小 `LoopThread`，不用根包的 `LoopBridge`：老 HTTP 面要在 W00c4 退役。
10. **Mosquitto 配置按空白切词**，`render_conf` 遇到带空白的路径直接拒绝（生产路径 `/var/lib/d1max-site/…` 没有空白）。
11. **狗的发布包里也带着 `packages/site-node` 与 `deploy/site`**（`release pack` 打整个 `packages/` 与 `deploy/`），但狗的 `install.sh` 不装它们。
12. **新鲜度按站点自己的钟。** 派遣条件里的「状态新鲜」按站点收到**实时**（非 retained）status 的时刻算，不按狗填的 `last_seen`：Orin 的钟现场就错过。代价：站点刚重启时只有 retained 的旧 status，要等狗下一次心跳（≤ 30 s）才算新鲜。
13. **broker 的 client_id 用证书名**（`use_username_as_clientid true`）。不然一台狗拿别人的名字当 client_id 就能把站点踢下线，或接管另一台狗的持久会话（攒着的 `abort` 就丢了）。
14. **站点证书总带 `127.0.0.1` 与 `localhost`**：`serve` 默认连本机 broker，要过主机名校验。
15. **命令行必须以站点目录的属主跑**（安装后是 `d1max-site`）。root 跑会把 CRL 重写成 root 的 0600，broker 重启后读不了。
16. **站点侧 `robot_id` 比契约更严**：只许 ASCII 字母、数字、`. _ -`，1–64 个字符（它要进证书 CN、openssl 的 `index.txt`、broker 用户名）。主机名同理，挡住 SAN 注入。

## 内部评审

只读子代理评审一轮（带复现脚本、对真 Mosquitto 跑过），**阻断 4 条，都已修**：

1. **站点连不上自己的 broker。** `serve` 连 `mqtts://127.0.0.1`，站点证书只带 `--hostname` 给的名字；安装示例没给 127.0.0.1，`d1max-site.service` 会一直重启。测试没发现是因为夹具写死了 `localhost/127.0.0.1`。修：站点证书总带本机两个名字；加「只给局域网名字 init，再连本机 broker」的真 broker 测试。M15。
2. **任何一台登记过的狗都能用别人的 client_id 把站点或别的狗踢下线**，还能接管别的狗的持久会话、吞掉排队的 `abort`。修：`use_username_as_clientid true`；加真 broker 测试。M10。
3. **登录接口没鉴权也能绕过请求体上限。** `Content-Length: -1` 让 `rfile.read(-1)` 一直读到 EOF；也没有套接字超时。修：负数 400，每个请求 30 s 超时。M11、M12。

## 外审第 1 轮（FIX-THEN-APPROVE）的处理

**阻断：CA 吊销失败会被静默当成成功。** 属实，已修。原来的 `cmd_revoke` 只在注册表与 CA 两边都失败时才报错；完整登记的狗若注册表吊销成功、CRL 更新失败，命令返回 0 并打印「已吊销」，重启 broker 之后那张证书照样能连。

现在 `revoke` 先看两边各有没有这台狗，再分开处理：

- **某一侧本来就没有**（enroll 半路失败留下的半状态）：跳过那一侧，照做另一侧，成功。
- **某一侧有、但吊销执行失败**（openssl 出错、CRL 写不进、库被锁，任何异常）：命令非零退出，消息写明哪一侧完成、哪一侧失败，例如「A 只吊销了一部分:注册表已吊销;CRL 更新失败: …」。**不打印「已吊销」。**
- **两侧都没有**：非零退出。
- 顺序不变：注册表先（派遣器立刻停派），CA 后。修好之后再跑一次 `revoke` 就能补完：已吊销的注册表行可以重复吊销，CA 那边已吊销的会被跳过。
- 成功时的输出带上两侧各自的结果，例如「已吊销 A（注册表已吊销;CRL 已更新）」。
