## 我替你做的决定（可以改）

1. **答题不签「要申请的证书指纹」**（设计里写了）：领证书时私钥是站点生成的，没有机器人自己的证书指纹可签。题是站点出的、5 分钟、只能用一次，绑了用途、站点、序列号，跟令牌在同一个请求里，效果一样。
2. **「同一序列号、同一把钥匙、原机在线 = 整盘克隆」没做**：在线的机器人自己重新开通也是这个样子，分不出来。整盘拷到别的板子，芯片编号对不上，已经拦住。
3. **续签**：要求这台在本站点核过设备身份。自动续签直接跳过（不告警）；网页上手动点「立即续签」只回中性的那句。开发样机、用 U 盘拷证书装的机器人，证书到期前要用开通码重新开通一次。
4. **站点主机上 `d1max-site enroll` + U 盘拷证书的老办法还留着**（工程师兜底用）：这样装的证书照常能用到期，但不给续签。有站点 root 的人本来就拦不住（设计第五节）。
5. **解绑时清掉这个序列号记下的设备公钥**：换主板以后同一序列号能重新加入，不会被判仿冒。
6. **老站点兼容**：站点没有出题的接口（旧版本），机器人就不答，照旧加入；新版本站点没装出厂公钥，谁都进不来，所以发行脚本要求包里有出厂公钥。
7. **顺手修了一个老毛病**：站点出的开通码里端口总写 8443，站点不在 8443 上听时（演示站点）机器人领证书连错。现在写站点实际听的端口。正式站点就在 8443，不受影响。
