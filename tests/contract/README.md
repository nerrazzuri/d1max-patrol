# 契约测试

这里的测试定义 `NavBackend` 的行为约定,与任何具体实现无关。

## 规矩

- 只能 import `d1max_patrol.backends.base` 和 `d1max_patrol.protocol.nav_types`
- 不许 import `vendor_nav`、不许 import `d1max_sim`、不许碰 `sim.faults`
- 不许断言任何实现独有的属性(`fallback_matches`、`_pending`、…)

违反以上任何一条,这套测试就不再是契约测试,换后端时会假通过。

（`conftest.py` 是唯一的例外:它必须知道跑的是哪个实现,才能把它装起来。）

## 核心契约与能力集

两条路线的能力天生不一样。厂商设备自己会建图、能重命名删除地图、能重定位;
自建路线的图是 ROS 侧 slam_toolbox 出的文件,这三件事都不归导航后端管。

于是契约分成两截:

- **核心契约** —— 每个后端都必须过:地图列举与加载、路径存取、栅格图、
  定位状态、点到点导航、速度、事件流。
- **可选能力** —— 只有声明了该能力的后端才跑对应的那组测试。

| 能力 | 含义 | vendor | local |
| --- | --- | --- | --- |
| `mapping` | 设备自己能建图 | ✅ | ❌ |
| `map_admin` | 设备自己能重命名/删除地图 | ✅ | ❌ |
| `reloc` | 设备自己能重置定位 | ✅ | ❌ |

**没有某项能力不等于可以什么都不做。** 每项能力都配了一条反向测试
(`test_不建图的后端必须明确拒绝建图` 等),要求后端**抛 `NavRequestError`**。
少了这一条,"不支持"就跟"悄悄什么也没干"分不出来 —— 上层会以为图正在建,
然后一直等一张永远不会出现的图。

## 加一个新后端

改 `conftest.py` 里的三张表,本目录其余文件不用动:

1. `BACKEND_FACTORIES` —— 一个异步上下文管理器,产出连好的后端;
2. `BACKEND_CAPS` —— 它声明支持哪些可选能力;
3. `BACKEND_READY` —— 怎么把它弄成"有一张可用的图",返回图名。
   厂商后端是自己建一张,自建后端是往工作目录里摆文件。

除这三处以外还要改别的,说明抽象漏了 —— 该修的是 `base.py`。
