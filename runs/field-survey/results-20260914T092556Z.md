## 厂商 nav 协议/状态机 深挖（2026-09-18）★重要
- **信封有多个变体，且有拼写错**（交付解析器必须都认）：
  - `get_loc_status`/`get_mapping_status`/`get_nav_status` → `data.req_result.AppResponse.{req_func,status,msg,data,error_code}`

- **设备真报 `data:"Unknown"`**：遥控器接管驱动机器后，loc/mapping/nav 全变 `Unknown`（不是解析失败，是设备真值）。

- **`odom_ground_truth` 推送**（app_sub_topic）：上装主动推真值里程 —— pose.position(x,y,z)+orientation(四元数)+twist。可直接订阅拿位姿，不必自建 SLAM 定位。

- **map-start 二次确认**：即使抓到 `建图:MappingReady` 的瞬间发 map-start，仍被拒"无法建图的状态" → **MappingReady 状态不是充分条件**。强烈怀疑：**vendor 建图需要 上装持有 SDK 控制权，而 patrol_agent 握着 → 建不了**。待用"遥控器接管(held=0)时发 map-start"验证。

## ★ 建图畸变 —— 根因定位与解决（2026-09-18，按现场专家框架逐层诊断）
**逐层测试结论：**
- Test A 静止：墙帧间抖动 -90°仅0.1cm → 传感器/TF/外参基线 OK。
- Test C 转360°：odom 测得 -362.4°（实转360°），首末朝向差 2.4° → **odom yaw 准（0.7%误差），不是漂移问题**。
- deskew 前后对比：full"穿插快走"包 deskew 也救不回（帧间跳太大）；慢走包 deskew 后墙变直。
- **诊断链**：静止OK + odom准 → massive 扭曲/扇形 = **快速驾驶（5Hz扫描+快动，帧间位姿跳跃 → 扫描匹配失败）**，不是硬件/odom。
**解决：**
1. **deskew**（自研节点 deskew_scan.py）：用逐点绝对时戳+odom SE2插值把帧内100ms点校正回帧头位姿。治弯墙。
2. **只用前雷达**：消除双雷达外参误差 + 305ms 时间不同步两大脏源。
3. **极慢平滑驾驶**：降低帧间运动，让扫描匹配可靠。
**验证**：慢走+deskew → 墙变直（技术通）。剩余唯一缺口=**驾驶覆盖**（单点扫不全整房，需机器实际走遍房间各处）。
**关键教训**：厂商 demo 图漂亮是因为走得极慢；快走+稀疏扫描是畸变主因，不是算法问题。

## ★★ 建图问题最终定论（2026-09-18）
- **实体墙测试（户外/隔离玻璃变量）**：deskew+慢走管线 → **两面干净直墙拼成清晰直角**。**管线验证正确。**
- **房间建图失败真因 = 玻璃墙**：现场房间四面是玻璃，2D LiDAR 打玻璃穿透/乱反射 → 玻璃墙扫不到或鬼点 → 之前的稀疏/扭曲主要源于此（叠加早期快走）。**这是 2D 雷达对玻璃的物理限制，非 SLAM 算法可解。**
- **玻璃场景的解法（交付需知）**：① 玻璃上雷达高度贴反光条/反光贴 ② 靠玻璃以下的实体踢脚线/窗框（mullion）/固定家具做特征 ③ 加超声/ToF 补玻璃 ④ 高度带调到能扫到实体结构的位置。纯靠 2D LiDAR SLAM 建玻璃房间不可靠。
- **交付管线（已验证可用，实体环境）**：机器狗自己的前 RS-Airy（/front_lidar）→ deskew_scan.py（逐点时戳+odom 校正）→ slam_toolbox。零上装依赖。慢走是关键。

## ★★★ 建图架构结论 —— 修正版（2026-09-18，经技术评审 + 决定性实验）
**纠正之前两处错判：**
1. RS-Airy 是 **360°×90° 半球 3D LiDAR**（192线, ~172万点/s, 自带IMU），**不是"前向半球"**。有效FoV被机身/腿遮挡是另一回事。
2. 不能说"2D SLAM 对商场必然不可行" —— 优质360° 2D LiDAR+odom+IMU 在商场可正常SLAM。真正问题：**我们拿 3D 雷达压成了信息量极低的单层 2D observation。**

**决定性实验（一帧原始点云量化）：**
- 46,302 点 / 帧，水平 **-180~+180°(360°)**，垂直 **z 0.19~14.14m**。
- 高度分布：0.15-1.5m=63%，1.5-2.5m(高墙/招牌)=17%，2.5-5m(天花板/梁)=16%，>5m=2%。
- **当前 2D 投影(0.1-1.5m + range≥1.2)只保留 7%（3680点），扔掉 93% 高度信息。**
- **铁证：环境几何在雷达数据里，是 3D→2D 投影丢掉了天花板/柱子/招牌等所有高度约束。**

**严谨结论（写给研发报告）：**
> 当前 RS-Airy → 2D LaserScan → 2D occupancy SLAM 方案，在该商场测试区域观测稀疏、结构缺失。实体墙附近轮廓较稳，进入开阔/远距/玻璃区后有效2D return骤降。由于 RS-Airy 是 360°×90° 3D LiDAR，直接压成单层2D丢失天花板/立柱/门框等高度约束。下一阶段应优先验证 **原始 PointCloud2 + IMU 的 3D LIO（FAST-LIO2）**，其6DoF pose + 注册3D点云可再经高度过滤+XY投影生成 Nav2 用的2D occupancy。玻璃的无返回/异常反射需独立处理，LIO 提升定位鲁棒性但不消除玻璃问题。

**实施优先级（评审建议）：**① 单 Airy + IMU → FAST-LIO2 跑通验证；② 稳定后再加后雷达（双雷达外参+时间同步必须极准，40ms@1rad/s=2.3°重影）；③ 多高度带(0.15-2.0m)投影而非薄片；④ 大回环加 loop closure+pose graph。
